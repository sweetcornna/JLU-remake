# 01 知识点总览

这份是整门课的地图，内容来自 `分布式存储笔记.pdf` 全篇（169 页）。开学摸底和考前最后一遍看这份，细节去对应的分册里查。

## 全课的一条主线

这门课其实在回答一个问题：**一台机器存不下、算不动的数据，怎么摊到一堆便宜机器上还不出错。**

顺着这条线，六章的排布是这样的：

```
为什么要分布式          第一章 导论
    ↓
多台机器怎么协作          第二章 分布式系统基础（并行计算、MPI、集群管理）
    ↓
单机上怎么存             第三章前半（存储引擎、数据模型、事务）
    ↓
摊到多机会遇到什么问题     第三章后半（数据分布、容错、可扩展性、分布式协议）
    ↓
真实系统怎么解决          第四到六章（GFS/HDFS、Dynamo、Bigtable）
```

后面三个系统可以当成**同一组问题的三份答卷**来读。每读一个就回答同样五个问题，答案自然就记住了：数据怎么分布、副本怎么放、一致性保证到什么程度、故障怎么恢复、负载怎么均衡。

## 核心对比表

这几张表是简答题的主力，建议默写一遍。

### 三种单机存储引擎

| | 哈希（Bitcask） | B 树（InnoDB） | LSM 树（LevelDB） |
| --- | --- | --- | --- |
| 顺序扫描 | 不支持 | 支持 | 支持 |
| 磁盘写 | 顺序追加 | 随机写 | 顺序写，有写放大 |
| 随机读 | $O(1)$ | $O(\log_d N)$ | 可能查多层 |
| 索引位置 | 全部在内存 | 磁盘上的非叶子节点 | 稀疏索引，不全在内存 |
| 容量瓶颈 | 内存 | 磁盘 | 磁盘 |
| 对应系统 | 键值存储 | 关系数据库 | Bigtable、LevelDB、Cassandra |

### 两种数据分布

| | 哈希分布 | 顺序分布 |
| --- | --- | --- |
| 设计 | 一致性哈希 | 划分子表 |
| 功能 | 随机读 | 顺序读 |
| 优点 | 节点动态上下线容易 | 顺序扫描 |
| 缺点 | 负载均衡、可扩展性 | 主从结构 |
| 适用 | 键值对存储 | 关系、表格 |
| 一句话 | 一致性哈希环 | 子表分层索引 |
| 代表 | Dynamo | Bigtable |

### 心跳与租约

| | 心跳 | 租约 |
| --- | --- | --- |
| 假设 | 服务正常，用来检测出错 | 服务可能随时中断 |
| 收不到的含义 | 可能坏了，也可能只是网络抖动或对方太忙 | 租约过期就确定对方已停服 |
| 能否支撑强一致 | 不能，会出现双主写同一份数据 | 能 |
| 实现细节 | 重试若干次后判定故障 | 要留提前量，比如租约 10 秒、A 等到 11 秒才判过期 |

### 2PC 与 Paxos

| | 2PC | Paxos |
| --- | --- | --- |
| 解决什么 | 跨多个数据分片操作的**原子性** | 同一数据分片多副本的**一致性** |
| 角色 | 协调者、参与者 | Proposer、Acceptor、Learner |
| 阶段 | 请求（prepare）、提交（commit） | 准备（prepare）、批准（accept）、确认（acknowledge） |
| 是否阻塞 | 阻塞，一个参与者慢就拖住全部 | 不阻塞，多数派即可推进 |
| 容错 | 协调者宕机就整体阻塞 | 容忍少数派故障， $F$ 个故障需 $2F+1$ 个节点 |
| 典型用途 | 分布式事务 | Chubby、ZooKeeper、Megastore、Spanner |

组合用法：用 2PC 保证跨分片原子性，用 Paxos 保证单分片多副本一致性，再用 Paxos 给 2PC 选新协调者以解决它的阻塞问题。

### COW 与 MVCC

| | COW | MVCC |
| --- | --- | --- |
| 怎么让读不加锁 | 写在副本上改，提交时原子切根指针 | 每行多版本，读按版本号挑 |
| 写的开销 | 拷贝叶子到根的整条路径 | 每行多存两个隐含列和多个旧版本 |
| 写并发 | 互斥 | 可以并发 |
| 垃圾回收 | 引用计数为 0 时回收 | 定期删除不再需要的版本 |

### 同构系统与异构系统

| | 同构系统 | 异构系统 |
| --- | --- | --- |
| 数据摆放 | 一组节点存完全相同的数据 | 切成大量小分片，副本落在任意节点 |
| 补副本 | 只能从同组兄弟整体拷贝，1TB 加 20MB/s 要十几个小时 | 全集群一起补，时间被并行度除 |
| 元数据 | 固定 | 动态 |
| 线性可扩展 | 做不到 | 做得到 |

### 四个真实系统的五个问题

| | GFS | HDFS | Dynamo | Bigtable |
| --- | --- | --- | --- | --- |
| 数据怎么分布 | 64MB chunk，Master 决定 | 64/128MB block，NameNode 决定 | 一致性哈希加虚拟节点 | 按 row key 顺序切 100 到 200MB 子表 |
| 副本怎么放 | 3 副本跨机架 | 本地、本地机架、远程机架 | 顺时针 $N$ 个节点 | 服务层单副本，持久化交给 GFS |

## 易混点速查

- **集群、网格、云**：管理域是关键。集群单组织单管理域走 LAN，网格多组织多管理域走 WAN，云单一管理域但强调按需和商业化。
- **Flynn 分类和按存储方式分类**是两套独立的分类，前者按指令流和数据流的数目（SISD/SIMD/MISD/MIMD），后者按内存组织（共享内存、分布内存、集群）。
- **阻塞与非阻塞**的分界是"返回后缓冲区能不能用"，不是"操作有没有做完"。
- **通信模式（4 种）与通信机制（阻塞、非阻塞）**是两个维度，相乘才得到 8 种发送操作。
- **广播和散播**：广播发的是同一份数据，散播发的是切开的不同数据块。
- **不可重复读和幻读**：前者是同一行读出来变了（UPDATE 或 DELETE），后者是多出来一行（INSERT）。
- **第一类和第二类丢失更新**：第一类是回滚覆盖了别人已提交的修改，第二类是后写的盖了先写的（都没回滚）。
- **UNDO 和 REDO**：UNDO 记修改前，REDO 记修改后。checkpoint 恢复依赖 REDO 记录的是结果（幂等）。
- **minor 和 major compaction**：minor 是内存转储成 SSTable，major 是跨层级多路归并。
- **一致性哈希的三种位置信息**： $O(1)$ 空间换 $O(N)$ 查找、 $O(\log N)$ 对 $O(\log N)$、 $O(N)$ 空间换 $O(1)$ 查找，Dynamo 选最后一种。
- **consistent 和 defined**：consistent 是所有副本值相同，defined 是在此基础上还能完整反映一次写入的结果。并发追加的结果是 consistent but undefined。
- **GFS 的三类元数据**：命名空间和文件到 chunk 的映射要持久化，chunk 副本位置不用（ChunkServer 汇报即可重建）。
- **Secondary NameNode 不是热备**，它只做元数据快照和日志合并，NameNode 故障期间集群不可用。
- **Hinted Handoff 和 Merkle 树**：前者管临时故障，后者管永久故障；再加上读取修复共三条恢复途径。
- **向量时钟只能检测冲突，不能解决冲突**。解决靠客户端逻辑（购物车取并集）或 last write wins。
- **Bigtable 的列族和 qualifier**：列族建表时定义、个数受限、是权限单元；qualifier 任意多、不用预定义、每行可以不同。
- **分裂和合并**：分裂由 Tablet Server 发起且不搬数据，合并由 Master 发起且要先迁移子表。
