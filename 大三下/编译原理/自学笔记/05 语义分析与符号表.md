# 语义分析与符号表

整理自 `编译原理笔记/编译原理学习笔记.pdf` 第 96–125 页（第 4 章语义分析）和第 190–193 页（复习补充里的过程/函数标识符、size 属性、往年题），`编译原理笔记/编译原理期末题型整理.pdf` 第 1–5 页（高频考点）和第 81–90 页（4 语义分析），以及 `编译原理期末资料/吉林大学编译原理期末试题解答.pdf` 第 3 页（No6 结构体声明）。本章选择题收在 `10 选择题精编.md`，历年卷里的符号表大题见 `30 历年题（2003–2011级）.md` 到 `33 历年题（2016–2022级）.md`，`20 大题题型精讲.md` 第 7 节另有一道驻留法例题。

## 本章要点

- 语义分析查的是**静态语义**：标识符有没有声明、同层有没有重复声明、种类和类型用得对不对、函数调用的参数个数和类型对不对。除零、越界这类动态语义错误编译时查不全。
- 语义分析的主要产物是**符号表**。它在语义分析阶段用于语义检查，在中间代码生成阶段用于类型检查和转换，在目标代码生成阶段是地址分配的依据。
- 记住四种标识符的内部表示（常量、类型、变量、过程/函数）和各类型的内部表示（标准类型、子界、枚举、数组、结构体/联合体、指针）。
- 空间约定：int、char、bool 占 1，real（float）占 2，指针占 1；数组 = 元素个数 × 元素大小；struct 求和，union 取最大。
- 形参空间：值参按类型大小，变参（var 参数）占 1，过程/函数形参占 2。
- **抽象地址 = (层数, 偏移)**。Pascal 主程序 0 层，第 i 层过程里声明的标识符为 i+1 层；C 语言只有 0 层（全局量、函数名）和 1 层（形参、局部量，块里声明的也算 1 层）。
- 局部化处理：全局符号表有**删除法**和**驻留法**，局部符号表用 Scope 栈，只用删除法。声明性出现只查本层，使用性出现由内向外查。
- 原稿批注：驻留法考试重点考跳转法的"从后往前查"。

## 概念与解释

### 1. 语义分析做什么

#### 1.1 语法和语义

程序设计语言有四个方面：

1. 词法：最小有意义单元（关键字、标识符、运算符等）的规则。
2. 语法：什么样的单词序列能组成结构上合法的程序，管的是结构。
3. 语义：结构合法的程序是什么意思，执行时做什么，各部分怎样相互作用。
4. 语用：语言在实际使用中的上下文、约定和对环境的影响。

语法正确不等于有意义。下面这段 C 代码能通过语法分析，但有三处语义错误：

```c
int x=10;              // 变量声明，语法、语义都对
Main( )
{ printf("%d", x+x);
  x( );                // 函数调用的语法，但 x 是变量，语义错
  f = x;               // 赋值语句的语法，但 f 此处未声明（f 是后面的函数），语义错
}
float f( )             // 函数声明，语法、语义都对
{ int x=20, y;
  float x;             // 变量声明的语法，但 x 在同一层重复声明，语义错
  printf("%d", x);
}
```

常见语义错误：标识符未声明、重复声明、操作数类型与运算符不匹配（如 `"hello" / 2`）、变量被当作函数调用、函数调用参数个数或类型不匹配、数组下标越界、不可达代码、无意义的循环或条件。

#### 1.2 静态语义和动态语义

| | 静态语义 | 动态语义 |
|---|---|---|
| 检查时间 | 编译时 | 目标程序运行时 |
| 例子 | 标识符未声明、类型不匹配、参数个数或类型不符 | 除零、溢出、数组下标越界（运行时检查）、空指针引用 |
| 谁来查 | 语义分析器主要查这一类 | 编译程序不能完全查出 |

#### 1.3 语义分析的主要任务

1. 根据声明部分建立符号表。符号表是编译器保存源程序各种信息的数据结构，每个表项对应一个标识符，记录名字、种类、类型、作用域、存储位置等属性。
2. 在整个程序范围内检查常见语义错误。

声明和使用方面的错误：

- 每个使用性标识符是否都有声明。
- 同一层内有没有标识符被声明多次（要刻画作用域才能判断）。
- 标号是否声明，有无重复声明、重复定位，有无非法转入。

检查办法：遇到新声明的标识符就查符号表，当前有效的同层标识符里有同名的就报重复声明，否则生成属性信息填表；遇到标识符的使用也查符号表，查不到就是未声明，查到了就取出属性做后续检查（如类型检查）。

类型方面的错误（匹配问题）：

- 条件表达式（如 if 的条件）是不是 boolean 型。
- 运算符的分量类型是否相容。
- 赋值语句左右部类型是否相容。
- 形参和实参的类型、个数、传递方式是否相容。
- 下标表达式的类型是否允许；数组引用 `V[E]` 中 V 是不是数组类型的变量，E 是不是整型。
- 函数说明中的函数类型和返回值类型是否一致。
- 记录引用 `V.id` 中 V 是不是记录类型的变量，id 是不是该记录的域名。
- 指针引用 `V↑` 或 `*V` 中 V 是不是指针类型。
- 函数调用 `y+f(...)` 中 f 是不是函数名，过程调用 `p(...)` 中 p 是不是过程名，形参和实参个数是否一致。
- 子界类型的上下界类型是否相容，下界是否不大于上界。

#### 1.4 实现方式

- 不单独作为一遍：类型错误检查放到中间代码生成时做（生成代码时本来就要确定运算分量和运算符的类型）；一般的语义检查和语法分析结合，在语法规则里嵌入语义动作，识别到声明就填符号表。
- 独立一遍：输入语法分析树（或抽象语法树）和 TokenList，依据用自然语言描述的语义规定（类型规则、作用域规则等）遍历语法树并做判定，输出填好的符号表和新的 Token 序列（或带语义信息的语法树）。

语义分析处理后的结果（原稿第 99 页的图）：Token 序列经语义分析变成新的 Token 序列，标识符 Token 指向符号表；符号表的类型字段指向类型表，类型表再连到数组信息表、记录信息表等；另外还有常量表和特殊符表。

### 2. 标识符的语义表示

#### 2.1 出现方式和种类

- 声明性出现：标识符被定义的地方，如 `int x; int a[10];`，编译器在此收集属性。Pascal 里多在程序头、函数头（参数声明）。
- 使用性出现：标识符被引用的地方，如 `x = x + 1;`，编译器在此检查使用是否合法。Pascal 里多在程序体、函数体。

标识符的种类（符号表的 Kind 字段）：

| 种类 | 细分 |
|---|---|
| 常量标识符 | |
| 类型标识符 | |
| 变量标识符 | 实在变量；形参变量（值参、变参） |
| 过程/函数标识符 | 实在过程/函数；形式过程/函数 |
| 域名标识符 | 结构体/记录的成员名 |

标识符的语义信息 = 名字（Name）+ 种类（Kind）+ 类型（Type）+ 各种类特有的信息。

#### 2.2 常量标识符

内部表示：(Name, Kind=constKind, Type, Value)。Type 指向常量类型的内部表示，Value 指向常量值的内部表示。

```c
#define pai 3.14
#define count 100
```

| Name | Kind | Type | Value |
|---|---|---|---|
| pai | constKind | realPtr | ↑〈3.14〉 |
| count | constKind | intPtr | ↑〈100〉 |

#### 2.3 类型标识符

内部表示：(Name, Kind=typeKind, Type)，Type 指向它所代表的类型的内部表示。

```c
typedef int t1;
typedef int t2[10];
```

| Name | Kind | Type |
|---|---|---|
| t1 | typeKind | intPtr |
| t2 | typeKind | ArrayTyPtr，指向 (10, ArrayTy, 0, 9, intPtr) |

#### 2.4 变量标识符

内部表示：(Name, Kind=varKind, Type, Access, Level, Off, Value)。

- Access：dir 为直接变量，按地址直接访问；indir 为间接变量（如变参），取到地址后再间接访问。
- Level：变量声明所在主程序、过程或函数的嵌套层数。
- Off：相对所在主程序、过程或函数内存块起始地址的偏移。
- Value：有初值时指向初值的内部表示，否则为空。

例：`int x=10; float y; float* z;`，当前层为 L，当前偏移为 off，实型占 2 个单元。

| Name | Kind | Type | Access | Level | Off | Value |
|---|---|---|---|---|---|---|
| x | varKind | intPtr | dir | L | off | ↑〈10〉 |
| y | varKind | realPtr | dir | L | off+1 | null |
| z | varKind | ↑(1, pointTy, realPtr) | indir | L | off+3 | null |

x 占 1，y 占 2，所以 z 从 off+3 开始。

#### 2.5 过程/函数标识符

内部表示：(Name, Type, Kind=routKind, Level, Off, Param, Class, Code, Size, Forward)。

| 字段 | 含义 |
|---|---|
| Type | 函数返回值类型；过程为 NULL |
| Level | 过程/函数声明所在的层数 |
| Off | 只对形式过程/函数有效，是它在所属过程/函数内存块中的偏移 |
| Param | 参数表指针，参数表结构和符号表类似，可嵌在符号表里也可单独存 |
| Class | actual 为实在过程/函数，formal 为形式过程/函数 |
| Code | 只对实在过程/函数有效，目标代码起始地址，目标代码生成时回填；形式过程/函数为 NULL |
| Size | 只对实在过程/函数有效，活动记录的大小（变化过程见下文） |
| Forward | 只对实在过程/函数有效，true 表示超前声明（先声明后定义） |

- 实在过程/函数：在代码里真正定义、实现过、可以调用的过程/函数。
- 形式过程/函数：出现在某个过程/函数参数表里的过程/函数名（过程型、函数型参数），只是占位符，具体行为由调用时传进来的实在过程/函数决定。
- 超前声明：在使用前先声明过程/函数的名字、参数类型、返回类型，暂不给实现，用来解决互相调用或引用顺序的问题。

例（Pascal）：

```pascal
function f(x: integer; var y: real;
           function inc(a: integer): integer): integer;   (* 头 *)
begin
  ...  (* f 的函数体 *)
end;
```

f 本身在 L 层：

| Name | Type | Kind | Level | Off | Param | Class | Code | Size | Forward |
|---|---|---|---|---|---|---|---|---|---|
| f | intPtr | routKind | L | | 指向参数表 | actual | （回填） | XXX | false |

f 的参数表（参数是 f 里声明的标识符，层数为 L+1）：

| Name | Kind | Type | Access / Class | Level | Off |
|---|---|---|---|---|---|
| x | varKind | intPtr | dir | L+1 | off₀ |
| y | varKind | ↑(1, pointTy, realPtr) | indir | L+1 | off₀+1 |
| inc | routKind | intPtr | formal，Param 指向 a | L+1 | off₀+2 |
| a | varKind | intPtr | dir | | |

原稿批注：

- y 前面有 var，是变参，传的是地址，所以只占 1 个单元。
- inc 的形参 a 不分配抽象地址，没有层数和偏移，只用于调用 inc 时的类型检查。a 不属于 f 的作用域，只在 inc 被调用时才出现在 inc 的活动记录里。

另外，inc 是形式函数，占 2 个单元（见第 4.3 节），f 若还有第四个参数，应从 off₀+4 开始。

#### 2.6 size 属性在各阶段的变化

| 阶段 | 作用与处理 | size 内容 | 说明 |
|---|---|---|---|
| 语义分析 | 建立符号表条目，赋初值 | 活动记录的基础结构大小 | 包括管理信息、形参信息和局部变量信息的空间 |
| 中间代码生成 | 加上临时变量所占空间 | 增加临时变量的大小 | size 扩大，匹配完整的栈帧结构 |
| 中间代码优化 | 变量复用、删除死代码 | 根据优化减少部分空间 | 优化后的 size 更紧凑 |
| 目标代码生成 | 用 size 分配过程调用所需的栈空间 | 使用最终 size 值 | 生成函数入口、出口指令 |
| 运行时 | 调用时根据 size 创建活动记录 | 使用最终 size 值 | 按 size 分配栈空间，压入控制信息和局部变量 |

（更正：原表"中间代码生成"一行写的是"添加局部变量、临时变量、参数等所占空间"，与上一行"初值已含形参和局部变量"矛盾；按往年题答案，这一步增加的是临时变量。）对应的问答题见典型题 3。

### 3. 类型的语义表示

类型信息有两个用处：做类型检查（运算符与分量、赋值号左右部、形参与实参），以及确定变量要分配多少空间。

类型分类：标准类型（int、float/real、bool、char）；自定义类型（子界、枚举）；结构类型（数组、记录/结构体、联合体）；指针类型。

空间约定：**RealSize = 2，IntSize = BoolSize = CharSize = 1**，指针占 1（具体取决于目标机和语言规范）。

#### 3.1 标准类型

内部表示 (Size, Kind)：

| 指针 | Size | Kind |
|---|---|---|
| intPtr | 1 | intTy |
| boolPtr | 1 | boolTy |
| charPtr | 1 | charTy |
| realPtr | 2 | realTy |

#### 3.2 子界类型

内部表示 (Size, Kind=subrangeTy, Low, Up, ElemType)，Size 与基类型相同，ElemType 指向基类型。

例（Pascal）：`type letter = 'a'..'z';`，定义小写字母范围。

| Size | Kind | Low | Up | ElemType |
|---|---|---|---|---|
| 1 | subrangeTy | 'a' | 'z' | charPtr |

#### 3.3 枚举类型

内部表示 (Size, Kind=enumTy, ElemList)，Size 通常为 1，ElemList 指向枚举常量表 (Name, Value)。

| 声明 | 内部表示 | 枚举常量表 |
|---|---|---|
| `enum color {red, yellow, blue}` | (1, enumTy, ↑常量表) | red 0，yellow 1，blue 2（默认从 0 开始） |
| `enum color {red=10, yellow=red+2, blue}` | (1, enumTy, ↑常量表) | red 10，yellow 12，blue 13 |

#### 3.4 数组类型

内部表示 (Size, Kind=ArrayTy, Low, Up, ElemType)，Size = (Up − Low + 1) × 元素大小，C 语言 Low 为 0。

| 声明 | 内部表示 |
|---|---|
| `typedef int A[10];` | (10, ArrayTy, 0, 9, intPtr) |
| `typedef char B[5][10];` | 外层 (50, ArrayTy, 0, 4, ↑内层)，内层 (10, ArrayTy, 0, 9, charPtr) |

二维数组看成"数组的数组"：B 有 5 个元素，每个元素是 `char[10]`。

#### 3.5 结构体和联合体

内部表示 (Size, Kind=structTy 或 unionTy, RecBody)。RecBody 指向域名表，表项为 (Name, Type, Off, Link)：Off 是域相对结构体起始地址的偏移，联合体所有域偏移相同（都为 0，可省略）；Link 指向下一个域。

例 1：`typedef struct Date {int year, month, day;} datetype;`

datetypePtr → (3, structTy, ↑FieldList)

| Name | Type | Off | Link |
|---|---|---|---|
| year | intPtr | 0 | → month |
| month | intPtr | 1 | → day |
| day | intPtr | 2 | null |

例 2：`typedef union {char ch; int i; float f;} data;`

dataPtr → (2, unionTy, ↑MemberList)，Size 取最大的 float：

| Name | Type | Off | Link |
|---|---|---|---|
| ch | charPtr | 0 | → i |
| i | intPtr | 0 | → f |
| f | realPtr | 0 | null |

#### 3.6 指针类型

内部表示 (Size, Kind=pointTy, BaseType)，Size 为地址长度（1 个单元），BaseType 指向被指对象的类型。

| 声明 | 内部表示 |
|---|---|
| `typedef int* T1;` | (1, pointTy, intPtr) |
| `typedef float* T2;` | (1, pointTy, realPtr) |

#### 3.7 结构体类型声明和变量声明的区分

来自试题解答第 3 页：

```c
struct {
    int a, b, c;
} s1;                      // 无名结构体类型声明，同时声明变量 s1

struct Sample1 {
    int a, b, c;
} s1;                      // 结构体类型 struct Sample1 的声明，同时声明变量 s1
struct Sample1 t1, *t2;    // 声明了两个变量

typedef struct {
    int a, b, c;
} Simple2;                 // 结构体类型声明，Simple2 是类型名
Simple2 t3, *t4;           // 声明了两个变量
```

（更正：原文第二段注释只写"结构体类型声明"，漏了变量 s1；下一行原文作 `struct Simple1 t1, *t2;`，与上面的 Sample1 不一致。）

填符号表时，有变量名的才分配偏移；`typedef` 后面的 Simple2 是类型标识符（typeKind），不占空间。

### 4. 抽象地址

#### 4.1 分配原则

- 静态分配：编译时给所有数据对象分配固定地址，运行时不变。直观，但处理不了动态申请的空间、递归调用和运行时才定大小的数据，适合全局变量、静态变量。
- 动态分配：编译时只分配**抽象地址**，运行时再根据抽象地址在栈或堆上分配具体地址，支持递归和动态数据结构。

抽象地址是二元组 (层数, 偏移)。层数主要针对嵌套式语言，表示函数或块的嵌套定义层次，刻画作用域；偏移是相对**过程活动记录**的偏移，运行时用活动记录首地址加偏移得到实际地址。

#### 4.2 层数怎么定

嵌套式语言（Pascal）：

- 主程序为 0 层，主程序中声明的标识符（包括过程/函数名）为 1 层。
- 第 i 层过程/函数中声明的标识符（形参、局部量、内层过程名）为 i+1 层。
- 所以过程名本身的层数比它过程体里的变量少 1。第 2.5 节的 f 在 L 层，它的形参都在 L+1 层。

原稿第 113 页的例子按"局部化单位"说层数：

```pascal
procedure P();          (* 局部化单位 1，层数记为 L_P *)
  var x, y: integer;    (* x、y 在 L_P 层 *)
  procedure Q();        (* 局部化单位 2，嵌套在 P 内，层数 L_P+1 *)
    var x, z: real;     (* x、z 在 L_P+1 层 *)
```

这里的 `L_P` 指 P 的过程体（局部化单位）的层数，按上面的规定它等于 P 这个过程名的层数加 1。

并列式语言（C）：全局变量和所有函数名为 0 层，函数的形参和局部变量为 1 层，函数内复合语句里声明的变量也是 1 层。

#### 4.3 过程活动记录和空间分配

每次调用函数都会给它分配一片存储空间，叫过程活动记录（栈帧）。从栈顶往下依次是：

```text
临时变量区    ← 计算中间结果的临时变量
局部变量区    ← 函数内定义的局部变量
形参区        ← 调用时传入的参数
管理信息      ← 返回地址、旧栈帧指针、静态链等
```

偏移从管理信息的最底部开始算，所以第一个形参的偏移 off₀ 等于管理信息所占的大小。活动记录的详细内容见 `08 运行时存储空间管理.md`。

空间分配原则：

| 对象 | 分配的单元数 |
|---|---|
| 临时变量 | 1（假设，实际看目标机和操作数类型） |
| 局部变量 | 按类型大小，int 为 1，float 为 2 |
| 值参 | 按类型大小 |
| 变参（var，地址传递） | 1，存实参地址 |
| 过程/函数形参 | 2，一个存入口地址，一个存静态链或 display 信息，用来访问非局部变量 |

### 5. 符号表的组织

#### 5.1 符号表的作用

- 语义分析：登记的内容用于语义检查，检查名字的使用和声明是否一致。
- 中间代码生成：用于类型检查和类型转换（如整型加法与实型加法）。
- 目标代码生成：给名字分配地址时，符号表是依据（存有偏移、类型大小）。

编译过程中要频繁查表、填表，合理组织符号表、选好查填方法对编译效率影响很大。要解决三个问题：总体组织、表项排列、局部化处理。

#### 5.2 总体组织

符号表存的是名字及其语义字（种类、类型、抽象地址等）。不同种类的标识符属性不同，组织方式没有统一规定：

| 方式 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 多表结构 | 属性完全相同的符号放一张表：常量表、类型表、变量表、函数表 | 每张表等长、每个属性都有效，管理一致，空间效率高 | 要同时管理多张表，共同属性（如类型）要设重复的机制 |
| 单表结构 | 所有符号放一张表 | 管理集中，共同属性可以统一处理 | 表项不等长、属性位置交错，管理复杂；若把所有可能属性都做成字段，又会浪费空间 |
| 折中方式 | 按属性相似程度分成几张表，如常量和类型一张，变量和函数一张 | 每张表内相似度高 | |

#### 5.3 表项排列

建表是一次性的，查表是反复的，查表效率决定建表方法。

| 组织 | 做法 | 查表方法 | 特点 |
|---|---|---|---|
| 线性组织 | 按扫描到的先后顺序录入 | 顺序查找 | 没有空白项，省空间；表大时效率很低；符号个数事先确定且较少（公认小于 20）时合适 |
| 排序组织 | 按符号字符串的代码值大小排序 | 折半查找 | 比线性快得多 |
| 散列组织 | $V_{hash} = f_{hash}(符号代码值)$， $L_{hash} = V_{hash} \bmod N$（N 为表长） | 散列查找 | 平均效率最高；实现复杂，要额外空间处理冲突 |

### 6. 符号表的局部化处理

#### 6.1 局部化单位和作用域

程序中允许有声明的部分叫**局部化单位**：子程序（过程、函数）、分程序（`{}` 或 `begin...end` 括起的复合语句）、主程序。

一个局部化单位建立的全部表项叫该局部化单位的符号表（这些表项在存储上不一定相邻），它的有效范围就是这个局部化单位。在程序点 P，有效的是包含 P 的各层局部化单位的符号表：内层能访问外层（包括全局）的标识符，外层不能访问内层的。

**局部化处理的本质**：在点 P 遇到使用性标识符时，只能按由内层到外层的次序，查在 P 处有效的那些符号表，不访问已经无效的符号表。编译程序要能在每一点判断出哪些局部化单位的符号表有效。

C 语言分程序的例子（原稿第 118 页）：

```c
void main()
{                                        /* B1 */
    int a = 1;
    int b = 1;
    {                                    /* B2 */
        int b = 2;
        {                                /* B3 */
            int a = 3;
            printf("a = %d, b = %d\n", a, b);   /* a = 3, b = 2 */
        }
        {                                /* B4 */
            int b = 4;
            printf("a = %d, b = %d\n", a, b);   /* a = 1, b = 4 */
        }
    }
    printf("a = %d, b = %d\n", a, b);           /* a = 1, b = 1 */
}
```

#### 6.2 局部化区里的语义检查和处理原则

局部化区里要查两类错误：同一局部化区内重复声明；使用的标识符有没有声明（C、Java、Pascal 这类强类型语言要求先声明后使用，Python、JavaScript 这类弱类型语言没有严格要求）。

处理原则：

- 遇到声明性标识符：查**当前局部化单位**的符号表有没有同名的，有就报重复定义，没有就把名字和属性填进当前局部化单位的符号表。
- 遇到使用性标识符：**由内到外**依次查各嵌套外层局部化单位的符号表，找到就按属性判断使用是否合法（类型检查、参数匹配），找不到就报"有使用而无声明"。
- 进入局部化区时记下本层符号表的起始地址，退出时作废本层符号表（逻辑上不可见或物理删除）。

例（原稿引 PPT 第 27 页）：

```c
int x = 10;           /* 全局 x */
fun1() {
    int x = 20, z;    /* 与全局 x 不在同一作用域，合法 */
    z = x + 10;       /* 这里的 x 是 fun1 的 x（20），内层优先 */
}
fun2() {
    int y;
    y = x + 30;       /* fun2 里没有 x，向外找到全局 x（10） */
}
```

PPT 第 28 页讲建表时查重复定义：如果 fun1 里在 `int x=20, z;` 之后再写一句 `int x=30;`，填表前查本层符号表会查到同名的 x，报重复声明；而 `int x=20` 与全局 x 不在同一局部化区，不算重复。

#### 6.3 全局式符号表

整个程序的符号表是一张大表，建表和查表单位都是整张表。

- 进入局部化区：记住本层符号表在全局表中的始地址。用 **Scope 栈**实现嵌套作用域，`Scope[ℓ]` 指向第 ℓ 层符号表的始地址。
- 遇到定义性标识符：构造语义信息，查本层符号表（从本层始地址到表尾），有同名就报错，没有就填入。
- 遇到使用性标识符：查整个符号表（从后往前查），查不到就报错。
- 结束局部化区："删除"本层符号表。

设 ℓ 为当前层数计数器，s 为符号表最后一项的地址。"删除"有两种做法：

| | 删除法（真删除） | 驻留法（跳转法） |
|---|---|---|
| 退出局部化区时 | `s := Scope[ℓ] - 1`，`ℓ := ℓ - 1`，表尾指针退回本层开始之前 | `s := s + 1`，`SymbTab[s] := (#, Scope[ℓ]-1)`，然后弹出本层 Scope 栈项 |
| 表项 | 本层表项被回收，后面的声明会覆盖这些位置 | 表项保留，只增不减 |
| 查表 | 从 s 往前查 | 从 s 往前查，遇到跳转项 # 就跳到它记的地址继续往前查，跳过已经结束的局部化区 |
| 优点 | 省空间 | 插入、删除简单，不移动数据 |
| 缺点 | 频繁插入删除可能耗时 | 表不断增长 |

#### 6.4 局部式符号表

每个局部化单位的符号表是一张独立的表，建表和查表单位都是这张局部表。

- 某一时刻并非所有局部表都有效，用 Scope 栈记录当前有效的局部表始地址（或指针）。
- 进入新的局部化区，把它的符号表始地址压入 Scope 栈；退出时弹出栈顶。
- 查表从 Scope 栈顶（最内层）的表开始，依次往栈底（外层）查，直到找到或查完。
- 删除法、驻留法之分是针对全局表的；局部表通常只用删除法，弹出 Scope 栈后这张表的空间就可以回收。

原稿批注：局部表也可以用数组模拟出驻留法，但那样就不算局部表了；全局表和局部表相比，局部表更高效。

### 7. 符号表管理实例

语义分析阶段的三件事：检查语义错误；分配抽象地址（层数、偏移）；符号表局部化和标识符作用域，后者是前两件事的基础。

#### 7.1 Pascal（嵌套式）：删除法

Pascal 允许过程嵌套声明，作用域管理最复杂。示例程序（原稿引 PPT 第 6 页，过程名后的数字是该过程的层数）：

```pascal
program example;
  procedure P1;
    var i, j, k: integer;
    procedure Q2;
      var a, b: real;
      procedure R3;
        var a, b: boolean;
      begin (* R3 的过程体，用到 a, b, i *) end;
    begin (* Q2 的过程体，用到 a, b, i *) end;
    procedure S2;
      var c, e: char;
    begin (* S2 的过程体，用到 a, b, i, Q *) end;
  begin (* P1 的过程体，用到 a, b, i, P, Q, S *) end;
begin
  P1
end.
```

（更正：原稿代码注释把 i、j、k 标为 L=1，Q2 的 a、b 标为 L=2，R3 的 a、b 标为 L=3，S2 的 c、e 标为 L=2，与原稿同一节给出的层数规定（本文第 4.2 节）和 f 的例子都矛盾；按"第 i 层过程中声明的标识符为 i+1 层"应分别为 2、3、4、3。原稿 P1 过程体末尾的 `END.` 也应为 `END;`。下面的跟踪表按规定重写，原稿的跟踪表只有 Scope 栈的示意，没有表项内容。）

扫描到 R3 过程体时的全局符号表（整理补充）：

| 地址 | Name | Kind | Type | Level | Scope 栈 |
|---|---|---|---|---|---|
| 1 | P1 | routKind | | 1 | ← 主程序这一层的起点 |
| 2 | i | varKind | integer | 2 | ← P1 层的起点 |
| 3 | j | varKind | integer | 2 | |
| 4 | k | varKind | integer | 2 | |
| 5 | Q2 | routKind | | 2 | |

退出后 s 回退，后面的查找就碰不到已结束的层；S2、c、e 写在了原来 a、b、R3 所在的第 6–8 项上。

同一个程序改用驻留法（整理补充，原稿只说"PPT 第 9 页的图在每次退出作用域时插入一个 # 和一个指针"）。前 10 项与上表相同，之后：

#### 7.3 C 语言（并列式）

C 语言的特点：

- 函数不能嵌套声明，所有函数并列，地位相同，main 是入口；后声明的函数可以调用前面声明的函数（通过函数原型）。
- 标识符只有两层：0 层是全局标识符和所有函数名，1 层是函数的形参和局部标识符。
- 支持分程序结构，`{}` 块里可以有声明，块可以嵌套，每个分程序是一个局部化区。块里声明的变量层数仍为 1，偏移相对本层局部化区（函数）的起始地址接着往下排。

驻留法示例（原稿引 PPT 第 11 页，只列了各标识符的层数，表项顺序和跳转项位置按驻留法算法整理）：

| Name | Kind | Level | 说明 |
|---|---|---|---|
| x | varKind | 0 | 全局变量 |
| y | varKind | 0 | 全局变量 |
| swap | routKind | 0 | |
| a | varKind | 1 | swap 的形参，indir |
| b | varKind | 1 | swap 的形参，indir |
| tmp | varKind | 1 | swap 的局部变量 |
| # | | | 退出 swap，指向 swap 这一项 |
| main | routKind | 0 | |
| x | varKind | 1 | main 的局部变量 |
| y | varKind | 1 | main 的局部变量 |

swap 退出后，a、b、tmp 的表项仍留在全局表里，查表时通过 # 跳过。PPT 第 13 页的带分程序的例子同理：外部 `int a;` 在 0 层，内部块的 `int c;` 在 1 层，进出 `{}` 时用 # 或指针回退管理可见范围。

#### 7.4 嵌套式语言和并列式语言

- 嵌套式语言（Pascal）处理更复杂：层数随嵌套加深，访问非局部变量要靠静态链或 Display 表这类机制。
- 并列式语言（C）相对简单：层数只有 0 和 1。C 的函数并列，但分程序（块）是嵌套的；块里的局部化区层数都记为 1，块之间仍按嵌套规则决定可见性（内层块能访问外层块的局部变量）。

## 易混对比

| 对比项 | A | B |
|---|---|---|
| 语法分析 / 语义分析 | 查结构是否合法，依据语法规则，如括号不匹配 | 查意义是否合法，依据语义规则，如类型不兼容、未声明 |
| 静态语义 / 动态语义 | 编译时检查 | 运行时才能检查 |
| 声明性出现 / 使用性出现 | 只查本层符号表，查到同名报重复声明 | 由内向外查所有有效符号表，查不到报未声明 |
| struct / union | 各成员分别分配内存，Size 为各成员之和，各域偏移递增，可以同时使用多个成员 | 成员共用一块内存，Size 为最大成员，各域偏移都是 0，一次只用一个成员，用于省空间或对同一数据做不同解释 |
| 值参 / 变参 / 过程函数形参 | 按类型大小分配，dir | 变参占 1，indir；过程函数形参占 2 |
| 实在过程 / 形式过程 | Class=actual，有 Code、Size、Forward | Class=formal，有 Off，Code 为 NULL |
| 删除法 / 驻留法 | 退出时 `s := Scope[ℓ]-1`，表项回收 | 退出时追加 `(#, Scope[ℓ]-1)`，表只增不减，查表遇 # 跳转 |
| 全局式 / 局部式符号表 | 一张大表，Scope 栈记各层在表中的始址，可用删除法或驻留法 | 每个局部化单位一张表，Scope 栈记各表始址，只用删除法，更高效 |
| Pascal / C 的层数 | 主程序 0 层，第 i 层过程里声明的标识符 i+1 层 | 全局量和函数名 0 层，形参和局部量（含块内）1 层 |

### 1. 语义分析与语法分析的区别；函数调用语句的语义检查

题目（题型整理第 2–3 页）：简述语义分析与语法分析的区别，并列举三种语义错误。在进行语义分析时，处理函数调用语句需要做哪些语义检查？

思路：区别从"管结构还是管意义"说；函数调用的检查围绕"f 是什么、参数对不对、返回值怎么用"。

解答：

- 语法：什么样的单词序列能组成结构上合法的程序，是结构上的合法性。语义：结构合法的程序有什么意义，执行时做什么。语法分析依据语法规则检查结构，语义分析依据语义规则检查意义。
- 常见语义错误：标识符未声明、重复声明、类型不匹配。
- 分析 `f(a, b, c)` 这样的函数调用时要检查：
  1. f 是否已定义或声明（符号表里要有 f 的定义或前向声明）。
  2. f 是否为可调用的函数标识符，而不是变量或数组名。
  3. 实参与形参个数是否一致，如 f 定义为 `f(int, float)`，调用时不能写三个参数。
  4. 实参与形参的类型（和种类，值参还是变参）是否匹配。
  5. 参数求值顺序和副作用（可选，如 `f(i++, i++)`）。
  6. 若返回值参与赋值或表达式（如 `x = f(1, 2);`），检查返回类型能否赋给 x。

### 3. 过程/函数的 size 属性

题目（题型整理第 1 页；学习笔记第 193 页"往年题"是同一问）：过/函信息表中有一项属性叫 size，存放该过程或函数活动记录的大小。(1) 什么时候填写 size？(2) 什么时候修改？(3) 什么时候使用？

解答：

1. 语义分析阶段，过程/函数中局部变量的符号表信息都填写完毕之后，填写该过程/函数符号表项里 size 的初值。初值包括活动记录中管理信息、形参和局部变量三部分的空间。
2. 中间代码生成之后和中间代码优化之后，size 的值都会改变（生成时加上临时变量的空间，优化后删掉不用的临时变量会减小）。
3. 目标代码生成时，以及运行时创建过程活动记录时，使用 size 的值。

### 4. 类型声明的符号表信息

题目（题型整理第 90 页作业）：设有如下声明，请填写相应标识符的符号表信息。数据区起始偏移从 off₀ 开始，整型、字符型变量占 1 个存储单元，浮点型变量占 2 个存储单元。

解答：

| Name | Kind | Type | Access | Level | Off |

| student | typeKind | sptr | | | |
| a | varKind | aptr | dir | 0 | off₀ |
| b | varKind | bptr | dir | 0 | off₀+100 |

类型表：

- sptr → (23, structTy, ↑域名表)。23 = 1 + 20 + 2。
- 域名表：

| Name | Type | Off | Link |
|---|---|---|---|
| number | intPtr | 0 | → name |
| name | ↑(20, arrayTy, 0, 19, charPtr) | 1 | → achievement |
| achievement | realPtr | 21 | NULL |

- aptr → (100, arrayTy, 0, 9, ↑(10, arrayTy, 0, 9, intPtr))。
- bptr → (230, arrayTy, 0, 9, sptr)。230 = 10 × 23。

a 占 100 个单元，所以 b 从 off₀+100 开始。以上 Size 和偏移已用 Python 复核。题型整理第 4 页还有一道"根据下面声明，写出类型标识符的内部表示"，原稿没有附声明，做法与本题相同。

### 5. 三种方法下的符号表内容

题目（题型整理第 88–89 页作业）：给出下面 C 程序扫描到语句 `b=a+b;` 时相应的符号表内容。标识符属性只需写出名字 Name、种类 Kind、类型 Type、层数 Level 和偏移 Off，数据区起始偏移从 off₀ 开始，整型变量占 1 个存储单元，浮点型变量占 2 个存储单元。(1) 采用全局符号表驻留方法；(2) 采用全局符号表删除方法；(3) 采用局部符号表。

```c
int main ()
{
    int a=0;
    int b=1;
    {
        float a=3.0;
        {
            float x=1.3;
            float b=0.3;
            a=a+b+x;
        }
        {
            int b=10;
        }
        b=a+b;          /* 目标语句 */
    }
    return 0;
}
```

思路：C 语言里 main 在 0 层，main 里所有变量（包括块内的）都在 1 层，偏移接着往下排。扫描到目标语句时，两个最内层块都已结束，第二层块还没结束。

解答（原答案为手画表格，Scope 栈用箭头表示，这里改成表格和文字）：

(1) 全局符号表驻留法：

| 序号 | Name | Kind | Type | Level | Off | Scope 栈 / 跳转 |
|---|---|---|---|---|---|---|
| 1 | main | routKind | intPtr | 0 | | ← Scope 栈 |
| 2 | a | varKind | intPtr | 1 | off₀ | ← Scope 栈 |
| 3 | b | varKind | intPtr | 1 | off₀+1 | |
| 4 | a | varKind | realPtr | 1 | off₀+2 | ← Scope 栈（栈顶） |
| 5 | x | varKind | realPtr | 1 | off₀+4 | |
| 6 | b | varKind | realPtr | 1 | off₀+6 | |
| 7 | # | | | | | 跳到第 4 项 |
| 8 | b | varKind | intPtr | 1 | off₀+8 | |
| 9 | # | | | | | 跳到第 7 项 |

从表尾往前查 `b=a+b`：查 a 时第 9 项跳到第 7 项，第 7 项再跳到第 4 项，找到 real 型的 a（off₀+2）；查 b 时同样跳到第 4 项，往前第 3 项是 int 型的 b（off₀+1）。

(2) 全局符号表删除法：

| 序号 | Name | Kind | Type | Level | Off | Scope 栈 |
|---|---|---|---|---|---|---|
| 1 | main | routKind | intPtr | 0 | | ← |
| 2 | a | varKind | intPtr | 1 | off₀ | ← |
| 3 | b | varKind | intPtr | 1 | off₀+1 | |
| 4 | a | varKind | realPtr | 1 | off₀+2 | ←（栈顶） |

(3) 局部符号表：Scope 栈有三项，自底向上分别指向三张表。

| Scope 栈 | 指向的局部表 |
|---|---|
| 栈底 | main，routKind，intPtr，0 层 |
| 中间 | a，varKind，intPtr，1 层，off₀；b，varKind，intPtr，1 层，off₀+1 |
| 栈顶 | a，varKind，realPtr，1 层，off₀+2 |

（更正：原答案图 (3) 中 main 的层数写成 1，与 (1)(2) 不一致，C 语言函数名应为 0 层。）

说明：原答案里第二个内层块的 `int b` 排在 off₀+8，即退出块后偏移不回收，接着往下分配。

### 6. 单表结构驻留法与多表结构 Scope 栈方法的异同

题目（题型整理第 4 页，原稿无答案）：比较说明单表结构下的驻留法管理和多表结构下的 Scope 栈辅助管理方法的异同。

思路：两者要解决的问题相同，区别在表怎么存、退出时怎么"删"、查表怎么走。

解答（整理补充，依据第 6.3、6.4 节）：

- 相同点：都是为了在程序每一点判断哪些局部化单位的符号表有效；都用 Scope 栈记录当前有效各层的起始位置，进入局部化区压栈、退出弹栈；声明性标识符只查本层，重名报错；使用性标识符由内层向外层查，查不到报未声明。
- 不同点：
  - 存储：驻留法所有表项连续存在一张全局表里；多表方法每个局部化单位一张独立的表，Scope 栈存各表的始地址。
  - 退出局部化区：驻留法不删表项，在表尾加跳转项 `(#, Scope[ℓ]-1)`，表只增不减；多表方法弹出 Scope 栈即可，这张局部表的空间能回收（局部表只用删除法）。
  - 查表：驻留法从表尾往前查，遇到 # 按地址跳过已结束的区；多表方法从栈顶的表开始逐表往栈底查。
  - 效率：驻留法插入删除简单，但表不断增长；局部表查找范围只是有效的表，原稿批注认为局部表更高效。

### 7. 嵌套式语言与并列式语言的处理区别

题目（题型整理第 4 页，原稿无答案）：高级语言可分为嵌套式语言（如 Pascal）和并列式语言（如 C）两大类，请分析编译过程中对两者的处理有哪些区别。

解答（整理补充，依据第 4.2、7.4 节）：

- 层数：Pascal 主程序 0 层，过程每嵌套一层层数加 1，层数可以很多；C 只有 0 层（全局量、函数名）和 1 层（形参、局部量，块里声明的也是 1 层）。
- 符号表局部化：Pascal 要用 Scope 栈管理多层嵌套的局部化区，退出过程时按层删除或加跳转项；C 的函数之间是并列的，只有函数内的分程序块需要按嵌套可见性处理。
- 运行时访问非局部变量：Pascal 过程能访问外层过程的变量，需要静态链或 Display 表；C 只要能访问全局区和当前活动记录。
- 总体上嵌套式语言的处理更复杂，并列式语言相对简单。
