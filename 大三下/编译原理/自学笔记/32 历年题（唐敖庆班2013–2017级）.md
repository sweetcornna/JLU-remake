## 2013级唐敖庆班（2016年6月，A卷）

来源：`编译原理期末资料/吉林大学编译原理期末试题解答.pdf` 第 69–71 页为试题（卷面标题"2013 级《编译原理与实现》唐班考试试题（A）"，考试时间 2016 年 6 月），第 72–74 页为解答。卷面共五道大题：一、简答题（每题 5 分，共 40 分）；二至五各 15 分。

### 一、简答题（每题 5 分，共 40 分）

#### 1. 过程活动记录主要由哪些内容构成？

解答：动态链指针、返回地址、返回值；寄存器内容、层数、活动记录空间大小、变量访问环境；形参变量区、局部变量区、临时变量区。

#### 2. 编译程序按功能分为哪几个阶段？

解答：词法分析、语法分析、语义分析、中间代码生成、中间代码优化、目标代码生成。

#### 3. 请给出识别语言 $\{a^{2n+1}b^{n+1} \mid n \ge 0\} \cup \{a^{2n}b^{n+2} \mid n \ge 0\}$ 的上下文无关文法，要求不超过 3 条产生式。

解答：

```text
S → aaSb | ab | bb
```

S 每展开一次 aaSb，左边多两个 a、右边多一个 b。最后用 ab 收尾得到 $a^{2n+1}b^{n+1}$，用 bb 收尾得到 $a^{2n}b^{n+2}$。（Python 枚举 n ≤ 7 核对过，两边集合相同。）

#### 4. 写出识别能被 5 整除的非空二进制数串的确定有限自动机。

解答：模 5 的余数有五种情况：0，1，2，3，4；对应五种状态 S0, S1, S2, S3, S4。

（更正：原稿只写了五个余数状态。如果把 S0 当初态，它同时是终态，空串也会被接受，题目要求非空，所以要另加一个非终态的初态 S。补全后的转换表如下，读入 d 时余数 r 变成 $(2r+d) \bmod 5$。）

| 状态 | 0 | 1 |
|---|---|---|
| →S（初态） | S0 | S1 |
| S0（终态） | S0 | S1 |
| S1 | S2 | S3 |
| S2 | S4 | S0 |
| S3 | S1 | S2 |
| S4 | S3 | S4 |

用 Python 对 1～299 的二进制串（含前导 0）逐个跑过，接受当且仅当能被 5 整除。这 6 个状态两两可区分，已经是最小 DFA（S 和 S0 的转移相同，但一个是终态一个不是）。2014 级唐班卷第 8 题问的就是它的最小 DFA。

#### 5. 设有如下文法，请给出句子 (a,(a,a)) 的所有短语、简单短语和句柄。

```text
S → a | (T)
T → T,S | S
```

解答：只含终极符的句型就是句子。

- 短语：`(a,(a,a))`、`a,(a,a)`、`(a,a)`、`a,a`、`a`（三个）。
- 简单短语（直接短语）：`a`（三个）。
- 句柄：第一个 a。

（更正：原稿短语里漏了 `a,a`，它是内层 `(T)` 中 T 的子树 T → T,S 的叶子串。）

语法树（缩进表示子结点）：

```text
S
├─ (
├─ T
│  ├─ T ─ S ─ a            ← 第一个 a
│  ├─ ,
│  └─ S
│     ├─ (
│     ├─ T
│     │  ├─ T ─ S ─ a      ← 第二个 a
│     │  ├─ ,
│     │  └─ S ─ a          ← 第三个 a
│     └─ )
└─ )
```

每棵子树的叶子串是一个短语；只有 S → a 这三棵子树的孩子全是叶子，所以简单短语是三个 a，最左边的那个是句柄。

```text
B → aB | b
```

解答：先写增广文法：

```text
S → A
A → BA | λ
B → aB | b
```

| I0 | S→·A，A→·BA，A→·，B→·aB，B→·b | A→I2，B→I3，a→I4，b→I1 |
| I1 | B→b· | |
| I2 | S→A· | 接受 |

#### 7. 语法制导方案

某语言的文法如下，其中 D 表示声明，S 表示语句。

```text
P → D; S
D → D; D | id: T | proc id
T → integer
S → S; S | id := n
```

写出一个语法制导方案，计算用该语言写的程序中，声明部分声明了多少个 id 及每个 id 在语句部分出现的次数。

原稿解答：假设使用自顶向下方法，需要四个函数，两个变量。DCount 代表声明部分 id 出现次数，SCount 代表语句部分 id 出现次数。

- IntiDCount：初始化 0；IntiSCount：初始化 0。
- AddDCount：DCount 增一；AddSCount：SCount 增一。

于是语法制导方案是：

```text
P → D #IntiDCount# ; S #IntiSCount#
D → D; D | id #AddDCount# : T | proc id #AddDCount#
T → integer
S → S; S | id #AddSCount# := n
```

（更正：原稿有两处问题。第一，初始化动作放在 D、S 之后，执行时会把刚数好的计数清零，应放在最前面。第二，SCount 只统计语句部分 id 的总次数，题目要的是每个 id 各自的出现次数，要借助一张表给每个声明过的 id 记一个计数。）改正后的方案（整理补充）：

```text
P → #Init# D ; S #Output#
D → D; D
D → id #AddDecl# : T
D → proc id #AddDecl#
T → integer
S → S; S
S → id #AddUse# := n
```

- Init：DCount := 0，把计数表清空。
- AddDecl：DCount := DCount + 1；把当前 id 登记进表，它的计数 cnt 置 0。
- AddUse：在表里查当前 id，cnt := cnt + 1（查不到可以报"使用而无声明"）。
- Output：输出 DCount，以及表中每个 id 的 cnt。

#### 8. 符号表

```pascal
    var i, j, k: integer; {t1}
    procedure Q()
        var a, b: real;

            R的过程体

        Q的过程体
    end
    procedure S()
        var c, e: char; {t4}
    begin
        S的过程体
```

原稿解答：假设 int 占一个单元，real 占两个单元，boolean 占一个单元（char 也按一个单元算）。这题省略 size 是因为过程体有省略，所以无法求出 size。

- 变量的符号表设计：Name、Kind、Type、Access、Level、Offset。
- 函数的符号表设计：Name、Kind、Type、Class、Level、（Offset）、Param、Size、Forward。Class → actual \| formal（是 formal 的时候 Offset 生效）。

| Name | Kind | Type | Access / Class | Level | Offset / Param | Forward |

| P | routKind | | actual | 0 | | false |
| i | varKind | intPtr | dir | 1 | 0 | |
| j | varKind | intPtr | dir | 1 | 1 | |
| k | varKind | intPtr | dir | 1 | 2 | |
| Q | routKind | | actual | 1 | | false |
| a | varKind | realPtr | dir | 2 | 0 | |
| b | varKind | realPtr | dir | 2 | 2 | |
| R | routKind | | actual | 2 | | false |
| a | varKind | boolPtr | dir | 3 | 0 | |
| b | varKind | boolPtr | dir | 3 | 1 | |
| # | 指向 Q | | | | | |
| S | routKind | | actual | 1 | | false |
| c | varKind | charPtr | dir | 2 | 0 | |
| e | varKind | charPtr | dir | 2 | 1 | |

说明：原稿这张表是驻留法的写法，退出的局部化区表项保留，用 # 跳过。按 `05 语义分析与符号表.md` 第 7.2 节的做法，退出 R、退出 Q 时各加一个跳转项（分别指回 R、Q 那一项），原稿合成了一项指向 Q，查表时效果一样。若用删除法，t4 时刻 Q 里的 a、b、R 和 R 里的 a、b 都已删掉，表里只剩 P、i、j、k、Q、S、c、e 八项。原表头 Forword 是 Forward 的笔误；同一程序的逐步跟踪见 `05 语义分析与符号表.md` 第 7 节。

### 二、（15 分）设计一个与正则表达式 `(a|b)*bb(a|b)*` 等价的最小确定有限自动机。

原稿解答：1. 画出等价的 NFA；2. 表格法（子集法）确定化；3. 等效状态合并。子集表如下（+ 标初态，\* 标终态）：

| I | Ia | Ib |
|---|---|---|
| {S0,S1,S2}+ | {S1,S2} | {S1,S2,S3} |
| {S1,S2} | {S1,S2} | {S1,S2,S3} |
| {S1,S2,S3} | {S1,S2} | {S1,S2,S3,S4,S5,S6} |
| {S1,S2,S3,S4,S5,S6}\* | {S1,S2,S5,S6} | {S1,S2,S3,S4,S5,S6} |
| {S1,S2,S5,S6}\* | {S1,S2,S5,S6} | {S1,S2,S3,S5,S6} |
| {S1,S2,S3,S5,S6}\* | {S1,S2,S5,S6} | {S1,S2,S3,S4,S5,S6} |

该题和 2015 级唐班试题第一题相同（那题字母表是 0、1）。

（更正：原稿子集表漏了 {S1,S2} 这一行，上表第二行是补上的。原稿没画 NFA，也没写最小化结果，下面是整理补充。）

原稿的 NFA 可以从子集表反推出来：S0 为初态，S0 -ε→ S1；S1 在 a、b 上自环；S1 -ε→ S2；S2 -b→ S3 -b→ S4；S4 -ε→ S5；S5 在 a、b 上自环；S5 -ε→ S6，S6 为终态。用 Python 按这个 NFA 做子集法，得到的正是上表六个状态。

最小化：记六个子集依次为 A、B、C、D、E、F。

1. 初始划分：非终态 {A,B,C}，终态 {D,E,F}。
2. {A,B,C} 读 b：A、B 到 C（非终态），C 到 D（终态），分成 {A,B} 和 {C}。
3. {D,E,F} 读 a、b 都落在终态组里，不再分；{A,B} 读 a 都到 B，读 b 都到 C，也不再分。

最小 DFA（q0 = {A,B}，q1 = C，q2 = {D,E,F}）：

| 状态 | a | b |
|---|---|---|
| →q0（初态） | q0 | q1 |
| q1 | q0 | q2 |
| q2（终态） | q2 | q2 |

q0 表示"还没出现 bb 且上一个字符不是 b"，q1 表示"刚读了一个 b"，q2 表示"已经出现过 bb"。用长度 ≤ 8 的全部 a、b 串核对过。

### 三、（15 分）说明如下文法是否是 LL(1) 文法，若不是，将其转换为 LL(1) 文法并给出转换后文法的 LL(1) 分析表。

```text
S → (L) | aS | a
L → LbS | S
```

原稿解答：有左递归，还有公共前缀，必不是 LL(1) 文法。

```text
First(S) = { (, a }      First(L) = { (, a }
Follow(S) = { #, b, ) }  Follow(L) = { ), b }
```

（更正：Follow(S) 原文作 { # }。L → LbS 和 L → S 都把 Follow(L) 传给 S，所以还要加上 b 和 )；Follow(L) 原文作 { }, b }，右括号印错。）

```text
Predict(S → (L)) = { ( }
Predict(S → aS)  = { a }
Predict(S → a)   = { a }
Predict(L → LbS) = { (, a }
Predict(L → S)   = { (, a }
```

S 的两个候选式在 a 上冲突，L 的两个候选式在 (、a 上冲突，所以不是 LL(1) 文法。

通过增广、合并（提公共前缀）、消除左递归，得到：

```text
Z → S
S → (L) | aS'
S' → S | ε
L → SL'
L' → bSL' | ε
```

| 文法符号 | First 集 | Follow 集 |
|---|---|---|
| Z | (, a | # |
| S | (, a | b, ), # |
| S' | ε, (, a | b, ), # |
| L | (, a | ) |
| L' | b, ε | ) |

（更正：First(Z) 原文作 `(`，漏了 a。）

| 编号 | 文法产生式 | Predict 集 |
|---|---|---|
| 1 | Z → S | (, a |
| 2 | S → (L) | ( |
| 3 | S → aS' | a |
| 4 | S' → S | (, a |
| 5 | S' → ε | b, ), # |
| 6 | L → SL' | (, a |
| 7 | L' → bSL' | b |
| 8 | L' → ε | ) |

（原表第 7 行印作 L' → bSL，漏了末尾的 '。）

分析表如下：

| | ( | a | b | ) | # |
|---|---|---|---|---|---|
| Z | 1 | 1 | | | |
| S | 2 | 3 | | | |
| S' | 4 | 4 | 5 | 5 | 5 |
| L | 6 | 6 | | | |
| L' | | | 7 | 8 | |

（更正：L' 这一行原表只在 ) 列填了 7，b 列空着。按 Predict 集应是 b 列填 7（L' → bSL'），) 列填 8（L' → ε）。）

每行各候选式的 Predict 集互不相交，变换后的文法是 LL(1) 文法（Python 核对过）。

### 四、（15 分）已知文法如下，1）构造该文法的 LR(1) 归约规范活前缀状态机；2）构造相应的 LR(1) 分析表。

```text
Z → A
A → BB
B → aB
B → b
```

原稿解答只给了 First、Follow 集：

| | First | Follow |
|---|---|---|
| Z | a, b | # |
| A | a, b | # |

| 状态 | LR(1) 项目 | 转移 |
|---|---|---|
| I0 | [Z→·A, #]，[A→·BB, #]，[B→·aB, a/b]，[B→·b, a/b] | A→I2，B→I3，a→I1，b→I4 |
| I1 | [B→a·B, a/b]，[B→·aB, a/b]，[B→·b, a/b] | B→I5，a→I1，b→I4 |

| I5 | [B→aB·, a/b] | |
| I6 | [B→a·B, #]，[B→·aB, #]，[B→·b, #] | B→I9，a→I6，b→I7 |
| I7 | [B→b·, #] | |
| I8 | [A→BB·, #] | |
| I9 | [B→aB·, #] | |

LR(1) 分析表（sN 表示移入并转到状态 N，rN 表示按第 N 条产生式归约）：

| 状态 | a | b | # | A | B |
|---|---|---|---|---|---|
| 0 | s1 | s4 | | 2 | 3 |
| 1 | s1 | s4 | | | 5 |
| 2 | | | acc | | |
| 3 | s6 | s7 | | | 8 |
| 4 | r4 | r4 | | | |

| 6 | s6 | s7 | | | 9 |

### 五、（15 分）请写出如下 pascal 程序的局部优化后的四元式形式的中间代码。

```pascal
program main()
    var a: ARRAY[1..10] of integer;
    procedure f(m: integer)
        var b: integer;
        var i: integer;
        begin
            b := 10;
            for i := 1 to 10 do
                a[i] := m + b*2
        end
    begin
        f(2)
    end.
```

原稿解答：假定 int 类型占一个单元。

| 四元式 | 解释 |
|---|---|
| (ENTRY, L1, -, -) | L1：程序入口 |
| (ENTRY, L2, -, -) | L2：f 函数入口 |
| (=, 10, -, b) | |
| (=, 1, -, i) | for 语句的初值赋值 |
| (FOR, -, -, -) | 标定循环开始 |
| (<=, i, 10, t1) | 条件判断 |
| (DO, t1, -, -) | 执行循环 |
| (-, i, 1, t2) | |
| (\*, t2, 1, t3) | |
| ([], a, t3, t4) | a[i] 的地址 |
| (\*, b, 2, t5) | |
| (+, m, t5, t6) | |
| (=, t6, -, t4) | |
| (ENDFOR, -, -, -) | |
| (ENDPROC, -, -, -) | |
| (VALACT, 2, 0, 1) | |
| (CALL, f, true, -) | |
| (ENDPROG, -, -, -) | |

第一个和第二个四元式同样可以写成 `(ENTRY, L1, 16, 1)`、`(ENTRY, L2, 6, 2)`，但是不建议写，因为涉及到计算，容易出错。

（更正：赋值那一条原文作 `(=, t4, -, t6)`，方向反了。课程约定 `(ASSIG, x, -, y)` 表示 y := x，这里是把 t6 存进 t4 所指的 a[i]。另外原稿循环体后面漏了循环变量加一，ENDFOR 之前应补 `(+, i, 1, t7)`、`(=, t7, -, i)`。）

几点补充说明（整理补充）：

- `([], a, t3, t4)` 就是课程记法里的 `(AADD, a, t3, t4)`，下标变量每一维三条：SUBI、MULTI、AADD。
- 按 `06 中间代码生成.md` 第 10 节的动作文法，#Entry# 放在声明部分之后，所以过程 f 的 ENTRY…ENDPROC 会先生成，主程序的入口四元式排在它后面。原稿把两个 ENTRY 连着写在最前面，顺序上不太对。
- 题目要的是"局部优化后"。局部优化只在基本块内做常表达式节省和公共表达式节省。FOR 是标号性四元式，DO 是转移性四元式，所以 `b := 10` 和循环体不在同一个基本块，块内也没有重复的表达式，局部优化后四元式基本不变，原稿也没做改动。若再做循环优化，`(*, b, 2, t5)`、`(+, m, t5, t6)` 的分量在循环里都没被定值，是循环不变式，可以提到 FOR 之前。方法见 `07 中间代码优化.md`。

### 三、（15 分）已知文法如下：1）将文法等价变换为 LL(1) 文法；2）构造变换之后的文法的 LL(1) 分析表。

```text
S → Aa | Ab | c
A → Ad | Se | f
```

解答（整理补充）：

1）文法有间接左递归（S ⇒ Aa ⇒ Sea），A 还有直接左递归，S 的前两个候选式有公共前缀 A。

1. 消除 A 的直接左递归：A → SeA' | fA'，A' → dA' | ε。
2. 把 A 代入 S：S → SeA'a | SeA'b | fA'a | fA'b | c。
3. 提公共因子，记 B → a | b：S → SeA'B | fA'B | c。
4. 消除 S 的直接左递归：S → fA'BS' | cS'，S' → eA'BS' | ε。A 已经用不到，删掉。

变换后的文法：

```text
S  → fA'BS' | cS'
S' → eA'BS' | ε
A' → dA' | ε
B  → a | b
```

用 Python 枚举长度 ≤ 7 的句子，原文法和新文法都是 127 个，完全相同。

2）First、Follow 与 Predict 集：

| 编号 | 产生式 | Predict 集 |
|---|---|---|
| 1 | S → fA'BS' | f |
| 2 | S → cS' | c |
| 3 | S' → eA'BS' | e |
| 4 | S' → ε | # |
| 5 | A' → dA' | d |
| 6 | A' → ε | a, b |
| 7 | B → a | a |
| 8 | B → b | b |

其中 Follow(S) = Follow(S') = {#}，Follow(A') = First(B) = {a, b}，Follow(B) = {e, #}。

LL(1) 分析表：

| | a | b | c | d | e | f | # |
|---|---|---|---|---|---|---|---|
| S | | | 2 | | | 1 | |
| S' | | | | | 3 | | 4 |
| A' | 6 | 6 | | 5 | | | |
| B | 7 | 8 | | | | | |

没有多重表项，是 LL(1) 文法。

提示：如果先把 S 代入 A（得到 A → Ad | Aae | Abe | ce | f），再消左递归、给 S 提公共因子 A，会得到 `A' → dA' | aeA' | beA' | ε`，其中 A' → ε 的 Predict 集是 Follow(A') = {a, b}，和 aeA'、beA' 冲突，而且 S → AS'' 与 S → c 在 c 上冲突，不是 LL(1)。所以这题要把 A 消掉。

### 一、（20 分）设有限自动机 M 接受字母表 Σ={0,1} 上所有满足如下条件的串：串中至少要包含两个连续的 1。据此回答下列问题：（1）写出与 M 等价的正则表达式；（2）构造与 M 等价的最小确定有限自动机；（3）构造与 M 等价的 3 型文法（正则文法）。

原稿解答：注意第三问要求的是 3 型文法。

（1）`(0|1)*11(0|1)*`

（2）原稿空着。解答（整理补充）：做法与 2013 级唐班卷第二题相同（a 换成 0，b 换成 1），NFA 确定化后得到 6 个状态，分割法合并成 3 个：

| 状态 | 0 | 1 |
|---|---|---|
| →q0（初态） | q0 | q1 |
| q1 | q0 | q2 |
| q2（终态） | q2 | q2 |

q0：还没出现 11，上一个字符不是 1（或还没读）；q1：还没出现 11，刚读了一个 1；q2：已经出现 11。三个状态两两可区分。

（3）原稿空着。解答（整理补充），按 DFA 直接写右线性文法，S 对应 q0，A 对应 q1，B 对应 q2，读入后到达终态时再多写一条只含终极符的产生式：

```text
S → 0S | 1A
A → 0S | 1B | 1
B → 0B | 1B | 0 | 1
```

DFA、正则表达式、文法三者用长度 ≤ 10 的全部 0/1 串核对过，接受的集合相同。

### 二、（20 分）分支语句 if-then-else 的一个文法如下：（1）计算每一条产生式的 predict 集合；（2）规定"e 与最近的 t 相匹配"，给出相应的 LL(1) 分析表。

```text
S → iBtSE | a
E → eS | ε
B → b
```

原稿解答：

| | first | follow |
|---|---|---|
| S | {i, a} | {e, #} |
| E | {e, ε} | {e, #} |
| B | {b} | {t} |

| 编号 | 产生式 | predict |
|---|---|---|
| 1 | S → iBtSE | i |
| 2 | S → a | a |
| 3 | E → eS | e |
| 4 | E → ε | e, # |
| 5 | B → b | b |

由 predict 集合看出，其不符合 LL(1) 文法（E 的两个候选式在 e 上冲突），但是可以定义规则消除冲突，规定"e 与最近的 t 相匹配"，那么 LL(1) 分析表如下：

| | i | a | b | e | # |
|---|---|---|---|---|---|
| S | 1 | 2 | | | |
| E | | | | 3 | 4 |
| B | | | 5 | | |

E 行 e 列本来有 3、4 两项，按"e 与最近的 t 匹配"只保留 3（E → eS），也就是遇到 e 就把它归给当前最内层的 if。原稿答案 Python 核对无误。

### 三、（20 分）根据如下文法，回答问题：（1）构造该文法的 LR(1) 归约规范活前缀状态机；（2）根据构造的状态机说明该文法是否为 LR(1) 文法，给出理由。

```text
S → AA
A → Aa | a
```

原稿无解答。解答（整理补充）：拓广 Z → S。`#/a` 表示向前看符号是 # 或 a 的两个项目。

| 状态 | LR(1) 项目 | 转移 |
|---|---|---|
| I0 | [Z→·S, #]，[S→·AA, #]，[A→·Aa, a]，[A→·a, a] | S→I2，A→I1，a→I3 |
| I1 | [S→A·A, #]，[A→A·a, a]，[A→·Aa, #/a]，[A→·a, #/a] | A→I4，a→I5 |
| I2 | [Z→S·, #] | 接受 |
| I3 | [A→a·, a] | |
| I4 | [S→AA·, #]，[A→A·a, #/a] | a→I6 |
| I5 | [A→Aa·, a]，[A→a·, #/a] | |
| I6 | [A→Aa·, #/a] | |

（2）不是 LR(1) 文法。I5 里 [A→Aa·, a] 和 [A→a·, #/a] 在向前看符号 a 上都要归约，有归约-归约冲突。原因是文法有二义性：`aaa` 可以拆成 a·aa，也可以拆成 aa·a，两个 A 各分到几个 a 不确定。

### 四、（20 分）根据如下 C 程序片段回答问题：（1）写出语义分析结束后，该段程序的全局符号表；（2）写出该段程序的四元式中间代码。

```c
int fact(){
    static int i=5;
    if(i==0) return 1;
    else { i=i-1; return (i+abs(1))*fact(); }
}
main()
{
    printf("factor of 5=%d\n", fact());
}
```

原稿无解答。

（1）解答（整理补充）。约定：C 语言函数名在 0 层，函数里声明的变量在 1 层；按驻留法，退出函数时追加跳转项；abs、printf 是库函数，程序里没有声明，不进表；else 后的复合语句没有声明，不单独留表项。static 局部变量存放在静态数据区，不在活动记录里，偏移相对静态区起点（记作 s₀），课程资料里没有统一写法，答题时写清约定即可。

| 序号 | Name | Kind | Type | Access | Level | Off | 其他 |
|---|---|---|---|---|---|---|---|
| 1 | fact | routKind | intPtr | | 0 | | Param 为空，Class = actual |
| 2 | i | varKind | intPtr | dir | 1 | s₀（静态区） | Value ↑〈5〉 |
| 3 | # | | | | | | 退出 fact，指向第 1 项 |
| 4 | main | routKind | intPtr | | 0 | | 老式 C 省略返回类型时默认 int |
| 5 | # | | | | | | 退出 main，指向第 4 项 |

若用删除法，语义分析结束后表里只剩 fact 和 main 两项。同类题（fact 函数的全局符号表）见 `33 历年题（2016–2022级）.md` 的 2017 级试卷一第三题。

（2）解答（整理补充）。写法与 `31 历年题（2012–2015级）.md` 里 fab 函数那道题一致：return 记作 `(RETURN, -, -, 返回值)`，参数用 VALACT 传递，形参偏移从 off₀ 开始。表达式按第五题（4）的策略生成：`(i+abs(1))*fact()` 两边都有函数调用，从左向右；`i+abs(1)` 只有右边有调用，先生成 abs(1)。

```text
1.  (ENTRY, fact, -, -)
2.  (EQ, i, 0, t1)
3.  (THEN, t1, -, -)
4.  (RETURN, -, -, 1)
5.  (ELSE, -, -, -)
6.  (-, i, 1, t2)
7.  (:=, t2, -, i)
8.  (VALACT, 1, off₀, 1)
9.  (CALL, abs, true, t3)
10. (+, i, t3, t4)
11. (CALL, fact, true, t5)
12. (*, t4, t5, t6)
13. (RETURN, -, -, t6)
14. (ENDIF, -, -, -)
15. (ENDFUNC, -, -, -)
16. (ENTRY, main, -, -)
17. (CALL, fact, true, t7)
18. (VALACT, "factor of 5=%d\n", off₀, 1)
19. (VALACT, t7, off₀+1, 1)
20. (CALL, printf, true, t8)
21. (ENDFUNC, -, -, -)
```

`static int i=5` 的初值在程序装入时放进静态区，只做一次，不在 fact 每次执行的代码里生成赋值四元式。printf 的第一个实参是字符串常量，传的是它的地址，这里按占 1 个单元写。

### 五、（20 分，每题 5 分）简答（直接写答案即可）

#### （1）下列 5 项关于过程活动记录的相关描述正确的有哪些？

- ① 运行时过程活动记录的管理工作是由编译器生成的目标代码运行时完成的。
- ② 若目标机确定，则目标代码生成阶段可以精确计算出每个过程活动记录的大小。
- ③ 同一个函数被多次调用时所生成的所有过程活动记录的大小一定是相同的。
- ④ 动态链指针指向栈区、返回地址指向目标代码区。
- ⑤ 存在间接递归时，递归调用的函数的多个过程活动记录可能不止一个是活跃的。

原稿无解答。答案（整理补充）：①②③④。

①②③ 与学习通 9-5 单选题的前三个选项相同，那道题的答案说它们正确（见 `10 选择题精编.md`）。④ 动态链指向调用者的活动记录，在栈区；返回地址是调用指令下一条指令的地址，在代码区。⑤ 错：同一个函数不论怎样递归，活跃活动记录只有最新的一个。

#### （2）"不含公共前缀和左递归的 2 型文法一定是 LL(1) 文法"，这种说法是否正确？若正确请证明之，否则举例说明。

原稿无解答。解答（整理补充）：不正确。没有公共前缀和左递归，只能保证候选式的"字面开头"不同，不能保证 Predict 集不相交。两种反例：

- 候选式经过非终极符推出相同的首符号：`S → A | B`，`A → a`，`B → a`。Predict(S→A) = Predict(S→B) = {a}。
- 有 ε 候选式时，Follow 集与其他候选式的 First 集相交：本卷第二题的 if-then-else 文法 `S → iBtSE | a`，`E → eS | ε`，`B → b` 就没有公共前缀和左递归，但 Predict(E→eS) = {e}，Predict(E→ε) = {e, #}，不是 LL(1) 文法。

#### （3）有如下 C 程序，经过编译连接后，单步跟踪执行时，查看 a 的值，某些调试器会报告"无此变量"。根据所学编译知识解释出现此问题的原因。

```c
main(){ int x;
    const int a=1;
    x=100+a;
    printf("%d\n", x);}
```

原稿无解答。解答（整理补充）：a 是常量标识符，语义分析时在符号表里登记为 constKind，只记它的值 1，不分配存储空间（没有偏移）。生成中间代码和优化时，用到 a 的地方直接换成常数 1，`100+a` 在编译时就算成 101（常表达式节省）。目标程序里根本没有 a 的存储单元，调试信息里也就没有这个变量，所以调试器报告"无此变量"。2016 级唐班卷第四题的解析是同一个意思。

#### （4）表达式代码生成顺序与程序输出

表达式 "E1 op E2" 的代码生成顺序采用如下策略：若 E1 和 E2 中都有函数调用，则按从左向右顺序生成；若 E1 和 E2 中只有一个含有函数调用，则先生成含有函数调用的那个子表达式。在该策略下，若将题四中的表达式 "(i+abs(1))\*fact()" 替换为 "(i+1)\*fact()"，其余程序不变（abs 为求绝对值库函数），则程序的执行结果会不同，请写出替换前和替换后程序的输出结果。

原稿无解答。解答（整理补充）：

- 替换前输出 `factor of 5=120`。两边都有函数调用，先算 `i+abs(1)` 再调 fact()。每层先把 i 减 1，马上用当前的 i 算出左因子，依次是 5、4、3、2、1，最内层 i 为 0 返回 1，结果 5×4×3×2×1×1 = 120。
- 替换后输出 `factor of 5=1`。只有右边有函数调用，先调 fact()，等递归全部返回时静态变量 i 已经是 0，每层的左因子 i+1 都是 1，结果为 1。

用 Python 按这两种求值顺序模拟过，分别得 120 和 1。

### 一、（10 分）设有如下 NFA：（1）构造与之等价的 DFA；（2）完成自动机的最小化。

原卷为状态图，转写成转换表（1 为初态，6、7 为终态）：

| 状态 | a | b | c |
|---|---|---|---|
| →1 | {2, 3} | | |
| 2 | | {3} | {4} |
| 3 | | | {5} |
| 4 | {3, 6} | {4} | {7} |
| 5 | | {4} | {7} |
| 6（终态） | | | |
| 7（终态） | | | |

原稿解答。解析：NFA 化成等价的 DFA，先画表；要求最简的 DFA 则需要状态合并。

第一步：画表（+ 标初态，\* 标终态）。

| | I | Ia | Ib | Ic |
|---|---|---|---|---|
| A | {1}+ | {2,3} | | |
| B | {2,3} | | {3} | {4,5} |
| C | {3} | | | {5} |
| D | {4,5} | {3,6} | {4} | {7} |
| E | {5} | | {4} | {7} |
| F | {3,6}\* | | | {5} |
| G | {4} | {3,6} | {4} | {7} |
| H | {7}\* | | | |

（原表 H 行没有标 \*，{7} 含终态 7，应为终态。）

于是等价的 DFA 如下（原稿为状态图，转写成表）：

| 状态 | a | b | c |
|---|---|---|---|
| →A | B | | |
| B | | C | D |
| C | | | E |
| D | F | G | H |
| E | | G | H |
| F（终态） | | | E |
| G | F | G | H |
| H（终态） | | | |

第二步：最简化，采用分割法。

- 非终止集：{A,B,C,D,E,G} → {A} ∪ {B} ∪ {C} ∪ {D,G} ∪ {E}
- 终止集：{F,H} → {F} ∪ {H}

D 和 G 在 a、b、c 上分别都到 F、G、H，合并；其余状态出边不同（空着的格子按死状态算），各自单独一组。

于是最简的 DFA 如下（D、G 合并记作 D|G）：

| 状态 | a | b | c |
|---|---|---|---|
| →A | B | | |
| B | | C | D\|G |
| C | | | E |
| D\|G | F | D\|G | H |
| E | | D\|G | H |
| F（终态） | | | E |
| H（终态） | | | |

子集法和分割法的结果用 Python 核对无误。

### 二、（10 分）一个机器人在一个平面空间移动，已知机器人在接到命令 F 时可以向前移动，接到命令 L 时左转 90 度，接到命令 R 时右转 90 度。请给出一个文法 G，该文法 G 的语言为：使得机器人的最终方向与初始时方向相同的所有命令序列（例如 FLR、RRRR）。

原稿解答。解析：该题可以先画状态转换图，然后写文法；但是如果对文法熟练，可以直接写文法。

答：设 S 是朝向前（初始方向）的状态；A 是朝向右状态；B 是朝向后状态；C 是朝向左状态；R 是向右转命令；L 是向左转命令；F 是向前移动命令。原稿的状态转换图转写成表（S 为初态兼终态）：

| 状态 | F | R | L |
|---|---|---|---|
| S（前） | S | A | C |
| A（右） | A | B | S |
| B（后） | B | C | A |
| C（左） | C | S | B |

于是文法 G 如下：

```text
S → FS | RA | LC | ε
A → LS | FA | RB
B → LA | FB | RC
C → LB | FC | RS
```

（更正：F 的说明原文作"向前转命令"，F 是向前移动，不转向。）每个非终极符表示"当前朝向"，F 不改变朝向，只有回到 S 时才能用 ε 结束。用 Python 核对过长度 ≤ 7 的全部命令串：文法接受当且仅当 R 的个数减 L 的个数是 4 的倍数。

### 三、（30 分）考虑有如下文法：

```text
G: S → a | S$S | S@S
```

（1）判断该文法是否为二义性文法并说明理由。（5 分）

（2）假设存在以下规则：a）运算符 `$` 是右结合、低优先；b）运算符 `@` 是左结合、高优先。给出一个新的文法 G1 使得其描述与 G 相同的语言，并符合上述规则。（5 分）

（3）构建 G 的 LR(0) 可归前缀状态机（需添加拓广产生式）。（10 分）

（4）分别求出 First(S) 和 Follow(S)，并结合问题 3 中的自动机回答和解释在该 LR(0) 可归前缀状态机中，哪些冲突不能被 LR(0) 语法分析方法解决但可以被 SLR(1) 方法解决，哪些冲突不能被 SLR(1) 方法解决。（10 分）

原稿解析：

- （1）要判断一个文法有二义性，画出两个不同语法生成树即可；判断一个文法一定没有二义性比较难，记住一个结论：满足 LL(1) 的文法一定没有二义性。
- （2）可以把 `@` 看成乘法，`$` 看成加法，于是文法 G1 可以写出来（教材上有加法、乘法的文法，但是没有考虑左结合、右结合）。
- （4）LR(0) 冲突就是一个状态里既有可归约的项又有可移入的项；如果一个状态的归约项的 Follow 集合与其可移入的字符集合交集不为空，那么就不符合 SLR(1)。

答：

（1）是二义性文法，`a$a@a` 有两个不同的语法生成树（原稿为图，转写成缩进文本）：

```text
树一：先 $ 后 @                树二：先 @ 后 $
S                             S
├─ S                          ├─ S ─ a
│  ├─ S ─ a                   ├─ $
│  ├─ $                       └─ S
│  └─ S ─ a                      ├─ S ─ a
├─ @                             ├─ @
└─ S ─ a                         └─ S ─ a
```

（2）参考加法和乘法的文法产生式，修改即可：

```text
E → T        (1)
E → T$E      (2)
T → F        (3)
T → T@F      (4)
F → a        (5)
```

第二条产生式是右递归，`$` 右结合；第四条是左递归，`@` 左结合。`@` 在更低一层（T），所以优先级高。用 Python 数过长度 ≤ 7 的句子，G1 下每个句子只有一棵语法树。

（3）增加拓广产生式后，文法如下：

```text
Z → S
S → a
S → S$S
S → S@S
```

于是 LR(0) 可归前缀状态机如下（原稿为图，转写成表）：

| 状态 | 项目 | 转移 |
|---|---|---|
| S0 | `Z→·S`，`S→·a`，`S→·S$S`，`S→·S@S` | S→S1，a→S2 |
| S1 | `Z→S·`，`S→S·$S`，`S→S·@S` | `$`→S3，`@`→S4 |
| S2 | `S→a·` | |
| S3 | `S→S$·S`，`S→·a`，`S→·S$S`，`S→·S@S` | S→S5，a→S2 |
| S4 | `S→S@·S`，`S→·a`，`S→·S$S`，`S→·S@S` | S→S6，a→S2 |
| S5 | `S→S$S·`，`S→S·$S`，`S→S·@S` | `$`→S3，`@`→S4 |
| S6 | `S→S@S·`，`S→S·$S`，`S→S·@S` | `$`→S3，`@`→S4 |

（4）First(S) = {a}，Follow(S) = `{#, $, @}`。

有 LR(0) 冲突的状态有：S1、S5、S6。SLR(1) 可以解决 S1 的冲突，但是不能解决 S5 和 S6 的冲突。

理由：S1 里归约项是 Z→S·，只在 # 上接受，移入符号是 `$`、`@`，不相交。S5、S6 里归约项的左部是 S，Follow(S) = `{#, $, @}`，与移入符号 `$`、`@` 相交，SLR(1) 仍有移入-归约冲突。状态机和冲突判断都用 Python 核对过。

### 四、（10 分）设有如下程序：

```pascal
const m=333;
const n=444;
Type at=array[1..10] of real;        //类型声明，长度为 10 的实型数组
     rt=record i,j:integer end;      //类型声明，含有整型 i、j 的结构体
```

### 五、（20 分）有关于变量的文法如下：

```text
V → id
V → V[E]
```

当采用语法制导的方法实现语义分析及中间代码生成时，应该在文法中增加什么样的语义动作以及这些语义动作要实现什么功能才能实现：（1）语义错误检查（最少写出 3 种）；（2）生成含有数组越界检查的中间代码，并请解释为什么一般的编译器中没有数组越界检查。（数组越界是一种目标程序运行时可能发生的 runtime error。例如声明了一个数组为 int a[100]，程序中出现 a[i]，且在程序运行时 a[i] 中的 i 在某一时刻为 100，就发生了数组越界。）

原稿解析：（1）要求是在这里添加语义动作，以及要说明这个动作要实现什么功能。数组的语义错误检查有哪些呢？从最基本的想，首先这个变量 id 是否已经声明？其次，要检查 V[E] 是不是数组类型，还要检查数组下标 E 是不是合法。（2）检查数组越界的中间代码就是与上下界做比较。

解答：

（1）

```text
V → id #Live#
V → V[E #CheckMark#] #CheckArray#
```

各动作符的含义如下：

- Live：用来检查有没有这个变量 id 的声明。
- CheckMark：检查 E 是不是一个数组下标类型。
- CheckArray：检查 V[E] 是不是一个数组类型。比如 a[n]，变量 a 确实声明了，但是它是一个类型定义的标识符，显然不对，是一个语义错误。

（更正：最后一句原文作"是一个语法错误"。a[n] 在语法上合法，标识符种类用错属于语义错误。）

（2）需要加的动作是：

```text
V → V[E] #OutBound#
```

数组越界的中间代码就是检查当前的数组下标是不是在上界 U 和下界 L 之间，如果是，则没有越界；如果不是则越界，转错误处理。原稿"中间代码略"，下面是整理补充。设 V 的类型为 (Size, ArrayTy, L, U, ElemType)，元素大小为 S：

```text
E 的中间代码，结果为 t
(LT, t, L, t1)
(JMP1, t1, -, Lerr)      下标小于下界，转错误处理
(GT, t, U, t2)
(JMP1, t2, -, Lerr)      下标大于上界，转错误处理
(SUBI, t, L, t3)
(MULTI, t3, S, t4)
(AADD, V, t4, t5)        t5 为 V[E] 的地址
```

Lerr 处是运行时的越界错误处理程序。

没有数组越界检查的原因是：可以提高目标代码效率。数组基本上都和循环一起用，每次循环都检查下标是否越界，会多执行很多条指令，导致目标程序效率很低，所以现在的语言编译时基本上不检查数组是否越界。

### 六、（10 分）如果语言中允许在嵌套声明的内层函数体中用 goto L 语句跳转到外层函数的函数体，即允许非正常出口，若 L 位于 Q 的函数体中，（1）跳出后的新动态 AR 链应怎么变化，并举例说明？（2）编译程序需要额外保存哪些信息，并如何求得新的 SP 和 TOP 的值？

原稿解析：允许 goto 语句的话，也就是允许一次退出多个过程活动记录。例子：

```c
void P(){
    void Q(){
        ......
        L: int a;
        int b;
        void R(){
            int c;
            goto L;
        }
    }
}
```

解答：

（1）找到当前活跃的过程活动记录 Q，把该记录后面的记录删除。

（2）知道 L 所在的层数，这样就知道了 Q 的层数，也就能够找到 Q 函数当前活跃过程活动记录的 sp，这个就是新的 sp 的值；知道了 sp，就可以求新的 top，top = 新 sp + Q 的过程活动记录大小（size）。

补充说明（整理补充）：

- 例如调用链为 P → Q → R，R 里执行 goto L，动态链从 [AR(P), AR(Q), AR(R)] 变成 [AR(P), AR(Q)]，接着从 Q 的函数体里 L 处往下执行。若 R 又递归调用过自己，栈里的几个 AR(R) 都要一起弹掉。
- 编译时要额外记下标号 L 所属函数 Q 的层数和 L 的代码地址（标号表里登记）。运行时 R 嵌套在 Q 里，Q 一定在 R 的变量访问环境中：用局部 Display 表时新 sp = 当前 AR 的 `Display[Q 的层数]`，用静态链时沿静态链往外找到 Q 的 AR。然后 top = sp + Q.size，再转到 L。变量访问环境的求法见 `08 运行时存储空间管理.md` 第 9–12 节。

### 二、简答题（6 分×5）

#### 1. 画出能被 3 整除的十进制数的 DFA。注意：不允许出现前导 0，即 099 是非法的，不需要考虑负数。

回忆稿特别提醒：一定要注意，不允许出现前导 0。

原卷无答案。解答（整理补充）：S 为初态；Z 表示整个数就是 0；R0、R1、R2 表示已经读了一个以非 0 开头的数，除以 3 余 0、1、2。终态为 Z 和 R0。十进制数除以 3 的余数等于各位数字之和除以 3 的余数，所以只按数字模 3 分三组：{0,3,6,9}、{1,4,7}、{2,5,8}。

| 状态 | 0 | 3,6,9 | 1,4,7 | 2,5,8 |
|---|---|---|---|---|
| →S | Z | R0 | R1 | R2 |
| Z（终态） | | | | |
| R0（终态） | R0 | R0 | R1 | R2 |
| R1 | R1 | R1 | R2 | R0 |
| R2 | R2 | R2 | R0 | R1 |

Z 没有出边，0 后面再跟任何数字都拒绝，这就排除了前导 0；S 读 0 不能直接进 R0，否则 099 会被接受。用 Python 对 1～4 位的全部数字串核对过，接受的正好是"0 或不以 0 开头且能被 3 整除"的串；这 5 个状态两两可区分。

#### 2. 从状态数和描述能力来对比 LR(0)、SLR(1)、LR(1) 和 LALR(1)？

原卷无答案。解答（整理补充）：

- 描述能力：LR(0) < SLR(1) < LALR(1) < LR(1)，LR(1) 最强。
- 状态数：LR(0) = SLR(1) = LALR(1) ≤ LR(1)。SLR(1) 就用 LR(0) 状态机，只是归约时看 Follow 集；LALR(1) 把 LR(1) 状态机里同心的状态合并，状态数回到 LR(0) 的水平，但合并后可能出现归约-归约冲突（本卷第五题就是例子）。

详见 `04 语法分析方法（LL1、递归下降、LR）.md` 题 12。

#### 3. 什么是过程活动记录？它包含哪些内容？

### 四、已知文法 G 如下所示，请构造 LL(1) 分析表（10 分）

### 六、Display 表

一个类 C 语言的递归的程序片段如下，采用的是局部 display 表方法，问第二次调用递归的时候，栈区内容。

```c
void g(){
    int i, j;
    void f(int n){
        …
    }
    f(10);
}
void main(){
    int a, b;
    g();
}
```

原卷无答案，回忆稿也没有记下 f 的函数体。解答要点（整理补充）：假设 f 的函数体里递归调用 f(n-1)。main 和 g 都在最外层，是同层函数，层数为 0；f 嵌套在 g 里，层数为 1。局部 Display 表按 `NewAR.Display = CurrentAR.Display 的前 N 项 ⊕ newsp` 求（N 是新过程的层数）。

把"第二次调用递归"理解为 f(10) 递归调用 f(9) 之后，f(9) 再调用 f(8)，此时栈区从底到顶为（若理解为 f(9) 那一次，去掉最上面一个 AR 即可）：

| 活动记录 | 动态链指向 | 局部 Display 表 | 形参、局部变量 |
|---|---|---|---|
| AR(main)，首地址 ar0 | （无） | [ar0] | a、b 未赋值 |
| AR(g)，首地址 ar1 | AR(main) | [ar1] | i、j 未赋值 |
| AR(f)，首地址 ar2 | AR(g) | [ar1, ar2] | n = 10 |
| AR(f)，首地址 ar3 | AR(f)（ar2） | [ar1, ar3] | n = 9 |
| AR(f)，首地址 ar4（栈顶） | AR(f)（ar3） | [ar1, ar4] | n = 8 |

每个 AR 里还有返回地址等管理信息。要点：g 的 Display 表只有它自己，不含 main（两者同层，main 不在 g 的声明链上）；f 的每个 AR 的 Display 表第 0 项都是 g 的 AR，第 1 项是它自己。求法见 `08 运行时存储空间管理.md` 第 10 节。

### 七、语法制导

变量声明的语法制导，要求给出对应动作的具体实现，实际上就是填符号表。

原卷无答案，回忆稿没有记下具体文法。提示（整理补充，一种写法）：阅卷要求见下面"阅卷情况"，动作要写成程序，并且写清楚查表、填表。设声明文法为：

```text
VarDec → T IdList ;
T      → int #IntType# | real #RealType#
IdList → id #AddVar# | IdList , id #AddVar#
```

```c
/* 全局量：SymbTab 符号表，s 为表尾，Scope[level] 为本层起点，off 为本层当前偏移 */
void IntType()  { CurType = intPtr;  }          /* intPtr->size = 1 */
void RealType() { CurType = realPtr; }          /* realPtr->size = 2 */
void AddVar() {
    char *name = CurrentToken.name;
    for (int k = s; k >= Scope[level]; k--)     /* 只查本层 */
        if (strcmp(SymbTab[k].name, name) == 0) {
            error("重复声明");
            return;
        }
    s = s + 1;                                  /* 填表 */
    SymbTab[s].name   = name;
    SymbTab[s].kind   = varKind;
    SymbTab[s].type   = CurType;
    SymbTab[s].access = dir;
    SymbTab[s].level  = level;
    SymbTab[s].off    = off;
    off = off + CurType->size;                  /* 按类型大小推进偏移 */
}
```

符号表项的内容和局部化做法见 `05 语义分析与符号表.md` 第 2.4 节、第 6 节。
