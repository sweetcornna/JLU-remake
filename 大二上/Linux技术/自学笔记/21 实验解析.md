#### （2）使用 shell

a．分别执行 `help exit`、`help ls` 和 `help`，查看命令运行结果。

思路：`help` 只能查 bash 的内部命令。`exit` 是内部命令，`ls` 是外部命令。

```bash
help exit
```

```text
exit: exit [n]
    退出 shell。

    退出 shell，退出状态为 N。如果 N 被省略，则退出状态为最后一个执行的
    命令的退出状态。
```

`exit n` 以状态 n 退出 shell，不写 n 时退出状态等于最后执行的那条命令的退出状态。退出状态的约定：

| 退出状态 | 含义 |
| --- | --- |
| 0 | 命令成功执行 |
| 非 0 | 出错，可以用不同的值区分不同错误，例如 `exit 42` |
| 1 | 最常用的通用错误码 |
| 2 | shell 内置命令使用不当 |
| 126 | 找到了命令但无法执行，比如没有执行权限 |
| 127 | 找不到命令，常见原因是拼写错误或 PATH 设置有问题 |
| 128+n | 被信号 n 终止。按 Ctrl+C 发送的是 SIGINT（2 号信号），程序返回 130 |

退出状态只占一个字节，范围是 0 到 255，超出范围会回绕：`exit 383` 得到 127，`exit -1` 得到 255。上一条命令的退出状态保存在变量 `$?` 里，可以用 `echo $?` 查看。

```bash
help ls
```

```text
-bash: help: 没有与 "ls" 匹配的帮助主题。尝试使用 "help help" 或 "man -k ls" 或 "info ls"。
```

`ls` 是外部命令，`help` 查不到。


c．执行 `who` 命令和 `who am i`，对比其执行结果。

```text
$ who
user1    pts/4        2023-12-04 10:11 (192.168.x.x)
user2    pts/5        2023-12-04 10:57 (192.168.x.x)

user1    pts/4        2023-12-04 10:11 (192.168.x.x)
```

- `who` 列出当前登录系统的所有用户，每行是用户名、终端、登录时间和来源地址。
- `who am i` 只显示当前终端这一次登录的记录，格式和 `who` 一样。

（更正：原稿说"`who am i` 显示当前有效用户的用户名，在 root shell 中 `su` 切换到另一个用户后，`who am i` 会输出切换后的用户"。这是 `whoami` 的行为。`who am i` 读的是登录记录，`su` 之后显示的仍然是最初登录这个终端的用户；`whoami` 显示当前有效用户，`su` 之后显示切换后的用户。）

d．执行 `date` 命令，查看当前日期时间。

```text
$ date
2023年 12月 04日 星期一 11:00:16 CST
```

date 可以用 `+` 开头的格式串定制输出：

```bash
date +%Y-%m-%d    # 年-月-日，如 2023-12-04
date +%H:%M:%S    # 时:分:秒，如 10:14:57
date +%A          # 星期几，中文环境下是"星期一"，英文环境下是 Monday
```

`%Y` 四位年份，`%m` 月，`%d` 日，`%H` 小时，`%M` 分钟，`%S` 秒，`%A` 星期几。更多控制符见 `20 作业解析.md` 第三次作业。

e．执行 `tty` 命令，查看自己所在的登录终端。

```text
$ tty
/dev/pts/4
```

`tty` 打印连接到标准输入的终端设备文件名。这里是 `/dev/pts/4`，说明当前 shell 通过伪终端 4 号与用户交互。pts 是 pseudo terminal slave（伪终端从设备），是 pty（伪终端）的从设备部分。通过 SSH、PuTTY 这类远程程序连到 Linux 时，用的就是 pts 会话。

f．分别执行 `file /`、`file /etc/passwd`、`file /bin/bash`、`file /dev/tty1`、`file /dev/sda1`，查看命令执行结果。

`file` 对参数做一系列测试，判断文件类型。

| 命令 | 输出 | 说明 |
| --- | --- | --- |
| `file /` | `/: directory` | 根目录是目录 |
| `file /etc/passwd` | `/etc/passwd: Unicode text, UTF-8 text` | UTF-8 编码的文本文件 |
| `file /bin/bash` | `/bin/bash: ELF 64-bit LSB pie executable, x86-64, ... dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2, ...` | 64 位 ELF 可执行文件，动态链接，用 `/lib64/ld-linux-x86-64.so.2` 加载 |
| `file /dev/tty1` | `/dev/tty1: character special (4/1)` | 字符设备文件，括号里是主设备号/次设备号 |
| `file /dev/sda1` | `/dev/sda1: block special (8/1)` | 块设备文件 |

#### （3）内容查找

a．使用斜线（`/`）在 vi 中查找单词 vi，使用 `n` 遍历所有查找结果。

命令模式下输入 `/vi` 回车，光标跳到光标之后第一个 vi。反复按 `n`，光标依次跳到下一个 vi，到文件尾后从头继续。

b．使用问号（`?`）在 vi 中查找单词 vi，使用 `n` 遍历所有查找结果。

命令模式下输入 `?vi` 回车，光标向前（向上）找。刚打开文件时光标在第一行，向前找会绕到文件末尾，所以先跳到最后一个 vi。之后按 `n` 继续向前找上一个。

`n` 沿用搜索命令的方向：`/` 之后按 `n` 往下找，`?` 之后按 `n` 往上找。`N` 方向相反。

### 三、目录与文件初级操作

#### （1）使用 `ls /` 命令查看根目录中都有哪些系统目录，说出这些目录的用途。

```text
$ ls /
bin   cdrom  etc   lib    lib64   lost+found  mnt  proc  run   snap  swap.img  tmp  var
boot  dev    home  lib32  libx32  media       opt  root  sbin  srv   sys       usr  z
```

| 目录 | 用途 |
| --- | --- |
| `/bin` | 存放最常用的程序和指令 |
| `/boot` | 启动 Linux 时使用的核心文件，包括一些链接文件和镜像文件 |
| `/cdrom` | 光盘驱动器这类可移动设备的挂载点 |
| `/dev` | Linux 的外部设备。在 Linux 中访问设备和访问文件的方式相同 |
| `/etc` | 系统管理所需的配置文件和子目录 |
| `/home` | 用户的主目录，每个用户都有自己的目录 |
| `/lib`、`/lib32`、`/lib64`、`/libx32` | 系统最基本的动态链接共享库，作用类似 Windows 里的 DLL 文件 |
| `/lost+found` | 一般为空，系统非法关机后这里会存放一些文件 |
| `/media` | 系统自动识别的 U 盘、光驱等设备挂载到这个目录下 |
| `/mnt` | 让用户临时挂载别的文件系统 |
| `/opt` | 主机额外安装的软件 |
| `/proc` | 虚拟目录，是系统内存的映射，存放当前内核运行状态的一系列特殊文件 |
| `/root` | 系统管理员（超级用户）的主目录 |
| `/run` | 临时文件系统，存储系统启动以来的信息，重启时清除 |
| `/sbin` | 系统管理员使用的系统管理程序 |
| `/snap` | Snap 软件包 |
| `/srv` | 服务启动之后需要提取的数据 |
| `/swap.img` | 交换文件（是文件，不是目录），物理内存不够用时使用 |
| `/sys` | Linux 2.6 内核引入的 sysfs 文件系统挂载在这里 |
| `/tmp` | 临时文件 |
| `/usr` | 用户的很多应用程序和文件，类似 Windows 下的 Program Files |
| `/var` | 不断增长、经常修改的文件，包括各种日志 |
| `/z` | 不是标准目录，是实验平台管理员自己建的 |

（更正：原稿说 `/z` "看起来像是你自己创建的"。下一题可以看到普通用户在根目录下建不了目录，所以它只能是管理员建的。）


```bash
#!/bin/bash
sum=0
for ((i=$1; i<=$2; i++))
do
    sum=$((sum + i))
done
echo "$1 + ... + $2 = $sum"
```

- `$[ ]` 是旧的算术写法，bash 还支持但已不推荐，用 `$(( ))`。

### 1．在 exp4 目录下创建一个 shell 脚本 largest

要求：

4. 之后，显示最大的整数

思路：先假设第一个数最大，再依次和第二、第三个数比较，谁大就换成谁。

```bash
#!/bin/bash

read a1
echo -n "Please enter the second integer:"
read a2
echo -n "Please enter the third integer:"
read a3
res=$a1
if [ $a2 -gt $res ]    # -gt 表示大于，小于是 -lt
then
     res=$a2
fi
if [ $a3 -gt $res ]
then
     res=$a3
fi
echo "$res"
```

- `echo -n "提示"` 加 `read 变量` 可以合成一句：`read -p "Please enter the first integer:" a1`。
- `[ ]` 里的整数比较：`-gt` 大于，`-lt` 小于，`-ge` 大于等于，`-le` 小于等于，`-eq` 等于，`-ne` 不等于。`>`、`<` 在 `[ ]` 里会被当成重定向。

```bash
echo -n "Please input a username:"
read name
if [ id -u $name >/dev/null 2>&1 ]   # 如果用户存在，id -u $name 会返回该用户的用户 ID，否则会返回一个错误
then
    m1=$(getent passwd $name | cut -d: -f7)   # getent passwd $name 返回该用户在 passwd 文件中的条目；cut -d: -f7 取出第 7 个字段，也就是默认 shell
    echo "$name's shell is $m1"
else
    echo "$name not exists."
fi
```

（更正：`if [ id -u $name >/dev/null 2>&1 ]` 有错。`[ ]` 是 test 命令，方括号里的 `id -u $name` 不会被当作命令执行，test 把它当成三个参数，报"-u: binary operator expected"，返回非 0。报错信息又被 `2>&1` 丢进了 `/dev/null`，所以脚本不提示错误，但不管输入什么用户名都会输出 not exists。）

`if` 后面可以直接跟命令，按命令的退出状态判断。改成：

```bash
#!/bin/bash
read -p "Please input a username:" name
if id -u "$name" >/dev/null 2>&1
then
    m1=$(getent passwd "$name" | cut -d: -f7)
    echo "$name's shell is $m1"
else
    echo "$name not exists."
fi
```

- `id -u 用户名`：用户存在时输出 UID，退出状态为 0；不存在时报错，退出状态非 0。
- `>/dev/null 2>&1`：把正常输出和错误输出都丢掉，只留退出状态给 if 判断。
- `getent passwd 用户名` 输出该用户在 `/etc/passwd` 里的那一行，字段用冒号分隔，第 7 个是默认 shell，所以 `cut -d: -f7`。
- 什么时候用 `[ ]`：比较字符串、数字或测试文件时用 `[ ]`；判断一个命令成不成功，直接把命令写在 if 后面。

### 3．在 exp4 目录下创建一个 shell 脚本 exercise4

要求：

1. 判断 exp4 目录下是否存在目录 FILE4，如果存在则先删除再新建，否则新建
2. 在 FILE4 目录下，新建 100 个文件，文件名依次为 file001 至 file100
3. 使用 tar 命令打包并压缩这 100 个文件为 allfile.tar.gz，将该文件移动到 exp4 目录下
4. 查看 allfile.tar.gz 文件的权限，并将其权限修改为 user 可读可写可执行，group 可读，other 可读

原稿脚本：

```bash
#!/bin/bash

if [ -d ~/exp4/FILE4 ]     # -d 检查目录是否存在
then
     rm -rf ~/exp4/FILE4   # -r 递归删除，-f 强制删除不提示
     mkdir ~/exp4/FILE4
else
     mkdir ~/exp4/FILE4
fi

cd ~/exp4/FILE4
touch file{001..100}
tar -czf allfile.tar.gz *                   # c 创建归档，z 用 gzip 压缩，f 指定归档文件名
mv -f ~/exp4/FILE4/allfile.tar.gz ~/exp4
cd ~/exp4
ls -l allfile.tar.gz                        # 看详细信息里的权限
chmod u+rwx allfile.tar.gz
chmod g+r-w allfile.tar.gz
chmod o+r-w allfile.tar.gz
```

（更正：原稿注释作"-d 用来检查一个目录或文件是否存在"。`-d` 要求路径存在并且是目录，普通文件会返回假；检查任意类型的文件是否存在用 `-e`。原稿注释里两处"注意 gz 后面有空格"没有实际含义，已删去。）

逐条说明：

- `touch file{001..100}`：大括号展开，bash 生成 file001、file002……file100 共 100 个文件名。起始写成 `001`，生成的数字会补零到 3 位。
- `tar -czf allfile.tar.gz *`：`*` 在 tar 运行前就已展开成 100 个文件名，那时 allfile.tar.gz 还不存在，所以不会把压缩包自己打进去。`f` 后面必须紧跟归档文件名。
- 查看压缩包内容可以用 `tar -tzf allfile.tar.gz`，解压用 `tar -xzf allfile.tar.gz`。
- 权限要求是 user 读写执行、group 只读、other 只读，也就是 `rwxr--r--`，八进制 744。原稿用 `chmod g+r-w` 这种相对写法，只加上 r、去掉 w，组和其他用户原来如果有 x 不会被去掉。新建文件的默认权限通常是 `rw-r--r--`，所以原稿结果碰巧对。直接指定最终权限更稳：

```bash
chmod 744 allfile.tar.gz
# 或者
chmod u=rwx,go=r allfile.tar.gz
```

| 数字 | 权限 |
| --- | --- |
| 4 | r |
| 2 | w |
| 1 | x |
| 7 = 4+2+1 | rwx |
| 5 = 4+1 | r-x |
| 4 | r-- |
