# 输入输出系统（第 5 章）

整理自 `计组部分知识点整理.docx` 的中段截图（唐朔飞教材 5.4～5.6 节），内容是程序查询、程序中断和 DMA 三种方式。简答题里的同类题（DMA 三种方法、中断全过程等）在 `10 简答题精编（唐朔飞教材）.md` 第 26～35 题，这里侧重原理细节和计算例题。

## 本章要点

- 程序查询方式的开销用"每秒查询所需时钟周期数 ÷ 每秒时钟周期数"算，高速设备用查询方式会把 CPU 占满（例 5.1）。
- 中断判优可以用**链式排队线路**实现，设备编码器在 INTA 有效时把被选中设备的向量地址送上数据总线（例 5.2）。
- 一次 I/O 中断处理：中断请求 → 中断判优 → 中断响应 → 中断服务 → 中断返回。
- 中断服务程序的流程：**保护现场、中断服务、恢复现场、中断返回**。保存断点由中断隐指令完成，保存寄存器内容由服务程序完成。
- DMA 靠主存与接口之间的直接数据通路传送，不经 CPU、不保护现场，适合高速设备。高速设备和 CPU 同时访存时，CPU 要把总线让给 DMA 接口（周期窃取）。
- DMA 接口六个部件：AR、WC、BR、DMA 控制逻辑、中断机构、DAR。
- DMA 传送三阶段：预处理、数据传送、后处理。DMA 的中断只用来报告一批数据传送结束。

## 概念与解释

### 程序中断方式的两个细节

**链式排队线路与设备编码器**（电路图见 `图/5-42_链式排队与设备编码器.png`）：

- $\text{INTR}_i$ 为设备中断请求，有请求时 $\text{INTR}_i=1$（即 $\overline{\text{INTR}_i}=0$）。
- 排队器是一串"非门 + 与门"：高优先级设备有请求时，经非门、与门把低优先级的排队信号封住，所以只有优先级最高的请求设备输出 $\text{INTP}_i$ 有效。
- 点画线框里是设备编码器：每个设备 6 个三态门接数据总线，向量地址中为 0 的位用带反相圈的门。INTA 有效时，被选中的 $\text{INTP}_i$ 打开对应的门，向量地址经数据总线送 CPU。

**中断服务程序的流程**：

1. 保护现场：一是保存程序断点，由中断隐指令完成；二是保存通用寄存器和状态寄存器的内容，由服务程序开头的存数指令或进栈指令（PUSH）完成。
2. 中断服务（设备服务）：程序主体，不同中断源内容不同。例如打印机要 CPU 把一行字符代码经接口送入打印机缓冲存储器；显示设备要 CPU 把一屏字符代码送入显示存储器。
3. 恢复现场：退出前用取数指令或出栈指令（POP）把保存的内容送回原寄存器。
4. 中断返回：最后一条通常是中断返回指令，返回原程序断点。

### DMA 方式的特点

- 主存和 DMA 接口之间有数据通路，交换信息不经过 CPU，也不需要 CPU 暂停现行程序，省去了保护和恢复现场，所以比程序中断快。适合高速 I/O 或辅存与主存之间的信息交换。
- 高速设备如果每次交换信息都要等 CPU 响应中断，很可能丢数据，这是用 DMA 的主要原因。
- 高速 I/O（经 DMA 接口）和 CPU 同时访问主存时，CPU 必须把地址线、数据线的占有权让给 DMA 接口，即 DMA 用周期窃取的方式占用一个存取周期。

### DMA 与主存交换数据的三种方法（细节）

1. **停止 CPU 访问主存**：传一批数据时 DMA 接口发停止信号，CPU 让出总线，传完再交回。控制简单，适合传输率很高的设备成组传送。缺点是这期间 CPU 基本不工作；而且设备再快，两个数据之间的准备间隔也总大于一个存取周期（例如软盘读一个 8 位数约 32 μs，半导体存储器存取周期远小于 1 μs），主存利用率不高。改进办法是在接口里设一个小容量半导体存储器，设备先和它交换数据，它再和主存交换，缩短占用总线的时间。
2. **周期挪用（周期窃取）**：I/O 设备请求 DMA 时会遇到三种情况：
   - CPU 此时不需要访存（如正在执行耗时的乘法指令），两者不冲突；
   - CPU 正在访存，必须等这个存取周期结束，CPU 才让出总线；
   - I/O 要访存时 CPU 也要访存，出现冲突。此时 **I/O 访存优先**，因为不立即访存可能丢数据，I/O 窃取一两个存取周期，CPU 推迟一两个存取周期再访存。

   这种方法应用最广。但 I/O 每挪用一个主存周期，都要申请、建立、归还总线控制权，对 DMA 接口来说传一个字实际要占 2～5 个主存周期，所以它适合 I/O 设备读写周期大于主存周期的情况。
3. **DMA 与 CPU 交替访存**：适合 CPU 工作周期比主存存取周期长的情况。例如 CPU 周期 1.2 μs、主存存取周期小于 0.6 μs，就把 CPU 周期分成 $C_1$、 $C_2$， $C_1$ 专供 DMA 访存， $C_2$ 专供 CPU 访存。总线使用权由 $C_1$、 $C_2$ 分别控制，不需要申请、建立、归还，总线相当于受 $C_1$、 $C_2$ 控制的多路转换器。CPU 和 DMA 接口各有独立的访存地址寄存器、数据寄存器和读写信号。DMA 传送速率很高，CPU 既不停主程序也不等待，代价是硬件逻辑更复杂。

### DMA 接口的组成

组成图见 `图/5-47_DMA接口组成.png`。

| 部件 | 作用 |
| --- | --- |
| 主存地址寄存器 AR | 存放要交换数据的主存地址。传送前由程序送入首地址，每交换一次加 1 |
| 字计数器 WC | 记录传送的字数，通常以字数的**补码**预置，每传一个字加 1，计到 0（最高位产生进位）表示传完，于是向 CPU 发中断请求。若以原码预置，则每传一个字减 1，减到 0 结束 |
| 数据缓冲寄存器 BR | 暂存每次传送的数据。接口与主存之间通常按字传送，与设备之间可能按字节或位传送，所以接口里还可能有装配、拆卸字的逻辑（移位缓冲寄存器、字节计数器等） |
| DMA 控制逻辑 | 管理 DMA 传送全过程，由控制电路、时序电路、命令状态控制寄存器组成。设备准备好一个字就发 DREQ；控制逻辑向 CPU 发总线请求 HRQ；收到 CPU 的 HLDA 后接管传送：修改 AR 和 WC、识别总线地址、指定传送类型（输入或输出）、用 DACK 通知设备已获得一个 DMA 周期 |
| 中断机构 | WC 溢出（全 0）时，由溢出信号经中断机构向 CPU 发中断请求，请 CPU 做 DMA 后处理 |
| 设备地址寄存器 DAR | 存放设备码，或设备信息存储区的寻址信息，如磁盘数据所在的区号、盘面号、柱面号 |

DMA 接口的中断和 I/O 中断技术相同，目的不同：I/O 中断是为了输入输出数据，DMA 的中断是为了报告一批数据传送结束。

### DMA 的工作过程

**预处理**：CPU 执行几条 I/O 指令，给接口预置四项信息：传送方向（输入是写主存，输出是读主存）、设备号（送 DAR 并启动设备）、主存起始地址（送 AR）、交换数据个数（送 WC）。之后 CPU 继续执行原程序。设备准备好后经接口申请占用总线，多个 DMA 同时申请时由硬件排队判优。

**数据传送**（以周期挪用为例，按块传送，流程图见 `图/5-48_DMA传送过程.png`）：

| 步骤 | 输入数据 | 输出数据 |
| --- | --- | --- |
| ① | 设备准备好一个字，发选通信号把它读入 BR，BR"满"（面向字符的设备一次读一个字节，组装成字） | BR 已把数据送给设备，BR"空" |
| ② | 设备向接口发 DREQ | 同左 |
| ③ | 接口向 CPU 发 HRQ 申请总线 | 同左 |
| ④ | CPU 回 HLDA，把总线控制权交给接口 | 同左 |
| ⑤ | AR 中的主存地址送地址总线，命令存储器**写** | AR 中的主存地址送地址总线，命令存储器**读** |
| ⑥ | 用 DACK 通知设备已获得 DMA 周期，准备下一个字 | 同左 |
| ⑦ | BR 的内容送数据总线 | 主存相应单元的内容经数据总线读入 BR |
| ⑧ | 主存把数据总线上的信息写入地址总线指定的单元 | BR 的内容送输出设备（字符设备要拆成字符输出） |
| ⑨ | 修改主存地址和字计数值 | 同左 |
| ⑩ | 判断数据块是否传完：没完继续；完了（WC 溢出）向 CPU 申请程序中断 | 同左 |

**后处理**：DMA 的中断请求被响应后，CPU 停止原程序，执行中断服务程序做结束工作：校验送入主存的数据是否正确；决定是否继续用 DMA 传送其他数据块（继续就重新初始化接口，不继续就停止外设）；测试传送中是否出错，出错转错误诊断和处理程序。

## 易混对比

| 对比项 | 程序查询 | 程序中断 | DMA |
| --- | --- | --- | --- |
| CPU 与 I/O | 串行，CPU 踏步等待 | 并行 | 并行 |
| 数据怎么传 | 程序传送 | 程序传送（中断服务程序） | 硬件传送（直接数据通路） |
| 何时响应 | 无请求，CPU 主动查询 | 一条指令执行结束时 | 指令周期内任一存取周期结束时 |
| 保护现场 | 不涉及 | 需要 | 不需要 |
| 处理异常事件 | 不能 | 能 | 不能 |
| 优先级 | | 低于 DMA | 高于程序中断 |
| 适用 | 慢速、简单 | 中低速设备 | 高速、大批量数据（硬盘、图像、高速采集） |

| 对比项 | 停止 CPU 访存 | 周期挪用 | 交替访存 |
| --- | --- | --- | --- |
| CPU 状态 | 基本不工作 | 做自身操作，暂停访存 | 照常工作 |
| 总线控制权 | 整批数据期间归 DMA | 每挪用一周期申请、建立、归还一次 | 按 $C_1$/ $C_2$ 分时，无需申请 |
| 优点 | 控制简单 | 兼顾 I/O 与 CPU 效率，应用最广 | DMA 速率和 CPU 效率最高 |
| 缺点 | 主存和 CPU 利用率低 | 每传一个字实际占 2～5 个主存周期 | 硬件复杂 |

## 典型题

### 例 5.1 程序查询方式占用 CPU 的比例

题：程序查询方式下，不计处理时间，每次查询需 100 个时钟周期，CPU 时钟频率 50 MHz。鼠标每秒查询 30 次；硬盘以 32 位字长为单位传数据，每 32 位查询一次，传输率 2 MBps。求 CPU 对两个设备查询所花的时间比率，能得出什么结论？

思路：比率 = 每秒查询所需时钟周期数 ÷ 每秒时钟周期数（ $50\times10^6$）。

解：

1. 鼠标：100 × 30 = 3000 个时钟周期，比率 = $3000/(50\times10^6)\times100\%=0.006\%$，基本不影响 CPU。
2. 硬盘：每秒查询 2 MB / 4 B = 512 K 次，所需时钟周期 = 100 × 512 × 1024 ≈ $52.4\times10^6$，比率 = $52.4\times10^6/(50\times10^6)\times100\%=105\%$。

结论：比率超过 100%，CPU 全部时间都用来查询硬盘也来不及，高速设备不能用程序查询方式。

### 例 5.2 链式排队线路和设备编码器

题：设备 A、B、C 优先级降序，向量地址分别为 001010、001011、001100。设计链式排队线路和产生向量地址的设备编码器。

解：见 `图/5-42_链式排队与设备编码器.png`。链式排队器由三级"非门 + 与门"串成，来自高一级排队器的信号依次传下去， $\overline{\text{INTR}_A}$、 $\overline{\text{INTR}_B}$、 $\overline{\text{INTR}_C}$ 分别进入各级与门；每个设备的 $\text{INTP}_i$ 由 INTA、 $\text{INTR}_i$ 和排队器输出相与得到。编码器每个设备 6 个三态门，向量地址中为 0 的位用带反相圈的门：A 组第 1、2、4、6 个门带圈，B 组第 1、2、4 个，C 组第 1、2、5、6 个。

### 例 5.3 DMA 与中断方式占用处理器的时间

题：DMA 接口用周期窃取方式把字符传送到存储器，最大批量 400 字节。存取周期 100 ns，每处理一次中断需 5 μs，字符设备传输率 9600 bps，字符间无间隙，忽略预处理时间。DMA 方式每秒因数据传输占用处理器多少时间？完全采用中断方式又占用多少？

思路：DMA 每个字符占一个存取周期，每 400 个字符中断一次；中断方式每个字符中断一次。

解：

- 每秒传 9600 / 8 = 1200 个字符。
- DMA：0.1 μs × 1200 + 5 μs × (1200/400) = 135 μs。
- 中断方式：5 μs × 1200 = 6000 μs。

### 例 5.4 DMA 辅助操作的时间比率

题：磁盘用 DMA 方式与主机交换信息，传输率 2 MBps；预处理需 1000 个时钟周期，传完后处理中断需 500 个时钟周期；平均每次传 4 KB。50 MHz 的处理器要用多少时间比率做 DMA 辅助操作？

思路：先算传一块要多久，再算每秒有多少次预处理加后处理。

解：

- 传 4 KB 需 4 KB / 2 MBps = 0.002 s。
- 磁盘不断传输时，每秒辅助操作的时钟周期数 = (1000+500) / 0.002 = 750000。
- 比率 = $750000/(50\times10^6)\times100\%=1.5\%$。
