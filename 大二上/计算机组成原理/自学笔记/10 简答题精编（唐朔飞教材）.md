## 第 1 章 计算机系统概论

### 1. 说明计算机系统的层次结构（P7）

从上到下五层，上层靠下层翻译或解释来执行：

| 层次 | 名称 | 怎样到下一层 |
| --- | --- | --- |
| M4 | 虚拟机器（高级语言机器） | 用编译程序翻译成汇编语言程序 |
| M3 | 虚拟机器（汇编语言机器） | 用汇编程序翻译成机器语言程序 |
| M2 | 虚拟机器（操作系统机器） | 用机器语言解释操作系统 |
| M1 | 传统机器（机器语言机器） | 用微程序解释机器指令 |
| M0 | 微程序机器（微指令系统） | 由硬件直接执行微指令 |

### 2. 说明冯·诺依曼体系结构的特点（P8）

1. 计算机由**运算器、存储器、控制器、输入设备、输出设备**五大部件组成。
2. 指令和数据以同等地位存放在存储器内，可按地址寻访（**存储程序**）。
3. 指令和数据都用**二进制**表示。
4. 指令由操作码和地址码组成：操作码表示操作的性质，地址码表示操作数在存储器中的位置。
5. 指令在存储器内按顺序存放，通常顺序执行；特定条件下可根据运算结果或设定的条件改变执行顺序。
6. 机器以**运算器为中心**，输入输出设备与存储器之间的数据传送经过运算器完成。

### 3. 什么是机器字长、指令字长、存储字长

- 机器字长：CPU 一次能处理的数据位数，通常与 CPU 中寄存器的位数有关（P17）。
- 指令字长：一个指令字中包含二进制代码的总位数。它取决于操作码的长度、操作数地址的长度和操作数地址的个数。（更正：yy 汇总原文作"操作码地址的长度和操作码地址的个数"，应为操作数地址。）
- 存储字长：一个存储单元存放二进制代码的位数（P13）。

## 第 3 章 系统总线

### 4. 系统总线包括哪三类？各起什么作用（P43）

- 数据总线：在各功能部件之间传输数据信息。
- 地址总线：指出数据总线上源数据或目的数据所在的主存单元地址或 I/O 设备地址。
- 控制总线：发出各种控制信号，同时监视各部件的状态。

### 5. 总线判优控制解决什么问题？分哪两种方式

- 解决的问题：总线上多个主设备同时申请总线时，按优先等级决定谁获得总线使用权；只有拿到使用权的主设备才能传送数据。
- 两种方式：**集中式**（控制逻辑集中在一处，如 CPU 中）和**分布式**（控制逻辑分散在连到总线的各个部件或设备上）。

### 6. 集中式总线控制的三种优先权仲裁方式及特点（P58）

控制信号：BS 总线忙，BR 总线请求，BG 总线同意。

| 方式 | 优点 | 缺点 | 控制线 |
| --- | --- | --- | --- |
| 链式查询 | 线少，按优先次序实现控制，容易扩充设备 | **对电路故障最敏感**；优先级低的设备可能很难获得总线 | 只靠 BG、BR 两根线确定总线归哪个设备；离总线控制部件最近的设备优先级最高 |
| 计数器定时查询 | 优先次序灵活：计数从 0 开始则优先级固定（按 0,1,…,n 降序）；从上次终止点开始则各设备优先级相等（循环）；计数初值可由程序设置 | 控制线增多，控制较复杂 | n 个设备需 $\lceil\log_2 n\rceil+2$ 根（原稿注：教材上没有写 +2） |
| 独立请求 | **响应速度最快**，优先次序可由程序改变 | 控制线最多，总线控制最复杂 | n 个设备需 2n 根 |

计数器定时查询对电路故障不如链式查询敏感。

### 7. 总线周期（总线传输周期）的 4 个阶段（P59）

完成一次总线操作的时间叫总线周期。

1. **申请分配**：主模块提出申请，总线仲裁机构决定下一个传输周期的总线使用权给谁。
2. **寻址**：获得使用权的主模块发出要访问的从模块地址和有关命令，启动从模块。
3. **传数**：主从模块交换数据，数据由源模块发出，经数据总线流入目的模块。
4. **结束**：主模块的有关信息从总线上撤除，让出总线使用权。

### 8. 总线通信控制解决什么问题？有哪几种方式？各自特点

解决的问题：通信双方怎样知道传输开始和结束，双方怎样协调配合。四种方式：

- **同步通信**：有公共时钟。规定明确统一，模块间配合简单。缺点是时间配合是强制的，必须在限定时间内完成；公共时钟只能按最慢的部件设计，影响总线效率，缺乏灵活性。适合总线较短、各部件存取时间比较一致的场合。总线传输周期越短、数据线位数越多，数据传输率越高。
- **异步通信**：没有公共时钟，允许各模块速度不一致，采用应答（握手）方式：主模块发请求（Request），等从模块回"响应"（Acknowledge）后才通信，需要增加两条应答线。应答方式分不互锁、半互锁、全互锁三种。可用于并行传送或串行传送。
- **半同步通信**：保留同步通信的特点（地址、命令、数据信号的发出时间都参照系统时钟前沿，接收方在系统时钟后沿判断识别），又像异步通信一样允许不同速度的模块协同工作。做法是增设一条"等待"（$\overline{\text{WAIT}}$）响应信号线，插入时钟（等待）周期来协调。适合工作速度不高、但包含许多速度差异较大设备的简单系统。控制比异步简单，可靠性较高；缺点是系统时钟频率不能太高，整体速度不高。（更正：原稿"系统时钟厚沿"应为"后沿"。）
- **分离式通信**：
  1. 各模块要占用总线都必须先提出申请；
  2. 得到使用权后，主模块在限定时间内用同步方式向对方传送信息，不再等回答信号；
  3. 各模块准备数据时不占用总线，总线可以接受其他模块的请求；
  4. 总线被占用时都在做有效工作，没有空闲等待，实现了总线在多个主、从模块间交叉重叠传送。

  控制比较复杂，普通微机很少用，主要用于大型计算机系统。

### 9. 同步通信与异步通信的主要区别？两种方式下双方怎样联络（P59）

- 同步通信有公共时钟，总线上所有设备按统一的时序、统一的传输周期传送信息，双方按约定好的时序联络。
- 异步通信没有公共时钟，没有固定的传输周期，采用应答方式。联络方式有三种：不互锁（双方没有相互制约）、半互锁（有简单的制约关系）、全互锁（有完全的制约关系）。其中**全互锁可靠性最高**。

### 10. 串行传输和并行传输的区别及适用场合（P44）

| | 串行传输 | 并行传输 |
| --- | --- | --- |
| 做法 | 数据在一条线路上按位依次传输 | 每个数据位一条线，所有位同时传输 |
| 成本 | 线路成本低 | 成本高 |
| 速度 | 慢 | 快 |
| 适用 | 远距离传输 | 近距离、高速传输 |

## 第 4 章 存储器

### 11. 试比较 RAM 和 ROM（P69）

| | RAM（随机存取存储器） | ROM（只读存储器） |
| --- | --- | --- |
| 读写 | 程序执行过程中既能读又能写 | 程序执行过程中只能读，不能写 |
| 断电后 | **易失**，数据丢失 | **非易失**，可长期保存 |

### 12. 从实现技术角度比较 SRAM 和 DRAM（P87）

两者都是随机存储器，执行中可读可写，断电都丢信息。

| 对比项 | SRAM（静态） | DRAM（动态） |
| --- | --- | --- |
| 存储原理 | **触发器**，读出后仍保持原状态 | 靠**电容**存电荷，电容会漏电 |
| 单元结构 | 通常 6 个晶体管 | 通常 1 个晶体管 + 1 个电容 |
| 刷新 | 不需要刷新（再生） | 需要定期刷新，要配再生电路，也要耗一部分功率 |
| 集成度 | 低 | 同样大小的芯片中远高于 SRAM |
| 引脚 | 地址一次送入 | 行、列地址分时（先后）送入，引脚少，封装尺寸小 |
| 功耗 | 大 | 小 |
| 价格、容量 | 贵、容量小 | 便宜、容量大 |
| 速度 | 快 | 慢，存取周期长 |

（更正：yy 汇总里 SRAM 第③条写"SRAM 在不断刷新的过程中保持数据的稳定性"，和它自己第⑤条"SRAM 不需要定期刷新"矛盾。SRAM 靠触发器保存数据，不需要刷新。）

### 13. 存储芯片内的地址译码方式有几种？特点和应用场合（P75）

- **线选法**：一根字选择线直接选中一个存储单元的各位，地址信号只经过一个方向的译码。结构简单，只适合地址线少、容量不大的芯片。
- **重合法**：地址线分成两组，分别经行、列两个方向译码，行、列都选中的存储元才能读写。适合地址线多的芯片。

### 14. 什么是动态 RAM 的刷新？刷新有几种方式（P86）

刷新：DRAM 靠电容存电荷（有电荷为 1，无电荷为 0），漏电流会让电荷流失，所以每隔一段时间要把原信息读出，由刷新放大器形成原信息后重新写入，这个再生过程叫刷新。规定时间内（一般 2 ms，叫刷新周期或再生周期）必须把全部单元刷新一遍，刷新按行进行。

| 方式 | 做法 | 优缺点 |
| --- | --- | --- |
| 集中刷新 | 刷新周期内集中一段时间逐行刷新，期间停止读写 | 有访存"**死时间**" |
| 分散刷新 | 每行的刷新分散到每个存取周期内完成 | 没有死时间，但存取周期变长，系统变慢 |
| 异步刷新 | 前两种结合，按 2 ms 的最大刷新间隔分散安排各行刷新 | 缩短死时间；若安排在 CPU 指令译码阶段（此时不访存），既不加长存取周期，也没有访存死区 |

### 16. 汉明码校验位数 k 与信息位数 n 要满足什么关系？为什么（P100）

$$2^k \ge n+k+1$$

理由：n 位信息加 k 位校验位共 n+k 位。k 位校验位要能区分 n+k 个"某一位出错"的情况，再加上"没出错"这一种，共 n+k+1 种状态，而 k 位二进制只能表示 $2^k$ 种状态。（更正：原稿写作"k 位能检测出 2k 种"，应为 $2^k$。）

教材补充（yy 汇总里的截图）：

- 编码最小距离 L、检错位数 D、纠错位数 C 满足 $L-1=D+C$ 且 $D\ge C$。L=3 时可检两位错，或检一位错并纠一位错。汉明码就是按这个理论设计的、有一位纠错能力的编码。
- n+k 位代码自左向右编为第 1,2,3,… 位，k 位校验位 $C_i$ 放在第 1,2,4,8,…,$2^{k-1}$ 位上。
- 分组：$C_1$ 管 1,3,5,7,9,11,… 位；$C_2$ 管 2,3,6,7,10,11,14,15,… 位；$C_4$ 管 4,5,6,7,12,13,14,15,… 位；$C_8$ 管 8～15,24,… 位。规律是第 $2^{i-1}$ 位只属于 $g_i$ 组；两组共有第 $2^{i-1}+2^{j-1}$ 位；三组共有第 $2^{i-1}+2^{j-1}+2^{l-1}$ 位。

### 17. 收到海明码 0100111（配偶原则），欲传送的信息是什么

按位置编号 1～7，各位依次是 0 1 0 0 1 1 1。

- $P_1 = 1\oplus3\oplus5\oplus7 = 0\oplus0\oplus1\oplus1 = 0$
- $P_2 = 2\oplus3\oplus6\oplus7 = 1\oplus0\oplus1\oplus1 = 1$
- $P_4 = 4\oplus5\oplus6\oplus7 = 0\oplus1\oplus1\oplus1 = 1$

$P_4P_2P_1=110$，第 6 位出错，纠正为 0100101。信息位在第 3、5、6、7 位，所以欲传送的信息是 **0101**。

### 18. 什么是多体并行存储器？两种编址方式及特点（P104）

多体并行系统由多个存储体模块组成，每个模块容量和存取速度相同，各有独立的地址寄存器（MAR）、数据寄存器（MDR）、地址译码、驱动电路和读写电路，既能并行工作，也能交叉工作。

| | 高位交叉编址（顺序方式） | 低位交叉编址（交叉方式） |
| --- | --- | --- |
| 地址划分 | 高位表示体号，低位是体内地址 | 低位表示体号，高位是体内地址 |
| 特点 | 一个体内地址连续，便于扩充存储器；合理调度让不同请求源访问不同体即可并行 | 又叫模 M 编址（M 为模块数，一般取 2 的方幂）；在不改变每个模块存取周期的前提下提高存储器带宽 |

### 19. 为什么要使用高速缓存（P109）

多体并行存储系统中，I/O 设备向主存请求的级别高于 CPU 访存，CPU 可能要空等；CPU 的速度又远高于主存，也会空等。为了避免 CPU 与 I/O 设备争抢访存、减少 CPU 空等，在 CPU 和主存之间加一级 Cache。

### 20. Cache、主存、辅存构成三级存储系统的目的和设计依据

- 目的：**提高访存速度，扩大存储容量**。Cache-主存层次解决 CPU 与主存速度不匹配；主存-辅存层次解决容量问题。
- 设计依据：**程序访问的局部性原理**。CPU 在一段时间内只访问主存的局部地址区域，因为指令和数据在主存中连续存放，而且子程序、循环、常数等会被多次调用，地址分布是相对簇聚的。（更正：2020 年整理版写作"局限性原理"。）

### 21. 简述 Cache 的基本工作原理

CPU 读主存某字时有两种情况：

1. 该字已在 Cache 中（命中），直接访问 Cache。
2. 该字不在 Cache 中，从主存读出该字，同时把它所在的整个主存块调入 Cache（Cache 与主存之间以块为单位传送）。Cache 未满时直接调入，该主存块与 Cache 块建立对应关系；Cache 已满时，由替换机构按替换算法选一块移出，再调入新块。

### 22. 比较主存-Cache 的三种地址映射方式，并给出主存地址划分

设 Cache 有 $2^c$ 块，每块 $2^b$ 个单元，主存地址共 m 位。

| 方式 | 映射关系 | 主存地址划分 | 特点 |
| --- | --- | --- | --- |
| 直接映射 | 每个主存块只能映射到一个固定的 Cache 块：$i=j \bmod C$ | 主存字块标记 t 位 \| Cache 字块地址 c 位 \| 字块内地址 b 位 | 实现简单；不灵活，命中率低 |
| 全相联映射 | 主存任一块可放到 Cache 任一块 | 主存字块标记 t+c 位 \| 字块内地址 b 位 | 最灵活，命中率高，块冲突少；比较电路多，成本高 |
| 组相联映射 | Cache 分 Q 组，每组 R 块，$i=j \bmod Q$，组内任意放 | 主存字块标记 s=t+r 位 \| 组地址 q=c−r 位 \| 字块内地址 b 位 | 直接映射与全相联的折中，应用最广 |

（更正：几份汇总都写作"组相联映射是直接映射和组相联映射的一种折中"，应为直接映射和**全相联**映射的折中。）

### 23. Cache-主存间的替换策略

| 算法 | 做法 | 评价 |
| --- | --- | --- |
| 先进先出 FIFO | 替换最早调入的块 | 不用记录使用情况，容易实现，开销小；没利用局部性，命中率提不上去（最早调入的可能还常用，如循环程序） |
| 近期最少使用 LRU | 替换近期用得最少的块，要随时记录各块使用情况（简化做法是记录每块最近一次使用的时间） | 较好地利用了局部性，平均命中率比 FIFO 高；实现较复杂 |
| 随机法 | 用随机数产生器随机选被替换块 | 简单；没利用局部性，不能提高命中率 |

### 24. 发生写主存请求时，如何保证 Cache 与主存一致

- **写直达法**（Write-through，又叫存直达法）：写操作同时写 Cache 和主存，始终保持一致，但增加了访存次数。读操作失效时，被替换的 Cache 块不必写回主存，更新策略容易实现；写操作时间等于访问主存的时间。
- **写回法**（Write-back，又叫拷回法）：写操作只写 Cache，块被替换时才写回主存。每块设一个标志位，"清"表示没修改过，"浊"表示修改过；写 Cache 时置"浊"，替换时"浊"块要写回主存并置"清"，"清"块不必写回。写操作时间等于访问 Cache 的时间，速度快，对同一块的多次写只需一次写入主存；但读失效时可能要把被替换块写回主存，Cache 更复杂。

## 第 5 章 输入输出系统

### 25. I/O 地址码的编址方式有哪两种（P160）

| | 统一编址 | 不统一编址（独立编址） |
| --- | --- | --- |
| 做法 | 把 I/O 地址看作存储器地址的一部分 | I/O 地址和存储器地址分开 |
| 访问 I/O | 用与访存类似的指令，不需要专用 I/O 指令 | 必须用专用 I/O 指令 |
| 代价 | 占用存储空间，主存容量变小 | 不占主存空间 |

### 26. I/O 与主机交换信息有哪几种控制方式？各有何特点（P162）

1. **程序查询方式**：CPU 通过程序不断查询设备是否准备好。主机与 I/O **串行**工作，设备没准备好时 CPU 反复查询、"踏步"等待，效率很低。
2. **程序中断方式**：CPU 启动 I/O 后继续执行自己的程序，设备准备好后发中断请求，CPU 在适当时候响应，暂停现行程序为 I/O 服务。主机与 I/O **并行**工作，消除了踏步现象。
3. **DMA 方式**：主存与 I/O 之间有直接数据通路，交换信息不调用中断服务程序。CPU 启动 I/O 后不必查询；设备准备好后发 DMA 请求，CPU 只是把外部总线使用权暂时交给 DMA 接口，自己仍可做内部操作（如加法、移位），不必中断现行程序，只需暂停一个存取周期访存（周期挪用），效率更高。
4. **通道方式**：通道是有特殊功能的处理器，CPU 把部分权力下放给通道，由通道统一管理外设及外设与主存间的数据交换。CPU 效率大大提高，代价是更多硬件。
5. **I/O 处理机方式**：通道方式的进一步发展，CPU 把 I/O 操作和外设管理权全部交给 I/O 处理机，实质是多机系统，效率更高。

### 27. 什么是 I/O 接口？与端口有何区别？为什么要设置？如何分类（P186）

1. **I/O 接口**：主机与 I/O 设备之间设置的硬件电路及相应的软件控制。一般说来，接口是两个系统或两个部件之间的交接部分，可以是两种硬件之间的连接电路，也可以是两个软件之间的共同逻辑边界。
2. **端口**：接口电路中的寄存器，分别存放数据、控制、状态信息，对应叫数据端口、控制端口、状态端口。CPU 用输入指令从端口读信息，用输出指令向端口写信息。**若干端口加上相应的控制逻辑才组成接口**。
3. 设置接口的理由：
   - 实现**设备选择**：一台机器配多台设备，各有设备号（地址）。
   - 实现**数据缓冲**，达到速度匹配。
   - 实现**串-并格式转换**。
   - 实现**电平转换**。
   - **传送控制命令**：CPU 通过接口向设备发各种控制信号。
   - **反映设备状态**：接口保存"忙""就绪""错误"等状态供 CPU 查询。
4. 分类：

| 分类依据 | 类别 |
| --- | --- |
| 数据传送方式 | 并行接口（一个字节或字的所有位同时传送）、串行接口（设备与接口间逐位传送） |
| 功能选择的灵活性 | 可编程接口（功能可用程序改变）、不可编程接口（靠硬连线逻辑实现） |
| 通用性 | 通用接口、专用接口 |
| 数据传送的控制方式 | 程序型接口（接慢速设备）、DMA 型接口（接高速设备） |

`计组简答题.docx` 另有一种更短的说法：接口是 CPU 和 I/O 设备间的连接部件，端口是接口内 CPU 能访问的寄存器；按控制方式也可分为程序控制接口、程序中断接口、DMA 接口三种。

### 28. 程序查询方式和程序中断方式都靠程序实现输入输出，有何不同

- 程序查询：用户程序里安排一段由 I/O 指令、测试指令、转移指令组成的 I/O 程序。CPU 启动 I/O 后就进入这段程序，时刻查询设备，没准备好就踏步等待，准备好就传送。整个输入输出过程中 **CPU 停止自身的操作**。
- 程序中断：I/O 程序以中断服务程序的形式插入用户程序。CPU 启动 I/O 后继续自己的工作，不查询设备状态；设备准备就绪后提出中断请求，CPU 满足条件时暂停现行程序，转去执行服务程序传送数据。
- 结论：中断方式消除了踏步现象，CPU 与 I/O 并行工作，CPU 利用率更高。

### 29. 以 I/O 设备的中断处理为例，说明一次程序中断的全过程（P198）

先记五个阶段，再按需要展开十步：

1. **中断请求**：CPU 启动 I/O 后，设备进入准备阶段，准备就绪时向 CPU 提出中断请求。
2. **中断判优**：多个请求同时出现时，由判优逻辑（硬件排队或软件排队）选出优先级最高的。
3. **中断响应**：允许中断触发器为 1 且设备未被屏蔽时，进入中断响应周期。CPU 自动执行中断隐指令，保存程序断点和程序状态字，硬件关中断，并把向量地址送 PC。
4. **中断服务**：响应周期结束后 CPU 转入取指周期，按向量地址取出一条无条件转移指令（或查入口地址表），转到服务程序入口，执行服务程序（保护现场、与 I/O 传送信息、恢复现场）。
5. **中断返回**：服务程序最后一条是中断返回指令，执行后回到程序断点。

十步细节（以输入设备为例）：

1. CPU 发启动 I/O 设备命令，接口中 B（工作触发器）置 1，D（完成触发器）置 0。
2. 接口启动输入设备开始工作。
3. 输入设备把数据送入数据缓冲寄存器。
4. 输入设备向接口发"设备工作结束"信号，D 置 1、B 置 0，表示设备就绪。
5. 设备就绪（D=1）且未被屏蔽（MASK=0）时，在指令执行阶段结束时刻，CPU 发中断查询信号。
6. 中断请求触发器 INTR 置 1，设备向 CPU 提出中断请求；INTR 同时送排队器判优。
7. CPU 允许中断（EINT=1）且该设备被排队选中，进入中断响应阶段，中断响应信号 INTA 把排队器输出送编码器形成向量地址。
8. 向量地址送 PC，作为下一条指令地址。
9. 向量地址中放的是无条件转移指令，执行后转到设备服务程序入口，进入中断服务阶段：用输入指令把数据缓冲寄存器中的数据送 CPU 通用寄存器，再存入主存相关单元。
10. 服务程序最后一条是中断返回指令，执行后返回原程序断点，一次中断处理结束。

### 30. DMA 方式中有没有中断请求？为什么？DMA 接口应设置哪些硬件（P205）

- **有**。DMA 方式靠主存与 I/O 接口间的直接数据通路传送数据，不靠中断传送信息；但一组数据传送完毕后，接口仍要向 CPU 发中断请求，报告传送结束。CPU 中断现行程序去做 DMA 的结束处理，比如测试传送中是否出错，这类工作 DMA 接口自己做不了，只能靠中断服务程序完成。
- 接口硬件：主存地址寄存器（AR）、字计数器（WC）、数据缓冲寄存器（BR）、DMA 控制逻辑、中断机构、设备地址寄存器（DAR）。组成图见 `图/5-47_DMA接口组成.png`。

### 31. DMA 方式中的中断请求和程序中断方式中的中断请求有何区别（P210）

- DMA 的中断请求**不是为了传送信息**（信息走主存与 I/O 间的直接通路），只是报告一组数据传送结束，让 CPU 做后处理：检查传送是否出错、决定是否继续用 DMA 传送等。
- 程序中断方式的中断请求**是为了传送数据**，I/O 与主机交换信息完全靠 CPU 响应中断后转入服务程序完成。

### 32. 与程序中断方式相比，DMA 方式有哪些特点

有两份汇总把这五条写在上一题下面，它们其实回答的是"DMA 方式的特点"：

1. 数据传送：程序中断靠**程序**传送，DMA 靠**硬件**传送。
2. 响应时间：程序中断在一条**指令执行结束**时响应，DMA 可在指令周期内任一**存取周期结束**时响应。
3. 程序中断能处理异常事件，DMA 不能；DMA 主要用于大批数据传送（硬盘存取、图像处理、高速数据采集），可提高吞吐量。
4. 程序中断要中断现行程序，需保护现场；DMA 不中断现行程序，不用保护现场。
5. DMA 的优先级比程序中断高。

### 33. DMA 与主存交换数据的三种方法（P202）

| 方法 | 做法 | 特点 |
| --- | --- | --- |
| 停止 CPU 访问主存 | 外设要传一批数据时，DMA 接口向 CPU 发停止信号，CPU 放弃地址线、数据线和有关控制线；传完后接口把总线控制权交回 CPU | 控制简单；传送期间 CPU 基本不工作或保持原状态，主存利用不充分 |
| 周期挪用（周期窃取） | CPU 照常访存，一旦 I/O 有 DMA 请求，就挪用一个或几个存取周期；此时 CPU 可做自身操作但要停止访存 | 既实现了 I/O 传送，又较好发挥了主存和 CPU 的效率，**应用最广** |
| DMA 与 CPU 交替访存 | 适合 CPU 工作周期比主存存取周期长的情况，如 CPU 周期大于主存周期两倍时，上半周期专供 DMA 访存，下半周期专供 CPU 访存；CPU 和 DMA 接口各有独立的访存地址寄存器、数据寄存器和读写信号 | 不需要总线使用权的申请、建立、归还过程，DMA 传送和 CPU 效率最高；硬件逻辑更复杂 |

### 34. 简述 DMA 的工作过程（P207）

分预处理、数据传送、后处理三个阶段，流程图见 `图/5-48_DMA传送过程.png`。

1. **预处理**（CPU 执行几条 I/O 指令完成）：
   - 指明传送方向是输入（写主存）还是输出（读主存）；
   - 向设备地址寄存器送设备号，启动设备；
   - 向主存地址寄存器送交换数据的主存起始地址；
   - 向字计数器送交换数据的个数。

   之后 CPU 继续执行主程序。
2. **数据传送**：CPU 继续执行主程序，同时由 DMA 接口完成一批数据的传送。每个字的循环是：主存地址送总线，数据送 I/O 设备（或主存），修改主存地址，修改字计数器，直到数据块传送结束，再向 CPU 申请程序中断。
3. **后处理**：CPU 执行中断服务程序做 DMA 结束处理：校验送入主存的数据是否正确；决定是否继续用 DMA 传送；测试传送过程中是否出错，出错则转诊断程序。然后继续执行主程序。

### 35. DMA 接口的类型有哪几种（P210）

- **选择型**：物理上可连多个设备，逻辑上同一时间只为一个设备服务；关键是预处理时把所选设备号送入设备地址寄存器。适合数据传输率很高的设备。
- **多路型**：物理上连多个设备，逻辑上也允许多个设备同时工作，各设备以字节交叉方式通过接口传送。适合同时为多个传输率不太高的设备服务。又分**链式多路型**和**独立请求多路型**。

## 第 6 章 计算机的运算方法

### 36. 说明浮点加减运算的步骤（P269）

1. **对阶**：使两数小数点位置对齐，小阶向大阶看齐（小阶数的尾数右移）。
2. **尾数求和**：按定点加减规则求和（差）。
3. **规格化**：对双符号位补码尾数，结果必须是 `00.1xx…x` 或 `11.0xx…x` 形式，否则左规或右规。
4. **舍入**：对阶或右规时右移丢掉的位，用"0 舍 1 入"法或恒置 1 法处理，保证精度。
5. **溢出判断**：看阶码是否溢出。阶码下溢（移码表示为 00…0）时结果置机器零；上溢时置溢出标志。

例（出自 `计组简答题.docx`）：$X=0.0110011\times2^{11}$，$Y=0.1101101\times2^{-10}$（均为二进制），求 X+Y。

```text
[X]浮 = 0 1010 1100110      （符号位 阶码(移码) 尾数）
[Y]浮 = 0 0110 1101101
1) 求阶差 |ΔE| = |1010 - 0110| = 0100
2) 对阶：Y 阶小，尾数右移 4 位 → [Y]浮 = 0 1010 0000110，移出的 1101 暂存
3) 尾数相加（双符号位补码）：
     00 1100110
   + 00 0000110
     00 1101100
4) 规格化：已满足
5) 舍入：移出部分最高位是 1，0 舍 1 入，尾数加 1 → 1101101
结果 [X+Y]浮 = 0 1010 1101101，即 X+Y = +0.1101101×2^10
```

### 37. 说明浮点乘除运算的步骤

1. **阶码运算**：乘法阶码相加，除法阶码相减，同时判断溢出。$[E_x+E_y]_移=[E_x]_移+[E_y]_补$，$[E_x-E_y]_移=[E_x]_移+[-E_y]_补$。
2. **尾数运算**：同定点乘除。
3. **尾数规格化**。
4. **舍入处理**。

例：同上题的 X、Y，求 X×Y。

```text
1) 阶码相加：[Ex+Ey]移 = [Ex]移 + [Ey]补 = 1 010 + 1 110 = 1 000（移码的 0）
2) 原码尾数相乘：0.1100110 × 0.1101101 = 0.10101101101110
3) 规格化：已满足，尾数、阶码不变
4) 舍入：保留 7 位，第 8 位是 1，加 1 修正 → 0.1010111
结果 X×Y = 0.1010111 × 2^0
```

### 40. 指令中有哪些字段？各有何作用？如何确定位数（P300）

- **操作码字段**：指出机器完成哪种操作，位数取决于指令系统的**操作种类**。

### 41. RISC 和 CISC 各自的特点（P330）

| RISC | CISC |
| --- | --- |
| 选取使用频度较高的**简单指令**，复杂功能由简单指令组合实现 | 指令系统**复杂庞大**，各指令使用频度相差很大 |
| 指令**长度固定**，指令格式种类少，寻址方式少 | 指令字长**不固定**，格式多，寻址方式多 |
| 只有 **LOAD/STORE** 指令访存，其余操作在寄存器之间进行 | 可以访存的指令不受限制 |
| CPU 中有**多个通用寄存器** | CPU 中设有专用寄存器 |
| 采用**流水技术**，大部分指令在 1 个时钟周期内完成 | 指令执行时间相差很大，大多数指令需多个时钟周期 |
| 控制器采用**组合逻辑**控制 | 控制器大多采用**微程序**控制 |
| 采用优化的编译程序 | 难以用优化编译生成高效的目标代码 |

2020 年整理版和 `计组简答题汇总.docx` 写的是优缺点（原稿注明是网上查的），可作补充：

- CISC 优点：指令丰富，功能强；寻址方式灵活；以微程序控制器为核心，指令存储器与数据存储器共享同一物理存储空间。缺点：指令使用率不均衡；不利于采用先进结构提高性能；结构复杂，不利于 VLSI 实现。
- RISC 优点：结构简单，易于设计；指令精简，使用率均衡，程序执行效率高。缺点：指令数少，功能不及 CISC；寻址方式不够灵活。

## 第 8 章 CPU 的结构和功能

### 42. CPU 有哪些功能？画出内部组成框图并说明各部件作用（P337）

- 功能：**指令控制**（控制程序顺序执行）、**操作控制**（产生每条指令所需的控制命令）、**时间控制**（对各种操作做时间上的控制）、**数据加工**（算术和逻辑运算）、**处理中断**。
- 框图：见 `图/8-2_CPU内部结构.png`。CPU 由 ALU、寄存器、CU、中断系统四部分组成，经内部数据总线相连，对外连控制总线、数据总线、地址总线。
- 各部件作用：
  - 寄存器：专用寄存器（PC、IR、堆栈指示器、MAR、MDR、状态寄存器等）存当前指令地址、指令和状态；通用寄存器存操作数。
  - CU：产生各种微操作命令序列。
  - ALU：完成算术和逻辑运算。
  - 中断系统：处理异常情况和特殊请求。

### 43. 影响流水线性能的因素有哪些？原因和解决方法（P348）

| 相关（冒险）类型 | 原因 | 解决方法 |
| --- | --- | --- |
| **结构相关**（资源相关） | 指令重叠执行时，不同指令争用同一功能部件 | 插入暂停周期（气泡），如前一条指令访存时暂停取后一条指令；设置相互独立的指令存储器和数据存储器（或独立的指令 Cache 和数据 Cache）；指令预取：CPU 设指令队列，执行阶段存储器空闲时预先取指 |
| **数据相关** | 指令重叠操作，改变了对操作数的读写访问顺序 | 后推法：停顿后继指令，直到前面指令的结果生成；**定向技术**（旁路、相关专用通路），把执行结果直接送到后续指令需要的地方，不必等写回寄存器再取；指令调度（静态或动态），让相关指令间隔足够远 |
| **控制相关** | 转移指令及其他改变 PC 的指令 | 冻结或排空流水线；尽早判别转移是否发生、尽早生成转移目标地址；预取转移成功和不成功两个方向的目标指令；加快和提前形成条件码；分支预测，提高转移方向的猜准率 |

### 44. 流水线性能指标：吞吐率、加速比、效率的定义（P353）

- **吞吐率**：单位时间内流水线完成的指令（任务）数或输出结果的数量，分最大吞吐率和实际吞吐率。
- **加速比**：完成同样一批任务，不用流水线的时间与用流水线的时间之比，即 m 段流水线速度与等功能非流水线速度之比。
- **效率**：流水线中各功能段（设备）的利用率，即设备实际使用时间与整个运行时间之比。在时空图上，是 n 个任务占用的时空区面积与 k 个段总时空区面积之比。

### 45. 五个中断源的屏蔽字

题目：某机有五个中断源 L0～L4，响应次序由高到低为 L0→L1→L2→L3→L4，要求处理次序为 L1→L3→L4→L0→L2，写出各中断源的屏蔽字。

思路：屏蔽字按 L0 L1 L2 L3 L4 排列。处理某个中断时，屏蔽**它自己**和**处理次序排在它后面**的源（置 1），其余置 0。处理次序越靠前，1 越多。

| 中断源 | L0 | L1 | L2 | L3 | L4 |
| --- | --- | --- | --- | --- | --- |
| L0 | 1 | 0 | 1 | 0 | 0 |
| L1 | 1 | 1 | 1 | 1 | 1 |
| L2 | 0 | 0 | 1 | 0 | 0 |
| L3 | 1 | 0 | 1 | 1 | 1 |
| L4 | 1 | 0 | 1 | 0 | 1 |

### 46. 什么是中断？中断系统需要解决哪些问题（P358）

- 中断：计算机运行中出现某些意外情况需要主机干预时，机器能自动停止正在运行的程序，转去处理新情况的程序，处理完毕后返回原程序继续运行。
- 需要解决的问题：
  1. 各中断源如何向 CPU 提出请求；
  2. 多个中断源同时请求时，如何确定优先响应哪一个；
  3. CPU 在什么条件、什么时候、以什么方式响应中断；
  4. 响应后如何保护现场；
  5. 如何停止原程序，转入中断服务程序入口；
  6. 处理结束后如何恢复现场，如何返回原程序断点；
  7. 中断处理过程中又出现新的中断请求怎么办。

### 47. CPU 响应中断的条件和时间

- 条件：**允许中断触发器 EINT 为 1**（开中断）；中断源提出请求、未被屏蔽，并且排队选中。
- 时间：**每条指令执行周期结束时刻**，CPU 发中断查询信号。

### 48. CPU 进入中断周期后完成哪些操作

中断周期内由中断隐指令（硬件）完成三件事，这是答题主干：

1. **保存断点**：保存当前程序的地址，以便返回。
2. **形成中断服务程序入口地址**并送 PC（硬件向量法或软件查询法）。
3. **关中断**：防止处理过程中再被中断。

yy 汇总还往下写了中断服务程序做的事，可以作为补充：

4. 保护现场：保存 PC、程序状态字、通用寄存器等内容。
5. 中断服务：执行服务程序，处理中断请求。
6. 恢复现场。
7. 中断返回：服务程序最后一条中断返回指令把堆栈中保存的 PC 和程序状态字弹出，回到断点继续执行。

### 49. 什么是中断隐指令？有哪些功能（P363）

- 中断隐指令：机器指令系统中没有的指令，是 CPU 在中断周期内由**硬件自动完成**的一条指令。CPU 响应中断后，要经过一些操作才转去执行中断服务程序，这些操作由硬件直接实现。
- 功能：**保护程序断点**、**寻找中断服务程序入口地址**、**关中断**。

（更正：2020 年整理版和 `计组简答题汇总.docx` 写作"开中断"，应为关中断。）

### 50. 什么是中断屏蔽字？有什么作用

- 每个中断请求触发器对应一个屏蔽触发器，所有屏蔽触发器组成屏蔽寄存器，其内容叫屏蔽字。屏蔽字与中断源的优先级别一一对应。
- 作用：
  1. 在中断服务程序中设置适当的屏蔽字，可以屏蔽优先级别不同的中断源。（更正：2020 年整理版写作"起到……中断作用"，应为屏蔽作用。）
  2. 用屏蔽技术可以改变 CPU 处理各中断源的优先等级，从而改变 CPU 执行程序的轨迹。

## 第 9 章 控制单元的功能

### 51. 什么是多级时序（P385）

- 机器周期和节拍（状态）组成多级时序系统。
- 机器周期：所有指令执行过程中的基准时间，取决于指令的功能和器件的速度。
- 节拍：由时钟信号控制节拍发生器产生，每个节拍宽度对应一个时钟周期，是控制计算机操作的最小时间单位。
- 关系：一个指令周期包含若干机器周期，一个机器周期包含若干时钟周期（节拍）。各指令周期内的机器周期数可以不等，各机器周期内的节拍数也可以不等。

## 第 10 章 控制单元的设计

### 52. 简述微程序设计的思想

- 一条机器指令编写成一个**微程序**，每个微程序包含若干**微指令**，每条微指令对应一个或几个微操作命令。
- 微程序存放在**控制存储器**中，用类似寻找用户程序机器指令的方法来寻找微指令。
- 微指令用二进制代码表示，每一位代表一个控制信号（1 有效，0 无效）。逐条执行微指令，就完成了一条机器指令的全部操作。
- 微程序控制单元的核心部件是控制存储器；执行一条机器指令要多次访问控存，所以控存速度要高。

### 53. 水平型微指令与垂直型微指令及其特点（P411）

| | 水平型微指令 | 垂直型微指令 |
| --- | --- | --- |
| 定义 | 一次能定义并执行**多个并行**操作的微命令 | 采用类似机器指令操作码的方式，设微操作码字段，由微操作码规定微指令功能 |
| 每条微指令的微命令 | 多个，大多数可直接控制对象 | 通常 1～2 个，要译码后才控制对象 |
| 编码方式 | 直接编码、字段直接编码、字段间接编码、直接与字段混合编码都属于水平型；直接编码最快，字段编码要译码，速度受影响 | 微操作码译码 |
| 并行能力、效率 | 强、高、灵活 | 不强调并行 |
| 速度 | 执行一条机器指令所需微指令少，快 | 慢 |
| 结构取舍 | 用较短的微程序换取较长的微指令 | 用较长的微程序换取较短的微指令 |
| 与机器指令的相似度 | 差别大 | 相似 |
