## 开篇简答：什么是多态

原稿开头单独放了这道题，没有注明年份。课程目录 `README.md` 里提到 2022 级简答题也考过"什么是多态"。

答案要点：

- **多态**：同一个接口（同名函数、同一个运算符、通过基类指针或引用发出的同一次调用）作用在不同类型的对象上，执行不同的代码。
- 编译时多态（静态多态）：函数重载、运算符重载、模板。调用哪个函数在编译时就按参数类型确定。
- 运行时多态（动态多态）：公有继承 + 虚函数 + 通过基类指针或引用调用。运行时根据对象的实际类型决定调用哪个版本，靠虚函数表实现。
- 好处：调用方只依赖基类接口，新增派生类时调用代码不用改。

```cpp
class Shape {
public:
    virtual ~Shape() {}
    virtual double Area() const = 0;
};
class Circle : public Shape {
public:
    explicit Circle(double r) : r_(r) {}
    double Area() const { return 3.14159 * r_ * r_; }
private:
    double r_;
};
void Print(const Shape& s) { cout << s.Area() << endl; }  // 传进 Circle 就调用 Circle::Area
```

原稿说法需要修正的两处：

- 原稿说"不能对基本类型使用运算符重载"。准确的说法是：重载的运算符至少要有一个操作数是类类型或枚举类型，不能改变内置类型之间的运算，比如不能重载两个 `int` 相加。
- 原稿说覆盖时"返回类型必须相同"。一般情况确实相同，但 C++ 允许协变返回：基类虚函数返回 `Base*` 或 `Base&`，派生类覆盖版本可以返回 `Derived*` 或 `Derived&`。

## 18-19 学年第 2 学期 A 卷（2019年7月4日）

### 一、判断正误，对错误的论述说明原因或举出反例（共20分，每题2分）

1. C++ 不允许实例化抽象类的对象，因此抽象类中不需要设计构造函数。

   答案：错误。抽象类不能单独创建对象，但它可以有数据成员，这些成员要靠抽象类自己的构造函数初始化；创建派生类对象时，会先调用抽象基类的构造函数。

2. 在异常处理时，异常抛出后，会导致所有程序被终止运行。

   答案：错误。异常抛出后，程序沿调用链逐层退出（栈展开），找到类型匹配的 `catch` 就进入处理，之后继续执行。只有一直找不到匹配的 `catch`，才会调用 `std::terminate` 终止程序。

3. 通过常量对象只能直接调用常成员函数和静态成员函数。（原稿抄作"常成员数"，扫描件是"常成员函数"。）

   答案：正确。常对象的 `this` 是指向常量的指针，只能调用 `const` 成员函数；静态成员函数没有 `this`，也可以通过常对象调用。

4. 如果类 B 和类 A 中都只由成员函数组成，则 `sizeof(B)` 一定等于 `sizeof(A)`。

   答案：错误。有没有虚函数会影响大小。比如 `class E {};` 的 `sizeof` 是 1，`class F { virtual void g() {} };` 在 64 位下是 8，多出来的是虚表指针。虚继承也会增加对象大小。

5. 若有类 A、类 B，且 `B b; A a = b;`，则类 B 一定是通过 public 继承方式从类 A 派生的。

   答案：错误。类 A 有形如 `A(const B&)` 的转换构造函数，或类 B 定义了 `operator A()`，两个类没有继承关系也能这样写。（更正：原稿答案还说 B 可以是保护继承或私有继承 A。在 `main` 这类外部代码里，私有、保护继承的派生类对象不能转换成基类，编译器会报 `cannot cast to its private base class`。）

6. 对已知函数 `void func(int a=0, int b=0, int c=0)`，用 `func(2)` 进行调用，参数匹配时，各参数的实参值分别为 a=0，b=0，c=2。

   答案：错误。实参从左向右匹配形参，缺省值只能从右边补，所以是 a=2，b=0，c=0。

7. 对象可以隐式或显式地使用 `this` 指针来引用自身数据成员和函数成员，`this` 指针是对象自身的一部分，`this` 指针占用的内存大小可以反映在对对象进行 `sizeof` 的运算结果中。

   答案：错误。`this` 是调用非静态成员函数时编译器隐式传入的参数，不存放在对象里，`sizeof` 不包含它。

8. 根据里氏替换原则，需要基类对象的任何地方都可以使用其派生类的对象来替代，程序的行为没有变化。

   答案：正确。这句话就是里氏替换原则的表述。提示：这是设计时应遵守的原则，编译器不检查；"行为没有变化"指程序仍然正确，派生类重写虚函数后具体执行的代码可以不同。

9. 虚函数是派生类对基类的覆盖而不是重载，其判断依据是参数的个数、类型、顺序、返回类型必须相同。

   答案：错误（更正：原稿答案作"正确"）。前半句没问题。判断覆盖要看函数名、参数列表（个数、类型、顺序）和 `const` 限定是否一致；返回类型允许协变，基类返回 `A*`，派生类可以返回 `D*`（D 公有派生自 A），所以"返回类型必须相同"不成立。

10. 静态数据成员在 `main` 函数之前构造，生命周期等同于全局对象，所以不需要其他声明情况下就可以在程序的任何地方访问到静态数据成员。

    答案：错误。静态数据成员在类内只是声明，还要在类外定义一次（如 `int A::count = 0;`，C++17 起也可以写 `inline static`）；在类外访问要加类名限定 `A::count`，并且受 `private`、`protected` 访问权限限制。

### 二、简答题（共30分）

#### 1. 请说出 static 在 C++ 语言中的全部作用（3分）

- 静态局部变量：函数内用 `static` 定义，存放在静态存储区，只初始化一次，函数返回后值保留；作用域仍然只在函数内。
- 静态全局变量、静态全局函数：具有内部链接，只在定义它的源文件里可见，别的文件用不到，也就不会和其他文件的同名符号冲突。
- 静态数据成员：属于整个类，所有对象共用一份；类内声明，类外定义并初始化；可以用 `类名::成员` 访问；不计入对象的 `sizeof`。
- 静态成员函数：没有 `this` 指针，只能直接访问本类的静态成员；可以不通过对象、直接用 `类名::函数()` 调用；不能声明为 `virtual` 或 `const`。

原稿列了 5 条，其中"控制链接性"和"静态全局变量"说的是同一件事，这里合并了。

#### 2. 请解释 C++ 的友元关系的概念，并说明友元关系的副作用（2分）

- 概念：类用 `friend` 声明某个普通函数、另一个类的成员函数或另一个类为友元，友元可以访问这个类的 `private` 和 `protected` 成员。
- 友元关系是单向的，不能传递，也不能继承。
- 副作用：**破坏封装**。类的内部实现一改，友元代码可能要跟着改；友元用多了，类之间耦合变紧，代码难维护。所以只在确实需要时使用，比如重载 `operator<<`。

#### 3. 为类添加有参构造函数（4分）

有类 A、B、C 的定义如下，请为各类添加有参构造函数，初始化各类中的数据成员。

```cpp
class A {
public:
    static int s_a;
    int const c_a;
    int d_a;
};
class B : public A {
public:
    int d_b;
    int& r_b;
};
class C {
public:
    B b_c;
    int d_c;
};
```

参考答案（原稿给出，编译通过）：

```cpp
class A
{
public:
    static int s_a;
    int const c_a;
    int d_a;
    A(int sa, int ca, int da) : c_a(ca), d_a(da)
    {
        s_a = sa;
    }
};
int A::s_a = 0;

class B : public A
{
public:
    int d_b;
    int& r_b;
    B(int sa, int ca, int da, int db, int& rb) : A(sa, ca, da), d_b(db), r_b(rb)
    {
    }
};

class C
{
public:
    B b_c;
    int d_c;
    C(int sa, int ca, int da, int db, int& rb, int dc) : b_c(sa, ca, da, db, rb), d_c(dc)
    {
    }
};
```

得分点：

- `c_a` 是 `const` 成员、`r_b` 是引用成员，只能在初始化列表里初始化。
- A 没有无参构造函数，B 必须在初始化列表里写 `A(sa, ca, da)`；C 的成员对象 `b_c` 同理，必须写 `b_c(...)`。
- `s_a` 是静态成员，要在类外定义 `int A::s_a = 0;`，构造函数里只能给它赋值。
- `r_b` 要绑定到调用者的变量上，所以参数要写成 `int&`。如果写成 `int rb`，`r_b` 会绑到形参上，构造函数返回后就成了悬空引用。

原稿在这里还贴了一张截图，总结类成员的初始化规则。截图的说法有几处过于绝对，按标准 C++ 改正如下：

| 成员种类 | 截图原文 | 更准确的说法 |
| --- | --- | --- |
| 非 static、非 const 的普通成员 | 必须在构造函数中进行初始化 | 可以在初始化列表里初始化，也可以在构造函数体里赋值；C++11 起还能在类内写默认值。不初始化也能编译，只是值不确定 |
| static 成员变量 | 必须在类的外面进行初始化 | 正确，类外定义一次；C++17 起 `inline static` 可以在类内初始化 |
| const 成员变量 | 必须在构造函数的初始化列表中初始化 | 正确；C++11 起也可以在类内给默认值。引用成员同样必须在初始化列表中初始化 |
| static const 成员变量 | 可以在类的内部声明时初始化 | 只限整型和枚举类型；其他类型要用 `constexpr static`（C++11）或在类外定义 |

#### 4. 请说出静态绑定和动态绑定的不同之处，并解释虚函数的工作机理（3分）

- 静态绑定：编译时就确定调用哪个函数，依据是函数名、参数类型和调用表达式的静态类型。普通函数、非虚成员函数、通过对象（非指针非引用）调用虚函数，都是静态绑定。
- 动态绑定：运行时才确定调用哪个函数，依据是指针或引用所指对象的实际类型。条件是**虚函数 + 通过基类指针或引用调用**。
- 工作机理：每个含虚函数的类有一张**虚函数表**（vtable），存放本类各虚函数的地址，派生类覆盖了哪个函数，表中对应位置就换成派生类版本的地址。每个对象里有一个**虚表指针**（vptr），在构造时指向所属类的虚表。通过基类指针调用虚函数时，程序先取对象的 vptr 找到虚表，再按函数在表中的位置取地址调用。

#### 5. 类 A 依赖类 B 的改进（3分）

题目（扫描件原文，原稿只抄了前半句）：类 A 直接依赖类 B，假如要将类 A 改为依赖类 C，则必须通过修改类 A 的代码来实现。该场景中，类 A 是高层模块，负责复杂的业务逻辑；类 B 和类 C 是低层模块，负责基本的细节操作；假如修改类 A，会给程序带来不必要的风险。请你给出一个无需修改类 A 代码的解决方案。

原稿无答案。答案要点（整理补充）：

- 用**依赖倒置**：抽象出一个接口类（只含纯虚函数），让 B、C 都公有继承这个接口并实现它。
- A 里只保存接口的指针或引用，只调用接口里的函数，不出现 B、C 的名字。
- 具体用 B 还是 C，由创建 A 的代码通过构造函数参数（或 setter）传进来。以后换成 C，或者再加一个 D，只改创建对象的那一处，A 的代码不动。

```cpp
#include <iostream>
using namespace std;

class IWorker {                 // 抽象出 A 真正需要的接口
public:
    virtual ~IWorker() {}
    virtual void Work() = 0;
};

class B : public IWorker {
public:
    void Work() { cout << "B 干活" << endl; }
};

class C : public IWorker {
public:
    void Work() { cout << "C 干活" << endl; }
};

class A {                       // A 只认识 IWorker，不认识 B、C
public:
    explicit A(IWorker& w) : worker_(w) {}
    void Run() { worker_.Work(); }
private:
    IWorker& worker_;
};

int main() {
    B b;
    C c;
    A a1(b);                    // 想换成 C，只改创建 A 的这一行
    A a2(c);
    a1.Run();
    a2.Run();
    return 0;
}
```

### 设计题：小汽车类 Car（原稿编号 6，分值原稿未写）

补充设计一个小汽车类 Car，并能支持完成以下代码调用的相应功能：

```cpp
#include<iostream>
using namespace std;
class Car
{
	char* pName;/*发动机名字*/
	int iId;/*车架号，自动产生具有唯一性*/
	int iI;/*行车里程数，初始化为0*/
public:
	/*需要补充的代码*/
};
int main()
{
	Car c1("捷达发动机");
	Car c2("奥迪发动机");
	Car c3(c1);
	c3 = c1;
	c2 = c2 + 3;/*又跑了3公里*/
	++c2;/*又跑了1公里*/
	cout << c2 << endl;/*输出小汽车c2的信息*/
}
```

要补的东西可以从 `main` 逐行看出来：

- `Car c1("捷达发动机")`：参数为 `const char*` 的构造函数，给 `pName` 分配空间并复制字符串，车架号取静态计数器的下一个值，里程置 0。参数要写 `const char*`，C++11 起字符串字面量不能传给 `char*`。
- `Car c3(c1)`：类里有指针成员，要自己写**深拷贝**的拷贝构造函数；新车应拿一个新车架号。
- `c3 = c1`：深赋值的 `operator=`，要处理自赋值，释放旧空间；车架号保留自己的。
- 有 `new[]` 就要有析构函数 `delete[]`。
- `c2 + 3`：`operator+(int)`。
- `++c2`：前置 `operator++()`，返回引用。
- `cout << c2`：友元 `operator<<`，返回 `ostream&`。

原稿答案按上面的思路写全了，编译通过，运行结果如下（最后多一个空行，因为 `operator<<` 里已经输出了 `endl`，`main` 又输出一次）：

```text
发动机名字: 奥迪发动机
车架号: 2
行车里程数: 4

```

原稿答案有一处设计问题：它把 `operator+` 写成 `Car& operator+(int x) { iI += x; return *this; }`，`c2 + 3` 会直接改掉 `c2` 自己。题目里 `c2 = c2 + 3` 碰巧看不出来，但写 `c3 = c2 + 3` 时 `c2` 的里程也会变，这和 `+` 的通常含义不符。另外它的拷贝构造函数初始化列表顺序和成员声明顺序不一致，编译器会给 `-Wreorder` 警告（成员实际按声明顺序初始化，这里不影响结果）。改进后的完整代码：

```cpp
#include <iostream>
#include <cstring>
using namespace std;

class Car
{
    char* pName;          // 发动机名字
    int iId;              // 车架号，自动产生，唯一
    int iI;               // 行车里程数，初始为 0
    static int s_nextId;  // 所有 Car 共用的编号计数器
public:
    Car(const char* name) : pName(new char[strlen(name) + 1]), iId(++s_nextId), iI(0)
    {
        strcpy(pName, name);
    }
    Car(const Car& other)                      // 深拷贝；新车拿新车架号
        : pName(new char[strlen(other.pName) + 1]), iId(++s_nextId), iI(other.iI)
    {
        strcpy(pName, other.pName);
    }
    ~Car() { delete[] pName; }

    Car& operator=(const Car& other)           // 深赋值；车架号保持自己的
    {
        if (this != &other) {
            char* p = new char[strlen(other.pName) + 1];
            strcpy(p, other.pName);
            delete[] pName;
            pName = p;
            iI = other.iI;
        }
        return *this;
    }
    Car operator+(int km) const                // 返回新对象，不修改左操作数
    {
        Car t(*this);
        t.iI += km;
        return t;
    }
    Car& operator++()                          // 前置 ++，返回引用
    {
        ++iI;
        return *this;
    }
    friend ostream& operator<<(ostream& os, const Car& c)
    {
        return os << "发动机:" << c.pName << " 车架号:" << c.iId << " 里程:" << c.iI;
    }
};
int Car::s_nextId = 0;

int main()
{
    Car c1("捷达发动机");
    Car c2("奥迪发动机");
    Car c3(c1);
    c3 = c1;
    c2 = c2 + 3;   // 又跑了3公里
    ++c2;          // 又跑了1公里
    cout << c2 << endl;
    Car c4 = c1 + 10;
    cout << c1 << endl << c4 << endl;
    return 0;
}
```

运行结果：

```text
发动机:奥迪发动机 车架号:2 里程:4
发动机:捷达发动机 车架号:1 里程:0
发动机:捷达发动机 车架号:5 里程:10
```

`c2 + 3` 里的临时对象由拷贝构造函数产生，占用了 4 号车架号，所以 `c4` 拿到 5 号。`c1 + 10` 之后 `c1` 的里程还是 0，说明 `operator+` 没有改左操作数。

车架号在拷贝构造函数里分配，所以结果和编译器是否省略拷贝有关：用 `-std=c++11 -fno-elide-constructors` 编译，`operator+` 返回、初始化 `c4` 时各多一次拷贝构造，`c4` 的车架号变成 8，前两行不变。这类题如果要写出车架号，要说明是否考虑了拷贝省略。

### 七、综合编程题（12分）

各大通信运营商提供的手机运营业务主要包括通话业务、流量业务、短信业务等等，不同的业务具有不同资费方案。例如不同运营商具有不同通话业务基本资费标准，根据用户的不同需求还提供有月租套餐、包年套餐等，月租套餐一般包括基本的月基本费用（常规包含一定的本地或异地通话时间和数据流量），超出部分主叫费用/分钟和费用/流量等等（具体业务资费规则可参考同学自己的资费情况）。随着手机业务需求的不断发展，允许新的运营商加入竞争，并可能推出新的业务类型、新的资费方案。特别是 5G 即将全面上线，对于流量业务资费影响颇大。

请你设计并实现手机业务管理系统，请以收费为关注点设计类的体系和主要接口，并给出调用程序（比如 `main` 函数）模拟张同学在 2019 年 1 月到 2019 年 6 月期间手机业务的费用情况。

原稿贴的答案只有 `Service` 抽象类和通话、流量、短信三个子类，每个子类用"单价 × 用量"算钱，再由 `Customer` 求和。它能编译运行（输出 `Total charge: 382.2`），但题目要求的运营商、月租和包年套餐、套餐内含量加超出计费、按月模拟都没有体现，而且每加一种业务就要加一个几乎一样的类。下面按题意重新设计（整理补充）。

设计要点：

- 题目里会变化的东西有四样：运营商、业务类型、计费规则、套餐类型。把它们拆开，各自可以扩展。
- `ChargeRule`（抽象类）：某项业务怎么按用量收费。`UnitPrice` 纯按量；`Bundle` 套餐内含一定用量，超出按单价。以后出现阶梯价、5G 流量包，加一个子类即可。
- `Plan`（抽象类）：资费方案 = 固定费用 + 各业务的计费规则。固定费用怎么收由子类决定：`MonthlyPlan` 每月收月租，`YearlyPlan` 一月份收年费。业务类型用字符串做键，新增"5G流量"这类业务不用改类。
- `Carrier`：运营商，拥有若干方案。新运营商就是新建一个 `Carrier` 对象。
- `Subscriber`：用户，选定一个方案，按月记录各业务用量，按月出账。

```cpp
#include <iostream>
#include <map>
#include <string>
#include <vector>
using namespace std;

// 某种业务（通话、流量、短信、5G 流量……）的计费规则
class ChargeRule {
public:
    virtual ~ChargeRule() {}
    virtual double Fee(double used) const = 0;   // 用量 -> 费用
};

class UnitPrice : public ChargeRule {             // 纯按量计费
public:
    explicit UnitPrice(double price) : price_(price) {}
    double Fee(double used) const { return used * price_; }
private:
    double price_;
};

class Bundle : public ChargeRule {                // 套餐内含一定用量，超出按单价
public:
    Bundle(double included, double overPrice) : included_(included), over_(overPrice) {}
    double Fee(double used) const { return used > included_ ? (used - included_) * over_ : 0; }
private:
    double included_, over_;
};

// 资费方案：固定费用 + 各业务的计费规则
class Plan {
public:
    explicit Plan(const string& name) : name_(name) {}
    virtual ~Plan() {
        for (map<string, ChargeRule*>::iterator it = rules_.begin(); it != rules_.end(); ++it)
            delete it->second;
    }
    void SetRule(const string& service, ChargeRule* rule) { rules_[service] = rule; }
    const string& Name() const { return name_; }
    double MonthCharge(int month, const map<string, double>& usage) const {
        double sum = FixedFee(month);
        for (map<string, double>::const_iterator it = usage.begin(); it != usage.end(); ++it) {
            map<string, ChargeRule*>::const_iterator r = rules_.find(it->first);
            if (r != rules_.end()) sum += r->second->Fee(it->second);
        }
        return sum;
    }
protected:
    virtual double FixedFee(int month) const = 0;  // 月租、年费等固定部分由子类决定
private:
    string name_;
    map<string, ChargeRule*> rules_;
    Plan(const Plan&);
    Plan& operator=(const Plan&);
};

class MonthlyPlan : public Plan {                 // 月租套餐
public:
    MonthlyPlan(const string& name, double rent) : Plan(name), rent_(rent) {}
protected:
    double FixedFee(int) const { return rent_; }
private:
    double rent_;
};

class YearlyPlan : public Plan {                  // 包年套餐：1 月一次性交年费
public:
    YearlyPlan(const string& name, double yearFee) : Plan(name), yearFee_(yearFee) {}
protected:
    double FixedFee(int month) const { return month == 1 ? yearFee_ : 0; }
private:
    double yearFee_;
};

class Carrier {                                   // 运营商：拥有若干资费方案
public:
    explicit Carrier(const string& name) : name_(name) {}
    ~Carrier() { for (size_t i = 0; i < plans_.size(); ++i) delete plans_[i]; }
    Plan* AddPlan(Plan* p) { plans_.push_back(p); return p; }
    const string& Name() const { return name_; }
private:
    string name_;
    vector<Plan*> plans_;
};

class Subscriber {                                // 用户：选一个方案，按月记录用量
public:
    Subscriber(const string& name, const Carrier& c, const Plan& p) : name_(name), carrier_(&c), plan_(&p) {}
    void Record(int month, const string& service, double used) { usage_[month][service] += used; }
    double Bill(int month) const {
        map<int, map<string, double> >::const_iterator it = usage_.find(month);
        return plan_->MonthCharge(month, it == usage_.end() ? map<string, double>() : it->second);
    }
    void Report(int year, int from, int to) const {
        double total = 0;
        cout << name_ << "（" << carrier_->Name() << "，" << plan_->Name() << "）" << endl;
        for (int m = from; m <= to; ++m) {
            double b = Bill(m);
            total += b;
            cout << year << "年" << m << "月：" << b << " 元" << endl;
        }
        cout << "合计：" << total << " 元" << endl;
    }
private:
    string name_;
    const Carrier* carrier_;
    const Plan* plan_;
    map<int, map<string, double> > usage_;
};

int main() {
    Carrier carrier("某运营商");
    Plan* plan = carrier.AddPlan(new MonthlyPlan("38元月租套餐", 38));
    plan->SetRule("通话", new Bundle(200, 0.15));   // 含 200 分钟，超出 0.15 元/分钟
    plan->SetRule("流量", new Bundle(3000, 0.03));  // 含 3000 MB，超出 0.03 元/MB
    plan->SetRule("短信", new UnitPrice(0.1));      // 短信 0.1 元/条
    // 以后加 5G 流量：plan->SetRule("5G流量", new Bundle(...)); 不用改任何类

    Subscriber zhang("张同学", carrier, *plan);
    double calls[] = {180, 230, 150, 260, 190, 210};
    double data[]  = {2800, 3500, 2900, 4200, 3100, 2600};
    double sms[]   = {10, 5, 0, 8, 12, 3};
    for (int m = 1; m <= 6; ++m) {
        zhang.Record(m, "通话", calls[m - 1]);
        zhang.Record(m, "流量", data[m - 1]);
        zhang.Record(m, "短信", sms[m - 1]);
    }
    zhang.Report(2019, 1, 6);
    return 0;
}
```

运行结果（资费和用量数字是编的，只用来演示）：

```text
张同学（某运营商，38元月租套餐）
2019年1月：39 元
2019年2月：58 元
2019年3月：38 元
2019年4月：83.8 元
2019年5月：42.2 元
2019年6月：39.8 元
合计：300.8 元
```

以 2 月为例手算核对：月租 38；通话 230 分钟超出 30 分钟，30 × 0.15 = 4.5；流量 3500 MB 超出 500 MB，500 × 0.03 = 15；短信 5 × 0.1 = 0.5；合计 58 元。

### 二、1. 既然每个类的成员函数都是确定的，为什么还要通过建立虚表实现多态

原稿答案是机器生成的长段落，核心意思没错，整理成要点：

- 每个类有哪些成员函数、函数体是什么，编译时确实都知道。
- 但通过基类指针或引用调用时，编译器只知道指针的静态类型，不知道运行时它会指向哪个派生类的对象。比如 `Shape* p` 指向什么，可能取决于用户输入。
- 要在运行时调用"实际对象所属类"的版本，对象里就得带上类型相关的信息。C++ 的做法是每个含虚函数的类一张虚表，每个对象一个虚表指针，调用时按指针查表。
- 代价是每个对象多一个指针的空间，每次虚函数调用多一次间接寻址；非虚函数没有这笔开销，所以 C++ 默认不是虚函数。

### 四、移动通信工具的类设计（8分）

信息时代人们高度依赖移动即时通信工具，通信工具可以分解为移动通信功能和通信软件的叠加功能。常见的移动通信功能实现方式有：3G、4G、WiFi、蓝牙、微波、ZigBee 等（原稿作"Z1Gbee"），负责完成无线信号的传递；通信软件负责信号的呈现并完成人机交互模式，常见的有：QQ、微信、飞信、泡泡、阿里旺旺等。随着技术的发展，新的移动通信方式和通信软件也会发生新的变化。给出通信工具系统实现所需类的设计，需要满足可复用、可扩展、可维护的特点。

答案要点：

- 系统有两个独立变化的维度：通信方式和通信软件。如果每种组合都派生一个类（QQ 走 4G、QQ 走 WiFi……），类的个数是两者的乘积，加一种方式就要加一整列类。
- 做法是两套继承体系分开：`Channel` 抽象类及其子类表示通信方式，`IMSoftware` 抽象类及其子类表示通信软件；`IMSoftware` 里保存一个 `Channel*`，发送时交给它传输。这就是**桥接模式**，新增方式或软件都只加一个子类，类的个数是两者之和。
- 运行时可以给软件换通信方式（比如从 4G 切到 WiFi），软件类的代码不用改。

原稿答案给了 `MobileCommunication`、`CommunicationSoftware` 两个抽象类和一个同时持有两者指针的 `CommunicationTool`，方向是对的，但软件类的发送函数没有用到通信方式，两个体系实际上没有连起来；原稿代码还缺 `#include <string>` 和 `using namespace std;`，照抄编译不过。下面是改写后的参考实现（整理补充）：

```cpp
#include <iostream>
#include <string>
using namespace std;

// 维度一：移动通信方式，只负责把数据发出去
class Channel {
public:
    virtual ~Channel() {}
    virtual void Transmit(const string& data) = 0;
};
class G4 : public Channel {
public:
    void Transmit(const string& data) { cout << "[4G] " << data << endl; }
};
class WiFi : public Channel {
public:
    void Transmit(const string& data) { cout << "[WiFi] " << data << endl; }
};
class Bluetooth : public Channel {
public:
    void Transmit(const string& data) { cout << "[蓝牙] " << data << endl; }
};

// 维度二：通信软件，负责呈现和人机交互，通过 Channel 指针使用通信方式
class IMSoftware {
public:
    explicit IMSoftware(Channel* ch) : channel_(ch) {}
    virtual ~IMSoftware() {}
    void SetChannel(Channel* ch) { channel_ = ch; }      // 运行时可以换通信方式
    void Send(const string& to, const string& msg) { channel_->Transmit(Pack(to, msg)); }
protected:
    virtual string Pack(const string& to, const string& msg) const = 0;  // 各软件自己的消息格式
private:
    Channel* channel_;
};
class QQ : public IMSoftware {
public:
    explicit QQ(Channel* ch) : IMSoftware(ch) {}
protected:
    string Pack(const string& to, const string& msg) const { return "QQ消息 -> " + to + ": " + msg; }
};
class WeChat : public IMSoftware {
public:
    explicit WeChat(Channel* ch) : IMSoftware(ch) {}
protected:
    string Pack(const string& to, const string& msg) const { return "微信消息 -> " + to + ": " + msg; }
};

int main() {
    G4 g4;
    WiFi wifi;
    QQ qq(&g4);
    qq.Send("同学A", "下课了吗");
    qq.SetChannel(&wifi);
    qq.Send("同学A", "到宿舍了");
    WeChat wx(&wifi);
    wx.Send("同学B", "明天考试");
    return 0;
}
```

运行结果：

```text
[4G] QQ消息 -> 同学A: 下课了吗
[WiFi] QQ消息 -> 同学A: 到宿舍了
[WiFi] 微信消息 -> 同学B: 明天考试
```

### 五、群的设计（7分）

题目四中所提到的所有通信软件一般都有群的功能（原稿"所提到"误作"所把到"）。群可以模拟生活圈、工作圈、同学圈、生意圈等相对固定的组织，也可以模拟讨论组、读书会、畅读吧、学习班等临时性的组织，这些组织可以相互交叉、相互叠加，即每个组织下面都可以有若干个其他的组织。这些组织的本质都是群，其核心功能是群成员的信息共享。给出以上所描述的群的设计，实现群的信息共享的基本功能，体现群内可以任意个数、任意深度组合不同性质子群的特点。

答案要点：

- "群里可以放人，也可以放群，深度不限"，对应**组合模式**：抽象类 `Participant` 表示群里的一个成员，`User`（具体的人）和 `Group`（群）都从它派生。
- `Group` 里保存 `vector<Participant*>`，既能放 `User` 也能放 `Group`；收到消息时逐个转发给成员，成员是子群就继续向下转发，这样任意深度都能共享信息。
- 生活圈、读书会这些"性质"只是群的一个属性，不需要为每种性质写一个类。
- 同一个人可以被加进多个群（交叉），所以群只保存指针，不负责释放成员。要注意别把群加进它自己的子群里，否则转发会无限递归。

原稿答案只写了一个 `Group` 类，子群列表和成员列表分开存，发消息时只发给直接成员，不会传到子群，没有体现"任意深度"；代码用了 `remove` 却没有 `#include <algorithm>`。下面是改写后的参考实现（整理补充）：

```cpp
#include <iostream>
#include <string>
#include <vector>
using namespace std;

// 群里的"成员"既可以是人，也可以是另一个群
class Participant {
public:
    explicit Participant(const string& name) : name_(name) {}
    virtual ~Participant() {}
    const string& Name() const { return name_; }
    virtual void Receive(const string& from, const string& msg) = 0;
private:
    string name_;
};

class User : public Participant {                     // 叶子：具体的人
public:
    explicit User(const string& name) : Participant(name) {}
    void Receive(const string& from, const string& msg) {
        cout << "  " << Name() << " 收到[" << from << "]: " << msg << endl;
    }
};

class Group : public Participant {                    // 组合：群里可以再放群
public:
    Group(const string& name, const string& kind) : Participant(name), kind_(kind) {}
    void Add(Participant* p) { members_.push_back(p); }
    // 群内共享信息：转发给每个成员；成员是子群就继续向下转发
    void Receive(const string& from, const string& msg) {
        for (size_t i = 0; i < members_.size(); ++i)
            members_[i]->Receive(from + "/" + Name(), msg);
    }
    void Share(const User& sender, const string& msg) {
        cout << sender.Name() << " 在" << kind_ << "「" << Name() << "」发言" << endl;
        Receive(sender.Name(), msg);
    }
private:
    string kind_;                        // 工作圈、读书会、学习班……只是属性，不需要新类
    vector<Participant*> members_;       // 不负责释放，成员可以同时属于多个群
};

int main() {
    User a("小赵"), b("小钱"), c("小孙");
    Group cls("2班", "同学圈"), reading("周末读书会", "读书会"), school("年级群", "同学圈");
    cls.Add(&a);
    cls.Add(&b);
    reading.Add(&b);                     // 小钱同时在两个群
    reading.Add(&c);
    school.Add(&cls);                    // 群里嵌套群，深度不限
    school.Add(&reading);
    school.Share(a, "明天上午考 C++");
    return 0;
}
```

运行结果：

```text
小赵 在同学圈「年级群」发言
  小赵 收到[小赵/年级群/2班]: 明天上午考 C++
  小钱 收到[小赵/年级群/2班]: 明天上午考 C++
  小钱 收到[小赵/年级群/周末读书会]: 明天上午考 C++
  小孙 收到[小赵/年级群/周末读书会]: 明天上午考 C++
```

小钱同时在两个子群里，所以收到两次。实际系统里想去重，可以在一次转发过程中用 `set` 记下已经通知过的人。

### 八、编程题（12分）

欧洲杯激战正酣，组委会编写软件实现赛事的管理，需要管理的内容有：

1. 球员。信息：编号、姓名、位置、身价、红黄牌数目等。需要具有的功能有：攻击、防守、犯规等。
2. 教练。信息：编号、姓名、身价等。需要具有的功能有：阵型布置、战术指挥、场上球员更换等。
3. 裁判。信息：编号、姓名等。需要具有的功能有：犯规确认，红牌、黄牌、点球判罚、进球确认等。
4. 球队。信息：编号、名称、队员、教练、积分等。

在 `main` 函数里需要调试的功能有：每次比赛后需要统计所有球员红黄牌数目以确定出场受限情况；每次比赛后需要统计球队和球员进球情况以确定球队积分和球员身价；每次比赛后需要统计每个球员的上场时间；每次比赛后需要统计球队积分、阵型有效性评估等，以确认教练身价；每次比赛后可能阵前换帅（更换教练）。

在以上描述的基础上，完成比赛的管理模拟，给出类的设计并给出 `main` 函数测试代码。

原稿无答案。设计要点（整理补充）：

- 球员、教练、裁判都有编号和姓名，抽出基类 `Person`，三者公有继承。
- `Team` 和 `Player`、`Coach` 是聚合关系：球队保存队员和教练的指针，换帅就是换一个指针，球员和教练对象的生命周期不归球队管。
- 裁判的判罚直接修改球员和球队的统计数据（黄牌数、进球数），教练换人修改球队的场上名单。
- 单独设一个 `Match` 类表示一场比赛，比赛结束时统一结算：按比分给积分，按积分调整教练身价，检查停赛，打印每个球员的进球、上场时间和身价。
- 身价怎么涨跌、几张牌停赛，题目没规定，代码里用了简单规则（进球身价涨 5%，赢球教练身价涨 10%、输球降 10%，两黄或一红停赛），写在注释里。

```cpp
#include <iostream>
#include <string>
#include <vector>
using namespace std;

class Person {
public:
    Person(int id, const string& name) : id_(id), name_(name) {}
    virtual ~Person() {}
    int Id() const { return id_; }
    const string& Name() const { return name_; }
private:
    int id_;
    string name_;
};

class Player : public Person {
public:
    Player(int id, const string& name, const string& pos, double value)
        : Person(id, name), pos_(pos), value_(value), yellow_(0), red_(0), goals_(0), minutes_(0), suspended_(false) {}
    void Attack() const { cout << Name() << " 进攻" << endl; }
    void Defend() const { cout << Name() << " 防守" << endl; }
    void Foul() const { cout << Name() << " 犯规" << endl; }
    void AddYellow() { ++yellow_; }
    void AddRed() { ++red_; }
    void AddGoal() { ++goals_; value_ *= 1.05; }        // 进球提升身价
    void AddMinutes(int m) { minutes_ += m; }
    // 赛后统计：两黄或一红停赛一场
    void CheckSuspension() { suspended_ = red_ > 0 || yellow_ >= 2; if (suspended_) { yellow_ = 0; red_ = 0; } }
    bool Suspended() const { return suspended_; }
    void Print() const {
        cout << "  " << Name() << "(" << pos_ << ") 进球" << goals_ << " 上场" << minutes_
             << "分钟 身价" << value_ << (suspended_ ? " 下场停赛" : "") << endl;
    }
private:
    string pos_;
    double value_;
    int yellow_, red_, goals_, minutes_;
    bool suspended_;
};

class Team;

class Coach : public Person {
public:
    Coach(int id, const string& name, double value) : Person(id, name), value_(value) {}
    void SetFormation(const string& f) { formation_ = f; cout << Name() << " 布置阵型 " << f << endl; }
    void Command(const string& tactic) const { cout << Name() << " 指挥战术：" << tactic << endl; }
    void Substitute(Team& t, Player* out, Player* in) const;
    void Evaluate(int points) { value_ *= (points >= 3 ? 1.1 : (points == 0 ? 0.9 : 1.0)); }  // 按积分评估身价
    double Value() const { return value_; }
private:
    double value_;
    string formation_;
};

class Team {
public:
    Team(int id, const string& name, Coach* coach) : id_(id), name_(name), coach_(coach), points_(0), goals_(0) {}
    void AddPlayer(Player* p) { squad_.push_back(p); }
    void PutOnField(Player* p) { onField_.push_back(p); }
    void Replace(Player* out, Player* in) {
        for (size_t i = 0; i < onField_.size(); ++i)
            if (onField_[i] == out) onField_[i] = in;
    }
    void ChangeCoach(Coach* c) { cout << name_ << " 阵前换帅：" << coach_->Name() << " -> " << c->Name() << endl; coach_ = c; }
    int Id() const { return id_; }
    Coach* GetCoach() const { return coach_; }
    const string& Name() const { return name_; }
    void AddGoal() { ++goals_; }
    int Goals() const { return goals_; }
    void AddPoints(int p) { points_ += p; coach_->Evaluate(p); }
    const vector<Player*>& Squad() const { return squad_; }
    void ClearMatch() { onField_.clear(); goals_ = 0; }
    int Points() const { return points_; }
private:
    int id_;
    string name_;
    Coach* coach_;
    vector<Player*> squad_, onField_;
    int points_, goals_;
};

void Coach::Substitute(Team& t, Player* out, Player* in) const {
    cout << Name() << " 换人：" << out->Name() << " 下，" << in->Name() << " 上" << endl;
    t.Replace(out, in);
}

class Referee : public Person {
public:
    Referee(int id, const string& name) : Person(id, name) {}
    void ConfirmFoul(const Player& p) const { cout << Name() << " 确认 " << p.Name() << " 犯规" << endl; }
    void Yellow(Player& p) const { p.AddYellow(); cout << "裁判出示黄牌给 " << p.Name() << endl; }
    void Red(Player& p) const { p.AddRed(); cout << "裁判出示红牌给 " << p.Name() << endl; }
    void Penalty(const Team& t) const { cout << "裁判判给 " << t.Name() << " 点球" << endl; }
    void ConfirmGoal(Team& t, Player& p) const { t.AddGoal(); p.AddGoal(); cout << "进球有效：" << t.Name() << " " << p.Name() << endl; }
};

// 一场比赛：比赛结束后统一做统计
class Match {
public:
    Match(Team& home, Team& away, Referee& ref) : home_(home), away_(away), ref_(ref) {}
    void Finish() {
        int h = home_.Goals(), a = away_.Goals();
        home_.AddPoints(h > a ? 3 : (h == a ? 1 : 0));
        away_.AddPoints(a > h ? 3 : (h == a ? 1 : 0));
        cout << "主裁" << ref_.Name() << "，比分 " << home_.Name() << " " << h << ":" << a << " " << away_.Name() << endl;
        Report(home_);
        Report(away_);
        home_.ClearMatch();
        away_.ClearMatch();
    }
private:
    static void Report(Team& t) {
        cout << t.Id() << "号 " << t.Name() << " 积分" << t.Points() << " 主教练身价" << t.GetCoach()->Value() << endl;
        for (size_t i = 0; i < t.Squad().size(); ++i) {
            t.Squad()[i]->CheckSuspension();
            t.Squad()[i]->Print();
        }
    }
    Team& home_;
    Team& away_;
    Referee& ref_;
};

int main() {
    Coach c1(1, "教练甲", 500), c2(2, "教练乙", 400), c3(3, "教练丙", 450);
    Team t1(1, "A队", &c1), t2(2, "B队", &c2);
    Player p1(10, "球员1", "前锋", 3000), p2(11, "球员2", "中场", 2000), p3(12, "球员3", "前锋", 1500);
    Player q1(20, "球员4", "后卫", 1800), q2(21, "球员5", "门将", 1200);
    t1.AddPlayer(&p1); t1.AddPlayer(&p2); t1.AddPlayer(&p3);
    t2.AddPlayer(&q1); t2.AddPlayer(&q2);
    Referee ref(99, "裁判甲");

    t1.PutOnField(&p1); t1.PutOnField(&p2);
    t2.PutOnField(&q1); t2.PutOnField(&q2);
    Match m(t1, t2, ref);
    c1.SetFormation("4-3-3");
    c2.Command("防守反击");
    p1.Attack();
    q1.Foul();
    ref.ConfirmFoul(q1);
    ref.Yellow(q1);
    ref.Penalty(t1);
    ref.ConfirmGoal(t1, p1);
    q1.Foul();
    ref.Yellow(q1);
    c1.Substitute(t1, &p2, &p3);
    p1.AddMinutes(90); p2.AddMinutes(60); p3.AddMinutes(30);
    q1.AddMinutes(75); q2.AddMinutes(90);
    m.Finish();
    t2.ChangeCoach(&c3);                 // 输球后阵前换帅
    return 0;
}
```
