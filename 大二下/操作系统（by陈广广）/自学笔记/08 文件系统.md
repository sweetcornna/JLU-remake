## 本章要点

先分清逻辑结构（用户看到的，流式和记录式）和物理结构（在外存上怎么放，顺序、链接、索引、散列、倒排）。打开文件涉及的两张表（系统打开文件表、用户打开文件表）要能画出关系，创建、打开、关闭、读、写、连接这几个操作的步骤按"查表、检查、改表"的套路记。FCB 分主部次部的两个好处几乎年年出现。

## 名词解释

文件：具有符号名且在逻辑上有完整意义的信息项的有序序列。

信息项：构成文件内容的基本单位，可能是单个字节，也可能是多个字节；所有信息项可能等长，也可能不等长。

文件名：文件的符号名，由用户在创建文件时确定，访问文件时使用。

## 文件的结构

### 文件的逻辑组织形式主要有哪两种？各自有什么特点？

流式文件（非结构式）：操作系统对文件的外部结构不做解释。基本单位是字节。它是具有符号名且逻辑上有完整意义的字节序列，用户以字节为基本单位访问。每个文件内部有一个读写指针，可以用系统调用把指针定位到某一位置，后续读写从该位置开始。流式文件本身没有结构，但用户使用时可以自定义结构，例如一个学生的档案占 50 B，就把 50 B 当作一条记录。

记录式文件（结构式）：操作系统对文件的外部结构有解释。基本单位是记录，一条记录由一组逻辑上相关的信息项构成。它是具有符号名且逻辑上有完整意义的记录序列，用户以记录为基本单位访问。同样有读写指针，可以移动到某一位置后继续读写。

流式文件是记录式文件的特例。

### 什么是文件的逻辑结构和物理结构？各有哪几种形式？

逻辑结构是从用户观点看到的文件组织形式，与存储设备特性无关，分无结构的流式文件和有结构的记录式文件两种。

物理结构是文件在外存上的存储组织形式，与存储设备特性关系很大，通常有四种：顺序结构、链接结构、散列结构、索引结构。

### 为什么把文件定义为信息项的序列，而不是信息项的集合？

因为构成文件的信息项之间有次序关系。这与数据库不同，数据库中同一关系的记录之间没有次序关系，所以关系是记录的集合。

### 举例说明哪种文件长度固定，哪种动态变化

某些系统可执行程序（如 shell、vi）的长度通常固定不变；用户正在编辑的文本文件或源代码文件长度通常动态变化。

### 文件的物理组织有哪些形式？各自有什么特点？

保存文件的物理设备被划分为块，文件的物理结构就是确定怎样把记录或字节保存在物理块中。确定物理结构时要考虑四个因素：记录格式（定长、变长）、空间开销（除文件内容之外的额外存储开销）、存取速度（顺序存取、按号随机存取、按键随机存取）、长度变化（能否动态增减）。

顺序结构（连续结构）：一个文件占有若干连续的物理块，首块号和块数记录在文件控制块中。优点是访问速度快，缺点是文件长度增加困难。

链接结构（串联结构）：一个文件占有若干不连续的存储块，各块之间用指针相连，首块号和块数记录在文件控制块中。优点是长度易于动态变化，缺点是随机访问很慢，文件较长时尤其明显，因为要访问某一块必须把它之前的所有块逐个读入内存。

索引结构：一个文件占有若干不连续的存储块，这些块的块号记录在一个索引块中。优点是访问速度快、长度变化容易。缺点是系统存储开销大：每个文件都要一个索引块，占用额外外存空间；文件打开时索引块要读入内存，否则访问速度会降低一半，因此还占额外内存空间；索引块长度固定，限制了文件的最大长度。

散列结构（杂凑结构）：只适用于定长记录和按键随机查找的访问方式，常用于构造文件目录，涉及保存记录、查找记录、删除记录三类操作。

倒排结构：记录中的域称为键，能区分所有记录的键称为主键，其他键称为次键。以键值和记录地址构成的索引结构称为倒排结构。键值为主键的索引叫主索引，键值为次键的索引叫次索引。

### 关于散列文件结构的顺序探查法

1. 对一个非空闲记录来说，其键值 key 的散列值 `hash(key)` 是否一定与该记录的地址 addr 相同？不一定。前面的记录发生冲突时，可能在顺序探查中占用了本记录的位置。
2. 一条记录的冲突计数值为 0 时，该记录是否一定空闲？不一定，它可能存放着冲突的记录。
3. 一条记录空闲时，它的冲突计数值是否一定为 0？不一定。本记录被删除后，仍可能有其他记录的 `hash(key)` 指向这个入口地址。

## 文件存储空间的管理

### 文件存储空间的管理有哪些形式？各自有什么特点？

空闲块表：把所有空闲块记录在同一张表中，表中有首空闲块号和空闲块数两个栏目，空闲块数为 0 的表目标记为表尾。特别适合物理组织为连续结构的文件系统。原文的例子是一张记录"第 12 到 18 块、第 38 到 64 块、第 96 到 99 块空闲，其余块被占用"的空闲块表。

空闲块链：把所有空闲块连成一条链，外存空间的申请和释放以块为单位，申请时由链头取一块，释放时把它连入链头。比较节省外存空间，但速度较慢，每申请或释放一块都要执行一次输入输出操作。

位图：用 1 位表示外存中一块的状态，可以规定 0 为空闲、1 为占用。申请时在位图中从头查找为 0 的位，改成 1 并返回对应块号；归还时把对应位改回 0。

## 打开文件的表目与文件操作

### 文件打开时需要哪些内存表目？它们之间有什么联系？

系统打开文件表：内存中的一张表，保存已打开文件的文件控制块。除 FCB 主部外还包含三项信息：文件号（用于得到 FCB 主部在外存中的位置）、共享计数（记录当前有多少进程在使用该文件，值为 0 表示空表目）、修改标志（标识该 FCB 在内存期间是否被修改过；最后一个使用该文件的进程关闭文件时，若修改过就要把内存中的 FCB 写回外存，否则不必刷新外存）。这张表保存在操作系统空间，用户程序不能访问，它的长度决定了系统中能同时打开的文件的最大数目。

用户打开文件表：每个进程一张。文件可以共享，多个进程可能同时打开同一文件，打开方式可能不同、当前读写位置通常也不同，这些信息记录在这张表里。表中的"系统打开文件表入口"是一个指针，指向该文件的 FCB 在系统打开文件表中的入口地址；多个进程共用同一文件时，它们的用户打开文件表项指向同一个入口。文件描述符 fd（file descriptor）是一个正整数，它的值由表中位置隐含确定，所以并不实际记录在表中；文件打开后 fd 返回给进程，此后进程用它存取文件，不再使用文件名。用户打开文件表的位置记录在进程的 PCB 中，表的长度决定了一个进程能同时打开的文件的最大数量。

表间联系：用户打开文件表指向系统打开文件表；多个进程共享同一文件时，多个用户打开文件表项对应系统打开文件表中的同一入口。

### 为何文件在使用之前需要打开？共享同一文件时 FCB 为何在内存只保持一个副本？

文件被使用时 FCB 中的信息要被频繁访问，每次都去读写外存速度会大幅下降，所以在内存设立系统打开文件表，把 FCB 读进来备用，文件在使用前必须先打开。

内存中只保留一个 FCB 副本有三个好处：节省存储空间；避免多副本一致性维护的困难；减少 I/O 交换次数，提高系统效率。个性化的信息（打开方式、读写指针）则放在各进程自己的用户打开文件表中。

### 用户打开文件表包含哪些内容？为什么不能并入系统打开文件表？

内容是打开方式、读写指针、系统打开文件表入口（文件描述符由表中位置隐含表示）。

不能合并的原因：文件可共享，多个进程可能以不同方式打开同一文件、读写位置也不同。合并后一个共享文件会占多个系统打开文件表目，其中大部分内容重复；而且一个进程修改 FCB 后关闭文件就要写回外存，增加内外存传输次数，还容易导致 FCB 内容不一致。

### 用文件描述符存取打开的文件，比直接用文件名有什么优点？

文件名是字符串，比较和处理速度慢、占空间大，而文件描述符是一个整数，处理效率高得多。文件打开后 FCB 已缓冲在内存的系统空间，文件描述符作为用户打开文件表的入口可以直接与内存中的 FCB 建立联系，文件名做不到这一点。

### 描述创建文件的步骤

1. 为此文件分配一个 FCB 主部并初始化。
2. 把文件名称和文件号作为 FCB 次部，即把目录项填入文件路径名的末级目录。
3. 以写方式打开。

### 描述打开文件的步骤

1. 根据文件路径名查目录找到 FCB 主部。
2. 根据打开方式、共享说明和用户身份检查访问的合法性。
3. 根据文件号查系统打开文件表看该文件是否已被打开：已打开就把共享计数加 1；否则取一个空闲表项，把外存中的 FCB 主部等信息填入，共享计数置 1。
4. 在用户打开文件表中取一个空表项，填写打开方式等，并指向系统打开文件表的对应表项。
5. 返回文件描述符 fd，以后读写文件用它而不用文件名。

### 描述关闭文件的步骤

1. 由 fd 查用户打开文件表，找到系统打开文件表的入口。
2. 系统打开文件表中的共享计数减 1；减完为 0 且修改标志为 1 时，把该文件控制块由内存写回外存的 FCB 主部。
3. 把 fd 对应的用户打开文件表项置为空闲。

### 描述指针定位的步骤

1. 由 fd 查用户打开文件表找到对应入口。
2. 把表中的文件读写指针位置设为 offset，后续读写命令从该指针处存取文件内容。

### 描述读文件的步骤

原文这里给的是伪代码，要点如下（nrd 表示还需读的字节数，buf 是用户缓冲区）：

1. 由 fd 查用户打开文件表找到对应入口。
2. 按表中记录的打开方式和存取方式检查访问的合法性。
3. 查系统打开文件表找到文件的地址。
4. 循环，条件是还有字节要读且没到文件末尾（`offset < size`）：由 offset 和 nrd 算出下一个待访问块的逻辑块号和块内起止位置；按文件的物理结构把逻辑块号换成物理块号；该块已在内存缓冲区时，若有其他进程正在用这个缓冲区就等待，然后把所需部分复制到 buf，相应地调整 offset、nrd 和 buf，释放缓冲区；该块不在缓冲区时，分配缓冲区、填写头部、把它链入设备 I/O 队列，设备空闲就启动设备，等待 I/O 传输结束（这期间发生进程切换），传完后同样复制数据、调整指针、释放缓冲区。
5. 返回实际传输的字节数。

### 描述写文件的步骤

前三步与读文件相同（查用户打开文件表、检查合法性、查系统打开文件表）。第四步循环处理还未写完的 nwt 个字节：

由 offset 和 nwt 算出下一个待访问块的逻辑块号和块内起止位置。若物理块已存在（`offset < 长度`）：本块已有缓冲区时，若其他进程在用就等待；若是整块写就分配缓冲区并填写头部（出），否则分配缓冲区、填写头部（入）、把缓冲区链入设备 I/O 队列，设备不忙就启动设备并等待 I/O 结束（因为要先把原块读进来再改写）。然后把 buf 的内容复制到缓冲区的起止位置，调整头部为"出"，把缓冲区连到设备 I/O 队列，设备空闲就启动，并调整 offset、buf、nwt。

若物理块不存在（写在文件末尾之后）：先分配磁盘块，再分配缓冲区、填写头部、把 buf 内容复制进去、链入 I/O 队列、设备空闲就启动，然后调整 offset、buf、nwt。

### 描述建立连接的步骤

1. 查目录找到文件 `old_name` 的 FCB 主部，由此得到文件号。
2. 查目录找到文件 `new_name` 的末级目录。
3. 把文件号与 `new_name` 中的末级名字合起来构成一个新的目录项，填入 `new_name` 的末级目录文件中。
4. 把 FCB 主部中的连接计数加 1。

### 描述断开连接的步骤

1. 查目录找到文件 `path_name` 的 FCB 主部。
2. 把连接计数减 1。
3. 减完为 0 时归还该文件占用的全部存储块，文件被撤销。
4. 把 FCB 次部从末级目录中清除。

### 对下列文件操作命令，文件管理系统如何检查访问合法性？

打开文件：按打开方式、共享说明和用户身份检查。

读写文件：按用户打开文件表中记录的打开方式和存取方式检查。

删除文件：按共享说明和用户身份检查。

## 文件系统与 FCB

### 何谓文件系统？为何要引入？主要功能有哪些？

文件系统是负责存取和管理文件信息的机构，也就是负责文件的建立、撤销、组织、读写、修改、复制，以及管理目录表、存储介质等资源的那部分软件。

引入它的目的是实现文件的按名存取、让查找简单，并让用户能借助文件存储器灵活存取信息、实现共享和保密。

主要功能五项：有效分配文件存储器的存储空间；提供组织数据的方法（按名存取、逻辑结构）；提供合适的存取方法（顺序存取、随机存取等）；方便用户的服务和操作；提供可靠的保护和保密手段。

### 试说明文件系统中对文件操作的系统调用处理功能

系统调用是操作系统提供给编程人员的接口。用它可以在源程序中动态申请和释放系统资源，调用系统已有的功能来完成与硬件相关的工作。系统调用对使用者屏蔽了具体的操作动作，只提供功能。文件系统相关的系统调用包括创建（create）、打开（open）、读（read）、写（write）、关闭（close）等。

### 试比较文件名、文件号、文件描述符之间的关系

文件名是文件的外部名字，通常是字符串，同一文件可以有多个文件名（例如用 link 命令建立连接）。

文件号是文件的内部名字，通常是整数，与文件一对一。

文件描述符是文件打开时返回的整数，对应用户打开文件表中的一个入口。同一文件可以被多个用户同时打开，返回的描述符一般不同；同一用户多次打开同一文件，每次返回的描述符一般也不同。

采用文件连接技术后：文件名称与文件是多对一，文件号与文件是一对一，文件描述符与文件是多对一。

### 何谓文件连接？如何实现？

连接就是给文件起多个名字，这些名字都是路径名，不同用户可以用不同路径名访问同一文件，从而实现文件共享。

实现靠把 FCB 分成主部和次部，多个次部可以对应同一个主部。例如 UNIX 中的命令是 `link(old_name, new_name)`，执行步骤就是上面"建立连接的步骤"那四步。

### 将文件控制块分为两部分有何好处？目录项包含哪些成分？

两个好处：

1. 提高查找速度。查找文件要把目录从外存按块读入内存逐个比较文件名。一个完整的 FCB 信息多，一个外存块能装下的 FCB 少，查找慢。分成两部分后目录中只保存次部，一块能装更多表项，检索速度大幅提高，目录占的空间也减少了。
2. 实现文件连接。次部只包括一个文件名和一个标识主部的文件号；主部包括除文件名之外的所有信息，以及一个记录该主部对应多少个次部的连接计数。连接计数为 0 表示这是一个空闲未用的 FCB 主部。

目录项就是 FCB 次部，包含文件名和文件号。

## 易混对比

| 物理结构 | 访问速度 | 长度变化 | 主要开销 |
| --- | --- | --- | --- |
| 顺序（连续） | 快 | 难增长 | 外部碎片 |
| 链接（串联） | 随机访问慢 | 容易 | 指针占空间 |
| 索引 | 快 | 容易 | 索引块占内外存，限制最大长度 |
| 散列 | 按键查找快 | 只适合定长记录 | 冲突处理 |

| 对比项 | 系统打开文件表 | 用户打开文件表 |
| --- | --- | --- |
| 数量 | 全系统一张 | 每个进程一张 |
| 位置 | 操作系统空间 | 进程相关，位置记在 PCB 中 |
| 内容 | FCB 主部、文件号、共享计数、修改标志 | 打开方式、读写指针、系统表入口 |
| 长度限制的含义 | 全系统能同时打开的文件数 | 一个进程能同时打开的文件数 |

| 对比项 | 文件名 | 文件号 | 文件描述符 |
| --- | --- | --- | --- |
| 类型 | 字符串 | 整数 | 整数 |
| 与文件的对应 | 多对一 | 一对一 | 多对一 |
| 何时使用 | 打开、连接 | 系统内部标识 | 打开之后的读写 |
