## 名词解释

地址映射：把逻辑地址转为物理地址的过程。

存储管理部件 MMU：完成地址映射的硬件机构。

物理地址：存储器以字节为单位存储信息，每个字节单元有唯一的存储器地址，称为物理地址（Physical Address），又叫实际地址或绝对地址。

重定位：把程序的逻辑地址空间变换成内存中实际物理地址空间的过程。

可重定位程序：采用交换技术时，被换出的进程再次运行前必须重新换入内存，换入位置通常与换出前不同，这就要求程序编址与内存存放位置无关，这种程序称为可重定位程序。

纯代码：运行过程中不修改自身的代码。（更正：原文作"不修改自身发代码"。）

地址越界：进程运行时产生的地址在其地址空间之外。

操作越权：进程对共享区域的访问违反了权限规定。（更正：原文的词条名写成"操作越界"，但解释的是越权，教材中这个概念叫操作越权。）

存储扩充：把内存空间与外存空间结合在一起，形成一个容量相当于外存而速度接近于内存的虚拟存储系统。

页面：静态等长分区分配中，存储空间被静态划分成若干长度相等的区域，每个区域长 B，称为一个页面（或页）。

碎片：动态异长分区存储分配中形成的、很小以至以后无法利用的空闲区域。

紧凑：移动占用区域，使所有空闲区域连成一片。

对界：单一连续区存储管理中，一个进程在内存空间的地址由进程起始地址和长度两个参数决定，称为一个对界。

双对界：允许一个进程在内存中占有两个连续的区域。

交换：又称换入换出或滚入滚出，指进程在内存空间与外存空间之间的动态调度，是缓解内存空间使用矛盾的有效方法。

命中率：访问页号在快表中的次数与总访问次数之比。

快表可达：通过快表地址映射可以覆盖的内存范围。

## 存储管理的任务与分区方法

### 存储管理的基本任务是什么？

原文给了两种答法，都要会。

按功能分五项：存储分配、存储共享、存储保护、存储扩充、地址映射。

按另一种说法分四项：管理内存空间；进行虚拟地址（逻辑地址）到物理地址的转换；实现内存的逻辑扩充；完成内存信息的共享和保护。

### 存储管理的主要功能是什么？

解决多道作业的主存空间分配问题，包括三方面：内存区域的分配和管理（设计分配结构和调入策略，保证分配和回收）；内存的扩充技术（用虚拟存储或自动覆盖技术提供比实际内存更大的空间）；内存的共享和保护技术（除允许共享的部分外，作业之间不能相互干扰和破坏）。

### 内存有哪些分区方法？实际系统中一般怎么分区？

按划分时机分静态分区与动态分区。静态分区在系统运行之前就把内存划分成若干区域，分配给进程的区域可能比它实际需要的长；动态分区在系统运行过程中划分，可以按进程所需空间大小分配恰好满足要求的一个或多个区域。

按长度分等长分区与异长分区。等长分区把存储空间划分成若干长度相同的区域，异长分区划分成若干长度不同的区域。

实际系统中，静态分区与等长分区结合成静态等长分区（页式、段页式用），动态分区与异长分区结合成动态异长分区（界地址、段式用）。

### 静态等长分区的分配算法有哪些？各有什么特点？

常用于页式和段页式存储管理。三种办法：

位图（bitmap）：用 1 位代表一个页面的状态，0 表示空闲，1 表示被占用。

空闲页表（free page table）：有首页号和页数两个栏目，若干连续空闲页作为一组登记在表中。这种方法能让一个进程的若干页面尽量连续。

空闲页链（idle page link）：把所有空闲页面连成一条链，分配时取链头的页，去配时把释放的页连入链头。适用于内存页面的分配，但用于外存页面时分配和去配各需要一次数据传输，速度较慢。

### 为什么空闲页链不适合管理外存？

外存要分配多个空闲块时，先读取 head 指向的第一个空闲块，再分配下一块时必须把当前空闲块的内容读到内存才能找到第二块的地址，需要多次访问外存，速度慢。

### 动态异长分区的分配算法有哪些？

用于界地址存储管理和段式存储管理。系统中需要一张空闲区域表，记录当前所有未被占用的空闲区域。分配算法有 FF、NF、BF、WF 四种。

最先适应算法 FF：对每个存储申请，选取满足长度要求且起始地址最小的空闲区。实现时把所有空闲区按起始地址由小到大记录在空闲区域表中，申请时从表头查找，选第一个满足要求的表目。区域长度恰好相等就全部分配，否则分割成两部分，一部分给申请者，另一部分留在表中。优点是尽量使用低地址空间，高地址空间可能形成较大的空闲区，较大的请求有望在高地址得到满足。缺点是可能分割较大的空闲区。

下次适应算法 NF：从上次分配的空闲区的下一个位置开始，选第一个可满足的空闲区。实现时设一个循环查找指针，开始时指向表头，每次从指针处开始查找（查到表尾就回到表头），分配后把指针调整为所分配区域的下一个区域。优点是空闲区分布和分配更均匀，缺点是可能分割大的空闲区。

最佳适应算法 BF：取满足申请要求且长度最小的空闲区。实现时把空闲区按长度由小到大记录，从表头查找选第一个满足条件的表目。优点是尽量不分割大的空闲区，缺点是容易形成碎片。

最坏适应算法 WF：取满足申请要求且长度最大的空闲区。实现时把空闲区按长度由大到小记录，从表头查找选第一个满足条件的表目。优点是可以避免形成碎片，缺点是分割了大的空闲区，遇到较长的申请时无法满足的可能性较大。

四者的共同点是都要维护空闲区域表、都要处理区域分割与合并；区别在于表的排序方式和查找起点，进而决定了碎片和大区保留的不同倾向。（原文这道"简述四种算法异同点"的题只写了"根据上面的回答总结"，这句是按前面四段归纳的。）

### 什么是紧凑？

移动内存中已占用的区域，使所有空闲区域连成一片，用来解决碎片问题。代价是移动数据需要时间，而且要求程序可动态重定位。

## 连续分配与覆盖交换

### 介绍一下单一连续区存储管理

单一连续区（single contiguous region）存储管理又称单对界存储管理。一个进程在内存中的位置由起始地址和长度两个参数决定，称为一个对界。内存空间采用动态异长分区方法。

进程空间是连续的：设进程长度为 l，则逻辑地址为 0 到 l-1；若它在内存中的起始地址为 b，则物理地址范围是 b 到 b+l-1。

需要两张表：内存分配表（记录已分配区域，有时可省略，此时各分配区域登记在占有进程的 PCB 中）和空闲区域表（记录尚未分配的区域）。

硬件应提供两个寄存器（整个系统各一个）：首址寄存器保存正在运行进程的起始地址，限长寄存器保存正在运行进程的长度。

### 单对界存储管理中地址映射的步骤

1. 由程序产生逻辑地址 a。
2. 把 a 与限长寄存器的内容 l 比较，判断是否满足 $0 \le a < l$；不满足就是越界，发生越界中断。
3. 把 a 与首址寄存器的内容 b 相加，得到物理地址 b + a。

### 什么是双对界？与单对界的区别？如何实现？

单对界限制一个进程在内存中只占一个连续区域，双对界允许占两个连续区域，一个放代码，另一个放数据。代码区可以被多个进程共享，数据区为进程独享。

实现时硬件要提供两对寄存器：代码区首址寄存器和限长寄存器、数据区首址寄存器和限长寄存器。取指令时硬件用前一组，取数据时用后一组。

### 内存的覆盖和交换技术有什么区别？

交换又称换入换出或滚入滚出，指进程在内存与外存之间的动态调度，用来缓解内存空间紧张。

覆盖是把较大程序装入较小进程空间的技术：只把全局代码和数据静态放在内存，其他部分分阶段动态装入，后装入的对象重复使用以前对象占用的空间，这些动态装入的成分也称覆盖。

区别有三条：交换由操作系统自动完成，不需要用户参与，覆盖需要程序员给出各部分之间的覆盖结构并了解系统的存储结构；交换主要在不同作业之间进行，覆盖主要在同一作业内部进行；覆盖主要用于早期系统，交换在现代操作系统中仍在使用。

### 举例解释覆盖技术

原文用的例子是一个包括 4 遍扫描的编译程序。它运行时既可以对应 4 个进程，也可以通过覆盖由一个进程完成：把符号表、公共例程等公共数据作为共享成分静态分配空间，4 遍扫描的程序段则动态装入同一块覆盖区，每遍扫描结束时转到覆盖驱动程序装入下一遍扫描的代码。覆盖区的长度按最大的那一遍扫描来定，原文图中 4 遍扫描分别是 30 KB、50 KB、40 KB、25 KB，覆盖区取 50 KB。

## 页式存储管理

### 介绍页式存储管理

页式（Paging，也称分页）存储管理允许一个进程占有内存空间中的多个连续区域，这些区域长度相同，采用静态等长存储分配方法，不会产生碎片。

内存空间被静态划分成若干等长区域，每个区域称为一个物理页框。每个页框有 $2^i$ 个单元（i 为正整数），由 0 开始依次编址，称为页内地址。设内存容量为 $2^n$ B，则共有 $2^{n-i}$ 个页框，由 0 开始依次编号，称为页框号，第 k 个页框的首址是 $k \times 2^i$。把页框号作为高位、页内地址作为低位，就得到物理地址。

进程空间同样被静态划分成等长的逻辑页面，页面长度与页框相同。逻辑地址 = 逻辑页号 $\times 2^i$ + 页内地址，写成二进制时高 n-i 位是逻辑页号、低 i 位是页内地址。

进程的逻辑页面是连续的，但它们对应的页框不一定连续。

需要两张表：页表记录进程的逻辑页面与内存页框之间的对应关系；总页表记录页框的使用情况。

需要的寄存器：页表首址寄存器、页表长度寄存器、一组联想寄存器（快表）。

### 页式存储管理中地址映射的步骤

地址映射把逻辑地址 (p, d) 转换成物理地址 (f, d)，其中 p 是逻辑页号，d 是页内地址，f 是页框号。

1. 由指令产生逻辑地址 (p, d)。
2. 用 p 查快表。查到就直接得到页框号 f，与 d 合并成物理地址。
3. 查不到时，先把 p 与页表长度寄存器的内容 l 比较，判断是否满足 $0 \le p < l$，不满足则越界中断；再用页表首址寄存器的内容 b 查内存页表得到 f；把 f 与 d 合并得到物理地址；最后把 (p, f) 送入快表，快表已满就按置换算法淘汰一项。

### 多执行流进程中每个线程都要一个逻辑上连续且可伸缩的目态栈，怎么实现？

系统为每个线程分配充足的逻辑页面，但物理上只给真正用到的那些逻辑页面分配页框。实现时在页表中增加一个有效位：为 1 表示有对应页框，为 0 表示尚未分配。访问有效位为 0 的逻辑页面时触发物理页框的动态分配。

### 允许逻辑页号不连续带来的好处是什么？

可以给同一进程内的多个线程预留足够的堆栈空间，同时不浪费实际的内存页框。

### 为何引入多级页表？多级页表是否影响指令执行速度？

早期内存和进程空间都小，页表也小，可以在内存中分配一块连续区域存放。随着空间增长，单级页表难以存放。例如逻辑地址空间长度为 $2^{32}$、页面长度为 $2^{12}$（4 KB）时，一个进程最多有 $2^{20}$ 个页面，需要长度为 $2^{20}$ 的连续页表存储区，这很困难。于是把页表分级存放，把 $2^{20}$ 拆成 $2^{10} \times 2^{10}$ 两级，一级叫外页表、一级叫内页表，两者长度都在 $2^{10}$ 以内。二级页表可以自然地扩展为多级页表。

多级页表会降低地址映射速度，但靠快表仍能把效率保持在合理范围内。原文的例子：四级页表，快表命中率 98%，快表与内存访问时间分别为 20 ns 和 100 ns，

$$EAT = 98\% \times (20 + 100) + 2\% \times (20 + 500) = 128\ \text{ns}$$

额外开销是 128 - 100 = 28 ns。（式中 500 ns 是未命中时访问四级页表加访问数据共 5 次内存的时间。这个算式核对无误。）

### 什么是反置页表（倒置页表）？与传统页表的差别？有什么问题？怎么解决？

传统页表面向进程的虚拟空间，为进程的每个逻辑页面设一个表项，进程地址空间很大时页表要占很多空间。反置页表面向内存物理页框，为每个物理页框设一个表项，表项序号就是页框号 f，内容是进程标识 pid 与逻辑页号 p 的有序对。系统只需一张反置页表，所有进程共用。

明显问题是速度：顺序搜索反置页表需要多次访问内存，对不存在的页甚至要查到表尾。

解决办法是用杂凑（hash）技术，并在反置页表中增加冲突计数和空闲标志。地址映射时由 `hash(pid, p)` 算出反置页表的入口地址，从该入口向下探查找到对应表项，表项的位移 f 就是页框号。

## 段式与段页式存储管理

### 介绍段式存储管理

内存空间被动态划分成若干长度各异的区域，每个区域称为一个物理段。物理段在内存中的起始地址称为段首址，段内单元由 0 开始编址称为段内地址；长度为 m 的段，段内地址是 0 到 m-1。

进程空间被静态划分成若干长度各异的逻辑段，段内同样从 0 开始编址。每个逻辑段有一个段名，进程的所有逻辑段由 0 开始依次编号，称为段号；由 l 个逻辑段构成的进程，段号是 0 到 l-1。

源程序中使用段名，编译（汇编）、连接后段名被转换成段号，操作系统以段号区分进程的各个逻辑段。

地址的三种形式：源程序中的地址由段名和段内入口名构成，是二维的，称为程序地址；编译后的地址由段号和段内地址构成，也是二维的，称为逻辑地址；地址映射后只剩一维，即段首址与段内地址之和，就是物理地址。

进程的一个逻辑段对应内存的一个物理段。多个逻辑段可以存放在内存中若干个不相连的物理段里，段内地址连续，段与段之间可以不连续。

需要的表目：段表（记录段号与段首址、段长之间的关系）、空闲表（记录并管理内存中的空闲区域）。

硬件通常提供三组寄存器：段表首址寄存器、段表长度寄存器、一组联想寄存器（快表，保存当前正在访问的段所对应的段表项）。

### 段式存储管理中地址映射的过程

把逻辑地址 (s, d) 转换成物理地址，其中 s 是段号，d 是段内地址，b' 是段的起始地址。s 或 d 越界时地址映射没有意义。

1. 由指令产生逻辑地址 (s, d)。
2. 用 s 查快表得到段首址 b' 和段长 l'。查不到时，先把 s 与段表长度寄存器的内容 l 比较，判断是否满足 $0 \le s < l$，不满足则越界中断；再用段表首址寄存器的内容 b 查内存段表得到段首址和段长；然后把 (s, b', l') 送入快表，快表已满就按置换算法淘汰一项。
3. 把段内地址 d 与段长 l' 比较，判断是否满足 $0 \le d < l'$，不满足则越界中断。
4. 段首址 b' 与段内地址 d 相加，得到物理地址 b' + d。

### 简述什么是段的共享

一个进程的段号是连续的，段与段之间不一定连续。如果某进程的一个段与另一进程的一个段对应同一个段首址和段长，就实现了段的共享。

### 为什么分段技术比分页技术更容易实现共享？

每一段在逻辑上是相对完整的一组信息，共享发生在段这一级，任何要共享的信息都可以单独做成一个段，段中所有内容用相同的方式使用，可以规定相同的权限。

页是信息的物理单位，一个页面中可能有逻辑上互相独立的两组或更多组信息，它们各有不同的使用方式和存取权限，所以分页不便于共享。

### 共享段表的用途是什么？

两个用途：用来寻找共享段，进程首次访问某段时按段名在共享段表中查找，就知道该段是否已在内存；确保一个共享段只有一组描述信息，共享段的地址、长度等信息在共享段表中只记录一次，避免在多个进程的段表中重复登记带来的维护困难。

### 试举例说明段长动态增长的实际意义

对那些需要不断增加或改变数据、子程序的段很有好处。例如分配给进程的栈空间大小通常事先无法准确估计，分配过少可能不够用，分配过多会造成浪费。段可以动态增长时，系统开始只分配一个基本长度的栈空间，浪费很小；进程运行时发生栈溢出，通过中断进行动态扩展。

### 段式存储管理中，段的长度可否大于内存的长度？段页式呢？

段式中不能。一个独立的段要占用一段连续的内存空间，内存分配以段为单位，段长大于内存长度时无法调入内存。

段页式中可以。内存分配的单位是页，段内逻辑上连续的页面可以分配到不连续的内存页框中，也不要求一个段的所有逻辑页面都进入内存。

### 具有二级页表的页式存储管理与段页式存储管理有何差别？

具有二级页表的页式存储管理地址空间仍是一维的，两级页的划分对进程都是透明的。段页式的地址空间是二维的，段的划分用户能感觉到。

### 各种存储管理方式中进程空间怎么编址？

界地址方式：进程空间的首地址从 0 开始编址。页式：进程空间的首地址从 0 开始编址。段式：进程空间各段的首地址都从 0 开始编址。段页式：进程空间各段的起始地址都从 0 开始编址。

### 页式、段式、段页式各有哪些越界检查？

页式：逻辑地址形式为 (p, d)，逻辑页号 p 可能越界，意味着访问不存在的页面，检查要求是 $0 \le p \le l-1$，l 为页表长度寄存器的内容。页内地址 d 不必检查，因为它的位数固定，写不出超过页长的值。

段式：逻辑地址形式为 (s, d)，s 和 d 都可能越界，s 越界意味着访问不存在的段，d 越界意味着访问段内不存在的单元，检查要求是 $0 \le s \le l-1$ 且 $0 \le d \le l'-1$，l 为段表长度寄存器的内容，l' 为段表或快表中段长的内容。

段页式：逻辑地址形式为 (s, p, d)，段号 s 和段内逻辑页号 p 可能越界，检查要求是 $0 \le s \le l-1$ 且 $0 \le p \le l'-1$，l 为段表长度寄存器的内容，l' 为段表中页表长度的内容。

### 各种管理方式下进程地址空间是几维的？分页分段对用户是否可见？

页式是一维的，分页对用户透明，一个进程由若干等长的页构成。

段式是二维的，分段对用户可见，一个进程由若干长度可以不同的段构成，一个段恰好对应一个程序单位。

段页式是二维的，段的划分对用户可见，段内页的划分对用户透明，一个段由若干等长的页构成。

### 界地址存储管理与页式存储管理的异同

界地址方式要求一个进程占有内存中的一个连续区域，采用动态异长存储分配，可能产生碎片。页式允许一个进程占有内存中的多个等长连续区域，采用静态等长存储分配，不会产生碎片。

### 试比较段式与页式存储管理的优缺点

页式：静态等长存储分配简单，有效解决了内存碎片问题；共享和保护不够方便。

段式：动态异长存储分配复杂，存在碎片问题；共享与保护方便；可以实现动态连接和动态扩展。

### 页式与段式的异同点（完整版）

相同点是两者都是为进程分配内存空间的存储管理方式。不同点有五条：

1. 分页对用户透明，所有页长度相同；分段对用户可见，各段长度可以不同，一个段对应一个程序单位。
2. 分页出于系统管理的需要，分段出于用户应用的需要。一条指令或一个操作数可能跨越两个页的分界处，但不会跨越两个段的分界处。
3. 页大小由系统固定，段大小通常不固定。
4. 分页的逻辑地址是一维的，各模块链接时必须组织成同一个地址空间；分段是二维的，各模块链接时可以每段组织成一个地址空间。
5. 段通常比页大，段表比页表短，查找时间更短。

## 地址重定位与调页策略

### 解释地址空间、存储空间、逻辑地址、物理地址、虚地址、实地址、地址重定位

地址空间：目标程序所在的空间，即程序员用来访问信息的一系列地址单元的集合。存储空间：主存中一系列存储信息的物理单元的集合。

逻辑地址：用户程序经编译后，每个目标模块以 0 为基地址进行的顺序编址，又称相对地址。物理地址：内存中各物理存储单元的地址从统一的基地址进行的顺序编址，又称绝对地址，是数据在内存中的实际存储地址。

虚地址同逻辑地址，实地址同物理地址。

地址重定位：把逻辑地址转变为物理地址的过程。按重定位时机分静态重定位（装入内存时重定位）和动态重定位（程序执行时重定位）。

### 举例说明地址重定位

作业 J 的逻辑地址空间是 0 到 1 KB，分配给它的物理存储空间是 2 KB 到 3 KB。指令 `LOAD 1,500` 装入内存时必须做地址变换，实际执行的是 `LOAD 1,500+2K`，即访问物理地址 2548。

### 何谓请调？何谓预调？为何预调系统中必须辅以请调？

请调是在页故障发生时才调度，即被访问页面不在内存时由动态调页系统把它调入。纯请调策略下，调入内存的页面一定会被用到，不会发生无意义的调度。缺点是从缺页中断发生到页面调入内存这段时间进程必须等待，影响推进速度。

预调也称先行调度，在页故障发生前调度，即一个页面即将被访问之前就把它调入。预调能节省进程因页故障而等待的时间，降低页故障率。它通常根据程序的顺序行为做出判断：进程当前正访问第 12 页，接下来很可能访问第 13、14 页，于是提前调入。

预调不可能百分之百准确。程序中有转移语句，第 13 页用完后可能要访问第 10 页，而它不在内存中。也就是说预先调入的页面可能用不到，没调入的页面可能被用到，访问到未预先调入的页面时仍会发生缺页中断。所以采用预调的系统必须辅以请调。另外预调的实现开销也比较大。
