# 05 死锁与饥饿

整理自 `名词解释.pdf` 第 5 页和 `简答题.pdf` 第 38 至 41 页（原文第五章）。

## 本章要点

四个必要条件要能背下来并会逐条对应到预防策略：破坏"保持申请"对应预先分配，破坏"循环等待"对应有序分配。死锁与饥饿的区别是简答题常客，抓住四点差别（进程状态、等的是什么资源、是否有循环等待、涉及几个进程）。银行家算法属于死锁避免，不是死锁预防，选择题经常在这里设坑。

## 名词解释

死锁：一组进程中的每个进程都在等待此组进程中其他进程所占有的、因而永远无法得到的资源，这种现象称为进程死锁，简称死锁。

无限延迟：资源分配策略不公平时不能保证等待时间上界的存在。这种情况下即使系统没有发生死锁，某些进程也可能长时间等待，即无限延迟。

饿死：等待时间给进程的推进和响应带来明显影响时，称发生进程饥饿；当饥饿到一定程度、进程所承担的任务即使完成也不再有实际意义时，称该进程被饿死。

## 简答题

### 死锁有哪几种类型？

竞争资源引起的死锁、进程间通信引起的死锁、其他原因引起的死锁。

### 简述死锁的条件

1. 资源独占：一个资源同一时刻只能分配给一个进程。某进程申请的资源正被另一进程占有时，申请者需要等待，直到占有者释放。
2. 不可剥夺：申请者不能强行从占有者手中夺取资源，资源只能由占有者用完后自愿释放。
3. 保持申请：进程占有部分资源后还可以申请新资源，申请新资源时并不释放已占有的资源。
4. 循环等待：存在一个进程等待序列 {p1, p2, …, pn}，其中 p1 等待 p2 占有的某资源，p2 等待 p3 占有的某资源，……，pn 等待 p1 占有的某资源。

### 不让死锁发生的策略有哪些？

分两种。静态的称为死锁预防，指对进程的资源活动按某种协议加以限制，所有进程都遵守协议就不会发生死锁。动态的称为死锁避免，指对进程的资源申请命令做实时检测，拒绝不安全的请求，保证死锁不会发生。

### 常见的死锁预防策略有哪些？各有什么缺点？

预先分配策略：进程在运行前一次性申请它所需要的全部资源。系统当前不能满足全部请求时就不分配，该进程暂不投入运行；能满足时一次性把资源全部分配给它。缺点有两条：资源利用率低；进程在运行前可能并不知道自己需要的全部资源。

有序分配策略：事先把所有资源类完全排序，给每个资源类一个唯一的整数编号。进程必须按编号由小到大的次序申请资源：不占有任何资源时可以申请某资源类 ri 中的任意多个实例，此后能再申请另一资源类 rj 中实例的充分必要条件是 $f(r_i) < f(r_j)$。有序分配不会发生死锁。缺点有四条：给资源类合理编号比较困难；按编号申请增加了进程的负担；若有进程违反规定仍可能死锁；为保证申请次序，暂时不需要的资源也要提前申请，增加了资源占有时间。

### 为什么按资源号递增的顺序申请资源就不会死锁？

因为循环等待这个必要条件不可能成立。多个进程之间只可能出现"占据较低序号资源的进程等待占据较高序号资源的进程释放资源"，不可能出现反向的等待，所以形不成循环等待链。

### 简述饿死与死锁的联系与区别

联系：都是由竞争资源引起的。

区别有四点：

1. 从进程状态看，死锁进程都处于等待态；忙式等待的进程处于运行态或就绪态，并不处于等待态，却有可能被饿死。
2. 死锁进程等待的是永远不会被释放的资源；饿死进程等待的资源会被释放，只是不会分配给自己，等待时限没有上界（排队等待或忙式等待都算）。
3. 死锁一定发生了循环等待，饿死不一定。所以资源分配图能检测死锁，却不能检测饿死。
4. 死锁一定涉及多个进程，饥饿或被饿死的进程可能只有一个。

### 什么叫饥饿？什么叫饿死？什么叫活锁？

动态系统中资源请求与释放经常发生。对每类资源，操作系统要确定一个分配策略，决定多个进程同时申请时的分配次序。分配策略可能是公平的，能保证请求者在有限时间内获得资源；也可能是不公平的，不能保证等待时间上界存在。后一种情况下，即使没有死锁，某些进程也可能长时间等待。等待时间对进程推进和响应带来明显影响时，称发生了进程饥饿（starvation）；饥饿到任务即使完成也不再有实际意义时，称该进程被饿死（starve to death）。

例子：多个进程要打印文件，系统按短文件优先排序，平均等待时间短，看上去合理，但短文件打印任务源源不断时，长文件任务会被无限期推迟，导致饥饿乃至饿死。

活锁（live lock）：在忙式等待条件下发生的饥饿。例如不公平的互斥算法。

### 饥饿进程可能处于什么状态？

忙式等待的饥饿进程处于就绪或运行状态，例如改进之前的 `test_and_set` 互斥算法。排队等待的饥饿进程处于等待状态，例如用经典信号量和 PV 操作实现的带优先级的 PP 操作与 VV 操作。

### 下面关于死锁的叙述哪些正确？

1. "参与死锁的所有进程都占有资源"：错误。正确的说法是参与死锁的所有进程都在等待资源。
2. "参与死锁的所有进程中至少有两个进程占有资源"：正确，参与死锁的进程至少有两个。
3. "死锁只发生在无关进程之间"：错误，死锁也可能发生在相关进程之间。
4. "死锁可以发生在任意进程之间"：正确，相关进程和无关进程之间都可能发生。

### 进程是否会因为竞争处理器资源而发生死锁？

不会。处理器资源是可剥夺的。参与死锁的进程都处于等待状态，这种等待不包括对处理器的等待，等待处理器的进程处于就绪状态。

### 何谓银行家算法的保守性？

银行家算法只知道每个进程需要资源的最大量，具体的申请和释放顺序仍然未知，所以只能往最坏处设想。

### 能否给出避免死锁的充要性算法？

目前的避免死锁算法（如银行家算法）是充分性算法，确保系统时刻处于安全状态。在只知道每个进程资源最大需求量的条件下，这已经是最好的结果。

如果不仅知道最大需求量，还知道进程的资源活动序列，在这个更强的条件下可以给出充要性算法，但复杂度很高（NP 完全）。而且程序中有分支和循环，事先给出进程的资源命令序列一般不可能。

### 哲学家就餐问题中既有左撇子又有右撇子，是否有死锁？是否有饥饿？

右撇子饥饿时先取右边叉子再取左边，左撇子先取左边再取右边。

没有死锁，因为破坏了循环等待条件。

没有饥饿：把叉子作为资源、用初值为 1 的信号量管理，申请时执行 P 操作、释放时执行 V 操作，饥饿的进程终究能拿到左右两把叉子并进食。

## 易混对比

| 对比项 | 死锁 | 饥饿（饿死） |
| --- | --- | --- |
| 进程状态 | 都在等待态 | 可能在就绪态或运行态（忙式等待） |
| 等的资源 | 永远不会释放 | 会释放，但轮不到自己 |
| 循环等待 | 一定有 | 不一定有 |
| 涉及进程数 | 至少两个 | 可能只有一个 |
| 能否用资源分配图检测 | 能 | 不能 |

| 策略 | 属于 | 做法 | 破坏的条件 |
| --- | --- | --- | --- |
| 预先分配 | 死锁预防 | 运行前一次性申请全部资源 | 保持申请 |
| 有序分配 | 死锁预防 | 按资源编号递增申请 | 循环等待 |
| 银行家算法 | 死锁避免 | 实时检测，拒绝不安全请求 | 不破坏任何条件，靠安全状态判断 |
