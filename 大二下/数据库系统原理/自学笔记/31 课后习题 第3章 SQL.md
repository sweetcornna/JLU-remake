## 习题

### 3.1 university 模式上的基本查询

题目：在 university 模式上用 SQL 写出下列查询：

- a. 找出计算机系（Comp. Sci.）学分为 3 的课程名。
- b. 找出上过名叫 Einstein 的教师所讲课程的所有学生的 ID，结果不能有重复。
- c. 找出教师的最高工资。
- d. 找出工资最高的所有教师（可能不止一位）。
- e. 找出 2009 年秋季（Autumn）开设的每个课程段的选课人数。
- f. 找出 2009 年秋季所有课程段中最大的选课人数。
- g. 找出 2009 年秋季选课人数最多的课程段。

思路：

- b：`takes` 和 `teaches` 要按课程段的四个属性 `(course_id, sec_id, semester, year)` 对上，再连 `instructor` 按名字筛选，最后 `distinct`。
- d：用标量子查询求出最高工资再比较。
- e 到 g：先按课程段分组计数，再对计数结果求最大值。中间结果放进 `from` 子查询或 `with` 子句。

解答：

a.

```sql
select title
from course
where dept_name = 'Comp. Sci.' and credits = 3;
```

b.

```sql
select distinct takes.ID
from takes, teaches, instructor
where takes.course_id = teaches.course_id
  and takes.sec_id = teaches.sec_id
  and takes.semester = teaches.semester
  and takes.year = teaches.year
  and teaches.ID = instructor.ID
  and instructor.name = 'Einstein';
```

官方答案用的是 `join ... using` 的写法，效果相同：

```sql
select distinct student.ID
from (student join takes using (ID))
     join (instructor join teaches using (ID))
     using (course_id, sec_id, semester, year)
where instructor.name = 'Einstein';
```

外层只能 `using` 课程段的四个属性。如果全改成 `natural join`，学生的 `ID` 会和教师的 `ID` 被当成同一属性做等值比较，结果就错了。（更正：官方答案在文字说明里把连接属性写成 `section_id`，应为 `sec_id`。）

c.

```sql
select max(salary)
from instructor;
```

d.

```sql
select ID, name
from instructor
where salary = (select max(salary) from instructor);
```

e.

```sql
select course_id, sec_id, count(ID) as enrollment
from section natural join takes
where semester = 'Autumn' and year = 2009
group by course_id, sec_id;
```

`section` 和 `takes` 的公共属性正好是课程段的四个属性，自然连接没有问题；学期和年份已经在 `where` 里固定，分组只需要 `course_id, sec_id`。没人选的课程段不会出现在结果中。想让它显示为 0，可以把 `natural join` 换成第 4 章的 `natural left outer join`，或者在 `select` 子句里用标量子查询：

```sql
select course_id, sec_id,
       (select count(ID)
        from takes
        where takes.course_id = section.course_id
          and takes.sec_id = section.sec_id
          and takes.semester = section.semester
          and takes.year = section.year) as enrollment
from section
where semester = 'Autumn' and year = 2009;
```

子查询没有匹配行时 `count` 返回 0。（更正：官方答案这个子查询的最后一个条件写作 `takes.section_id = section.section_id`，两个关系里都没有 `section_id`，应为 `sec_id`。）

f.

```sql
select max(enrollment)
from (select count(ID) as enrollment
      from section natural join takes
      where semester = 'Autumn' and year = 2009
      group by course_id, sec_id) as T;
```

（更正：官方答案 `from` 子句里的子查询没有别名。MySQL、SQL Server 以及 PostgreSQL 16 之前的版本都要求派生表必须命名，这里补上 `as T`；Oracle 不接受表别名前的 `as`，写成 `) T`。）

如果当学期没有任何课程段有人选，内层结果为空，`max` 返回一行 null，不是 0。（更正：官方答案说这时结果为空，实际上不带 `group by` 的聚集在没有输入行时仍返回一行。）要得到 0，可以对 e 中带标量子查询的写法求最大值。

g.

```sql
with sec_enrollment as (
    select course_id, sec_id, count(ID) as enrollment
    from section natural join takes
    where semester = 'Autumn' and year = 2009
    group by course_id, sec_id)
select course_id, sec_id
from sec_enrollment
where enrollment = (select max(enrollment) from sec_enrollment);
```

不用 `with` 也能写，只是求各段人数的子查询要重复写两次。

### 3.2 用 `grade_points` 计算绩点

题目：给定关系 `grade_points(grade, points)`，把 `takes` 中的字母成绩换成分数，例如 A 为 4 分、A- 为 3.7、B+ 为 3.3、B 为 3。学生在一个课程段上获得的绩点等于该课程的学分乘以成绩对应的分数。假设 `takes` 中没有 `grade` 为空的元组，用 SQL 写出：

- a. ID 为 12345 的学生所修全部课程的总绩点。
- b. 这个学生的平均绩点 GPA，即总绩点除以这些课程的总学分。
- c. 每个学生的 ID 和 GPA。

思路：`takes` 连 `course` 拿到学分，再连 `grade_points` 拿到分数，然后 `sum(credits * points)`。c 按 `ID` 分组。难点在于没选过课的学生怎么处理，要分清"带不带 `group by`"两种情况下聚集对空输入的行为。

解答：

a.

```sql
select sum(credits * points)
from (takes natural join course) natural join grade_points
where ID = '12345';
```

`takes` 与 `course` 的公共属性只有 `course_id`，再与 `grade_points` 按 `grade` 连接，没有意外的同名属性。

学生一门课都没选时，希望得到 0。官方答案的办法是再 `union` 一个查询：当 `takes` 中没有这个学生的记录时，从 `student` 返回常量 0。

（更正：官方答案补充的查询写作 `select 0 from student where takes.ID = '12345' and not exists (...)`，外层 `from` 里只有 `student`，引用 `takes.ID` 会报错，应为 `student.ID`。改过之后仍有问题：不带 `group by` 的聚集在没有输入行时照样返回一行，`sum` 的值是 null，所以前半个查询返回 null，`union` 之后结果是 null 和 0 两行。）直接用 `coalesce` 更简单：

```sql
select coalesce(sum(credits * points), 0)
from (takes natural join course) natural join grade_points
where ID = '12345';
```

b.

```sql
select sum(credits * points) / sum(credits) as GPA
from (takes natural join course) natural join grade_points
where ID = '12345';
```

学生没选过课时，GPA 只能合理地定义为 null。官方答案担心此时总学分为 0 会除零，又补了一个 `union select null as GPA from student where ...` 的查询。（更正：补充的查询同样把 `student.ID` 误写成 `takes.ID`。另外没有输入行时 `sum(credits)` 是 null 而不是 0，上面的查询本来就返回一行 null，不会除零，不需要再补 `union`。）

c.

```sql
select ID, sum(credits * points) / sum(credits) as GPA
from (takes natural join course) natural join grade_points
group by ID
union
select ID, null
from student
where not exists (select *
                  from takes
                  where takes.ID = student.ID);
```

带 `group by` 时，没选课的学生形成不了分组，结果里根本没有他，所以这里确实需要 `union` 把他们补上，GPA 记为 null。4.5 题还会讨论成绩为空的情况。

### 3.4 插入、删除和更新

题目：在 university 模式上用 SQL 完成：

- a. 计算机系每位教师工资上涨 10%。
- b. 删除所有从未开设过的课程（即在 `section` 中没有出现的课程）。
- c. 把 `tot_cred` 大于 100 的每个学生插入为同系的教师，工资 10000 美元。

思路：b 用 `not in` 子查询找出没开过的课；c 用 `insert into ... select`，`select` 出来的列要和 `instructor(ID, name, dept_name, salary)` 的顺序一致。

解答：

```sql
update instructor
set salary = salary * 1.10
where dept_name = 'Comp. Sci.';
```

```sql
delete from course
where course_id not in (select course_id from section);
```

```sql
insert into instructor
select ID, name, dept_name, 10000
from student
where tot_cred > 100;
```

b 里用 `not in` 时要留意：子查询结果中只要有一个 null，`not in` 的判断就会变成 unknown，一行也删不掉。`section.course_id` 是主码的一部分，不会为空，这里没问题。

### 3.5 保险公司数据库

题目：保险公司数据库的模式如下（注释里是主码，`accident` 在原图中 `report_number` 和 `date` 都有下划线）：

```text
person       (driver_id, name, address)                   -- driver_id
car          (license, model, year)                       -- license
accident     (report_number, date, location)              -- report_number, date
owns         (driver_id, license)                         -- driver_id, license
participated (driver_id, car, report_number, damage_amount) -- driver_id, car, report_number
```

用 SQL 写出：

- a. 找出 1989 年其汽车出过事故的人的总数。
- b. 向数据库添加一起新事故，所需属性值自行假设。
- c. 删除 John Smith 名下的 Mazda 汽车。

思路：`participated` 把驾驶人、汽车和事故联系在一起。a 统计的是人数，一个人出了几次事故都只算一次，要用 `count(distinct ...)`。b 要同时插入 `accident` 和 `participated`。c 先通过 `owns` 找到 John Smith 的车牌，再删除其中型号为 Mazda 的车。

解答：

a.

```sql
select count(distinct person.driver_id)
from accident, participated, person
where accident.report_number = participated.report_number
  and participated.driver_id = person.driver_id
  and accident.date between date '1989-01-01' and date '1989-12-31';
```

（更正：官方答案的日期下界写作 `date '1989-00-00'`，这不是合法日期，应为 `'1989-01-01'`；官方答案统计的是 `count(distinct name)`，重名的两个人会被算成一个，按主码 `driver_id` 去重才准确。）

（存疑：题目问的是"拥有"出事汽车的人，这个查询统计的是 `participated` 里记录的驾驶人。如果驾驶人和车主可以不是同一个人，应改为通过 `participated.car = owns.license` 连接 `owns`，统计 `owns.driver_id`。）

b. 官方答案假设司机是 Jones，他只有一辆 Toyota；新事故报告号 4007，日期 2001-09-01，地点 Berkeley，损失金额 3000。先插入事故，再从 `person`、`owns`、`car` 中找到 Jones 那辆车的车牌，插入 `participated`：

```sql
insert into accident
values (4007, '2001-09-01', 'Berkeley');

insert into participated
select o.driver_id, c.license, 4007, 3000
from person p, owns o, car c
where p.name = 'Jones'
  and p.driver_id = o.driver_id
  and o.license = c.license
  and c.model = 'Toyota';
```

c.

```sql
delete from car
where model = 'Mazda'
  and license in (select o.license
                  from person p, owns o
                  where p.name = 'John Smith'
                    and p.driver_id = o.driver_id);
```

`model` 不是 `car` 的码。John Smith 如果只有一辆 Mazda，删的就是这一辆；有多辆就全部删掉，语句是一样的。这里还假设 `name` 能唯一确定一个人。删除后，`owns`、`accident`、`participated` 里与这辆车有关的记录仍然存在；如果定义了外码约束，需要 `on delete cascade` 或者先删这些记录。（更正：官方答案写作 `delete car`，标准 SQL 要求写 `delete from car`，只有 Oracle 等少数系统允许省略 `from`。）

### 3.6 按分数评等级

题目：关系 `marks(ID, score)`，按分数给学生评等级：score < 40 为 F，40 ≤ score < 60 为 C，60 ≤ score < 80 为 B，score ≥ 80 为 A。用 SQL：

- a. 显示每个学生的等级。
- b. 统计每个等级的学生人数。

思路：`case` 的 `when` 分支按顺序匹配，前面的分支已经排除了低分，后面的分支只写上界即可。b 先用 `with` 算出等级，再 `group by`。

解答：

a.

```sql
select ID,
       case
           when score < 40 then 'F'
           when score < 60 then 'C'
           when score < 80 then 'B'
           else 'A'
       end as grade
from marks;
```

b.

```sql
with grades as (
    select ID,
           case
               when score < 40 then 'F'
               when score < 60 then 'C'
               when score < 80 then 'B'
               else 'A'
           end as grade
    from marks)
select grade, count(ID)
from grades
group by grade;
```

也可以不用 `with`，把 `grades` 的定义直接写成主查询 `from` 子句里的子查询。另外，`score` 为 null 时所有比较都不成立，会落进 `else` 得到 A；如果 `marks` 允许分数为空，要单独加一个 `when score is null` 分支。

### 3.7 不区分大小写的 like

题目：SQL 的 `like` 区分大小写，但可以借助 `lower()` 做不区分大小写的匹配。写一个查询，找出名字中含有子串 "sci" 的系，不论大小写。

思路：先把系名全部转成小写，再和小写的模式匹配。

解答：

```sql
select dept_name
from department
where lower(dept_name) like '%sci%';
```

### 3.8 or 连接条件遇到空关系

题目：对于查询

```sql
select p.a1
from p, r1, r2
where p.a1 = r1.a1 or p.a1 = r2.a1;
```

在什么条件下，它能选出 `p.a1` 中出现在 `r1` 或 `r2` 里的那些值？仔细考虑 `r1` 或 `r2` 为空的情况。

思路：`from` 子句先求 `p × r1 × r2`，三个里任意一个为空，乘积就是空的。

解答：当且仅当 `r1` 和 `r2` 都不为空时，查询选出的正好是等于某个 `r1.a1` 或 `r2.a1` 的 `p.a1` 值。只要 `r1`、`r2` 中有一个为空，笛卡尔积为空，查询结果就是空，即使 `p.a1` 在另一个关系里出现过。`p` 本身为空时结果为空，这和预期一致。

### 3.9 银行数据库上的查询

题目：银行数据库的模式如下（注释里是主码）：

```text
branch    (branch_name, branch_city, assets)                 -- branch_name
customer  (customer_name, customer_street, customer_city)   -- customer_name
loan      (loan_number, branch_name, amount)                 -- loan_number
borrower  (customer_name, loan_number)                       -- customer_name, loan_number
account   (account_number, branch_name, balance)             -- account_number
depositor (customer_name, account_number)                    -- customer_name, account_number
```

用 SQL 写出：

- a. 找出在银行有账户但没有贷款的所有客户。
- b. 找出与 Smith 住在同一条街、同一个城市的所有客户的名字。
- c. 找出这样的支行名：该支行有住在 Harrison 的客户开设的账户。

思路：a 是集合差，用 `except`。b 是 `customer` 的自连接，两个别名分别代表"要找的人"和 Smith。c 把 `account`、`depositor`、`customer` 自然连接后按城市筛选。

解答：

a.

```sql
(select customer_name from depositor)
except
(select customer_name from borrower);
```

`except` 本身会去重，两边的 `select` 加不加 `distinct` 结果一样。

b.

```sql
select F.customer_name
from customer F join customer S using (customer_street, customer_city)
where S.customer_name = 'Smith';
```

连接条件也可以写到 `where` 子句里。结果里包括 Smith 本人。

c.

```sql
select distinct branch_name
from account natural join depositor natural join customer
where customer_city = 'Harrison';
```

`account` 和 `depositor` 按 `account_number` 连接，结果再和 `customer` 按 `customer_name` 连接，没有多余的同名属性。自然连接同样可以改成在 `where` 子句里写连接条件。

### 3.10 雇员数据库上的查询

题目：雇员数据库的模式如下（注释里是主码）：

```text
employee (employee_name, street, city)             -- employee_name
works    (employee_name, company_name, salary)     -- employee_name
company  (company_name, city)                      -- company_name
manages  (employee_name, manager_name)             -- employee_name
```

用 SQL 写出：

- a. 找出为 First Bank Corporation 工作的所有雇员的名字和居住城市。
- b. 找出为 First Bank Corporation 工作且收入超过 10000 美元的雇员的名字、街道和居住城市。
- c. 找出所有不为 First Bank Corporation 工作的雇员。
- d. 找出比 Small Bank Corporation 的每个雇员收入都高的所有雇员。
- e. 假设一家公司可以位于多个城市，找出位于 Small Bank Corporation 所在的每一个城市的所有公司。
- f. 找出雇员最多的公司。
- g. 找出平均工资高于 First Bank Corporation 平均工资的公司。

思路：

- c："不为某公司工作"要看假设。每人恰好在一家公司时用 `<>` 就够；有人不在 `works` 里、或一人在多家公司时，要从全体雇员里用 `not in` 排除。
- d：用 `> all`。
- e：公司 S 满足条件，等价于"Small Bank 所在城市的集合减去 S 所在城市的集合为空"，写成 `not exists (A except B)`。
- f：`having count(...) >= all (...)`；g：`having avg(...) > (标量子查询)`。

解答：

a.

```sql
select e.employee_name, e.city
from employee e, works w
where w.company_name = 'First Bank Corporation'
  and w.employee_name = e.employee_name;
```

b.

```sql
select *
from employee
where employee_name in (select employee_name
                        from works
                        where company_name = 'First Bank Corporation'
                          and salary > 10000);
```

如果一个人可以在几家公司工作，这里只看他在 First Bank Corporation 的那份收入。也可以像 a 那样用连接来写。

c. 假设每人恰好在一家公司工作：

```sql
select employee_name
from works
where company_name <> 'First Bank Corporation';
```

允许有人出现在 `employee` 中却不在 `works` 中，或者一人在多家公司工作：

```sql
select employee_name
from employee
where employee_name not in (select employee_name
                            from works
                            where company_name = 'First Bank Corporation');
```

d. 假设每人最多在一家公司工作：

```sql
select employee_name
from works
where salary > all (select salary
                    from works
                    where company_name = 'Small Bank Corporation');
```

如果一人可以在多家公司工作，并且按每人的总收入比较，先用 `with` 算出每人总收入：

```sql
with emp_total_salary as (
    select employee_name, sum(salary) as total_salary
    from works
    group by employee_name)
select employee_name
from emp_total_salary
where total_salary > all (select E.total_salary
                          from emp_total_salary E, works W
                          where W.company_name = 'Small Bank Corporation'
                            and E.employee_name = W.employee_name);
```

注意 Small Bank Corporation 一个雇员都没有时，`> all` 面对空集恒为真，会返回所有人。

```sql
from company S
where not exists ((select city
                   from company
                   where company_name = 'Small Bank Corporation')
                  except
                  (select city
                   from company T
                   where T.company_name = S.company_name));
```

结果里包括 Small Bank Corporation 自己。（更正：官方答案外层没有 `distinct`。公司可以位于多个城市时，`company` 中同一家公司有多行，同一个公司名会被重复输出。）

```sql
from company T
where (select R.city from company R where R.company_name = T.company_name)
      contains
      (select S.city from company S where S.company_name = 'Small Bank Corporation');
```

### 3.11 雇员数据库上的更新

题目：在雇员数据库上用 SQL：

- a. 把 Jones 的居住城市改为 Newtown。
- b. 给 First Bank Corporation 的所有经理涨 10% 工资；如果涨完超过 100000 美元，就只涨 3%。

思路：经理就是出现在 `manages.manager_name` 中的人。b 有两种涨法，拆成两条 `update` 时执行顺序会影响结果；用 `case` 写成一条语句最稳妥。

解答：

a.

```sql
update employee
set city = 'Newtown'
where employee_name = 'Jones';
```

这里假设每个人在 `employee` 中只有一个元组。（更正：官方答案写作 `set city = 'Newton'` 和 `where person_name = 'Jones'`。城市名拼错了；本题雇员库的属性叫 `employee_name`，没有 `person_name`。）

b. 拆成两条 `update`：

```sql
update works T
set salary = T.salary * 1.03
where T.employee_name in (select manager_name from manages)
  and T.salary * 1.1 > 100000
  and T.company_name = 'First Bank Corporation';

update works T
set salary = T.salary * 1.1
where T.employee_name in (select manager_name from manages)
  and T.salary * 1.1 <= 100000
  and T.company_name = 'First Bank Corporation';
```

必须先执行涨 3% 的那一条。顺序反过来的话，工资 90000 的经理先涨到 99000，第二条语句再判断 99000 × 1.1 > 100000，又涨 3%，一共涨了两次。

用 `case` 合成一条语句，不存在顺序问题：

```sql
update works T
set salary = T.salary * (case
                             when T.salary * 1.1 > 100000 then 1.03
                             else 1.1
                         end)
where T.employee_name in (select manager_name from manages)
  and T.company_name = 'First Bank Corporation';
```

（更正：官方答案的 `case` 表达式缺少 `end`，无法执行。官方答案的 `set` 子句还写成 `T.salary = ...`，PostgreSQL 等系统不允许在 `set` 左边的列名前加表名或别名，这里写成 `salary`。）
