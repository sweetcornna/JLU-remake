# 事务调度题

整理自 `笔记/数据库期末复习题整理.pdf` 第 22、36、53 页的原题，以及第 89–97 页的调度专题（优先图判定规则、手写优先图答案、视图可串行化判别和死锁检测例子），共 8 题。原稿有手写答案的题，都把冲突操作重新逐对列了一遍再核对结论；2014 年那道原卷无答案，解答为整理补充。原稿在调度表旁边统计各数据项读写次数的草稿没有保留。

## 解题方法

冲突可串行化（优先图法）：

1. 两个操作冲突的条件：属于不同事务，操作同一个数据项，且至少有一个是写。**两个读不冲突。**
2. 画边的规则：Ti 的操作排在 Tj 的冲突操作之前，就画边 Ti→Tj。具体是三种情况：
   - Ti 先 W(Q)，Tj 后 R(Q)；
   - Ti 先 R(Q)，Tj 后 W(Q)；
   - Ti 先 W(Q)，Tj 后 W(Q)。
3. 做题时按数据项分组：把每个数据项上的读写按时间排成一串，从前往后两两检查。这样比在整张表里来回找更不容易漏边，也不容易多画边。
4. 优先图有环，调度就不是冲突可串行化的，答题时要写出具体的环。无环就是冲突可串行化的。
5. 无环时做拓扑排序：每次取一个没有入边的事务输出，删掉它和它发出的边，重复到取完。输出顺序就是等价的串行调度。某一步同时有几个事务没有入边时，串行顺序不唯一；和别的事务之间没有边的事务，放在任何位置都行。

视图可串行化：

6. 调度 S 和串行调度 S' 视图等价，要同时满足三条：
   - 读初值：S 中读数据项 Q 初值的事务，在 S' 中也读 Q 的初值；
   - 读来源：S 中 Ti 读到的 Q 是 Tj 写的，在 S' 中 Ti 读到的 Q 也必须是 Tj 写的；
   - 最后写：S 中最后写 Q 的事务，在 S' 中也是最后写 Q。
7. 按数据项分别写出这三条对顺序的要求，再找一个同时满足所有要求的串行顺序。原稿提醒了两点：几个读初值的事务之间谁先谁后都可以，只要都排在写 Q 的事务前面；最后写 Q 的事务要排在其他写 Q 的事务之后，这条容易忘。
8. 冲突可串行化的调度一定是视图可串行化的。视图可串行化而不冲突可串行化的调度里一定有盲写（不读就写）。

死锁检测：

9. 等待图中边 Ti→Tj 表示 Ti 在等 Tj 释放数据项上的锁。图中有环就存在死锁，没有环就没有死锁。

## 题目

### 1. 两个事务的调度（2020-2021 学年第 1 学期 二.2）

题目：设有如下调度 S，分析是否为冲突可串行化调度。如果是，给出等价的串行化调度。如果不是，请说明理由。

| 时序 | T1 | T2 |
| --- | --- | --- |
| 1 | W(A) | |
| 2 | | W(A) |
| 3 | | R(B) |
| 4 | W(B) | |

第 90 页把这题标为"2018级"，附了手写优先图。

思路：A 上两个写给一条边，B 上一读一写给一条边，两条边方向相反。

解答：

| 数据项 | 冲突操作（括号里是时序） | 边 |
| --- | --- | --- |
| A | T1 W(A)(1) 在 T2 W(A)(2) 之前 | T1→T2 |
| B | T2 R(B)(3) 在 T1 W(B)(4) 之前 | T2→T1 |

边集 $\lbrace T_1 \rightarrow T_2,\ T_2 \rightarrow T_1 \rbrace$，有环 T1→T2→T1，S 不是冲突可串行化调度。

理由写成一句话：按 A 的写顺序 T1 要排在 T2 前面，而 T2 读 B 时 T1 还没写 B，又要求 T2 排在 T1 前面，两个要求矛盾，找不到冲突等价的串行调度。原稿手写答案"因为存在环，所以不是冲突可串行化调度"正确。

### 7. 视图可串行化判别（2011级）

题目：调度 S 如下表。

1. 判别 S 是否为视图可串行化调度；
2. 如果是视图可串行化调度，则给出与 S 视图等价的串行调度。

原稿表格跨了两页（第 94、95 页），这里合成一张：

| 时序 | T1 | T2 | T3 | T4 |
| --- | --- | --- | --- | --- |
| 1 | | R(A) | | |
| 2 | R(A) | | | |
| 3 | W(C) | | | |
| 4 | | | R(C) | |
| 5 | W(B) | | | |
| 6 | | | | R(B) |
| 7 | | | W(A) | |
| 8 | | | | R(C) |
| 9 | | W(D) | | |
| 10 | | R(B) | | |
| 11 | | | | W(A) |
| 12 | | | | W(B) |

思路：按 A、B、C、D 四个数据项，分别找读初值、读来源、最后写三条，写出对串行顺序的要求，再拼起来。

解答（按手写解答整理并补全推理）：

数据项 A，操作依次为 T2 R(A)、T1 R(A)、T3 W(A)、T4 W(A)。

- 读初值：T1、T2。
- 最后写：T4。
- 要求：T1、T2 都排在写 A 的 T3、T4 之前（T1 和 T2 之间谁先都行）；T4 排在 T3 之后。

数据项 B，操作依次为 T1 W(B)、T4 R(B)、T2 R(B)、T4 W(B)。

- 读来源：T4 和 T2 读到的 B 都是 T1 写的。
- 最后写：T4。
- 要求：T1 排在 T2、T4 之前；T2 读 B 时最近写 B 的必须是 T1，所以另一个写 B 的 T4 不能插在 T1 和 T2 之间，即 T4 在 T2 之后。

数据项 C，操作依次为 T1 W(C)、T3 R(C)、T4 R(C)。

- 读来源：T3 和 T4 读到的 C 都是 T1 写的。
- 最后写：T1。
- 要求：T1 排在 T3、T4 之前。

数据项 D，只有 T2 W(D)，最后写是 T2，对顺序没有要求。

把要求串起来：T1 在 T2 之前（B），T2 在 T3 之前（A），T3 在 T4 之前（A），得到 T1 → T2 → T3 → T4。其余要求（T1 在 T3、T4 之前，T2 在 T4 之前）也都满足，而且这是唯一满足全部要求的顺序。

在串行调度 T1 → T2 → T3 → T4 中逐条验证：

- T1、T2 读 A 时还没有事务写过 A，读的是初值；A 最后由 T4 写。
- T2、T4 读 B 时，最近一次写 B 的是 T1；B 最后由 T4 写。
- T3、T4 读 C 时，最近一次写 C 的是 T1；C 最后由 T1 写。
- D 最后由 T2 写。

结论：S 是视图可串行化调度，与串行调度 T1 → T2 → T3 → T4 视图等价。手写答案结论正确。

用优先图也能验证：边有 T1→T2、T1→T3、T1→T4、T2→T3、T2→T4、T3→T4，没有环，拓扑序只有 T1→T2→T3→T4。这个调度本身就是冲突可串行化的，所以一定视图可串行化，两种方法结论一致。

### 8. 死锁检测：等待图例子

题目（原稿例子）：

- 事务 T1 在等待事务 T2 与 T3；
- 事务 T3 在等待事务 T2；
- 事务 T2 在等待事务 T4。

画出等待图，判断系统中是否存在死锁。

思路：每条"Ti 在等 Tj"画一条边 Ti→Tj，然后找环。

解答：

边集 $\lbrace T_1 \rightarrow T_2,\ T_1 \rightarrow T_3,\ T_3 \rightarrow T_2,\ T_2 \rightarrow T_4 \rbrace$，原稿附的等待图就是这四条边。

T4 没有出边，不等任何事务。从任何一个事务出发顺着箭头走，最后都停在 T4，回不到出发点，图中没有环，当前不存在死锁。T4 执行完释放锁后，T2 可以继续；T2 结束后 T3 可以继续；T2、T3 都结束后 T1 才能继续。

（整理补充）如果这时 T4 又去申请 T3 持有的锁，等待图加上边 T4→T3，就出现环 T2→T4→T3→T2，发生死锁。系统要从环上选一个事务回滚（一般选回滚代价小的），把环打断。
