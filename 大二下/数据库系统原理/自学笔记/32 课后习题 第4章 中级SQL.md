## 习题

### 4.1 外连接与标量子查询

题目：用 SQL 写出下列查询：

- a. 列出所有教师的 ID、姓名和讲授过的课程段数，没讲过课的教师显示 0。要求用外连接，不用标量子查询。
- b. 与 a 相同，改用标量子查询，不用外连接。
- c. 列出 2010 年春季（Spring）开设的所有课程段，以及授课教师的姓名。一个课程段有几位教师就出现几次；没有教师的课程段也要出现，教师名显示为 "-"。
- d. 列出所有系以及各系的教师总数，不用标量子查询，没有教师的系也要正确显示。

思路：a、d 的关键是 `count` 的参数。外连接会给没匹配上的教师（或系）补一行，这行里来自右边关系的列全是 null。`count(列)` 不计 null，`count(*)` 会把补出来的这一行算成 1。所以要数右边关系中的某一列。c 做两次左外连接，再用 `coalesce` 把空的名字换成 "-"。

解答：

a.

```sql
select ID, name, count(sec_id) as "Number of sections"
from instructor natural left outer join teaches
group by ID, name;
```

`count` 的参数可以是 `teaches` 中任意一个不在 `instructor` 里出现的属性。`instructor` 自己的属性在教师没讲过课时也不为空，拿来计数会得到 1。

（更正：官方答案写作 `count(course_id, section_id, year, semester) as 'Number of sections'`。`count` 只接受一个参数（MySQL 只在 `count(distinct ...)` 里允许多列），`section_id` 应为 `sec_id`；标准 SQL 中带空格的列别名用双引号，单引号表示字符串常量。答案后文说"也可以写成 `count(section_id)`"，同样应为 `count(sec_id)`。）

b.

```sql
select ID, name,
       (select count(*)
        from teaches T
        where T.ID = I.ID) as "Number of sections"
from instructor I;
```

标量子查询里没有匹配行时 `count(*)` 返回 0，这里用 `count(*)` 没有问题。（更正：官方答案把别名 `as 'Number of sections'` 写在子查询内部的 `count(*)` 后面，这只给子查询自己的列命名，外层结果列拿不到这个名字，应放在子查询的括号外面。）

c.

```sql
select course_id, sec_id, ID, coalesce(name, '-') as name
from (section natural left outer join teaches)
     natural left outer join instructor
where semester = 'Spring' and year = 2010;
```

`section` 与 `teaches` 按课程段的四个属性连接，结果再和 `instructor` 只按 `ID` 连接，没有其他同名属性。`where` 里的 `semester`、`year` 来自最左边的 `section`，不会是外连接补出来的 null，放在连接之后筛选没有问题。官方答案用的是 Oracle 的 `decode(name, NULL, '-', name)`，和 `coalesce(name, '-')` 效果相同。还可以不用外连接，把连接结果和"没有教师的课程段"的查询 `union` 起来，做法参见 4.2。（更正：官方答案的 `section_id` 应为 `sec_id`。）

d.

```sql
select dept_name, count(ID)
from department natural left outer join instructor
group by dept_name;
```

`department` 与 `instructor` 的公共属性只有 `dept_name`，没有教师的系 `count(ID)` 为 0。

### 4.2 不用外连接改写外连接

题目：外连接可以不用 SQL 的 outer join 运算来计算。不用外连接，改写下面两个查询：

- a. `select * from student natural left outer join takes`
- b. `select * from student natural full outer join takes`

思路：左外连接的结果等于"自然连接的结果"并上"没匹配上的左边元组补 null"。没匹配上的元组用 `not exists` 找，补 null 时要按自然连接结果的列顺序对齐：`ID, name, dept_name, tot_cred, course_id, sec_id, semester, year, grade`，共 9 列。全外连接再并上"没匹配上的右边元组补 null"。

解答：

a.

```sql
select * from student natural join takes
union
select ID, name, dept_name, tot_cred, null, null, null, null, null
from student S
where not exists (select * from takes T where T.ID = S.ID);
```

b.

```sql
select * from student natural join takes
union
select ID, name, dept_name, tot_cred, null, null, null, null, null
from student S
where not exists (select * from takes T where T.ID = S.ID)
union
select ID, null, null, null, course_id, sec_id, semester, year, grade
from takes T
where not exists (select * from student S where S.ID = T.ID);
```

`takes.ID` 是参照 `student` 的外码，数据满足约束时第三部分为空，写上是为了和全外连接的定义一致。（更正：官方答案 b 第三部分的列表写作 `section_id`，应为 `sec_id`。）

### 4.3 左外连接的结合顺序

题目：有三个关系 r(A, B)、s(B, C)、t(B, D)，所有属性都声明为 not null。考虑两个表达式：

- `r natural left outer join (s natural left outer join t)`
- `(r natural left outer join s) natural left outer join t`

问：

- a. 给出 r、s、t 的实例，使第二个表达式的结果里 C 为 null 而 D 不为 null。
- b. 第一个表达式的结果里可能出现 C 为 null、D 不为 null 吗？说明理由。

思路：分别画出中间结果。第二个表达式中，t 直接和 r ⟕ s 的结果按 B 匹配，跟 s 有没有匹配无关。第一个表达式中，t 先挂在 s 上。

解答：

- a：取 r = {(a, b)}，s = {(b1, c1)}，t = {(b, d)}。r ⟕ s 得到 (a, b, null)，再和 t 按 B = b 匹配，得到 (a, b, null, d)。
- b：不可能。子表达式 s ⟕ t 里 C 来自 s，不会是 null，所以它的结果里不存在 C 为 null 而 D 非空的元组。整个表达式中 C 为 null，当且仅当某个 r 元组在 s 中找不到相同的 B 值，而这时 D 也是 null。

### 4.4 设计测试数据

题目：检验一个 SQL 查询是否正确实现了文字描述，通常要在多个测试数据库上运行它，由人检查结果是否符合本意。

- a. 3.3.3 节有一个错误查询：本意是找出每位教师讲过哪些课，却对 `instructor`、`teaches`、`course` 做了自然连接，无意中让 `instructor` 和 `course` 的 `dept_name` 也相等。给出一个能发现这个错误的数据集。
- b. 建测试库时，对每个外码，都应该在被参照关系里放一些没有被任何元组参照的元组。用 university 上的一个查询说明原因。
- c. 建测试库时，对允许为空的外码属性（SQL 允许外码为空，只要它不属于主码、也没声明 not null），应该造一些该属性为 null 的元组。用一个查询说明原因。（提示：用 4.1 的查询。）

思路：好的测试数据要让错误查询和正确查询给出不同结果。三小题分别对应"连接时意外多出的等值条件""内连接丢掉没匹配的元组""空值参与连接时丢元组"。

解答：

- a：让物理系的教师讲一门电子工程系的课。`teaches` 中有这条记录，但三表自然连接时教师的系和课程的系不相等，这条记录丢失，错误就暴露了。数据集：

  ```text
  instructor = {(12345, 'Gauss', 'Physics', 10000)}
  teaches    = {(12345, 'EE321', 1, 'Spring', 2009)}
  course     = {('EE321', 'Magnetism', 'Elec. Eng.', 6)}
  ```

- b：4.1a 就是例子。没讲过课的教师应显示 0。如果测试库里每位教师都讲过课，把外连接误写成内连接也看不出区别。同类的例子还有很多。
- c：官方答案举的例子是 `select * from teaches natural join instructor;`，说如果 `teaches.ID` 允许为 null 且确有这样的元组，这些课程段会在结果里丢失；只因为 `teaches.ID` 是外码就不造这种元组，这个错误就发现不了。

  （更正：`teaches` 的主码是 `(ID, course_id, sec_id, semester, year)`，`teaches.ID` 在主码里，不能为 null，不满足题目"外码允许为空"的前提。换成真正可空的外码更合适，例如 `instructor.dept_name`：`select * from instructor natural join department` 会漏掉 `dept_name` 为空的教师，要列出全部教师得用左外连接。）

### 4.5 定义 GPA 视图

题目：基于 3.2 的查询，定义视图 `student_grades(ID, GPA)` 给出每个学生的平均绩点，分数由 `grade_points(grade, points)` 换算。视图要正确处理 `takes` 中 `grade` 为 null 的情况。

思路：成绩为空的课程，学分不计入总学分，绩点按 0 算。学生没有任何有效学分时 GPA 应为 null，不能除以 0。做法是先在子查询里按学生求出总学分和总绩点，外层再相除；一门课都没选的学生另外 `union` 进来。

解答：

```sql
create view student_grades(ID, GPA) as
    select ID, credit_points / nullif(credit_sum, 0)
    from (select ID,
                 sum(case when grade is null then 0 else credits end) as credit_sum,
                 sum(case when grade is null then 0 else credits * points end) as credit_points
          from (takes natural join course) natural left outer join grade_points
          group by ID) as T
    union
    select ID, null
    from student
    where ID not in (select ID from takes);
```

- `natural left outer join grade_points` 保证成绩为空的选课记录不会在连接时被丢掉。
- `nullif(credit_sum, 0)` 在总学分为 0 时返回 null，除法结果也就是 null。官方答案用的是 `decode(credit_sum, 0, NULL, credit_sum)`，作用一样。
- 另一种写法是用 `student` 左外连接上面按学生求出的 GPA 结果，这样没选课的学生自然带着 null。

（更正：官方答案把 `union` 写在 `from` 子句的括号里面，`union` 一边是 3 列（`ID`、`credit_sum`、`credit_points`），另一边是 2 列（`ID`、`NULL`），列数不一致；派生表也没有别名。按原意，"没选课的学生 GPA 为 null"这一部分应放到外层去 `union`。）

### 4.6 补全 university 的 DDL

题目：补全 university 数据库的 SQL DDL，写出 `student`、`takes`、`advisor`、`prereq` 的定义。

思路：逐个关系写主码和外码，再想每个外码被删除时怎么处理。学生被删，他的选课记录和导师关系跟着删（cascade）；教师被删，学生的导师置空（set null）；系被删，学生的系置空。

解答：

```sql
create table student
    (ID        varchar(5),
     name      varchar(20) not null,
     dept_name varchar(20),
     tot_cred  numeric(3,0) check (tot_cred >= 0),
     primary key (ID),
     foreign key (dept_name) references department
         on delete set null);

create table takes
    (ID        varchar(5),
     course_id varchar(8),
     sec_id    varchar(8),
     semester  varchar(6),
     year      numeric(4,0),
     grade     varchar(2),
     primary key (ID, course_id, sec_id, semester, year),
     foreign key (course_id, sec_id, semester, year) references section
         on delete cascade,
     foreign key (ID) references student
         on delete cascade);

create table advisor
    (s_ID varchar(5),
     i_ID varchar(5),
     primary key (s_ID),
     foreign key (i_ID) references instructor (ID)
         on delete set null,
     foreign key (s_ID) references student (ID)
         on delete cascade);

create table prereq
    (course_id varchar(8),
     prereq_id varchar(8),
     primary key (course_id, prereq_id),
     foreign key (course_id) references course
         on delete cascade,
     foreign key (prereq_id) references course);
```

`prereq_id` 的外码没写删除动作，默认拒绝删除仍被当作先修课的课程。（更正：官方答案 `takes` 表中写作 `section_id`，与 university 模式的 `sec_id` 不一致。）

### 4.7 雇员库的 DDL

题目：为雇员库写出 SQL DDL，找出应当满足的参照完整性约束并写进定义。

思路：`works`、`manages` 里的人名都参照 `employee`，`works.company_name` 参照 `company`，`manages.manager_name` 也参照 `employee`。被参照的表要先建。

解答：

```sql
create table employee
    (person_name char(20),
     street      char(30),
     city        char(30),
     primary key (person_name));

create table company
    (company_name char(15),
     city         char(30),
     primary key (company_name));

create table works
    (person_name  char(20),
     company_name char(15),
     salary       integer,
     primary key (person_name),
     foreign key (person_name) references employee,
     foreign key (company_name) references company);

create table manages
    (person_name  char(20),
     manager_name char(20),
     primary key (person_name),
     foreign key (person_name) references employee,
     foreign key (manager_name) references employee);
```

数据类型可以有别的选择，哪些属性加 `not null` 也可以不同。（更正：官方答案先建 `works` 后建 `company`，`works` 的外码引用了还不存在的表，按顺序执行会出错，这里把 `company` 提前。）

（存疑：官方答案的列名用 `person_name`，而第 3 章 3.10、3.11 的雇员库用的是 `employee_name`。本题的图在答案 PDF 中没有给出，如果教材图用的是 `employee_name`，把列名替换即可，约束不变。）

### 4.8 同一时间段不能在两个教室上课

题目：约束"一位教师在一个学期的同一时间段内，不能在两个不同的教室讲课"应当成立。

- a. 写一个 SQL 查询，返回所有违反该约束的（教师，课程段）组合。
- b. 写一个 SQL 断言实施这个约束（现有数据库系统大多不支持断言，但它属于 SQL 标准）。

思路：把 `teaches` 和 `section` 连接，得到每位教师每个课程段的学期、时间段和教室。再把这个结果和自身连接：同一教师、同一学期、同一时间段，而教室不同，就是违反约束。同一时间段在同一个教室上的两个课程段（比如合班）不算违反，所以比较的是教室是否不同，不能只数课程段的个数。

解答：

a.

```sql
with inst_sec as (
    select ID, course_id, sec_id, semester, year,
           time_slot_id, building, room_number
    from teaches natural join section)
select distinct A.ID, A.course_id, A.sec_id, A.semester, A.year
from inst_sec A, inst_sec B
where A.ID = B.ID
  and A.semester = B.semester
  and A.year = B.year
  and A.time_slot_id = B.time_slot_id
  and (A.building <> B.building or A.room_number <> B.room_number);
```

b.

```sql
create assertion no_two_rooms check (not exists (
    select *
    from (select * from teaches natural join section) A,
         (select * from teaches natural join section) B
    where A.ID = B.ID
      and A.semester = B.semester
      and A.year = B.year
      and A.time_slot_id = B.time_slot_id
      and (A.building <> B.building or A.room_number <> B.room_number)));
```

（更正：官方答案的查询按 `(ID, name, section_id, semester, year, time_slot_id)` 分组，在 `select` 里算 `count(distinct building, room_number)`，在 `having` 里判断 `count(building, room_number) > 1`。问题有三处：分组里有段号却没有 `course_id`，只有两门课的段号碰巧相同时冲突才会被查出来，段号不同就查不到；`count` 不接受两个参数，`having` 里还漏了官方答案自己强调必须有的 `distinct`；`section_id` 应为 `sec_id`。断言部分沿用了同一个查询，并且 `create assertion` 后面缺少断言名，`check` 的条件也应放在括号里。）

### 4.9 引用自身的外码与级联删除

题目：SQL 允许外码参照同一个关系，例如：

```sql
create table manager
    (employee_name char(20),
     manager_name  char(20),
     primary key (employee_name),
     foreign key (manager_name) references manager
         on delete cascade);
```

`employee_name` 是码，表示每个雇员最多有一个经理；外码要求每个经理也是雇员。说明删除 `manager` 中一个元组时到底会发生什么。

思路：级联删除会沿着"经理是被删者"的方向一层层传下去。

解答：被删者手下各级下属的元组全都会被删除。删除一个元组先触发删除所有直接下属的元组（它们的 `manager_name` 等于被删者）；这些删除又触发删除第二级下属的元组，如此继续，直到所有直接和间接下属都被删掉。

（更正：原题建表语句写作 `primary key employee_name`，主码列必须放在括号里。）

### 4.10 用 coalesce 实现自然全外连接

题目：`coalesce(A1, A2, ..., An)` 返回列表中第一个非空的 Ai，全为空时返回 null。关系 a、b 的模式分别是 A(name, address, title) 和 B(name, address, salary)。用带 `on` 条件的全外连接和 `coalesce` 表示 `a natural full outer join b`，要求结果中 `name`、`address` 各只出现一次，并且 a、b 中有元组的 `name` 或 `address` 为 null 时也要正确。

思路：`on` 条件写成两个公共属性分别相等，这和自然连接的匹配规则相同。匹配不上的元组一边为 null，所以公共属性用 `coalesce` 从两边取非空的那个。

解答：

```sql
select coalesce(a.name, b.name) as name,
       coalesce(a.address, b.address) as address,
       a.title,
       b.salary
from a full outer join b
     on a.name = b.name and a.address = b.address;
```

`name` 或 `address` 为 null 的元组，和任何元组比较都不为真，不会被匹配上，这与自然连接一致。它们作为没匹配上的元组出现在结果中，`coalesce` 取到的就是它自己那一边的值。

### 4.11 用带标记的空值通过视图插入

题目：有研究者提出带标记的空值（marked null）：⊥i 等于它自己，但 i ≠ j 时 ⊥i ≠ ⊥j。它的一个用途是支持通过视图进行某些更新。以 4.2 节的视图 `instructor_info` 为例（视图属性是教师 ID、姓名和所在系的楼名，由 `instructor` 和 `department` 按 `dept_name` 连接得到），说明怎样用标记空值通过这个视图插入元组 (99999, "Johnson", "Music")。

思路：视图里没有 `dept_name`，插入时系名未知。如果两边都填普通 null，null = null 不为真，插进去的两个元组连接不上，视图里看不到这一行。用同一个新的标记空值 ⊥k 同时填入 `instructor` 和 `department` 的 `dept_name`，两个元组就能连接上；其余未知的值用普通空值。

解答：

$$instructor \leftarrow instructor \cup \lbrace(99999, \text{'Johnson'}, \perp_k, \perp)\rbrace$$

$$department \leftarrow department \cup \lbrace(\perp_k, \text{'Music'}, \perp)\rbrace$$

其中 ⊥k 是数据库里还没用过的新标记空值。这里的 Music 是楼名，和音乐系不一定有关系。
