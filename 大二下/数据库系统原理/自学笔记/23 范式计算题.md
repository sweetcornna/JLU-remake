# 范式计算题

整理自 `笔记/数据库期末复习题整理.pdf` 第 25、32、49、53 页的原题，以及第 69、79 页的手写解答，共 5 道。函数依赖集以原卷渲染页为准核对过。有手写解答的两题，按手写思路重新写出每一步闭包计算，并把结论验算了一遍；交通肇事和 2014 年的两题原卷无答案，解答为整理补充。

## 解题方法

1. 求属性闭包 $X^+$：从 X 出发扫一遍依赖集，某条依赖的左部已经全在结果里，就把右部并进来。一轮扫完没有新属性加入就停。
2. 求全部候选码：
   - 把属性分四类。L 类只出现在依赖左部，R 类只出现在右部，LR 类左右都出现，N 类左右都不出现。
   - **L 类和 N 类一定在每个候选码里，R 类一定不在任何候选码里。**
   - 令 X 为 L 类和 N 类属性的并，求 $X^+$。等于全部属性 U，X 就是唯一的候选码。
   - 否则给 X 逐个加一个 LR 类属性求闭包，等于 U 的就是候选码；再试加两个的组合，已经包含某个候选码的组合直接跳过。
3. 证明 X 是候选码要写两步： $X^+ = U$，说明 X 是超码；X 的每个真子集的闭包都不等于 U，说明 X 是最小的。
4. 判断范式：
   - BCNF：每个非平凡依赖 $\alpha \rightarrow \beta$ 的左部 $\alpha$ 都是超码。有一条不满足就不是 BCNF。
   - 3NF：不满足上一条的依赖， $\beta - \alpha$ 里的每个属性都得是主属性（包含在某个候选码中）。所有属性都是主属性的模式一定属于 3NF。
   - 2NF：非主属性不能部分依赖于候选码。候选码的某个真子集决定了非主属性，就不是 2NF。
5. 求正则覆盖 $F_c$：先把右部拆成单个属性；检查左部多余属性，用原依赖集求去掉该属性后的左部闭包，能推出右部就说明多余；再检查多余的依赖，去掉这条依赖后用剩下的依赖求左部闭包，还能推出右部就删掉；最后合并左部相同的依赖。
6. 3NF 合成算法： $F_c$ 中每条 $\alpha \rightarrow \beta$ 建一个模式 $\alpha\beta$。如果没有哪个模式包含候选码，再加一个由候选码组成的模式。最后删掉被其他模式包含的模式。结果既无损又保持依赖。
7. BCNF 分解：找一条违反 BCNF 的 $\alpha \rightarrow \beta$，把 R 换成 $\alpha \cup \beta$ 和 $R - (\beta - \alpha)$，对得到的模式继续检查。结果无损，但可能丢依赖。
8. 判断无损连接：分成 $R_1$、 $R_2$ 时，只要 $R_1 \cap R_2 \rightarrow R_1$ 或 $R_1 \cap R_2 \rightarrow R_2$ 成立就是无损的。判断保持依赖：每条依赖的左右部属性都落在同一个分解模式里就一定保持；有依赖跨模式时，要用各模式上限定依赖的并再求闭包检验。

## 题目

### 1. 证明 DF 是候选码并求全部候选码（2020-2021 学年第 1 学期 四）

题目：（原卷为计算题，每题 5 分，共 10 分）

已知关系模式 $R\langle U, F \rangle$，有 $U = \lbrace A, B, C, D, E, F \rbrace$， $F = \lbrace A \rightarrow BCD,\ BC \rightarrow DE,\ B \rightarrow D,\ D \rightarrow A \rbrace$。

1. 证明 DF 是一个候选码（请写出关键步骤）；
2. 写出所有候选码。

（更正：原卷印作 $U = \lbrace A, B, C, D, EF \rbrace$，E 和 F 之间漏了逗号，第 25 页和第 69 页的扫描件都是这样。）

注意属性 F 和依赖集 F 同名，读题时别看混。

思路：先给属性分类。属性 F 不出现在任何依赖里，是 N 类，必须在码里；E 只在右部，不在码里。然后拿 F 和 A、B、C、D 逐个组合求闭包。

解答：

属性分类（依赖左部出现过 A、B、C、D，右部出现过 A、B、C、D、E）：

| 类别 | 属性 |
| --- | --- |
| L 类（只在左部） | 无 |
| R 类（只在右部） | E |
| LR 类（左右都有） | A、B、C、D |
| N 类（都不出现） | F |

第 1 问，证明 DF 是候选码。

先求 $(DF)^+$：

- 初始为 $\lbrace D, F \rbrace$；
- 由 $D \rightarrow A$ 加入 A，得 $\lbrace A, D, F \rbrace$；
- 由 $A \rightarrow BCD$ 加入 B、C，得 $\lbrace A, B, C, D, F \rbrace$；
- 由 $BC \rightarrow DE$ 加入 E，得 $\lbrace A, B, C, D, E, F \rbrace = U$。

所以 DF 是超码。再看它的两个真子集：

- $D^+$：由 $D \rightarrow A$、 $A \rightarrow BCD$、 $BC \rightarrow DE$ 依次得到 $\lbrace A, B, C, D, E \rbrace$，没有 F；
- $F^+ = \lbrace F \rbrace$。

两个真子集都不是超码，DF 是最小的超码，即候选码。证明时也可以直接指出：F 不在任何依赖的右部，别的属性推不出 F，所以任何超码都必须含 F，而单独的 D 推不出 F。

第 2 问，求全部候选码。

L 类和 N 类的并是 $X = \lbrace F \rbrace$， $F^+ = \lbrace F \rbrace \ne U$，要往 F 上加 LR 类属性：

| 组合 | 闭包计算 | 结果 |
| --- | --- | --- |
| AF | $A \rightarrow BCD$ 得 ABCDF， $BC \rightarrow DE$ 得 ABCDEF | 候选码 |
| BF | $B \rightarrow D$ 得 BDF， $D \rightarrow A$ 得 ABDF， $A \rightarrow BCD$ 得 ABCDF， $BC \rightarrow DE$ 得 ABCDEF | 候选码 |
| CF | 没有哪条依赖的左部包含在 CF 里 | CF，不是超码 |
| DF | 见第 1 问 | 候选码 |

AF、BF、DF 的真子集都是单个属性，而 A、B、D 单独推不出 F，F 单独也推不出别的属性，所以三者都是最小的。含三个属性的组合里，F 加上 A、B、C、D 中的任意两个，一定含有 A、B、D 之一，也就包含了 AF、BF 或 DF，不会是新的候选码。

全部候选码为 AF、BF、DF。手写解答的结论正确。

### 2. 判断 3NF 和 BCNF（2019-2020 学年第 2 学期 六）

题目：（原卷为计算题，共 10 分）

设有属于 1NF 的关系模式 $R = (A, B, C, D, E)$，R 上的函数依赖集 $F = \lbrace BC \rightarrow AD,\ AD \rightarrow EB,\ E \rightarrow C \rbrace$。

- （1）R 是否属于 3NF？为什么？
- （2）R 是否属于 BCNF？为什么？

思路：先求全部候选码。五个属性左右两边都出现过，只能从单个属性、两个属性的组合一个个试。求出候选码后会发现所有属性都是主属性，3NF 直接成立； $E \rightarrow C$ 的左部不是超码，BCNF 不成立。

解答：

先求候选码。A、B、C、D、E 都是 LR 类，L 类和 N 类为空。

单个属性： $A^+ = \lbrace A \rbrace$， $B^+ = \lbrace B \rbrace$， $C^+ = \lbrace C \rbrace$， $D^+ = \lbrace D \rbrace$， $E^+ = \lbrace C, E \rbrace$（由 $E \rightarrow C$），都不是超码。

两个属性的组合共 10 个：

| 组合 | 闭包计算 | 是否候选码 |
| --- | --- | --- |
| AB | 没有可用的依赖，AB | 否 |
| AC | AC | 否 |
| AD | $AD \rightarrow EB$ 得 ABDE， $E \rightarrow C$ 得 ABCDE | 是 |
| AE | $E \rightarrow C$ 得 ACE | 否 |
| BC | $BC \rightarrow AD$ 得 ABCD， $AD \rightarrow EB$ 得 ABCDE | 是 |
| BD | BD | 否 |
| BE | $E \rightarrow C$ 得 BCE， $BC \rightarrow AD$ 得 ABCDE | 是 |
| CD | CD | 否 |
| CE | CE | 否 |
| DE | $E \rightarrow C$ 得 CDE | 否 |

三个属性的组合里，不包含 AD、BC、BE 的只有 ACE 和 CDE，闭包分别还是 ACE 和 CDE，不是超码。四个属性的组合都包含 AD 或 BC。所以候选码是 AD、BC、BE，和手写解答一致，没有漏。

（1）R 属于 3NF。三个候选码 AD、BC、BE 合起来覆盖了 A、B、C、D、E，所有属性都是主属性，3NF 的" $\beta - \alpha$ 中每个属性都是主属性"对任何依赖都成立。逐条看也一样： $BC \rightarrow AD$ 和 $AD \rightarrow EB$ 的左部是候选码； $E \rightarrow C$ 的左部不是超码，但 C 包含在候选码 BC 中。

（2）R 不属于 BCNF。 $E \rightarrow C$ 是非平凡依赖，而 $E^+ = \lbrace C, E \rbrace \ne U$，E 不是超码。

（整理补充）如果接着要求分解到 BCNF：按 $E \rightarrow C$ 分成 $R_1(C, E)$ 和 $R_2(A, B, D, E)$。 $R_2$ 上成立的依赖有 $AD \rightarrow BE$、 $BE \rightarrow AD$，候选码是 AD 和 BE，两个模式都属于 BCNF。但 B 和 C 分到了不同模式里， $BC \rightarrow AD$ 在哪个模式上都检查不了，用限定依赖求闭包也推不出来，依赖没有保持。本题的 R 已经是 3NF，想保持依赖就停在 3NF。

### 3. 交通肇事关系模式分解为 3NF（2015 年数据库原理A 四.2）

题目：

设有关系模式 R(A, B, C, D, E, F, G, H, I)，其中各属性分别代表：A 交通肇事编号，B 交通肇事发生时间，C 交通肇事具体原因，D 违章扣分，E 违章罚款金额，F 交通肇事发生车辆车牌号码，G 交通肇事车型号及颜色，H 违章驾驶员驾照号，I 驾照已扣分数。其中：

- 司机与车辆之间的联系为 1:1，车辆与违章之间的联系为 m:n；
- 一辆车只能有一个车牌号码，且车牌号码唯一；
- 一个人只能有一个驾照，且驾照号码唯一。

完成以下任务：

- （1）根据语义给出 R 的函数依赖；
- （2）将该关系模式分解为 3NF。

原卷无答案。

思路：函数依赖要逐条从语义里找。最容易错的是车辆与违章 m:n 这一条：一起肇事可能涉及好几辆车，一辆车也可能出过好几次事，所以肇事编号 A 决定不了车牌 F，F 也决定不了 A。依赖写出来后，求候选码，再用 3NF 合成算法分解。

解答（整理补充）：

（1）函数依赖。先写清语义假设：

- 发生时间和具体原因是整起肇事的信息，由肇事编号决定： $A \rightarrow B$， $A \rightarrow C$。
- 扣分和罚款开给这起肇事中的某一辆车（也就是它的司机），要同时知道肇事编号和车牌才能确定： $AF \rightarrow D$， $AF \rightarrow E$。
- 车牌唯一，车型号及颜色是车本身的属性： $F \rightarrow G$。
- 司机和车 1:1，知道车牌就知道司机的驾照号，反过来也一样： $F \rightarrow H$， $H \rightarrow F$。
- 驾照号唯一，已扣分数是这本驾照上的累计值： $H \rightarrow I$。
- A 和 F 是 m:n， $A \rightarrow F$ 和 $F \rightarrow A$ 都不成立。

为了和属性 F 区分，依赖集记为 $\mathcal{F}$。合并左部相同的依赖：

$$\mathcal{F} = \lbrace A \rightarrow BC,\ AF \rightarrow DE,\ F \rightarrow GH,\ H \rightarrow FI \rbrace$$

检查它已经是正则覆盖：

- $AF \rightarrow DE$ 的左部： $A^+ = \lbrace A, B, C \rbrace$， $F^+ = \lbrace F, G, H, I \rbrace$，单独都推不出 D、E，A 和 F 都不多余。
- 右部：去掉 $A \rightarrow B$ 后 A 推不出 B，C、D、E 同理；去掉 $F \rightarrow G$ 后 $F^+ = \lbrace F, H, I \rbrace$，推不出 G；去掉 $F \rightarrow H$ 后 $F^+ = \lbrace F, G \rbrace$，推不出 H；去掉 $H \rightarrow F$ 后 $H^+ = \lbrace H, I \rbrace$，推不出 F；去掉 $H \rightarrow I$ 后 $H^+ = \lbrace F, G, H \rbrace$，推不出 I。都不多余。

求候选码。A 只在左部，是 L 类；F、H 左右都有，是 LR 类；B、C、D、E、G、I 只在右部，是 R 类。

- $A^+ = \lbrace A, B, C \rbrace$，不是超码。
- $(AF)^+$： $A \rightarrow BC$ 得 ABCF， $AF \rightarrow DE$ 得 ABCDEF， $F \rightarrow GH$ 得 ABCDEFGH， $H \rightarrow FI$ 得 ABCDEFGHI，是超码。
- $(AH)^+$： $H \rightarrow FI$ 得 AFHI， $A \rightarrow BC$ 得 ABCFHI， $AF \rightarrow DE$ 得 ABCDEFHI， $F \rightarrow GH$ 得 ABCDEFGHI，是超码。
- 真子集 A、F、H 的闭包都不是全部属性，所以 AF、AH 都是最小的。

候选码为 AF 和 AH，主属性是 A、F、H。

R 现在的范式： $A \rightarrow BC$ 中 B、C 是非主属性，只依赖于候选码 AF 的一部分，是部分依赖，R 不属于 2NF，只属于 1NF。

（2）用 3NF 合成算法， $\mathcal{F}$ 中每条依赖建一个模式：

| 模式 | 来自依赖 | 候选码 | 含义 |
| --- | --- | --- | --- |
| $R_1(A, B, C)$ | $A \rightarrow BC$ | A | 肇事 |
| $R_2(A, F, D, E)$ | $AF \rightarrow DE$ | AF | 某起肇事中某辆车的处罚 |
| $R_3(F, G, H)$ | $F \rightarrow GH$ | F、H | 车辆及其司机 |
| $R_4(H, F, I)$ | $H \rightarrow FI$ | H、F | 驾照 |

- $R_2$ 包含候选码 AF，不用再加候选码模式。
- 四个模式没有谁被谁包含，不用删。
- 每个模式里依赖的左部都是该模式的候选码，四个模式都属于 BCNF，当然也属于 3NF。分解保持依赖，又含有原模式的候选码，是无损连接分解。

F 和 H 互相决定，把 $R_3$、 $R_4$ 合成 $(F, G, H, I)$ 也可以，合并后候选码是 F 和 H，仍属于 BCNF。

另一种理解：如果认为扣分和罚款只由违章原因决定，依赖集变成 $\lbrace A \rightarrow BC,\ C \rightarrow DE,\ F \rightarrow GH,\ H \rightarrow FI \rbrace$，候选码仍是 AF 和 AH。合成得到 $(A, B, C)$、 $(C, D, E)$、 $(F, G, H)$、 $(H, F, I)$，这几个模式都不含候选码，要再加一个 $(A, F)$，记录哪些车卷入了哪起肇事。

### 4. 求全部候选码（2014 年数据库原理A 四.2）

题目：设有关系模式 R(A, B, C, D, E, F, G)，其函数依赖集 $F = \lbrace AB \rightarrow C,\ B \rightarrow DE,\ C \rightarrow G,\ G \rightarrow A \rbrace$，求模式 R 的所有候选码。

原卷无答案。原卷把 $C \rightarrow G$ 和 $G \rightarrow A$ 之间的逗号印成了句点。

思路：B 只在左部，属性 F 不出现，每个候选码都含 BF。 $(BF)^+$ 不是全部属性，再分别加 A、C、G 试。

解答（整理补充）：

| 类别 | 属性 |
| --- | --- |
| L 类 | B |
| R 类 | D、E |
| LR 类 | A、C、G |
| N 类 | F |

$(BF)^+$：由 $B \rightarrow DE$ 得 BDEF。 $AB \rightarrow C$ 缺 A，推不下去。 $(BF)^+ = \lbrace B, D, E, F \rbrace \ne U$。

加一个 LR 类属性：

| 组合 | 闭包计算 | 结果 |
| --- | --- | --- |
| ABF | $AB \rightarrow C$ 得 ABCF， $B \rightarrow DE$ 得 ABCDEF， $C \rightarrow G$ 得 ABCDEFG | 候选码 |
| BCF | $B \rightarrow DE$ 得 BCDEF， $C \rightarrow G$ 得 BCDEFG， $G \rightarrow A$ 得 ABCDEFG | 候选码 |
| BFG | $G \rightarrow A$ 得 ABFG， $AB \rightarrow C$ 得 ABCFG， $B \rightarrow DE$ 得 ABCDEFG | 候选码 |

这三个组合去掉 B 或 F 后缺了必需属性，去掉 A、C、G 后剩 BF，已经算过不是超码，所以三者都是最小的。其他组合要么只是在 BF 上加 D、E（闭包还是 BDEF），要么包含 ABF、BCF、BFG 之一。

全部候选码为 ABF、BCF、BFG。

### 5. 逐步分解为 3NF（2014 年数据库原理A 四.3）

题目：设有关系 R 和函数依赖 F：R(A, B, C, D, E)， $F = \lbrace ABC \rightarrow DE,\ BC \rightarrow D,\ D \rightarrow E \rbrace$。请将关系 R 逐步分解为 3NF。

原卷无答案。

思路： $ABC \rightarrow DE$ 里的 A 是多余的，整条依赖能由另外两条推出。先求正则覆盖和候选码，看违反了哪一级范式，再按"先去部分依赖，再去传递依赖"一步步拆，最后用合成算法对一下答案。

解答（整理补充）：

第一步，求正则覆盖。右部拆开得到 $ABC \rightarrow D$、 $ABC \rightarrow E$、 $BC \rightarrow D$、 $D \rightarrow E$。

- $ABC \rightarrow D$ 中的 A：用原依赖集求 $(BC)^+$， $BC \rightarrow D$ 得 BCD， $D \rightarrow E$ 得 BCDE，含 D，A 多余。这条变成 $BC \rightarrow D$，和已有的重复。
- $ABC \rightarrow E$ 中的 A： $(BC)^+$ 含 E，A 多余，变成 $BC \rightarrow E$。
- $BC \rightarrow E$ 这条整体是否多余：去掉它，剩下 $\lbrace BC \rightarrow D,\ D \rightarrow E \rbrace$， $(BC)^+ = \lbrace B, C, D, E \rbrace$ 仍含 E，多余，删去。
- $BC \rightarrow D$： $B^+ = \lbrace B \rbrace$， $C^+ = \lbrace C \rbrace$，左部没有多余属性；去掉整条后 $(BC)^+ = \lbrace B, C \rbrace$，推不出 D，要保留。 $D \rightarrow E$ 同样要保留。

$$F_c = \lbrace BC \rightarrow D,\ D \rightarrow E \rbrace$$

第二步，求候选码。按原依赖集，A、B、C 只出现在左部，是 L 类；D 左右都有；E 只在右部。 $(ABC)^+ = \lbrace A, B, C, D, E \rbrace = U$，所以 ABC 是唯一的候选码。主属性是 A、B、C，非主属性是 D、E。

第三步，判断当前范式。

- $BC \rightarrow D$：D 依赖于候选码的真子集 BC，是部分依赖，R 不属于 2NF。
- $D \rightarrow E$： $ABC \rightarrow D$， $D \rightarrow E$，E 传递依赖于候选码。

第四步，逐步分解。

1. 消除部分依赖，得到 2NF。BC 决定 D，进而决定 E，把它们一起拆出去：
   - $R_1(B, C, D, E)$，依赖 $BC \rightarrow D$、 $D \rightarrow E$，候选码 BC；
   - $R_2(A, B, C)$，候选码 ABC，没有非平凡依赖。

   $R_1$ 中 E 通过 D 传递依赖于 BC，所以 $R_1$ 属于 2NF，不属于 3NF。
2. 消除传递依赖，得到 3NF。把 $R_1$ 按 $D \rightarrow E$ 拆开：
   - $R_{11}(D, E)$，候选码 D；
   - $R_{12}(B, C, D)$，候选码 BC。

分解结果为 $R_2(A, B, C)$、 $R_{12}(B, C, D)$、 $R_{11}(D, E)$，三个模式都属于 3NF（实际上都是 BCNF）。

检查：

- 用 3NF 合成算法做一遍： $F_c$ 的两条依赖得到 $(B, C, D)$ 和 $(D, E)$，都不含候选码 ABC，再加上 $(A, B, C)$，结果相同。
- 无损：第一次分解 $R_1 \cap R_2 = BC$，而 $BC \rightarrow BCDE$，即公共属性决定 $R_1$；第二次 $R_{11} \cap R_{12} = D$， $D \rightarrow DE$，即公共属性决定 $R_{11}$。两次都无损。
- 保持依赖： $BC \rightarrow D$ 在 $R_{12}$ 上检查， $D \rightarrow E$ 在 $R_{11}$ 上检查，原来的 $ABC \rightarrow DE$ 可以由这两条推出。
