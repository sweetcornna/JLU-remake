# 填空题与判断题精编

整理自 `期末笔记（考场版）/设计模式填空.docx`，并用 `历年题/2013级A卷(OCR).pdf` 的填空题和 `期末资料/《Java设计模式》刘伟 课后习题及模拟试题答案/` 里模拟试题的答案表核对了出处和答案。

这份填空稿里的题大多能查到出处。一部分是 2013 级 A 卷的填空题（标了"2013级"，模式部分基本是 GoF 书里各模式"适用性"的原话）；一部分和刘伟《Java设计模式》模拟试题的答案表对得上，"里氏代换""迪米特""简单工厂"到"访问者"这 10 个空是模拟试题一的填空题，第三节 20 道判断题是模拟试题三的判断题；还有行为特征那 10 条，是 2019 级荣誉课 A 卷的第一大题（设计模式识别题，每题 1 分）。整理稿作者提示这些题也可以改头换面成选择题出，复习时结合各模式的"适用场景"一起看，见 [02 创建型模式](<02 创建型模式.md>)、[03 结构型模式](<03 结构型模式.md>)、[04 行为型模式（上）](<04 行为型模式（上）.md>)、[05 行为型模式（下）](<05 行为型模式（下）.md>)。

## 一、设计原则与复用

| 题目 | 答案 |
| --- | --- |
| 在面向对象设计原则中，____ 是指子类应该可以替换父类并出现在父类能够出现的任何地方。 | 里氏代换原则 |
| 为了防止界面组件之间产生复杂的引用关系，可以提供一个中央控制器来专门负责控制界面组件之间的相互引用，这是使用 ____ 的重构实例。 | 迪米特法则 |
| （2013级）所谓高内聚，是指一个软件模块内各个元素彼此结合的紧密程度要高，即一个软件模块是由相关性很强的代码组成，只负责一项任务，也就是常说的 ____ 原则。 | 单一职责 |
| （2013级）对扩展开放，对修改关闭，是 ____ 原则。 | 开闭 |
| （2013级）面向对象系统中功能复用的两种最常用技术是类继承和对象组合。类继承允许你根据其他类的实现来定义一个类的实现。这种通过生成子类的复用通常被称为 ____。 | 白箱复用 |
| （2013级）在继承方式中，父类的内部细节对子类可见。对象组合是类继承之外的另一种复用选择。新的更复杂的功能可以通过组装或组合对象来获得。对象组合要求被组合的对象具有良好定义的接口。这种复用风格被称为 ____，因为对象的内部细节是不可见的。 | 黑箱复用 |

第二题的"中央控制器"其实就是中介者，出题角度是迪米特法则：组件之间不再直接引用，只和中央控制器通信。

## 二、看场景填模式

### 2013 级 A 卷填空（GoF 适用性原句）

| 题目 | 答案 |
| --- | --- |
| 当一个系统要由多个产品系列中的一个来配置时，我们选择 ____ 模式 | 抽象工厂 |
| 当创建复杂对象的算法应该独立于该对象的组成部分以及它们的装配方式时，我们选择 ____ 模式 | 建造者（生成器） |
| 当一个类希望由它的子类来指定它所创建的对象的时候，我们选择 ____ 模式 | 工厂方法 |
| 当一个系统应该独立于它的产品创建、构成和表示时，要使用 ____ 模式 | 原型（写抽象工厂也说得通，见下方说明） |
| 当类只能有一个实例而且客户可以从一个众所周知的访问点访问它时，要使用 ____ 模式 | 单例（单件） |
| 当你想使用一个已经存在的类，而它的接口不符合你的需求，要使用 ____ 模式 | 适配器 |
| 当你想表示对象的部分-整体层次结构，要使用 ____ 模式 | 组合 |
| 当不能采用生成子类的方法进行扩充时，要使用 ____ 模式 | 装饰 |
| 当你要为一个复杂子系统提供一个简单接口时，要使用 ____ 模式 | 外观 |
| 一个应用程序使用了大量的对象，要使用 ____ 模式 | 享元 |
| 在需要用比较通用和复杂的对象指针代替简单的指针的时候，使用 ____ 模式 | 代理 |
| 你想在不明确指定接收者的情况下向多个对象中的一个提交一个请求时，要使用 ____ 模式 | 职责链 |
| 访问一个聚合对象的内容而无需暴露它的内部表示，要使用 ____ 模式 | 迭代器 |
| 一组对象以定义良好但是复杂的方式进行通信，产生的相互依赖关系结构混乱且难以理解，要使用 ____ 模式 | 中介者 |
| 当对一个对象的改变需要同时改变其它对象，而不知道具体有多少对象有待改变，要使用 ____ 模式 | 观察者 |
| 一个对象的行为取决于它的状态，并且它必须在运行时刻根据状态改变它的行为，要使用 ____ 模式 | 状态 |

"当一个系统应该独立于它的产品创建、构成和表示"这句在 GoF 书里抽象工厂和原型两个模式的适用性中都出现过。2013 级这道题的 16 个空严格按 GoF 书里的模式顺序出（抽象工厂、生成器、工厂方法、原型、单件……），排在工厂方法之后、单件之前的这一空对应**原型**（更正：本文件初稿按抽象工厂给答案，逐空对照顺序见 [20 历年题（2011-2014级）](<20 历年题（2011-2014级）.md>) 2013 级填空题）。单独出现这句话时，还要看后半句："多个产品系列中的一个来配置"是抽象工厂，"要实例化的类在运行时指定""避免建立与产品平行的工厂层次"是原型，"创建算法独立于组成部分和装配方式"是建造者。

### 其他场景题

| 题目 | 答案 |
| --- | --- |
| ____ 模式可以根据参数的不同返回不同类的实例。 | 简单工厂 |
| 当需要创建的对象具有复杂的内部结构时，为了逐步构造一个完整的对象，并使得对象的创建更具弹性，可以使用 ____ 模式。 | 建造者 |
| 已知某子系统为外界提供功能服务，但该子系统中存在很多粒度十分小的类，不便被外界系统直接使用，采用 ____ 模式可以定义一个高层接口，这个接口使得这一子系统更加容易使用。 | 外观 |
| 当应用程序由于使用大量的对象造成很大的存储开销时，可以通过 ____ 模式运用共享技术来有效地支持大量细粒度对象的重用。 | 享元 |
| 在某电子商务系统中，站内检索功能的基本实现过程如下：先搜索商品表查询相关信息，再搜索商品类型表查询相关信息，然后搜索新闻表查询相关信息。该搜索次序可以灵活地调整并且可能会加入新的待查询的数据表。对于该站内检索功能，可采用 ____ 模式进行设计。 | 职责链 |
| 某软件公司计划开发一套简单的数据库同步指令，通过这套指令可以对数据库中的数据和结构进行快速备份，例如输入指令 `MOVE VIEW v_FemaleEmployee FROM srcDB to desDB` 表示将数据库 srcDB 中的视图 v_FemaleEmployee 移动至数据库 desDB 中。针对以上需求，可以使用 ____ 模式来设计该数据库同步指令系统。 | 解释器 |
| ____ 模式允许一个对象在其内部状态改变时改变它的行为。 | 状态 |
| 如果需要对一个集合对象中不同类型的元素施加不同的操作，可以采用 ____ 模式。 | 访问者 |

站内检索那题的判断依据是"次序可以灵活调整"和"可能加入新的数据表"：每张表一个处理者，链的顺序由客户端组装。

### 行为特征连线

2019 级荣誉课 A 卷第一大题原题：依据对设计目标或意图的简短描述，写出最适合的一个模式名称，不必解释。原稿按连线题整理。

| 行为特征 | 模式 |
| --- | --- |
| 支持转换行为 | 适配器 |
| 支持转移行为 | 命令 |
| 支持简化行为 | 外观 |
| 支持控制访问行为 | 代理 |
| 支持发布/订阅 | 观察者 |
| 可依据对象结构控制对象的产生 | 建造者 |
| 可依据对象的数据决定对象的行为 | 状态 |
| 能够在运行时改变一个对象的行为的算法 | 策略 |
| 可简化多个不同种类的对象之间复杂的关联或依赖关系 | 中介者 |
| 能够在不清楚具体步骤实现细节的情况下，给出一个过程的完整的流程定义 | 模板方法 |

"转移行为"指命令把"发出请求"和"执行请求"拆开，请求被封装成对象后可以传递、排队、记录，执行的时机和地点都转移了。

## 三、判断题

这 20 题和模拟试题三判断题的答案表一一对应。

| 题目 | 判断与理由 |
| --- | --- |
| 1. 一个类承担的职责越多，越容易复用，被复用的可能性越大。 | 错。职责多了耦合在一起，用到其中一项就得把其余的一起带上，反而难复用，这正是单一职责原则要避免的。 |
| 2. 工厂方法模式对应唯一一个产品等级结构，而抽象工厂模式则需要面对多个产品等级结构。 | 对。 |
| 3. 命令模式将一个请求封装为一个对象，从而使用户可用不同的请求对客户进行参数化。 | 对。这是命令模式的定义。 |
| 4. 在某酒店客房预订系统中，房间具有空闲、已预订、已入住等多个不同的状态，且在不同的状态下用户对于房间具有不同的操作行为，例如空闲的房间不支持退房操作，已入住的房间不支持再次入住操作等。此时可使用状态模式来设计该系统，状态模式可以封装对象状态的转换过程，增加新的状态无须修改已有代码，完全符合开闭原则。 | 错。前半句对，适合用状态模式；但增加新状态时，负责状态转换的代码（在环境类或其他具体状态类里）通常要改，状态模式对开闭原则的支持并不好。 |
| 5. 在某系统中经常需要重复创建一些相同或者相似的对象，可以考虑采用模板方法模式。 | 错。重复创建相同或相似对象应该用原型模式。 |
| 6. 控制对一个对象的访问，给不同的用户提供不同级别的使用权限时可以考虑使用虚拟代理。 | 错。按权限控制访问是保护代理；虚拟代理用来延迟创建开销大的对象。 |
| 7. 在某电子商务系统中站内检索功能的基本实现过程如下：先搜索商品表，再搜索商品类型表，然后搜索新闻表。该搜索次序可以灵活地调整并且可能会加入新的待查询的数据表。对于该站内检索功能，可采用职责链模式进行设计。 | 对。 |
| 8. Windows 操作系统中的应用程序桌面快捷方式体现了代理模式。 | 对。 |
| 9. 建造者模式允许用户可以只通过指定复杂对象的类型就可以创建它们，而不需要知道内部的具体构建细节。 | 对。客户端选好具体建造者交给指挥者即可，装配过程由指挥者和建造者完成。 |
| 10. Java I/O 库的设计应用了组合模式，其中 OutputStream 类和 InputStream 类充当抽象构件角色。 | 错。Java I/O 用的是装饰模式，InputStream、OutputStream 是抽象构件，FilterInputStream 一族是装饰类。 |
| 11. 合成复用将已有对象纳入新对象中，使之成为新对象的一部分，新对象可以调用已有对象的方法，从而实现行为的复用。 | 对。 |
| 12. 一个软件实体应当尽可能少地与其他软件实体发生相互作用，这样当一个模块修改时就会尽量少地影响其他模块，扩展会相对容易。 | 对。这是迪米特法则。 |
| 13. 接口应该尽量细化，同时接口中的方法应该尽可能少，理想情况是在每个接口中只定义一个方法，该接口使用起来最为方便。 | 错。接口隔离原则要求按角色拆接口，拆得过细会导致接口数量暴增，设计反而复杂，粒度要适中。 |
| 14. 在某多功能文本编辑器中允许用户插入图片、动画和视频等多媒体素材，为了节约系统资源，可使用享元模式来处理相同的素材。 | 对。相同素材只存一份，插入位置、大小等作为外部状态。 |
| 15. 在某财务系统中需要将阿拉伯数字（例如 1、2、3 等）转换成中文大写数字（例如壹、贰、叁等），并且系统需要支持中文大写数字的基本数学运算，例如"壹拾贰加贰拾捌"可计算得到"肆拾"，可以使用解释器模式来设计和实现该数字转换和计算功能。 | 对。 |
| 16. 某数据处理软件需要提供一个数据恢复功能，用户在操作过程中如果发生异常操作，可以将数据恢复到某一个历史状态。针对该需求可以采用备忘录模式来设计该数据恢复功能。 | 对。 |
| 17. 访问者模式让用户可以在不改变各元素对应的类的前提下定义作用于这些元素的新操作，在访问者模式中增加新的操作和元素都很方便，完全符合开闭原则。 | 错。增加新操作只要加一个访问者类，很方便；增加新元素类要在抽象访问者和所有具体访问者里加对应的 visit 方法，违背开闭原则（开闭原则的倾斜性）。 |
| 18. 采用模板方法模式可以定义一个操作中算法的骨架，而将一些步骤延迟到子类中实现。模板方法模式是一种代码复用技术，可以让系统更加符合合成复用原则。 | 错。前半句对，但模板方法靠继承复用，和合成复用原则提倡的组合方向相反。 |
| 19. 中介者模式通过引入一个中介对象来封装一系列其他对象之间的交互，降低对象之间的耦合度，使得系统更加符合迪米特法则。 | 对。 |
| 20. 电视机遥控器的设计中蕴含了迭代器模式和命令模式的思想。 | 对。按键对应命令对象，换台时逐个遍历频道对应迭代器。 |
