## 本章要点

四个模型按「同步方式 + 存储方式」两个维度就能串起来：PRAM 是共享存储加锁步同步，APRAM 是共享存储加路障同步，BSP 是分布存储加超级步路障，LogP 是分布存储加点对点即时通信。每个模型的复杂度公式都要会写，最后的四模型对比表是最常考的一道题。

## 8.1 并行算法基础

### 并行算法的定义

- **算法**：解题方法的精确描述，是一组有穷的规则，规定了解决某一类特定类型问题的一系列运算。
- **并行算法**：适合在各种并行计算机上求解问题和处理数据的算法，它是一些可同时执行的诸进程的集合，这些进程相互作用、协调动作，从而完成对给定问题的求解。

用途是解决大规模问题。

### 并行算法的分类

按三个维度各分两类：

| 维度 | 类别 | 含义 | 例子 |
| --- | --- | --- | --- |
| 运算基础 | **数值计算** Numerical Computation | 基于代数关系的运算 | 矩阵运算、多项式求解 |
| | **非数值计算** Non-Numerical Computation | 基于比较关系的运算 | 排序、选择、搜索、匹配、图论 |
| 进程间依赖 | **同步运算** Synchronized | 某些进程的执行必须等待别的进程（结果） | |
| | **异步运算** Asynchronized | 某些进程的执行不必等待别的进程（结果） | |
| 下一步怎么定 | **确定运算** Deterministic | 算法的每一步都能明确指明下一步如何行进 | |
| | **随机运算** Randomized | 算法的某一步随机地从指定范围内选取若干参数，由其确定下一步操作 | |

同步和异步是相对的。（更正：原文作「同步和一步是相对的」，「一步」是「异步」的笔误。）

### 算法的复杂度

时间复杂度和空间复杂度合称算法的复杂度。同一个算法里两者相互影响：追求较好的时间复杂度可能占用更多存储空间，追求较好的空间复杂度可能导致更长的运行时间。

设 $n$ 为问题规模，求解函数为 $f(n)$：

- **时间复杂度** Time Complexity：算法运行过程中占用执行时间大小的量度，记作 $T(n) = O(f(n))$。
- **空间复杂度** Space Complexity：算法运行过程中占用存储空间大小的量度，记作 $S(n) = O(f(n))$。

串行算法的复杂性度量分两种：最坏情况下的复杂度（Worst-Case Complexity）、期望复杂度（Expected Complexity）。

### 并行算法的复杂性度量指标

| 指标 | 定义 |
| --- | --- |
| **运行时间** $t(n)$ | 在给定模型上求解输入规模为 $n$ 的问题所需时间，即从第一台处理机开始执行到最后一台处理机执行中止所需时间 |
| 计算时间 $t_c$ | 在某一处理器执行运算所需时间 |
| 通信时间 $t_r$ | 数据从源处理机到目的处理机所需传送时间。算法在整个执行期间能传送的报文总数称为**通信复杂度** |
| **处理机数** $p(n)$ | 求解给定问题所需的处理机数量，通常取 $p(n) = n^c$，$0 < c < 1$ |
| **成本** $c(n)$ | $c(n) = t(n) \times p(n)$，即运行时间乘处理机数 |

**成本最优**（Cost Optimal）：$c(n) = t(n) \times p(n) = $ 串行计算的步数（节拍数）。

**工作量最优**：功耗低、环保。

### Brent 定理

令 $W(n)$ 是某并行算法 $A$ 在运行时间 $T(n)$ 内所执行的运算量，则 $A$ 使用 $p$ 台处理器可在

$$t(n) = O\!\left(\frac{W(n)}{p} + T(n)\right)$$

时间内执行完毕。

$W(n)$ 和 $c(n)$ 密切相关：

$$c(n) = t(n) \times p = O\!\left(\frac{W(n)}{p} + T(n)\right) \times p = O(W(n) + p \times T(n))$$

因此当 $p = O(W(n)/T(n))$ 时 $c(n) = O(W(n))$，$W(n)$ 和 $c(n)$ 两者渐近一致。

推论：对任意的 $p$ 都有 $c(n) \geq W(n)$，说明算法在运行过程中不一定能充分利用处理器。（原文写作 $c(n) > W(n)$，取等号的情况对应处理器被完全占满。）

习题里把这条写成了「Bernt 定理」（更正：应为 Brent 定理，正文里写对了）。

## 8.2 并行计算模型

并行计算模型指从并行算法的设计和分析出发，把各种并行计算机（至少某一类）的基本特征抽象出来，形成一个抽象的计算模型。从更广的意义上说，并行计算模型为并行计算提供了硬件和软件界面，在该界面的约定下，硬件设计者和软件设计者可以各自开发对并行性的支持机制，从而提高系统性能。

### PRAM 模型（SIMD-SM）

**并行随机存取机器**（Parallel Random Access Machine），也叫 SIMD-SM 模型，即共享存储的 SIMD 模型。

模型特点：

1. 一个集中的共享存储器，假设容量 $M$ 无限大。
2. $N$ 个功能相同的处理器，每个处理器有简单的算术运算和逻辑判断能力，每个处理器有局部存储器 LM（Local Memory）。
3. 所有指令按**锁步**方式操作。每一个计算步内，任一处理器都可通过对共享存储器某共享单元的读写与其他任一处理器交换数据，因此要求所有处理器**共享单一的数据地址空间**。
4. 每个处理器内部都没有控制器组件，所有处理器共享一个控制器，因此要求所有处理器**共享单一的程序地址空间**。
5. 采用**隐式同步机制**。处理器间通讯、存储管理、进程同步、存储带宽和延迟等低级操作细节都隐含在模型里。

结构图：一个共享存储器在上，下面挂 $N$ 个处理器 $P_1 \ldots P_N$，每个处理器各带一块 LM，所有处理器共用一个控制器。（原稿此处有图，PDF 中图片已丢失。）

#### 计算模式：三种竞争处理方式

按各处理器对共享存储器的竞争如何处理分三种。C 代表 Concurrent（允许并发操作），E 代表 Exclusive（禁止并发操作）。

| 模式 | 全称 | 强弱 |
| --- | --- | --- |
| PRAM-EREW | 互斥读互斥写 | 最弱 |
| PRAM-CREW | 并发读互斥写 | 居中 |
| PRAM-CRCW | 并发读并发写 | 最强 |

PRAM-CRCW 按并发写的裁决规则再分三类：

| 类别 | 规则 |
| --- | --- |
| **Common** PRAM-CRCW | 仅允许所有处理器同时写入相同数据 |
| **Priority** PRAM-CRCW | 仅允许优先级最高的处理器写入 |
| **Arbitrary** PRAM-CRCW | 允许任意处理器自由写入 |

#### 复杂度分析

对同一个算法的运行时间：

$$T_{EREW} \geq T_{CREW} \geq T_{CRCW}$$

$$T_{EREW} = O(T_{CREW} \cdot \log p) = O(T_{CRCW} \cdot \log p)$$

含义：如果一个算法在 PRAM-CREW 或 PRAM-CRCW 上的时间复杂度为 $T$，那么它可以在 PRAM-EREW 上以 $\log p \times T$ 的时间复杂度运行。换句话说，写能力强的模型最多只能省下一个对数因子。

### APRAM 模型（MIMD-SM）

**异步并行随机存取机器**（Asynchronous Parallel Random Access Machine），也叫 MIMD-SM 模型，也叫**分相（Phase）PRAM 模型**。

模型特点：

1. 一个集中的共享存储器，假设容量 $M$ 无限大。
2. $N$ 个处理器，每个处理器内部有简单的算术运算和逻辑判断电路、**独立的控制器**、局部存储器 LM、**独立的局部时钟**。
3. 处理器之间的通信通过共享存储器完成，因此要求所有处理器共享单一的数据地址空间。
4. 每个处理器有独立的控制器组件，因此要求所有处理器都有**独立的程序地址空间**。
5. **异步操作加显式同步**。系统没有全局时钟，每个处理器异步执行局部程序，处理器之间的时间依赖关系（例如通过共享变量读写实现通信）需要在各处理器的局部程序里加**同步路障**（Synchronization Barrier）来实现。两次同步路障之间的时间间隔称为一个**相**（phase）。

#### 计算模式

- 整个计算过程由一系列同步路障分开的多个全局相组成。
- 每个全局相内，每个处理器异步地运行其局部程序。
- 每个局部程序的最后一条指令是一条同步路障指令。
- 各处理器均可异步读写全局存储器，但同一个全局相内不允许两个处理器访问同一存储单元。

#### 复杂度分析

程序内指令分三类：全局同步、全局读/写、局部操作。

- 局部操作记为单位时间；
- 全局读/写平均时间为 $d$，$d$ 随处理器数目增加而增加；
- 同步路障时间为 $B = B(p)$，是处理器数 $p$ 的非降函数，处理器越多同步时间通常越长。

设 $T_i$ 为第 $i$ 个全局相内各处理器执行时间最长者，共 $n$ 个相，则

$$T = T_1 + T_2 + \cdots + T_n + B \times (n-1)$$

### BSP 模型（MIMD-DM）

**块同步并行模型**（Bulk Synchronization Parallel），也叫 MIMD-DM（distributed memory）模型、大同步模型、桥模型、桶同步并行模型。

模型特点：

1. 系统中有 $p$ 个计算节点，每个节点内部有独立的运算器、控制器、存储器、局部时钟。每个处理器有独立的数据地址空间和程序地址空间，可以异步执行局部程序。
2. 系统中有一个**路由器**，连接所有计算节点，实施节点之间点到点的消息传递。路由器的吞吐率和延迟有限：吞吐率 $t_h$（字节每秒），传输延迟 $t_l$（秒）。
3. 系统中有一个**路障同步器**，每隔时间间隔 $L$ 完成一次全局路障同步操作，用来实现节点之间的时间依赖关系。

#### 计算模式

整个计算过程由一系列用全局同步操作分开的、同步周期为 $L$ 的**超级步**（super step）组成。

- 每个超级步内，$p$ 个计算节点异步运行局部程序，并通过路由器收发消息。
- 路由器只做点到点消息传递，不提供组播、广播。路由器的消息收发能力用 $h$ 表示：每个处理器每超级步至多发送或接收 $h$ 条消息，称为 **h-relation**。某超级步内某节点收发总量超过 $h$ 会导致路由器拥塞，需要把该超级步扩展成多个超级步。
- **当前超级步中接收的消息，要到下一个超级步的计算中才可以使用。** 这条是 BSP 最容易考的细节。
- 每个超级步的时间片 $L$ 用完时，路障同步器发起一次全局路障同步检查。所有节点都完成本超级步的操作就打开路障，一起进入下一个超级步；只要有一个节点没完成，就保持路障，已到达的节点在路障处等待，未到达的节点再获得一个时间片 $L$。

实际实现中，每个超步结束后由各计算节点显式执行路障同步原语完成全局同步，代替周期性的同步检测。

代表性的进程代码：

```c
...                                 // 局部程序代码
Send(source, target, message);      // 源节点向目标节点发送一条消息
Receive(source, target, message);   // 目标节点从源节点接收一条消息
Global-Syn(k);                      // 第 k 次全局路障同步
...                                 // 局部程序代码
Send(source, target, message);
Receive(source, target, message);
Global-Syn(k+1);                    // 第 k+1 次全局路障同步
```

#### 复杂度分析

- $W_k$：第 $k$ 个超级步内各节点局部程序中本地计算运行时间最长者；
- $H_k$：第 $k$ 个超级步内各节点局部程序中收发消息个数最多者的收发操作执行时间；
- $B$：每次全局同步路障的开销；
- $q$：每个数据包大小（字节）。

$$H_k = h \times \left(t_l + \frac{q}{t_h}\right)$$

一个超级步内的总时间开销

$$T_k = W_k + H_k + B, \qquad T_k \leq L, \quad \text{效率} = \frac{T_k}{L}$$

$s$ 个超级步内的总时间开销

$$T = \sum_{k=1}^{s} W_k + \sum_{k=1}^{s} H_k + s \times B, \qquad T \leq s \times L, \quad \text{效率} = \frac{T}{s \times L}$$

（更正：原文把最后一个分母写成 $sc \times L$，多出来的 c 是笔误，应为 $s \times L$。）

#### BSP 模型小结

| 方面 | BSP 的做法与代价 |
| --- | --- |
| **有效避免死锁** | 把计算划分为超级步，同一超级步内不会互相等待 |
| **延迟通信** | BSP 把所有计算和通信视为一个整体行为，而不是单个进程的个体活动。它让每个进程尽可能把超级步内的消息收发押后，组成一个尽可能大的通信。好处是延迟的通信能提供更多优化通信的机会，坏处是延迟发送就意味着延迟接收 |
| **同步开销** | 依赖路障同步器。硬件实现横跨所有节点的路障同步器成本过大；软件实现同步库函数时，全部同步开销随节点个数增加而增大 |
| **硬件气泡** | 节点计算时网络资源空闲，节点收发消息时计算资源空闲；快速进程必须在路障处等慢速进程，造成节点空转。可以用节点内多进程或多线程来填充气泡 |
| **Tradeoff** | 编程的结构性对资源的有效性 |

#### BSP 与 MapReduce 对比

| | MapReduce | BSP |
| --- | --- | --- |
| 执行机制 | **数据流模型**。每个任务只对输入数据做处理，产生的输出数据作为另一个任务的输入。并行任务之间独立进行，串行任务之间以磁盘和数据复制作为交换介质和接口 | **状态模型**。各子任务在本地的子图数据上做计算、通信、修改图的状态等操作，并行任务之间通过消息通信交流中间计算结果，不需要像 MapReduce 那样对全体数据做复制 |
| 设计初衷 | 解决大规模、非实时数据处理问题。「大规模」决定数据有局部性可利用（因而可划分）、可以批处理；「非实时」代表响应时间可以较长 | 在实时处理上表现优异 |

两者最大的区别就在实时性这一条。

### LogP 模型（MIMD-DM）

LogP 用四个参数描述一种面向分布式存储器、点对点通信的多计算机系统的并行计算模型。

| 参数 | 全称 | 含义 |
| --- | --- | --- |
| **L** | Latency | 信息从源节点到目的节点所需的时间 |
| **o** | Overhead | 节点接收或发送一条消息所需的额外开销（操作系统开销和网络软件开销），这段时间内节点不能做任何操作 |
| **g** | Gap | 节点连续进行两次发送或接收消息之间必须有的时间间隔。超过此间隔数据包会因拥塞被网络丢弃，所以这个参数是对网络的限制而非对节点的限制 |
| **P** | Processor | 节点的数目 |

模型特点：

1. 系统中有 $p$ 个计算节点，每个节点内部有独立的运算器、控制器、存储器、局部时钟，每个处理器有独立的数据地址空间和程序地址空间，可以异步执行局部程序。
2. 系统中有一个大型互连网络（多个路由器节点组成的数据交换阵列），连接所有节点，实施点到点消息传递。带宽和延迟有限：带宽为 $g$ 的倒数（字节每秒），传输延迟 $L$（秒）。
3. 通过节点间的个体消息传递实现同步操作，消息一旦到达处理器就可以立即使用。

实际实现中，由各计算节点显式执行通信原语完成局部同步，代替周期性的同步检测。

代表性的进程代码（注意没有全局同步语句，而且收发顺序可以随局部逻辑变）：

```c
...                                 // 局部程序代码
Send(source, target, message);
Receive(source, target, message);
...                                 // 局部程序代码
Receive(source, target, message);
Send(source, target, message);
...                                 // 局部程序代码
```

#### 复杂度分析

一句话概括：

$$\text{LogP} = \text{BSP} + \text{Overhead} - \text{GlobalBarrier}$$

- 以 BSP 为基础，把所有并行进程按快慢分成若干子集，用每个子集内的小规模子集同步代替全局大同步。如果子集小到每个只包含两个进程（一个发送、一个接收），BSP 就变成了 LogP。
- LogP 的实质是把整个互连网络看作一个流水线部件，启动率为 $g$，延迟为 $L$，端点处理器开销为零。
- 网络容量有限：任何时刻从源处理器到目的处理器的网络路径上最多容纳 $L/g$ 条消息。
- 点到点传输一条消息的时间为 $o + L + o$。
- 当 $g = 0$、$L = 0$、$o = 0$ 时，LogP 等同于 PRAM。
- LogP 和 BSP 已被证明等效，可以相互模拟：用 BSP 模拟 LogP 通常慢常数倍，用 LogP 模拟 BSP 通常慢对数倍。
- SM 可以用 DM 模拟。

#### LogP 模型小结

| 方面 | LogP 的做法与代价 |
| --- | --- |
| **即时通信** | LogP 把计算和通信看作单个进程的个体活动，每个进程按需排布计算操作和消息收发，一旦收到消息立即可以使用 |
| **同步开销** | 不需要路障同步器，把路障同步的开销降低为两个进程之间的信息收发时间差 |
| **硬件气泡** | 节点计算时网络资源空闲，节点收发消息时计算资源空闲；但非阻塞进程不必等待阻塞进程，避免了节点空转。同样可用节点内多进程或多线程填充气泡 |
| **Tradeoff** | 编程的随意性对性能的可预测性 |

### Multi-BSP 模型（多层架构）

#### 为什么需要它

多核架构里有许多处理器、多个本地 cache、多个存储器，并行算法的设计和实施因此变难：

- 并行底层的算法设计比串行底层复杂得多；
- 设计出的并行算法要在性能上优于串行算法；
- 并行算法设计结果可能只是简单地增加处理器数量；
- 由于硬件差异，在本机上优化过的并行算法换一台电脑可能不起作用甚至起反作用。

#### 作用与结构

Multi-BSP 从两个方向拓展了 BSP：

1. 它是一个层次模型，可以表示单芯片或多芯片架构中的多个 memory 或多个 cache。
2. 每一层都把存储大小作为一个参数。

Multi-BSP 实际上是一棵深度为 $D$ 的树，内部节点表示 memory 和 cache，叶子节点表示处理器。这个模型不区分 memory 和 cache。每一层有四个参数 $(p_i, g_i, L_i, m_i)$：

| 参数 | 含义 |
| --- | --- |
| $p_i$ | 第 $i$ 级（层）组件里的 $i-1$ 级处理器的数量。$i=1$ 时可认为 $p_1$ 表示假想的 0 级处理器的数量 |
| $g_i$ | 通信带宽，$g_i = \dfrac{\text{处理器在一秒内执行的操作次数}}{\text{第 } i \text{ 级和第 } i+1 \text{ 级存储器之间一秒内传输的字数}}$。一个字是执行处理器操作的数据量（原稿记 1 Word = 2 Byte）。假设 $g_1 = 1$ |
| $L_i$ | 第 $i$ 层 superstep 的栅栏同步开销。这个栅栏指组件与组件之间的同步，不是分支语句引起的。特别地 $L_1 = 0$ |
| $m_i$ | 第 $i$ 层中存储器的数量 |

第 $i$ 层的 superstep 表示第 $i-1$ 层所有组件独立执行，直到到达同步栅栏。当 $i-1$ 层的组件全部到达 barrier 时，它们可以和第 $i$ 层的存储器交换信息，通信成本通常由 $m \cdot g_{i-1}$ 表示，其中 $m$ 表示第 $i$ 层组件的存储器与任何一个 $i-1$ 层子组件存储器之间传送的最大字数。然后下一层的 superstep 才开始执行。

Multi-BSP 是一个综合的计算模型，具有同步以及计算和通信的机制。定量计算证明，对于矩阵乘法、快速傅立叶变换、比较排序这类问题，即使参数很多，算法也可以在近似无参数的意义上做到最优。

#### 表达能力

用参数表把其他模型表示出来：

| 模型 | 深度 | 参数 |
| --- | --- | --- |
| 冯·诺依曼模型 | $d=1$ | $(p_1 = 1,\ g_1 = \infty,\ L_1 = 0,\ m_1)$ |
| PRAM 模型 | $d=1$ | $(p_1 \geq 1,\ g_1 = \infty,\ L_1 = 0,\ m_1)$ |
| BSP 模型 | $d=2$ | 第 1 层 $(p_1 = 1,\ g_1 = g,\ L_1 = 0,\ m_1 = m)$；第 2 层 $(p_2 = p,\ g_2 = \infty,\ L_2 = L,\ m_2)$ |

#### 算法评价

参数定义：

- $m = \min\{m_i \mid 1 \leq i \leq d\}$：每层缓存的最小值，表示数据处理的内存限制。
- $F_1, F_2$：两个基于不同参数集合（如 $p_i$、$g_i$、$L_i$、$m_i$）的函数，用于衡量不同层次的处理能力。

算法的相对效率：

- $F_1 \preceq F_2$：在某些条件下（如 $m$ 够大），对所有 $\epsilon > 0$ 都有 $F_1 < (1+\epsilon)F_2$。
- $F_1 \preceq_d F_2$：对某些依赖于 $d$ 的常量 $C_d$，假设 $m$ 和 $n$ 够大，则有 $F_1 < C_d F_2$。

Multi-BSP 算法的三种时间开销：$Comp(A^*)$ 并行计算开销、$Comm(A^*)$ 并行通信开销、$Synch(A^*)$ 并行同步开销。

$A^*$ 算法的基础定义：

- $Comp_{seq}(A)$：算法 $A$ 执行的计算操作总次数。
- $Comp(A)$：每个处理器执行的平均计算次数，$Comp(A) = Comp_{seq}(A)/P_d$，$P_d$ 是处理器数量。
- $Comm(A)$：在 $H$ 层上运行的算法的最小通信开销。
- $Synch(A)$：在 $H$ 层上运行的算法的最小同步开销。

满足下面三条就认为 $A^*$ 比 $A$ 更高效：

1. $Comp(A^*) \lesssim_d Comp(A)$，且 $Comp_{seq}(A^*) \lesssim Comp_{seq}(A)$
2. $Comm(A^*) \lesssim_d Comm(A)$
3. $Synch(A^*) \lesssim_d Synch(A)$

## 四个模型对比（常考）

| | PRAM | APRAM | BSP | LogP |
| --- | --- | --- | --- | --- |
| 别名 | SIMD-SM | MIMD-SM，分相 PRAM | MIMD-DM，桥模型 | MIMD-DM |
| 存储 | 集中共享存储器 | 集中共享存储器 | 分布存储，路由器传消息 | 分布存储，互连网络 |
| 控制器 | 所有处理器共用一个 | 每个处理器独立 | 每个节点独立 | 每个节点独立 |
| 程序地址空间 | 单一 | 独立 | 独立 | 独立 |
| 同步方式 | 锁步，隐式同步 | 显式同步路障，两障之间是一个相 | 全局路障，两障之间是一个超级步 | 无全局路障，靠点对点消息 |
| 通信何时可用 | 同一计算步内即可交换 | 相内异步读写共享存储 | 本超级步收到的消息下一超级步才能用 | 消息一到就能用 |
| 关键参数 | 无（理想模型） | $d$、$B(p)$ | $t_l$、$t_h$、$L$、$h$、$B$ | $L$、$o$、$g$、$P$ |
| 时间公式 | $T_{EREW} \ge T_{CREW} \ge T_{CRCW}$ | $T = \sum T_i + B(n-1)$ | $T = \sum W_k + \sum H_k + sB$ | 点到点 $o + L + o$ |
| 取舍 | 抽象，不反映通信代价 | 引入同步代价 | 结构性换资源有效性 | 随意性换性能可预测性 |

记忆线索：PRAM 到 APRAM 是把锁步换成路障，APRAM 到 BSP 是把共享存储换成消息传递，BSP 到 LogP 是把全局路障拆成点对点同步并加上端点开销 $o$。
