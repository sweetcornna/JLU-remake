## 本章要点

Amdahl 定律在第 1 章 1.4 节量化原理里已经出现过一次，那里讲的是单机上某个部件加速的情形，参数记作可改进比例和部件加速比；这一节换成了多处理器的语言，参数记作 $f$ 和 $p$。两套记法是同一个式子，做题时先看清题目给的是哪一套。

## 多处理器系统性能指标

### 工作负载

工作负载指一段时间内正在使用和等待使用 CPU 的平均任务数。CPU 使用率高不等于负载大。

- 一个程序一直占着 CPU 运算，使用率可能到 100%，但工作负载趋近于 1，因为 CPU 只负责一件工作。
- 同时跑两个这样的程序，使用率还是 100%，工作负载变成 2。

工作负载越大，CPU 越要在不同工作之间频繁做上下文切换。

### 峰值速度

计算峰值或浮点计算峰值指计算机每秒能完成的浮点计算最大次数，分理论浮点峰值和实测浮点峰值。理论浮点峰值主要由 CPU 主频决定：

$$\text{理论浮点峰值} = \text{CPU 主频} \times \text{CPU 每个时钟周期执行浮点运算的次数} \times \text{系统中 CPU 数}$$

中间那一项由处理器中浮点运算单元的个数，以及每个浮点运算单元每个时钟周期能处理几条浮点运算决定。

### 并行执行时间

$$T_n = T_{\text{comput}} + T_{\text{paro}} + T_{\text{comm}}$$

| 分量 | 含义 | 包含什么 |
| --- | --- | --- |
| $T_{\text{comput}}$ | 计算时间 | |
| $T_{\text{paro}}$ | 并行开销 | 进程管理时间（进程生成、结束、切换）；组操作时间（进程组生成、消亡）；进程查询时间（查询进程标识和等级、查询进程组的标识和大小） |
| $T_{\text{comm}}$ | 通信时间 | 同步时间（路障与事件、锁与临界区）；通信时间（点到点消息传递、共享变量读写）；聚合操作时间（规约操作、前缀运算） |

### 存储器性能

层次化存储结构，每一层都用三个参数表征：

| 参数 | 含义 | 单位 |
| --- | --- | --- |
| 容量 $C$ | 存储字节总量 | B（字节） |
| 延迟 $D$ | 读取一个字所需的全部时间 | s（秒） |
| 带宽 $B$ | 不同层次的存储器件间传输数据的速度 | Bps（Bytes Per Second） |

原稿画了一张存储层次图，链路是：寄存器 R 与 LSU Buff 互通，LSU Buff 连 L1 Cache，L1 连 L2，L2 连 L3，L3 连 Local Mem，Local Mem 分别连 Remote Mem 和 Local Disk，Remote Mem 连 Remote Disk。

## 通信开销

### 测量法（ping-pong scheme）

$K$ 个节点，用矩阵 $M[K \times K] = \{M_{ij}\}$ 记录两两之间的通信时延，每一对节点之间做一次来回传送再记时间：

```c
For (i=0; i<K; i++)
  For (j=0; j<K; j++)
  {
    If (my_id == i)              // 当前节点是 i
    {
      recordStart();             // 记录开始时间
      send m-Bytes to node j;    // 向节点 j 发 m 字节
      receive m-Bytes from node j;
      recordEnd();               // 记录结束时间
      M[i][j] = End - Start;     // 节点 i 到节点 j 的通信时延
    }
    If (my_id == j)              // 当前节点是 j，收了再发回去
    {
      receive m-Bytes from node i;
      send m-Bytes to node i;    // 形成一次双向通信
    }
  }
```

（更正：原稿写的是 `If (my_id = i)`，单个等号是赋值，条件判断要用 `==`。原稿的 `For (i=0,i<K,i++)` 用逗号分隔，C 语言里应为分号。）

注意 $M[i][j]$ 量的是一个来回的时间，拿它当单向时延时要除以 2。

### 解析法

发送一个长度为 $m$ 字节的消息，通信开销

$$T(m) = T_0 + \frac{m}{R_\infty}$$

- $R_\infty$ 是**渐近带宽**，单位 MBps。
- $T_0$ 是**通信延迟**，又叫**启动时间**。 $T_0$ 这段时间都在打通数据通路，第一个字节还没到达； $T_0$ 之后每隔一个周期时间到达一个字节。

消息越长， $T_0$ 被摊薄得越厉害，有效带宽越接近 $R_\infty$。短消息合并成长消息能省时间，原因就在这里。

### 整体通信开销的测量

各种集合通信的通信量：

| 操作 | From | To | 消息 | 传输量 |
| --- | --- | --- | --- | --- |
| 播送 Broadcast | 1 | N | 同一个 | M 个字节 |
| 收集 Gather | N | 1 | 不同 | M×N 个字节 |
| 散射 Scatter | 1 | N | 不同 | M×N 个字节 |
| 全交换 Total Exchange | N | N | 不同 | M×N×N 个字节 |
| 循环移位 Circular-shift | CPU[i] | CPU[i+1] | 不同 | M×N 个字节 |

全交换的传输量是 $M N^2$，比其他操作高一个量级，这也是第 3 章里 `MPI_Alltoall` 要慎用的原因。

## 性能价格比

- 价格 = 原料成本 + 直接成本 + 毛利 + 折扣。
- **性能价格比**（Performance/Cost Ratio）指用单位代价（通常以百万美元表示）所获取的性能（通常以 MIPS 或 MFLOPS 表示）。
- 高性能价格比意味着成本是有效的，成本的有效性用利用率衡量。
- **机器的利用率**（Utilization）= 可达到的速度 / 峰值速度。
- 性价比决定技术选型，比如超算和工作站集群之间怎么选。

## 多处理器性能定律

**多处理器系统的加速比**：对于给定的应用，并行算法（或并行程序）的执行速度相对于串行算法（或串行程序）的执行速度加快了多少倍。

三个定律适用的条件不同：

| 定律 | 什么时候用 |
| --- | --- |
| Amdahl 定律 | 计算负载固定时 |
| Gustafson 定律（1988） | 问题具备可扩放性时 |
| Sun&Ni 定律 | 存储器受限时 |

### 参数约定

| 符号 | 含义 |
| --- | --- |
| $p$ | 并行系统中处理器数 |
| $W$ | 问题规模，计算负载总量 |
| $W_s$ | 应用程序中的可串行分量 |
| $W_p$ | 应用程序中的可并行分量 |
| $f$ | 可串行分量的比例， $1-f$ 是可并行分量的比例 |
| $T_s$ / $T_p$ | 串行执行时间 / 并行执行时间 |
| $S$ / $E$ | 加速比 / 效率 |

### Amdahl 定律

出发点：在实时性要求很高的应用里，计算负载固定不变，把这些负载分布到多个处理器上，增加处理器可以加快执行速度。Amdahl 定律侧重减少给定的固定大小问题的时间，它指出问题（算法）的顺序部分限制了随系统资源增加可以实现的总加速。

$$S = \frac{W_s + W_p}{W_p/p + W_s} = \frac{p}{1 + f(p-1)} = \frac{1}{f + \dfrac{1-f}{p}} \xrightarrow{p \to \infty} \frac{1}{f}$$

处理机数无限增加时加速比收敛到 $1/f$， $f$ 就是程序的瓶颈。

**几何意义**，三张图：

- (a) 工作负载 $W$ 随处理器数 $p$ 不变，每根柱子都是 $W_1$ 加 $W_p$，高度一样。
- (b) 执行时间 $T$ 随 $p$ 增加而下降， $T_1$ 部分不变， $T_p$ 部分越来越薄。
- (c) 横轴是程序中顺序部分的百分比 $f$，纵轴是加速比 $S$，曲线 $S_{1024} = \dfrac{1024}{1 + 1023f}$ 从 1024 倍陡降到 1 倍。

$p = 1024$ 时这条曲线上的几个点（已用 Python 复核）：

| $f$ | 0 | 1% | 2% | 3% | 4% | 5% | 100% |
| --- | --- | --- | --- | --- | --- | --- | --- |
| $S$ | 1024 | 91.2 | 47.7 | 32.3 | 24.4 | 19.6 | 1 |

串行比例只要有 1%，1024 个处理器就只剩 91 倍加速，这是这张图最该记住的一点。（原稿图上 3% 处标的是 31x，按公式算是 32.3x，差别来自读图取点，答题按公式算即可。）

### Gustafson 定律

出发点：在对精度要求很高的应用里，为了提高精度必须加大计算量，相应地要增多处理器个数才能维持计算时间不变。这类应用通常先在小规模计算资源上跑粗粒度做调试测试，再到大规模计算资源上跑细粒度做正式运行。

$$S' = \frac{W_s + pW_p}{W_s + p \cdot W_p/p} = \frac{W_s + pW_p}{W_s + W_p} = \frac{W_s}{W_s + W_p} + \frac{pW_p}{W_s + W_p} = f + p(1-f) = p - f(p-1)$$

$p$ 充分大时加速比与处理器数量几乎呈线性关系， $f$ 不再是瓶颈。

**几何意义**，三张图：

- (a) 工作负载 $W$ 随 $p$ 增加而增加， $W_1$ 部分不变， $W_p$ 部分越来越厚。
- (b) 执行时间 $T$ 保持不变，每根柱子一样高。
- (c) 横轴还是 $f$，曲线 $S'_{1024} = 1024 - 1023f$ 是一条几乎平的直线。

$p = 1024$ 时（已用 Python 复核）：

| $f$ | 0 | 1% | 2% | 3% | 4% |
| --- | --- | --- | --- | --- | --- |
| $S'$ | 1024 | 1013.8 | 1003.5 | 993.3 | 983.1 |

和上面 Amdahl 那张表放一起看，同样的 $f=1\%$，一个掉到 91 倍，一个还有 1014 倍。差别全在负载是不是跟着处理器一起长。

### Sun&Ni 定律

出发点：Amdahl 定律和 Gustafson 定律各代表一种极端情况。为了把两者统一成一般化形式，Xian-He Sun（孙贤和，美国伊利诺伊理工学院计算机科学系教授）和 Lionel Ni（倪明选）于 1993 年提出了 Sun&Ni 定律。

这两个定律都没有对处理器个数和存储容量做限制，而实际上多节点并行系统里可求解问题的规模受存储容量限制。Sun&Ni 的基本思想是：只要存储空间许可，就尽量增大问题规模以产生更好更精确的解（此时执行时间可能略有增加），目标是更大的加速比、更高的求解精度、更好的资源利用率。

参数约定： $p$ 个节点，每个节点存储容量为 $M$，全部存储容量为 $pM$。问题规模从一个节点扩大到 $p$ 个节点，对存储的需求增加 $p$ 倍，并行工作负载计算量增大 $G(p)$ 倍。扩大前 $W = fW + (1-f)W$，扩大后 $W = fW + (1-f)W \cdot G(p)$。

$$S'' = \frac{fW + (1-f)G(p)W}{fW + (1-f)G(p)W/p} = \frac{f + (1-f)G(p)}{f + (1-f)G(p)/p}$$

（更正：原文右边那个分式写成 $\dfrac{f + (1+f)G(p)}{f + (1+f)G(p)/p}$，两处 $(1+f)$ 都应为 $(1-f)$，左边分式里写的就是 $(1-f)$，前后对不上。）

两个特例正好退回前两个定律：

| $G(p)$ | 结果 | 对应 |
| --- | --- | --- |
| $G(p) = 1$ | $S'' = \dfrac{1}{f + (1-f)/p} = S$ | Amdahl 定律，存储量增加 $p$ 倍而负载计算量不变 |
| $G(p) = p$ | $S'' = f + (1-f)p = S'$ | Gustafson 定律，存储量增加 $p$ 倍，负载计算量也增加 $p$ 倍 |

**几何意义**：负载随处理器数目的增加而增大，执行时间也相应增加。图 (a) 的工作负载柱子越来越高（比 Gustafson 涨得更快），图 (b) 的执行时间柱子也在涨（Gustafson 那张是平的）。

## 加速等级

| 等级 | 定义 |
| --- | --- |
| **绝对加速** | 对于给定的问题，最佳串行算法所用时间除以同一问题的并行算法所用时间 |
| **相对加速** | 同一问题的求解算法在单处理机上的运行时间除以在多个处理机上的运行时间 |
| **超线性加速** | 在特殊条件下产生的加速比 $S$ 大于处理器数 $p$ 的情况 |

超线性加速的两个例子：

1. 某并行搜索算法，不同处理器在不同分支方向上并行搜索，某一处理器迅速找到最优解并立即向所有处理器发终止信号，省掉了本该搜索的分支。
2. 某并行计算算法，只在一个处理器上算时 Cache 容量远小于滑动时空窗口，导致内存访问甚至硬盘访问；放到多个处理器上并行算时，所有处理器的 Cache 共同组成一个大的逻辑 Cache，容量大于滑动时空窗口，大幅降低内存和磁盘访问，节省的时间超过多处理器的通信开销。

## 加速比总结

由三个定律可知，处理器数量和问题规模都会影响加速比。除此之外影响加速比的因素：

- 求解问题中的串行分量；
- 并行处理引起的额外开销（通信、等待、冗余操作等）；
- 处理器数目的增加超过了算法中的并发程度。

增加问题规模有利于提高加速比，原因有三条：

- 加大问题规模可提供较高的并发程度；
- 额外开销的增加可能慢于有效计算的增加；
- 算法中串行分量的比例不是固定不变的，可能随问题规模增加而相对缩小。

增加处理器数会增大额外开销、降低处理器利用率，所以对一个特定的并行应用，它有效利用不断增加的处理器的能力是受限的。

## 易混对比速查

| 容易混的 | 区别 |
| --- | --- |
| Amdahl / Gustafson | 前者负载固定、时间缩短，加速比上限 $1/f$；后者时间固定、负载扩大，加速比近似线性 |
| Gustafson / Sun&Ni | 前者负载随 $p$ 线性增长且时间不变；后者负载按 $G(p)$ 增长且时间也增加 |
| 绝对加速 / 相对加速 | 分母都是并行时间，分子一个是最佳串行算法，一个是同一算法的单机运行 |
| 工作负载 / CPU 使用率 | 负载数的是任务数，使用率量的是忙闲比例 |
| $T_0$ / $R_\infty$ | 启动时间是固定开销，渐近带宽决定随消息长度增长的那一部分 |
| 峰值速度 / 利用率 | 峰值是理论上限，利用率是实测速度与峰值之比 |
