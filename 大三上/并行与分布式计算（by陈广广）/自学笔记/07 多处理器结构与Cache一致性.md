## 多处理器存储结构分类

按内存是否共享分两大类，每类四个点，考点里写的「2\*4 点」就是这个意思。

### 非共享存储多处理器

- 每个处理器**内存私有**，逻辑上独立编址不共享，**没有 Cache 一致性问题**。
- 属于**松散耦合**系统，支持**消息传递**编程模型，比如 OpenMPI。
- 多个处理器分散在多台计算机里，本质是**多进程 MIMD** 问题。
- 例子：集群工作站（Cluster of Workstations, COW）、大规模并行处理机（Massively Parallel Processing, MPP）。

### 共享存储多处理器

- 所有处理器**内存共享**，逻辑上统一编址，**有 Cache 一致性问题**。
- 属于**紧密耦合**系统，支持**共享存储**编程模型，比如 OpenMP。
- 多个处理器在同一台计算机里，本质是**多线程 MIMD** 问题。
- 例子：UMA、NUMA。

记忆窍门：私有内存配消息传递配多进程，共享内存配共享变量配多线程，四条一一对应，不会记混。

### 工作站机群 COW（5 点）

- 每个节点是一套完整的计算机系统（SMP 或工作站），有本地磁盘和独立完整的操作系统。
- 用**低成本的商用互联网络**实现节点间互联。
- 作业通常由大量**服务**组成，服务各有自己的私有地址空间。
- 服务之间用 RPC 或 RESTful API 互相调用，靠**消息队列**协调工作流程。（更正：原文作「ResfulAPI」，应为 RESTful API）
- 面向企业级应用，特点是廉价、大规模、可扩展，典型是 Hadoop 上的 MapReduce。

### 三高系统目标（3\*3 点）

COW 这类机群系统追求的三个目标，每个目标三条手段，括号里是原稿给的验证实验。

| 目标 | 三条手段 | 怎么验证 |
| --- | --- | --- |
| 高可用 | 结构鲁棒性（多活实例）、数据可靠（热备与副本）、可重构系统（多点协同） | 节点宕机与链路断路实验 |
| 高性能 | 负载均衡（反向代理）、弹性计算（web service）、低延迟（消息队列、分布式缓存） | 峰值性能暴力测试 |
| 高可信 | 数据加密、身份认证、权限控制 | 无 |

### 大规模并行处理机 MPP（5 点）

- 用**高带宽低延时**的通信网络实现节点间互联。
- 可扩放性好，支持数百万到千万级别的处理器规模。
- 作业通常由大量**进程**组成，进程各有自己的私有地址空间。
- 进程之间用**消息传递**机制，常采用**阻塞报文**交互方式。
- **一个操作系统管理所有硬件**。

MPP 和 COW 最好对着背，五条里有三条是镜像的：网络贵 vs 网络便宜、进程 vs 服务、一个 OS vs 每节点一个 OS。

### 超算与申威 CPU 架构

超级计算机被称为「国之重器」，MPP 是它的主流形态。

申威采用**主从异构结构**，由少量通用主核 MPE（Main Processor Element）和大量精简的从核（SPE，Synergistic Processor Element）组成，计算峰值很高。每个从核是一个协从运算单元，不支持硬件线程切换，不能运行操作系统，任务由主核分配。典型型号申威 26010，指令集源自 DEC Alpha 21164。

## 共享存储多处理器的分类

这一节同样是「2\*4 点」，两类结构各四个名字或特征。

### 集中式共享存储多处理器

- CSM：Centralized Shared-Memory Multiprocessor
- SMP：Symmetric Shared-Memory Multiprocessor
- UMA：Uniform Memory Access Multiprocessor，UMA 结构就是集中式共享存储体系结构
- 处理器访问存储器的时间是**一样的**（均匀的）

### 分布式共享存储多处理器

- DSM：Distributed Shared-Memory Multiprocessor
- AMP：Asymmetric Shared-Memory Multiprocessor
- NUMA：Non-Uniform Memory Access Multiprocessor，NUMA 结构就是分布式共享存储体系结构
- 处理器访问存储器的时间是**不一样的**（非均匀）

考点要求「画出 UMA 和 NUMA 的结构图」。原稿这两张图的链接已失效，按下面的样子画就对：

UMA：多个 CPU（每个带自己的 Cache）挂在同一条总线或一个交叉开关上，总线另一端接**一个**集中的共享存储器和 I/O。画的时候把存储器画在正中间，CPU 围在四周，每条连线等长，意思是任何 CPU 到存储器的距离都相同。

```
   CPU        CPU
     \        /
      \      /
  CPU--[ 共享存储器 ]--CPU
        （集中式）
```

NUMA：每个节点里是「CPU + Cache + 本地存储器 + I/O」，节点之间挂在一个互连网络上。访问本地存储器快，访问别的节点的存储器要走互连网络，所以慢。下面目录协议那一节的结构图就是标准的 NUMA 画法，把「目录」那一格去掉就是纯 NUMA。

## 处理器结构进化之问

单核靠提频率提性能走不下去了，原因是三个问题，考点要求答 3 点。

- **功耗问题**：芯片密度和时钟频率不断提高，系统功耗呈指数增长。原稿给的关系式是「芯片发热量 $= k \times$ 芯片密度 $\times$ 时钟频率」。（更正：原文写作 `芯片发热量=k&芯片密度*时钟频率`，其中 `&` 应为乘号）
- **制程问题**：CPU 制程精度逐步逼近制造设备的物理极限，摩尔定律失效。
- **复杂度问题**：超长流水线、超标量流水线、同时多线程等 ILP 技术让逻辑电路复杂度指数级增加，芯片设计、制造、调试都越来越难，流水线深度和宽度的扩展出现瓶颈。

## 多核技术

考点要求答 3 点，就是下面三句。

- 原有的**多处理器指的是多个 CPU**，每个 CPU 是单核的。多核技术是多处理器技术的进一步扩展，指**在一枚处理器中集成两个或多个完整的计算内核**，以此提高计算能力。
- 多核 CPU 采用了与原来单 CPU 相同的硬件体系结构，计算能力提上去了，硬件技术不用改。
- 当前 90% 以上的个人计算机处理器都是多核的。

多核架构的研究内容有四项，答多核技术的时候可以顺手带上：片内处理核心的个数、Cache 层次和容量分布、互连结构、晶体管使用的平衡度。

## 典型多核结构

四种结构，考点要求画图说明。四张图的骨架一样，差别只在「哪一级 Cache 是共享的，哪一级在片内」。画的时候先画一排 CPU 内核，每个核下面挂一对 L1 指令 Cache 和 L1 数据 Cache，再按下面的区别接后面几级。

### 专用 L1-Cache 结构

- 早期多核处理器的组织架构，现在在**嵌入式芯片**里还能见到。
- **只有一级片内 Cache**，每个核带自己的专用 L1 Cache，分成指令 Cache 和数据 Cache。
- 典型实例：**ARM11 MPCore**。
- 画图：芯片框里只有「内核 + L1 指令/数据 Cache」，L2 Cache 画在芯片框**外面**，L2 再接主存，主存旁边接 I/O。

### 专用 L2-Cache 结构

- 片内有足够的可用面积容纳多个 L2 Cache，所以每个核各带一个自己的 L2，**没有片内共享 Cache**。
- 典型实例：**AMD Opteron**。
- 画图：芯片框里每个核下面是「L1 指令 + L1 数据」，再下面是这个核**自己的 L2 Cache**；各个 L2 出芯片框后汇到一起接主存和 I/O。

### 共享 L2-Cache 结构

- 存储空间分配和专用 L2 类似，区别在于这套架构**拥有共享的 L2 Cache**。
- 典型实例：**Intel Core Duo**。
- 画图：芯片框里每个核带 L1 指令/数据，下面是**横跨所有核的一整条 L2 Cache**，出框接主存和 I/O。

### 共享 L3-Cache 结构

- 出于性能考虑分离出一个独立的三级 Cache。每个计算内核除了拥有专用的一级、二级 Cache，还共享 L3 Cache。
- 典型实例：**Intel Core i7**。
- 画图：芯片框里每个核带 L1 指令/数据和自己的 L2，最下面是**横跨所有核的一整条 L3 Cache**，出框接主存和 I/O。

### 基于 Cache 结构的优点（3 点）

考点提示的三个关键词是通信开销、不命中、系统功耗。

- 全局数据在共享 Cache 级上不需要复制，**内核间通信开销低**。
- 层次化 Cache 系统化地减少整个系统的不命中概率，局部线程能用上更多 Cache 空间。
- Cache 在芯片晶体管面积中占比增大，可以降低系统功耗。

## Cache 一致性问题

### 共享数据引发的问题

在共享存储多处理器结构中，只供一个处理器使用的数据叫**私有数据**，多个处理器共同使用的数据叫**共享数据**，各处理器通过对共享数据的读写来实现通信。

数据进入 Cache 可以减少平均访存时间，减轻对存储器的带宽要求。但是：

- 私有数据进入 Cache，不会引入新问题。
- **共享数据进入 Cache**，同一存储块就会在多个处理器的 Cache 里各有一份副本。某个处理器改了自己 Cache 里的副本之后，这份副本和其他副本的数据就对不上了，这就是**多处理机的 Cache 一致性问题**。

考点要求「画图说明」。原稿此处有图，PDF 中图片已丢失，按下面这个三步画就能说清问题：

1. 画三个 CPU，每个带一个 Cache，都挂在总线上，总线下面是共享存储器，里面存着 `X = 0`。
2. 三个 CPU 都读过 X，于是三个 Cache 里各有一份 `X = 0` 的副本。
3. CPU1 把自己 Cache 里的副本改成 `X = 1`。这时 CPU1 的 Cache 里是 1，CPU2、CPU3 的 Cache 里还是 0，存储器里也可能还是 0。CPU2 再读 X 就读到过期的值。

### Cache 基本结构

计组学过的内容，考的概率不大，记个大概。原稿此处有图，PDF 中图片已丢失，图讲的就是下面这套查表流程。

Cache 的组成：

- **Cache Data Table（数据表）**：存实际缓存的数据块，每个数据块对应特定的主存地址。
- **Cache Lookup Table（查找表）**：存每个数据块的标识信息 Tag 和两个额外字段。
  - EF（有效位，Valid Bit）：当前缓存数据是否有效。1 表示有效，0 表示无效、不能直接用。
  - DF（脏位，Dirty Bit）：当前缓存数据是否被修改过。
  - 标识信息用来快速判断某个数据块在不在缓存里。

工作流程：

1. **主存地址分解**。主存地址被拆成三段：Tag（标记，标识数据块的唯一信息）、Index（索引，定位到具体的 Cache 行）、Offset（偏移量，访问数据块中的特定字节）。
2. **目录匹配**。把主存地址的 Tag 和查找表里的 Tag 字段比较。找到匹配项且 EF 为 1 就是命中（Hit），直接从 Cache 读；Tag 不匹配或 EF 为 0 就是未命中（Miss），要从主存加载。

## Cache 一致性协议的分类

三组二选一，考点要求答「3\*2 点」。把三组各自解决的场景记住就不会串。

| 分类 | 二选一 | 区别在哪 |
| --- | --- | --- |
| 写作废（Write invalidate）vs 写更新 | 发生 WtHit 时 | 把其他副本**全部作废**，还是把新数据**同步更新**到所有副本 |
| 写直达 vs 替换写回 | 发生 RdMiss / WtMiss 时 | 去**存储器**拿最新数据，还是从**远程 Cache** 拿最新数据 |
| 按写分配（经过 Cache）vs 不按写分配（绕过 Cache） | 发生写操作时 | **先调入本地 Cache 再写**，还是直接到数据所在处写 |

写直达的含义：既写 Cache 又写内存。

写更新和写作废谁更好，要拿 Benchmark 测三项：

- 占用总线进行**状态信息**传输的次数、内容和数据量。
- 占用总线进行**数据**传输的次数、内容和数据量。
- 对同一个数据，从对它的写操作到对它的读操作之间的延迟。

## Cache 一致性协议的两种实现方式

两种方式用不同技术来记录和传递共享数据块的状态。

### 监听式协议

- 基于**总线**传递信息，是 **1 对 N** 的广播。
- 存储器中数据块的共享状态信息**分散保存在各个 Cache 中**。物理上分布的各个存储器拼成逻辑上统一的大存储器，物理上分布的 Cache 状态信息拼成逻辑上统一的 Cache 热状态。
- 所谓监听，就是每个 CPU 都有一个 Cache 控制器，随时判断总线上经过的数据，看自己这里有没有总线上请求的那个数据块。

### 目录式协议

- 基于**互连网络**传递信息，是 **1 对 1** 的点对点通信。
- 存储器中数据块的共享状态信息**集中保存在本地目录中**。物理上分布的各个存储器拼成逻辑上统一的大存储器，物理上分布的目录拼成逻辑上统一的大目录。

一句话区分：监听靠广播，目录靠点名。

## 监听协议的实现

答这道题按「保存什么信息 / 传递什么信息 / 状态、操作、时序」三段走。

### 保存什么信息

- 替换写回法里 Cache 的**修改位（dirty flag）** 可以直接用来实现一致性。修改位置 1 的那份，必然是系统中唯一的最新副本。
- Cache 原有的**有效位**可以直接实现作废操作。
- Cache 原有的 **Tag** 可以直接实现监听，靠地址 Tag 比对。
- 给每个 Cache 块**增设一个共享位**，独占为 0，共享为 1。

前三条都是现成的，只有第四条要新加，这也是监听协议「实现容易、成本较低」的原因。

### 传递什么信息

只有三种：`RdMiss` / `WtMiss` / `Invalidate`。

### 状态、操作、时序

- 每个 Cache 控制器内嵌一个**有限状态机**。
- 操作包括：改变 Cache 状态、通过总线访问存储器、通过总线发送 Cache 作废。
- **写访问串行化靠总线控制权的竞争来保证**。

### 实例：写作废协议 + 替换写回法 + 按写分配 + 监听协议

每个 Cache 包含四个部件：Cache 控制器、Cache 地址表（lookup table）、Cache 数据表（data table）、Cache 状态表。

每个 Cache 中的数据块只有三种状态：

| 状态 | 含义 |
| --- | --- |
| **Invalid（I）** | 无副本 |
| **Shared（S）** | 至少 1 副本，且存储器中的值是最新值，clean，只读 |
| **Modified（M）** | 唯一副本，且存储器中的值是旧值，dirty，读写 |

Cache 控制器有**两个探针**：一个探针监听本地 CPU，一个探针监听共享总线。每个 CPU 只与本地 Cache 控制器交互，**CPU 不连入共享总线**，所有远程访问都经过本地 Cache 控制器实现。

### 监听总线 + 写作废 + 写直达

考点要求画图描述。原稿此处有图，PDF 中图片已丢失，按下面四步画时序就是答案：

1. 初始：CPU1、CPU2、CPU3 的 Cache 里都有块 X 的副本，值为 0，存储器里也是 0。
2. CPU1 写 `X = 1`：写直达，新值同时写进本地 Cache 和存储器；同时向总线发 `Invalidate(X)`。
3. CPU2、CPU3 的控制器从总线上监听到 `Invalidate(X)`，把自己的副本置无效。
4. 之后 CPU3 读 X：本地无效，发 `RdMiss` 上总线，从存储器读回 1。

### 监听总线 + 写更新 + 写直达

同样是丢失的图，改成这样画：

1. 初始状态和上面一样，三份副本都是 0。
2. CPU1 写 `X = 1`：写直达，写本地 Cache 和存储器；同时把**新值本身**通过总线广播出去。
3. CPU2、CPU3 监听到广播，直接把自己的副本更新为 1，副本仍然有效。
4. 之后 CPU3 读 X 直接命中，读到 1，不产生总线事务。

两张图放在一起看，差别就是总线上传的是「作废信号」还是「新数据」。

### 本地 Cache 控制器监听本地 CPU 的状态转换表

这张表是考点明确点名的。表里 K 指请求地址，K1 是被替换掉的旧块地址，K2 是要调入的新块地址；B、B1、B2 分别是 K、K1、K2 对应的目录节点。目录协议里这张表和监听式完全一样，所以背一遍能用两次。

| Cache 块当前状态 | 查询结果 | Cache 控制器操作 | 状态变更 |
| --- | --- | --- | --- |
| I | RdHit | 不可能 | — |
| S | RdHit | read data | S |
| M | RdHit | read data | M |
| I | RdMiss | send RdMiss(K), 待收到 Data(K) 后 read data | S |
| S | RdMiss | 此时 clean 副本将被替换：send Quit(K1), send RdMiss(K2), 待收到 Data(K2) 后 read data | S |
| M | RdMiss | 此时 dirty 副本将被替换：send Update(K1), send RdMiss(K2), 待收到 Data(K2) 后 read data | S |
| I | WtHit | 不可能 | — |
| S | WtHit | send Invalidate(K), write data | M |
| M | WtHit | write data | M |
| I | WtMiss | send WtMiss(K), 待收到 Data(K) 后 write data | M |

### 监听式协议小结

- 两种情况下 Cache 块写回存储器：**发生 M 块替换**，以及 **M 变 S 之前**。
- 两种情况下作废：**收到 Invalidate**，以及**收到 WtMiss**。
- 调入新块时，优先从远程 Cache 调，没有才从存储器调。多个远程 Cache 可能都有 S 状态的副本，几个 Cache 要竞争。这样能最大程度减少对内存的访问，因为访问内存慢。
- 直接利用系统中已有的总线和 Cache 状态位，实现容易，成本较低。
- 一个 Cache 在总线上广播、其他 Cache 监听。系统规模变大时**广播操作会成为系统瓶颈**，所以这个协议的可扩放性较差。

最后这条是监听协议被目录协议取代的原因，简答题常拿来做对比的落脚点。

## 目录式协议的实现

### 目录是什么

- **目录**是一种**逻辑上集中**的数据结构。对于存储器中每一个可以调入 Cache 的数据块，目录里设一条**目录项**，记录该块的状态以及哪些 Cache 中有副本。对任何一个数据块，都能在唯一的一个位置快速找到相关信息。
- **物理上分布**：适用于分布式共享存储多处理器，目录与存储器都分布在各节点中。每个目录只保存对应本地存储器的 Cache 状态信息，对不同目录的访问可以在不同节点上并行。

「逻辑上集中、物理上分布」这八个字是这一节的题眼。

### 分布式共享存储多处理器结构图

考点要求「画出采用目录式协议的分布式共享存储多处理器的结构图」。图还在，画法是：

- 中间一条粗横线是**互连网络**。
- 互连网络上下各挂一排节点（原图上下各四个，共 8 个）。
- 每个节点从外向内是：`CPU + Cache` 圆圈 → 下面一行并排的「存储器」和「I/O」方框 → 再下面一个「目录」方框 → 目录接到互连网络上。
- 关键是每个节点都有自己的一块存储器和一份目录，这就是「物理上分布」。

### 节点分类及关系

三类节点，是后面所有表格的主语，必须先分清。

- **请求节点 A**：发出访问请求地址 K 的那个节点。
- **目录节点 B**：维护地址 K 对应的那个唯一存储器的目录，不分本地还是远程。
- **远程节点 C**：其 Cache 中拥有对应副本的节点，是逻辑上的远程。

角色是相对的，不是固定的：**每个缺副本的 Cache 都觉得自己是 A，看别的有副本的 Cache 都觉得别人是 C；每个有副本的 Cache 都觉得自己是 C，看别的没有副本的请求 Cache 都觉得别人是 A。**

### 宿主：A 怎么找到 B

- 请求节点 A 通过地址 K 可以解析出唯一的目录节点 B。K 的**高位是存储器节点索引**，K 的**低位是存储器节点内偏移**。
- 所有存储器采用**高位交叉编址**，对存储单元矩阵按**列优先**的方式编址，同一个存储器中的高 $\log_2 m$ 位都是相同的（m 是存储器个数）。
- 目录节点 B 查询目录状态信息后，可能从自己的存储器里取出数据向 A 提供服务，也可能从共享集中选中一个远程节点 C，从 C 的 Cache 里取回副本再向 A 提供数据服务。

### 系统各部件状态

目录和 Cache 各有三种状态，字母不一样，含义对得上，别写混。

| 目录为每个**存储块**记录的状态 | Cache 为每个**数据块**记录的状态 | 含义 |
| --- | --- | --- |
| **Uncached（U）** | **Invalid（I）** | 所有 Cache 中无副本 / 本地无副本 |
| **Shared（S）** | **Shared（S）** | 至少 1 副本且存储器中的值是最新值，clean，只读模式 |
| **Exclusive（E）** | **Modified（M）** | 拥有者 Cache 具有唯一副本且存储器中的值是旧值，dirty，读写模式 |

目录端用 U / S / E，Cache 端用 I / S / M，看到题目里出现哪一组字母就知道问的是哪一端。

### 目录状态信息

考点要求从「数据结构、实现技术、Cache、信息量、分类」五个角度描述。

- **数据结构**：目录状态信息是一种数据结构，用来记录哪些 Cache 拥有数据块的副本。
- **实现技术**：最常用的是**位向量**。为每个被缓存的主存块设一个位向量，向量中的每一位对应一个处理器，长度与处理器个数成正比。由位向量指定的处理机的集合称为**共享集 G**。
- **Cache 侧**：Cache 块的位向量用于记录该 Cache 块的共享情况，每一位代表一个处理器，某位为 1 就表示那个 CPU 有这个 Cache 块的副本。
- **信息量**：处理器个数 N，每个节点的本地存储块个数 m，则信息量为 $m \times N \times N$，量级 $O(N^2)$。（解释一下为什么是 $N^2$：系统里一共有 $N$ 个节点，每个节点管 $m$ 个存储块，所以目录项总数是 $m \times N$；每个目录项要存一个长度为 $N$ 的位向量，再乘一个 $N$，就得到 $m \times N \times N$。）
- **分类**：可以只对进入 Cache 的块设置目录（**动态法**），也可以让目录项的位向量长度固定（**静态法**）。

### 节点间消息

九条消息，A / B / C 三个角色两两之间传，这张表是后面三张状态转换表的字典。数据块 K 指的是区间内包含地址 K 的那个数据块。

| 源 | 目标 | 消息类型 | 含义 |
| --- | --- | --- | --- |
| A | B | RdMiss(K) | 请求数据块 K，并申请 A 加入共享集 G |
| A | B | WtMiss(K) | 请求数据块 K，并申请 A 独占共享集 G |
| B | A | Data(K) | 返回所请求的数据，K 是请求地址 |
| B | C | Invalidate(K) | 请求 C 将数据块 K 作废 |
| B | C | FetchS(K) | 请求数据块 K 的唯一副本，并请求将 C 的副本置为共享 |
| B | C | FetchI(K) | 请求数据块 K 的唯一副本，并请求将 C 的副本置为无效 |
| C | B | Quit(K) | C 中的 clean 副本将被替换，申请退出共享集 G |
| C | B | Update(K) | C 中的 dirty 副本将被替换，或响应 Fetch 请求，用 C 的唯一副本更新存储器 |
| C | B | Invalidate(K) | C 中的 clean 副本将被写入，申请 C 独占共享集 |

看消息名就能猜方向：`Fetch*` 只可能是 B 发给 C，`Quit` / `Update` 只可能是 C 发给 B，`RdMiss` / `WtMiss` 只可能是 A 发给 B。唯一双向的是 `Invalidate`：B→C 是命令作废，C→B 是申请独占。

### 表一：本地 Cache 控制器监听本地 CPU

和监听式协议的那张表完全一样，见上面「本地 Cache 控制器监听本地 CPU 的状态转换表」。

### 表二：远程节点 C 响应目录节点 B

C 根据 B 的请求操作自己的数据 Cache。

| Cache 块当前状态 | B 的请求 | Cache 控制器操作 | 状态变更 |
| --- | --- | --- | --- |
| I | Invalidate(K)（不可能） | Null | I |
| I | FetchS(K)（不可能） | Null | I |
| I | FetchI(K)（不可能） | Null | I |
| S | Invalidate(K) | Null | I |
| S | FetchS(K)（不需要，B 自有数据） | Null | S |
| S | FetchI(K)（不需要，B 自有数据） | Null | I |
| M | Invalidate(K)（不可能，自毁唯一副本） | Null | I |
| M | FetchS(K) | send Update(K) to B | S |
| M | FetchI(K) | send Update(K) to B | I |

推这张表只要两句话：**I 状态下 B 根本不会来找你**（目录里没把你记进共享集），所以前三行不可能；**S 状态下存储器已经是最新值，B 自己就有数据，不需要你 Fetch**，所以中间三行都是 Null，只有状态跟着变。真正要干活的只有 M 的两行：把唯一的最新副本 `Update` 回去，FetchS 之后留个只读副本，FetchI 之后自己作废。

### 表三：目录节点 B 响应 A

B 根据 A 发来的请求操作自己的目录信息。

| 目录项当前状态 | 收到消息类型 | B 的操作 | 状态变更 |
| --- | --- | --- | --- |
| U | RdMiss | send Data(K) to A, G={A} | S |
| U | WtMiss | send Data(K) to A, G={A} | E |
| S | RdMiss | send Data(K) to A, G+={A} | S |
| S | WtMiss | send Data(K) to A, send Invalidate(K) to all Cs in G, G={A} | E |
| E | RdMiss | 此时 C 有唯一副本：send FetchS(K) to C, 待收到 Update(K) 后 update mem, send Data(K) to A, G+={A} | S |
| E | WtMiss | 此时 C 有唯一副本：send FetchI(K) to C, 待收到 Update(K) 后 send Data(K) to A, G={A} | E |

两条规律：**RdMiss 一律把 A 加进共享集（`G+={A}`），WtMiss 一律把共享集清成只剩 A（`G={A}`）**；**收到 RdMiss 后目录变 S，收到 WtMiss 后目录变 E**。E 状态下数据在 C 手里，所以两行都要先去 C 那儿 Fetch 一趟。

注意 `E + RdMiss` 那行要 `update mem`，因为存储器里是旧值；`E + WtMiss` 那行不用 update，因为马上就有新的独占者要写了。

### 表四：目录节点 B 响应 C

B 根据 C 发来的请求操作自己的目录信息。

| 目录项当前状态 | 收到消息类型 | B 的操作 | 状态变更 |
| --- | --- | --- | --- |
| U | Quit(K)（不可能） | Null | U |
| U | Update(K)（不可能） | Null | U |
| U | Invalidate(K)（不可能） | Null | U |
| S | Quit(K) | G-={C}，然后判断 `# of G` 是否为 0 | S / U |
| S | Update(K)（不可能） | S 表示存储器中有新值，无需 fetch，排除了 FetchS 和 FetchI；C 中的 dirty 副本将被替换时，此目录项状态应该为 M 而不该为 S，因此 S 的情况下不会收到此消息 | S |
| S | Invalidate(K) | G={C}, send Invalidate(K) to all other Cs in G | E |
| E | Quit(K)（不可能） | Null | E |
| E | Update(K) | E 表示存储器中为旧值、C 中为新值：if fetchS then G={C}, state S；if fetchI then G={}, state U；if C 中的 dirty 副本将被替换，update mem and state U | S / U |
| E | Invalidate(K)（不可能） | Null | E |

这张表里「不可能」的行最多，理由是同一条：**U 状态意味着没有任何 Cache 持有副本，C 这个角色压根不存在**，所以 U 的三行都不可能；**E 状态下 C 手里是 dirty 的唯一副本，它要走只能发 Update 不能发 Quit**（Quit 是 clean 副本才用的），C 也不需要再申请独占，所以 E 的 Quit 和 Invalidate 两行不可能。

`S + Quit` 那行要特别注意：共享集减掉 C 之后要判断集合空没空，空了目录项就从 S 退回 U，所以状态变更栏写的是 `S/U`。

### 目录结构分为 3 类

考点要求「画图介绍目录结构的分类（3 点，加上画图）」。三类的空间开销公式是常考点，注意 $m$ 在有限映像和链式里是常数。

| 目录结构 | 每个目录项存什么 | 目录所占空间 | 备注 |
| --- | --- | --- | --- |
| **全映像目录**（全印像目录） | 一个 N 位的位向量，每一位对应一个处理机 | 与 $N^2$ 成正比 | 精确，但位向量随 N 线性变长 |
| **有限映像目录** | 一个处理机号码，共 m 个目录项，m 为常数 | $N \times m \times \log_2 N$ | 副本数超过 m 时要用替换策略 |
| **链式目录** | 一个指针链表项，链表长度随副本数增减动态变化，平均长度 m 为常数级 | $N \times m \times \log_2 N$ | 分单向链表和双向链表 |

原稿在有限映像和链式两处都标了「（所占空间不懂）」。空间怎么算出来的：

- **全映像**：一共 $N$ 个节点，每节点一份目录，每个目录项里的位向量长 $N$ 位，所以总量与 $N \times N = N^2$ 成正比。
- **有限映像**：每个目录项不再存位向量，改成存 $m$ 个处理机号码。要在 $N$ 个处理机里指名道姓，一个号码需要 $\lceil \log_2 N \rceil$ 位，所以一个目录项是 $m \times \log_2 N$ 位，全系统 $N$ 份目录就是 $N \times m \times \log_2 N$。
- **链式**：每个目录项存的是表头指针，指针同样要 $\lceil \log_2 N \rceil$ 位指向某个处理机，链表平均长 $m$，算法和有限映像一样。

三张图的画法（图还在原页面上，可以照着画）：

- **全映像目录**：上面一排圆圈 `P1 Cache`…`PN Cache`，下面画一条 N 格的位向量，格子里填 `1 0 1 … 1 0`，每一格用虚线指向对应的处理器，标注「第 1 位、第 2 位、…、第 N 位」。图下写出结论：共享集 $= \{P_1, P_3, \dots, P_{N-1}\}$。
- **有限映像目录**：上面一排 `P1 Cache`…`PN Cache`，下面画 m 个格子（原图 m=4，N≥8），格子里填处理机号码的二进制 `0001 0011 0101 0111`，每格用实线箭头指向对应的处理器，右边标注「每一项的位数 $= \lceil \log_2 N \rceil$」，下方用大括号标「m 项」。结论：共享集 $= \{P_1, P_3, P_4, P_7\}$。
- **链式目录**：上面一排 `P1`…`PN` 处理器，下面一排 Cache 方框，每个方框分成「数据 + 指针」两格。画一个「表头指针（$\lceil \log_2 N \rceil$ 位）」的方框，指向链上第一个 Cache，然后各 Cache 的指针格依次串下去，链尾那个画一个 `∧` 表示 NULL。结论：共享集 $= \{P_1, P_4, P_2\}$。

### 目录式协议小结

介绍目录式协议的时候把这几条带上，能拿满分。

- 目录式协议中，Cache 的基本状态、Cache 块的状态转换规则，与监听式协议在实质上是相同的。
  - 对 Cache 块进行写操作时，该块必须处于独占状态。
  - 对于任何一个处于共享态的块，目录节点的存储器内容是更新过的最新值。
- 监听式协议中的「消息广播」，在目录式协议中改成「点对点通信」。
  - 某 Cache 块被替换写回时，被写回的**旧块**有唯一目录节点 B1，被调入的**新块**有唯一目录节点 B2。Cache 和 B1、B2 都是单线联系。B1 和 B2 在逻辑上是不同的节点，当然地址分布重合也可能让 B1 和 B2 落在同一个物理节点里。

这条解释了为什么前面 RdMiss / WtMiss 表里会同时出现 K1、K2 和 B1、B2 两套地址。

## 易混对比

### 监听式协议 vs 目录式协议

| 对比项 | 监听式协议 | 目录式协议 |
| --- | --- | --- |
| 通信载体 | 总线 | 互连网络 |
| 通信模式 | 1 对 N 广播 | 1 对 1 点对点 |
| 状态信息存在哪 | 分散保存在各个 Cache 中 | 集中保存在本地目录中（逻辑集中、物理分布） |
| 适用结构 | 集中式共享存储（UMA / SMP） | 分布式共享存储（NUMA / DSM） |
| 实现成本 | 直接用已有的总线和 Cache 状态位，低 | 要额外建目录，$O(N^2)$ 的信息量 |
| 可扩放性 | 差，广播是瓶颈 | 好 |
| 状态字母 | Cache 端 I / S / M | Cache 端 I / S / M，目录端 U / S / E |

### 三对协议选项谁管谁

| 触发时机 | 由哪一对选项决定 |
| --- | --- |
| 写命中 WtHit | 写作废 vs 写更新 |
| 读缺失 / 写缺失 RdMiss、WtMiss | 写直达 vs 替换写回 |
| 任何写操作 | 按写分配 vs 不按写分配 |

### UMA vs NUMA

| 对比项 | UMA | NUMA |
| --- | --- | --- |
| 别名 | CSM、SMP | DSM、AMP |
| 存储器摆放 | 集中，一块共享存储器 | 分布，每个节点有本地存储器 |
| 访存时间 | 均匀，各处理器一样 | 非均匀，本地快远程慢 |
| 常配的一致性协议 | 监听式 | 目录式 |
