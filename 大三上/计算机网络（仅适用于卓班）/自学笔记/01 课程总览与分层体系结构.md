## 概念与解释

### 1 发展史时间线

| 年代 | 事件 |
| --- | --- |
| 1961-1966 | MIT 提出 packet / packet switching（分组、分组交换）这两个术语；ARPA 出资建一个实验网络 |
| 1969 | FCC 决定非 AT&T 制造的设备也可以接入其电话系统；该项目演变为 ARPANET（出发点是网络生存能力，能扛住二次核打击）。前四个结点是 SRI（斯坦福研究所）、UCLA、UCSB、犹他大学。承建方 BBN 是一家小咨询公司 |
| 1971/1972 | ARPANET 有 15 个站点、23 台主机；1972 年制定 FTP；同年 BBN 的 Ray Tomlinson 做出电子邮件，是当时最流行的软件；Telnet 协议也在这年提出 |
| 1974 | Vinton Cerf 和 Bob Kahn 在论文 "A Protocol for Packet Network Internetworking" 中提出 TCP，并第一次引入 Internet 这个词 |
| 1977 | 第一个无线网关接入 ARPANET，用无线电波传分组 |
| 1978 | Vinton Cerf、Bob Kahn 等人提出 IP 计划，把路由功能从 TCP 里拆出来单独做 |
| 1982 | TCP 和 IP 被定为 ARPANET 的主协议族 |
| 1983 | ARPANET 达到 500 个结点，转为真正的民用网络，一般把这一年当作 Internet 的起点 |
| 1988 | 主机数到 6 万台；欧洲和北美用光缆连通；第一个互联网病毒 Internet Worm 影响了 10% 的联网计算机 |
| 1990 | ARPANET 正式退役，11 个国家成为 NSFNET 新成员 |
| 1993 | 主机数超过 200 万，非洲、亚洲等 17 个国家接入 |
| 1999 | 主机数超过 1600 万；internet2；美国立法把域名确立为财产；美国骨干网速度达到 2.5 Gbps |
| 2000/2001 | IPv6 用于 internet2；开始大力推无线通信 |

课件里还有一页写"TCP/IP 之父"，表彰的是在互联网互联技术方面的开创性工作，包括 TCP/IP 基础通信协议的设计和实现，以及在网络领域的领导作用。两位获奖者是 Vinton Cerf（UCLA）和 Bob Kahn（BBN 公司），也就是 1974 年那篇论文的作者。

### 2 计算机网络的演变、功能和组成（1.1）

演变分四步，前两步还是"单个复杂系统在演化"，第三步才算真正的网络：

1. 具有通信功能的联机系统：`终端-线路-计算机`。
2. 具有通信功能的分时系统：`终端-集中器-计算机`。
3. 计算机网络：独立的计算机互连。
4. 国际标准化网络：开放式标准的计算机网络。

功能有五条：数据通信、资源共享、并行与分布式处理、提高可靠性（靠冗余和检错）、可扩充性。

组成分两块：

- **通信子网**：负责信息传递，完成数据传输和转发。包括结点转发设备、通信设备。
- **资源子网**：负责信息处理，提供资源和服务。包括计算机系统、外设、软件资源。

概念体系里四个名词分清楚：

- **网络（network）**：由若干结点和连接这些结点的链路组成。设备可以在同一地理区域内，也可以分布在不同地区。
- **结点（node）**：网络中的连接点，可以是计算机、路由器、交换机、集线器。结点负责发送、接收或转发数据，可以是数据的源点、终点，也可以是中途的转发点。
- **链路（link）**：连接两个结点的物理或逻辑通信路径。物理链路是电缆、光纤这类有形介质；逻辑链路可以是无线信号或者靠协议建起来的虚拟连接。
- **主机（host）**：连接在网络上的计算机或其他设备。主机是网络服务的使用者，也可以对外提供服务。

一句话定义：计算机网络是多个独立的计算机通过通信线路和通信设备互连起来的系统，目的是交换信息和共享资源。发展方向是互联网到物联网、固定终端到移动终端。

### 3 拓扑结构（1.2）

六种，各自特点如下。

| 拓扑 | 好处 | 毛病 |
| --- | --- | --- |
| 网状 Mesh | 避免拥塞；健壮性好；安全性好；便于管理，故障检测和故障隔离很容易 | 安装费用高 |
| 星状 Star | 结构简单；健壮性较好；便于管理 | 中央控制器是整个网络的瓶颈 |
| 树状 Tree | 扩展了网络距离；允许网络隔离不同计算机的通信 | （原文未列） |
| 总线型 Bus | 不存在路由和转发的问题；易安装 | 信号衰减导致总线长度和可接设备数有限；故障隔离困难 |
| 环状 Ring | 易安装；维护管理方便，故障隔离简单；传输时延可控 | 传输延迟大；单向环里一个故障就会让整网瘫痪 |
| 混合型 Hybrid | 结合以上各种拓扑的特点，按实际需求设计 | （原文未列） |

环状那一行看起来自相矛盾（"传输延迟大"又"传输时延可控"），其实说的是两件事：延迟绝对值大，但因为绕环一圈的路径是确定的，延迟上界算得出来。

### 4 网络分类（1.3）

七种分法。

1. 按作用范围（覆盖范围）：
   - LAN 局域网，覆盖一个房间、一层楼或整栋楼。
   - MAN 城域网，覆盖一个城市或校园。
   - WAN 广域网，覆盖一个国家或跨国。
   - PAN 个域网，便携消费电器和通信设备之间的短距离通信，半径一般在 10 米内，比如蓝牙耳机。
2. 按通信介质：有线网（同轴电缆、双绞线、光纤）、无线网（卫星、微波）。
3. 按传播方式：点对点网络（数据在两个结点之间直接传）、广播网络（一个结点发给多个结点）。
4. 按通信速率：低速网 kbps 到 1.4 Mbps；中速网 1.4 Mbps 到 45 Mbps；高速网 50 Mbps 到 1000 Mbps（1 Gbps）甚至更高。（45 到 50 之间的缺口是原文如此。）
5. 按使用范围：公用网 public（面向公众，比如联通、移动、电信，public 不等于免费）、专用网 private（为特定组织服务，校园网是专用网，但也不代表不交钱）。
6. 按网络控制方式：集中式网络（控制和管理集中在一个或几个结点，有中央控制环节，其他结点只负责执行，存在中央瓶颈）、分布式网络（控制权分散在多个结点，但需要协调）。
7. 按网络环境：部门网、企业网、校园网。

### 5 三种工作模型

课件把这三种叫 working models，本质是集中式和分布式两种思路的不同落点。

**集中式模型（Server Based）**。所有计算和数据处理都压在一台中心服务器上，早期网络里很普遍。代表是 IBM 的 SNA（System Network Architecture），时间跨度从 1960 年代到 1980 年代初。特点是把没有 CPU 的终端直接挂到大型机或小型机上，终端只做输入输出，处理全在主机完成，通信用 IBM 自家的 SNA 协议。

**客户/服务器模型（Client/Server）**，属于服务集中型。客户机和服务器是两个不同实体，通过网络通信和交换数据。

- 负载分配：把一部分负载从服务器挪到客户机，客户端自己有计算能力和存储能力。
- 用户界面：处理可以在客户机上做，界面更好，响应更快。
- 角色转换：同一台机器可以同时扮演服务器和客户机。原文用查询教职工/学生信息的例子说明：最下面一段里 web server 是 server；中间一段 web server 变成 client 去请求 application server；最上面一段 application server 又变成 client。
- C/S 是 Internet 上传统的、也是最成熟的方式，WWW、电子邮件、FTP 都是这个路子。
- 服务集中在数量远少于客户机的服务器上，所以常出现服务器跟不上大量客户机请求的情况，解决办法是用计算机群集（服务器场）拼出一个强大的虚拟服务器。
- **B/S 模式是 C/S 的一种**，browser 就是 client，区别在于把原来五花八门的客户端统一成了浏览器。
- C/S 架构的两个老问题：服务器的存储空间，服务器的并发服务能力。

**对等网络模型（Peer to Peer，P2P）**，属于服务分散型。每个结点都是平等的，既能当客户端发请求，也能当服务器响应请求。

- 资源共享：支持大规模的资源共享。
- 去中心化：没有中心服务器，结点之间可以直接通信。
- 应用：文件共享、分布式计算等。
- 原文用音乐分享举例：文件放在各个客户处，server 那里只留一个目录服务；客户之间可以直接通信，所以网络规模能扩展上去。

三者的适用场景：集中式适合小型或简单的网络环境；C/S 更灵活，适合需要快速响应和负载均衡的复杂环境，味道上偏集中式；P2P 适合需要大规模资源共享和分布式处理的环境，味道上偏分布式。

### 6 网络协议与分层（1.4.1、1.4.2）

**协议是水平的，服务是垂直的**，这句话贯穿整章。协议约束的是对等层之间（同一层的不同实体），服务是下层通过层间接口交给上层的。

网络协议是通信双方必须遵守的规则、标准、约定，作用在同层之间。三要素：

- **语法**：数据与控制信息的结构或格式，包括数据格式、编码方式、电压高低，规定数据怎么表示和组织。
- **语义**：控制信息的功能及动作，也就是数据的含义和怎么解释，包括打开/关闭连接、差错检测与纠正这些操作。
- **时序**：信息的同步、速度匹配、顺序，保证数据在正确的时间按正确顺序传输。

**体系结构**是计算机网络各层次及其协议的集合，是个抽象概念。它规定每层该做什么，但不规定怎么实现；实现这些功能的硬件和软件才是网络的实际运行部分。

分层的优点五条：独立（层内变化不影响别层，只要接口不变）、灵活（新服务新协议容易加进合适的层）、模块化、易于维护、标准化。原文在标准化后面标了一句"其中标准化最重要"。

分层的主要原则三条：

1. 功能相近的分在一层。
2. 每层的功能明确。
3. 边界信息要尽量少，也就是尽量减少层间接口的复杂性。

### 7 OSI 参考模型（1.4.3）

ISO 于 1984 年制定开放系统互连参考模型，用来解决网络之间的兼容和通信问题，共七层。

OSI 里物理层、数据链路层、网络层这三层实现了网络互连的功能，合起来就是通信子网。实通信只发生在两台主机的物理层之间，以及同一台主机内相邻的层与层之间。物理层那条实线代表传送的是信号，即 0/1 序列，通常是电信号。

课件里有一张标错的图，错在把会话层画成了主机间通信。**会话层不做主机间通信**，主机间的实际通信只靠物理层。

| 层 | 功能 | 数据单位 | 封装时加的头 |
| --- | --- | --- | --- |
| 7 应用层 Application | 最贴近用户，为应用程序提供网络服务，处理用户数据，完成用户想做的实际任务（文件传输、电子邮件等） | 数据 | AH |
| 6 表示层 Presentation | 数据的表示、安全、压缩和转换。解决用户信息的语法问题，对用户数据做翻译、编码和交换 | 数据 | PH |
| 5 会话层 Session | 在两个通信实体之间建立、管理、终止会话。两台机器上的用户进程建连接、互相确认身份、协商会话细节 | 数据 | SH |
| 4 传输层 Transport | 端到端的数据传输服务，从一个用户进程到另一个用户进程，含流量控制和差错控制 | 报文 Message | TH |
| 3 网络层 Network | 在任意结点之间选路由，把数据从源送到目的地。含路由选择、阻塞控制、网际互连 | 分组 Packet | NH |
| 2 数据链路层 Data Link | 在相邻结点之间可靠传输数据帧。含差错控制、流量控制、链路管理 | 帧 Frame | DH（头）+ DT（尾） |
| 1 物理层 Physical | 在物理媒介上传输原始比特流 | 比特 Bit | 无，直接是比特序列 |

物理层还要背四个特性：

- 机械特性：连接器的形状、大小、针脚排列。
- 电气特性：电压水平、信号编码、传输速率。
- 功能特性：数据线和控制线怎么用来传数据。
- 规程特性：数据传输的步骤和时序。

记网络层的功能时可以用一个字概括：找路。

### 8 TCP/IP 体系结构与 RFC（1.4.4）

OSI/RM 的制定意义重大，但实际跑的系统里用 OSI 模型的不多，因为 TCP/IP 普及得更彻底，业界一般把 TCP/IP 当作事实上的工业标准。OSI 模型对建网仍有指导意义。**TCP 工作在传输层，IP 工作在网络层**。

TCP/IP（Transmission Control Protocol / Internet Protocol）是 Internet 运行的基础，目前应用最广的网络通信协议簇。课件里两张图对应关系如下：

| OSI 七层 | TCP/IP 分层 | 这一层的典型协议 |
| --- | --- | --- |
| 应用层 + 表示层 + 会话层 | 应用层 | SMTP、FTP、TELNET、DNS、SNMP、GOPHER、HTTP、NNTP |
| 传输层 | 传输层 | TCP、UDP |
| 网络层 | 网络层（互联网络层 / 网际层） | IP、ICMP、IGMP、ARP、RARP |
| 数据链路层 + 物理层 | 网络接口层 | 该层协议由底层网络定义 |

原文批注写明：图中的网络接口层可以再分成数据链路层和物理层。

课件上还画了一个沙漏形状的图，腰部只有 TCP 和 IP 两层，旁边批注是"核心"、"往下兼容各种底层网络"、"往上开放"、"标准化"。这张图想说的是 TCP/IP 靠腰部的窄标准接住了上下两端的多样性。

**RFC 文档**：所有关于 Internet 的正式标准都以 RFC（Request for Comment）文档出版，出版目的只是提供相关信息。每一项用一个数字标识，比如 RFC983，数字越大说明内容越新。所有 RFC 都可以在网上免费获得。

### 9 层间通信与对等层间通信（1.5.1）

每层的功能由该层的实体实现，下层实体为上层实体提供服务，上层靠下层的服务完成自己的功能。

- **层间通信**：同一结点上相邻层次之间的通信。
- **对等层间通信**：不同网络结点上对等层之间的通信。
- **实通信**：层间通信，以及物理层之间的通信。这种通信是实际的，涉及物理媒介上的数据传输。
- **虚通信**：除物理层之外，对等层之间的通信。这种通信是逻辑上的，靠网络中的路由和交换机制来实现。

拿具体的层套一下就不会混：两台主机的应用层之间是虚通信；同一台主机的应用层和表示层之间是实通信；两台主机的物理层之间也是实通信。

### 10 服务与数据单元（1.5.2）

数据在结点内是沿层次往下传的，每层为它上面各层提供专门的通信服务。N 层是服务提供者，N+1 层是服务的使用者，服务通过一组服务原语来执行。

- **SAP（Service Access Point，服务访问点）**：层间接口处提供服务的地方，是层间通信的逻辑接口，定义了层与层交互的边界。
- **SDU（Service Data Unit，服务数据单元）**：相邻层之间传递的信息，包含从上层传下来的数据以及可能的控制信息。
- **PCI（Protocol Control Information，协议控制信息）**：每层往下发数据时自己加的控制信息，比如地址信息、错误检测和纠正码、同步、路由信息。
- **PDU（Protocol Data Unit，协议数据单元）**：对等层之间交换的信息单位，由本层 SDU 加上本层 PCI 构成。

两个关系式背下来：

$$(N)\text{PDU} = (N)\text{SDU} + (N)\text{PCI}$$

$$(N{+}1)\text{PDU} \longrightarrow (N)\text{SDU}$$

上层的 PDU 往下传时，整个被当成下层的 SDU；下层再加上自己的 PCI 变成下层的 PDU，继续往下。原文在这里写的是"N 层会将自己层的 SDU 与 PCI 结合，形成一个新的 PDU，然后传递给上层"（更正：原文作"传递给上层"，应为传递给下层。加完 PCI 组成 PDU 之后是继续往下交给 N-1 层，作为 N-1 层的 SDU）。

四个操作，成对记：

| 操作 | 发生在 | 做什么 | 为什么 |
| --- | --- | --- | --- |
| 拼接 Concatenation | 发送方 | 把多个较小的 PDU 合成一个较大的 SDU | 减少头部开销，数据量小又发得频繁时提高效率 |
| 分割 Separation | 接收方对等层 | 把收到的 SDU 拆回原来的多个 PDU | 让上层能正确处理每个独立的数据单元 |
| 分段 Segmenting | 发送方 | 一个 SDU 太大时切成多个小段，每段各加 PCI 组成 PDU | 让大数据单元适应各层的传输能力 |
| 合段 Reassembling | 接收方对等层 | 把这些 PDU 重新拼成原始的 SDU | 让上层收到完整数据 |

拼接和分段的方向正好相反：拼接是多合一，分段是一拆多。

### 11 服务原语（1.5.3）

服务原语是控制层次之间通信的一组规则和信号，定义了服务提供者（下层）和服务用户（上层）之间怎么交互。N+1 层实体通过使用 N 层的服务原语向 N 层请求服务。

四种类型：

| 原语 | 方向 | 含义 | 例子 |
| --- | --- | --- | --- |
| 请求 Request | N+1 层发给 N 层 | 要求提供某种服务 | 传输层向网络层请求分组的传输服务 |
| 指示 Indication | N 层发给 N+1 层 | 通知上层发生了某个事件，如连接建立、数据到达 | 网络层收到一个分组时向传输层发指示 |
| 响应 Response | N+1 层发给 N 层 | 对下层指示的回应 | 传输层收到指示后发一个确认作为响应 |
| 证实 Confirm | N 层发给 N+1 层 | 确认服务请求已完成 | 网络层成功发出分组后向传输层发证实 |

方向上有个规律：request 和 response 都是上层往下层发，indication 和 confirm 都是下层往上层发。

按要不要证实分两类服务：

- **证实型服务**：每次请求都必须得到证实，保证服务的可靠性。四个原语都会用上。
- **非证实型服务**：请求不一定要证实，适合不需要确认的场景，比如实时或流媒体应用。

服务原语由三部分组成：原语名字、原语类型、原语参数。例如 `T-CONNECT.request`，T 表示传输层（Transport），CONNECT 表明是链路连接，request 表示这是请求原语。（更正：原文写"T 指代 transfer"，实际取自 Transport；原文"connect表面链路连接"的"表面"应为"表明"。）

还有两个概念要记：

- **服务透明度**：上层服务用户只能"看到"服务，不需要知道下层怎么实现。这样网络设计者可以各管一层。
- 协议的水平性和服务的垂直性：协议定义对等层之间的通信规则，是水平方向；服务由下层通过层间接口提供给上层，是垂直方向。

### 12 面向连接和无连接的服务（1.5.4）

OSI 里下层能给上层提供两类服务。

**面向连接的服务**在传数据之前要先建一条稳定的连接，提供可靠传输，保证顺序和完整性。三个阶段：

1. 建立连接：双方交换地址、同步、流量控制参数这些必要的控制信息。TCP 在传数据前做三次握手。
2. 数据交换：连接建好后传数据，保证顺序、完整性和可靠性。丢失或损坏就重发，直到接收方正确收到。
3. 释放连接：传完后拆连接，把网络资源还给别的通信用。TCP 用四次挥手关连接。

**无连接的服务**不要求先建连接，每个数据单元独立发送，不保证顺序也不保证可靠性。三个要点：

1. 数据报：独立的传输单元，带源地址和目的地址，但不保证顺序和可靠性；每个数据报独立选路由，可能走不同路径到达目的地。
2. 证实交付：无连接服务本身不保证可靠传输，但某些协议可以提供可选的证实交付机制。UDP 是无连接协议，可以靠应用层的确认机制补上一定程度的可靠性。
3. 请求/响应：无连接的通信常是请求/响应模式，发送方发请求，接收方发响应。适合不需要持续连接的应用，比如 DNS 查询。

（原文这一小节的标题写作"面向无连接阶段"，应为"面向无连接的服务"。）

### 13 网络互连（1.6）

网络互连的根本目的是扩大资源的共享范围。主要形式有局域网与局域网、局域网与广域网、广域网与广域网三种。

网络互连设备按工作的层次分四大类：重发器（物理层）、网桥（数据链路层）、路由器（网络层）、网关（应用层或更高层）。每一类分别和 OSI 模型中不同层的协议交互作用。四类设备的工作原理、地址处理和相互区别见 `10 网络互连设备速查.md`。

**接入网（Access Network）**是用户或设备连到互联网或其他大型网络的最初那一段，指从用户端到服务提供商网络接入点之间的那部分网络。技术可以是 DSL、电缆调制解调器、光纤、卫星、WLAN、移动网络等。它的目的是给用户提供足够的带宽去访问互联网服务。接入网是用户和互联网之间的"最后一英里"（Last Mile），直接影响用户的网络体验和服务质量。

### 14 计算机网络的性能（1.7）

**吞吐量（throughput）**：单位时间内通过某个网络、信道或接口的数据量，单位一般是 bps。吞吐量常用来测量网络，看实际到底有多少数据量能通过。它受网络带宽或额定速率的限制。

- 网络带宽是网络连接的最高数据传输速率，是传输能力的上限，所以它限制了吞吐量。
- 实际吞吐量会因为网络拥塞、硬件性能、信号干扰、丢包和重传而低于带宽。

**信道利用率（Channel Utilization）**：两种等价说法。一是除去全部控制信息后的数据率与信道吞吐量之比，二是发送数据的时间和信道被占用时间之比。也就是一段时间里信道用于有效数据传输的时间占总时间的比例。这里的数据率指信道单位时间传输的数据量，含数据本身和控制信息；信道吞吐量指信道单位时间能传的最大数据量。

**延迟时间（Latency）**：数据从源头到达目的地所需的时间，由四部分组成。

| 时延 | 含义 |
| --- | --- |
| 排队时延 Queuing Delay | 分组在进入网络之前在队列里等待的时间，发生在网络拥塞或等待处理时 |
| 访问时延 Access Delay | 等待信道变空闲以便发送数据的时间，共享网络里要竞争信道使用权 |
| 发送时延 Transmission Delay | 从发送数据帧的第一个比特算起，到该帧最后一个比特发送完毕所需的时间 |
| 传播时延 Propagation Delay | 信号在物理介质中传播一定距离所需的时间，取决于传播速度和介质特性 |

$$\text{总时延} = \text{发送时延} + \text{传播时延} + \text{排队时延} + \text{访问时延}$$

发送时延和传播时延最容易混：发送时延跟数据量和发送速率有关，跟距离无关；传播时延跟距离和介质有关，跟数据量无关。

## 易混对比

| 对比项 | 一边 | 另一边 |
| --- | --- | --- |
| 通信子网 / 资源子网 | 通信子网管传递，含转发设备和通信设备，对应 OSI 下三层 | 资源子网管处理，含计算机系统、外设、软件 |

| 总线 / 环状 | 总线不用路由转发，易装，但故障隔离困难 | 环状易装且故障隔离简单，但单向环一处断全网瘫 |
| 公用网 / 专用网 | 面向公众开放接入，不代表免费 | 为特定组织服务，也不代表不收钱 |
| C/S / P2P | 服务集中型，服务器数量远少于客户机，易出现服务器扛不住 | 服务分散型，去中心化，规模能扩展 |
| B/S 和 C/S | B/S 是 C/S 的一种，客户端统一成浏览器 | C/S 的客户端各式各样 |
| 协议 / 服务 | 协议是水平的，管对等层之间 | 服务是垂直的，下层通过 SAP 给上层 |
| 实通信 / 虚通信 | 实通信：同一主机相邻层之间 + 两主机物理层之间 | 虚通信：除物理层外的所有对等层之间 |
| SDU / PDU | SDU 走层间接口，是相邻层之间传的东西 | PDU 走对等层，等于本层 SDU 加本层 PCI |
| 拼接 / 分段 | 拼接是多个 PDU 合成一个大 SDU，为省头部开销 | 分段是一个大 SDU 切成多段，为适应传输能力 |
| 分割 / 合段 | 分割是拼接的逆操作，在接收方对等层做 | 合段是分段的逆操作，在接收方对等层做 |
| 证实型 / 非证实型 | 每次请求必须有证实，四个原语齐全 | 请求不必证实，适合实时和流媒体 |
| 面向连接 / 无连接 | 先建连接，保证顺序和可靠，TCP 三次握手四次挥手 | 每个数据报独立发送独立选路，不保证顺序 |
| 发送时延 / 传播时延 | 与数据量和发送速率有关，与距离无关 | 与距离和介质有关，与数据量无关 |
