# 网络层：服务、路由与拥塞控制

## 本章要点

- 网络层的七项功能：信源到信宿的传输、逻辑寻址、路由、地址转换、复用、流量和拥塞控制、网络互连。
- **工作方式**说的是通信子网内部（网络层向传输层）怎么处理数据，**服务**说的是通信子网向端系统提供什么。原文在三处反复强调这个区别，考试爱考。
- 面向连接的网络服务就是虚电路，五步走完一次传输；面向无连接的就是数据报（CLNS），每个包独立找路。
- 路由选择算法分非适应性和适应性两大类。适应性又分孤立式、分布式、集中式，RIP 和 OSPF 都属于分布式。
- 距离向量（Bellman-Ford）只跟邻居换整张表，收敛慢会成环；链路状态（Dijkstra/SPF）向全网广播自己的邻居信息，全网视图一致。
- Dijkstra 的图里节点分网络和路由器两类，**路由器到网络的弧费用有效，网络到路由器的弧费用恒为 0**。
- IGP 管自治系统内部（RIP、OSPF、IS-IS），EGP 管自治系统之间（BGP）。
- 虚电路路由表四列 PORS / SNP / PORP / SNS，虚电路号是**局部编号**，每跳都会换。
- 拥塞控制管子网内部包太多，流量控制管发送方别压垮接收方。两者目标不同，别混。

## 5.1 网络层功能和服务

网络层要实现端到端的传递，提供交换和路由两种主要功能。交换和路由都要在原始数据包上附加源地址和目的地址，这两个地址是网络层地址（信源和信宿地址），和数据链路层的节点地址不是一回事。网络层提供任意两个网络节点之间的可靠通信。

### 5.1.1 网络层的功能

| 功能 | 说明 |
| --- | --- |
| 信源到信宿的传输 | 把多条物理链路连接成一条传输路径 |
| 逻辑寻址 | 在数据包头部加入源地址和目的地址，完成从信源到信宿的传输 |
| 路由 | 选择从一点到另一点发送数据包的最佳路径 |
| 地址转换 | 把网络层地址翻译成对应的物理地址 |
| 复用 | 同一条物理线路同时传输多个设备间的数据 |
| 流量和拥塞控制 | 管理网络流量，防止网络拥塞 |
| 网络互连 | 解决网络之间互连的相关问题 |

### 工作方式与服务的区别

这是原文标了批注的地方，两个词长得像但说的是两回事。

网络层有两种**工作方式**：面向连接和面向非连接。【网络内部（网络层向传输层）如何处理数据传输】

- 面向连接：先建立连接再传输数据，传输路径固定。
- 面向非连接：不建立连接，数据包独立传输，路径动态决定。

网络层有两种**服务**：面向连接的服务和面向非连接的服务。【通信子网向端系统提供的功能类型】

- 面向连接的服务：提供可靠、按序的数据传输服务。
- 面向非连接的服务：提供独立、灵活的数据传输服务。

一句话记：方式侧重网络内部怎么处理和传输数据，服务侧重网络层向端系统提供什么功能。

### 5.1.2 面向连接的网络服务【虚电路】

面向连接的网络服务为数据传输建立一条虚电路，这条电路在整个数据传输过程中保持有效。属于这次传输的所有包都按顺序沿这条电路走。【逻辑连接】

一次传输过程的五步：

1. 发送者发送一个连接请求包。
2. 接收者用一个连接确认包进行确认。
3. 发送者传输数据。
4. 发送者发送一个连接终止请求包。
5. 接收者用一个连接终止包进行确认。

优点：

- 协议可以包含全面的顺序、差错和流量控制。
- 流量控制上可以使用滑动窗口。
- 数据包里的协议控制信息较少，额外开销小。

缺点：

- 连接一旦建立，路由的灵活性就没了。链路阻塞或出问题，后续的包不能改走别的路径。
- 比面向非连接的网络服务速度低。包要被检查、确认或重传。
- 面向连接也不一定能完全保证数据可靠传输。链路中任何一个组成环节仍有可能失效，而这种失效很严重，可能导致所有数据丢失。

### 5.1.3 面向无连接的网络服务【数据报】

每个包被当作独立的单元传输。无连接协议不提供逻辑连接，发送者不需要提前通知接收者要通信，直接发数据。中间节点根据路由信息和报头地址选择路径。【现找路】

优点：

- 如果可靠性和排序交给上层协议处理，CLNS 在速度和开销上有优势。
- 路径阻塞或中断时，包可以改走另一条路径。
- 单个传输的各个片断可以走不同路径，效率最大化。

缺点：

- CLNS 不可靠，无法保证数据包顺序到达。
- 每个包开销较大，因为每个包必须携带完整的地址信息。

### 两种方式的总结

通信子网向端系统提供两种网络服务：虚电路和数据报。通信子网内部的工作也分虚电路和数据报两种方式。这两层是可以交叉组合的：

- 提供虚电路服务的通信子网，内部操作可以是虚电路方式，也可以是数据报方式。
- 操作方式为虚电路的网络通常提供虚电路服务。
- 数据报方式的网络也可以提供虚电路服务：子网内部按数据报方式交换数据，而与端系统连接的网络节点向端系统提供虚电路服务。

【下层不可靠，上层不一定不可靠】对端系统来说，它的网络层与网络节点的通信看起来就像虚电路操作方式：先建立虚电路，再交换数据，最后拆除连接。TCP/IP 里 IP 协议是无连接的，但 TCP 协议是面向连接的，就是这个道理。通信子网的数据报交换不可靠，但两端的网络节点通过排序、重发等操作，照样满足了虚电路的服务要求。数据报服务一般由数据报交换网提供。

## 5.3 路由选择策略

路由选择是指网络中各个节点为到来的数据包选择一条输出链路。

- 数据报方式：每个到来的包都要做一次路由选择。
- 虚电路方式：只在建立虚电路时做一次路由选择，之后所有数据包都按这条路由传送。

### 5.3.1 路由选择的基本要求

1. 正确性：路由算法必须是正确的。
2. 简单性：算法在计算上应该简单。
3. 坚定性：长时间运行不会出现系统故障。
4. 稳定性：算法是收敛的。
5. 公平性：通信节点利用信道的机会均等。
6. 最佳性：按一定的标准获得最好的效果。

### 5.3.2 路由选择策略

按算法能不能随网络的通信量或拓扑结构变化而调整，分两大类。

**1. 非适应性路由选择**

算法不随网络通信量变化而变化，但实现容易。【固定的，提前设计好的】

| 方法 | 做法 |
| --- | --- |
| 洪泛法（flooding） | 节点收到一个包，就向所有与此节点相连的链路发送这个包 |
| 有选择的洪泛法 | 只在满足事先确定的条件时才转发包 |
| 固定路由法 | 按最短路径建一个表，标明每个目的地址的包从哪条链路转发 |
| 随机走动法（random walk） | 随机选一条链路转发 |
| 分散通信量法 | 每个节点设一个表，给出几条可用的输出链路，每条链路赋一个概率，这个概率就是用它转发的概率 |

**2. 适应性路由选择**

适应网络中通信量变化较大的情况。

| 策略 | 做法 | 特点 |
| --- | --- | --- |
| 孤立的路由选择 | 各节点只根据自身状态决定路由，不与其它节点交换信息 | 算法简单但不准确，有时效率不高 |
| 分布式路由选择 | 每个节点有一张路由表，周期性地从相邻节点获得网络状态信息，同时通知相邻节点本节点的路由选择 | 路由选择动态变化。典型算法 RIP（距离向量）和 OSPF（链路状态，原文作"路由状态"） |
| 集中式路由选择 | 网络控制中心（NCC）负责全网状态信息的收集、路由计算及选择，每个节点定期向 NCC 报告状态 | 优点是各节点不用自己算路由；缺点是通信量大、可靠性差、网络规模有限 |

## 5.4 基本的路由算法【不一定按序到达】

距离最短的路径是最佳路径。"距离最短"的标准可以是费用最小、传输延迟最小、数据传输速率最大，或者这几个因素的某种组合。

两种最常用的最短路径计算方法：距离向量路由、链路状态路由。【都属于适应性的分布式，都基于最短路径】

### 5.4.1 距离向量路由算法

这是一种迭代算法，每个路由器周期性地把自己关于整个网络的信息发给邻居，交换周期通常 30 秒。三条规则：

1. 每个路由器保存关于整个网络的信息。
2. 仅与邻居交换网络信息。
3. 信息交换按有规律的时间间隔进行（一般每周期 30 秒）。

**路由表格式**：每一项是 `NetID : Distance : Nexthop`。

- `NetID`：网络标识符
- `Distance`：到目标网络的距离
- `Nexthop`：下一跳路由器

#### 算法特点

优点：简单，适用于小规模网络。

缺点：

- 网络规模伸展性差。
- 对链路状态变化响应慢。
- 路由包文尺寸大，长度与路由器数量成正比。

#### 典型协议 RIP

RIP（Routing Information Protocol）是典型的距离向量路由协议。配置命令示例：

```
Router rip
Network 192.168.1.0
Network 192.168.2.0
```

#### 例：节点 E 的距离表（原文第 131 页，图里的内容）

带权无向图，边为：`A-B 7`、`A-E 1`、`B-C 1`、`B-E 8`、`C-D 2`、`D-E 2`。E 的邻居是 A、B、D。

横轴是"经过哪个邻居"，纵轴是目的地。$D^E(A, D)$ 表示从 E 出发、经过 D 到 A 的代价。加粗的是每行的最小值，也就是 E 实际会选的下一跳。

| $D^E()$ | 经 A | 经 B | 经 D |
| --- | --- | --- | --- |
| A | **1** | 14 | 5 |
| B | 7 | 8 | **5** |
| C | 6 | 9 | **4** |
| D | 4 | 11 | **2** |

算法就是 $D^E(A,D) = c(E,D) + D^D(A,w) = 2 + 3 = 5$，本节点到邻居的链路代价，加上邻居报上来的到目的地的距离。

这个例子说明**距离向量法可能存在环路**。看"经 D 到 A"这一格的 5：D 报上来的 3 走的是 `D-E-A`，又绕回了 E 自己。表上看不出这一点，因为 E 只知道一个数字 3，不知道这条路径经过谁。真按这条转发就会兜圈子，这也是 RIP 要配水平分割和毒性逆转的原因。详细的计数到无穷推演见 `14 计算题精练.md` 题 20。

### 5.4.2 链路状态路由算法

每个路由器和互连网络中的**所有**其它路由器共享关于**它自己邻居**的信息。这是一种广播式的算法，信息共享按有规律的时间间隔进行（一般每 30 分钟）。

- 共享的是自己关于邻居的信息。
- 共享的信息发给所有的路由器。

理解链路状态路由的关键就在它和距离向量的这两点不同：距离向量是把整张表只发给邻居，链路状态是把自己这一条发给全网。

链路状态路由两步完成：

1. 共享链路状态信息：每个路由器把自己与所有邻居之间的链路状态信息发送给互连网络中的所有其它路由器。
2. 计算路由：每个路由器根据掌握的整个网络的链路状态信息，计算到每个网络的路由。

#### ① 链路状态信息共享

【注意图上有箭头，代表转发代价，A 到 F（Net3）的代价是 3，F 到 A 的代价是 2】同一条链路两个方向的费用可以不一样，A 到 Net3 这条弧费用 3，F 到 Net3 那条只有 2。

1. **路由器传输包的费用**：费用是多种因素的加权值，包括安全级别、流量和链路的传输速率等。
2. **链路状态包（LSP）**：路由器向所有路由器发送 LSP，在网络中扩散关于其邻居的信息。LSP 通常包含四个信息域：广告者的 ID、目标网络 ID、费用、邻居路由器 ID。
3. **获得邻居信息**：每个路由器周期性地发送简短的**问候包**获取邻居信息，问候包小且占用资源少。
4. **初始化**：路由器启动时向所有邻居发送问候包获取链路状态信息，根据结果准备 LSP 并扩散到整个网络，类似于说"大家好，我是新路由器，有人吗"。
5. **链路状态数据库**：每个路由器接收其他路由器发送的 LSP，把信息存放到链路状态数据库中。

#### ② Dijkstra 算法计算路由表

Dijkstra 算法（1959）用由节点和弧组成的图计算网络中两点之间的最短路径。

- 节点有两种类型：网络和路由器。
- 弧也有两类：路由器到网络的链路、网络到路由器的链路。
- **在 Dijkstra 算法中，从路由器到网络的链路费用有效，从网络到路由器的链路费用总是为 0。**

每个路由器按下面四步形成最短路径树：

1. **初始化**：选择自己作为树的根，把根标记为永久节点，从根连接所有邻居节点（临时连接）。
2. **累积费用**：比较所有临时连接，找出累积费用最小的路径，标记为永久部分。
3. **延伸节点**：从选定的最短路径向外延伸，连接所有非永久节点，把这些节点临时性地加到最短路径树上。【标记永久部分之后，永久部分需要向外延伸】
4. **重复**：重复步骤 2 和 3，直到所有节点都成为最短路径树上的永久部分。如果所有节点都已经是最短路径树上的永久部分，算法结束，去掉非永久性的弧；否则转步骤 2 继续执行。

**以路由器 A 为例的推演**（原文第 134～140 页全是图，这里用文字讲清过程，逐步推演图见原文第 134～140 页）：

整个过程就是"在所有临时弧里挑累积费用最小的那条，把它和它指向的节点转成永久，然后从这个新永久节点再向外延伸出新的临时弧"，一直转到所有节点都永久为止。注意原文图上箭头标的是**累积费用**，单段费用要看上面那份链路费用清单。按这个规则走一遍：

- 从 A 出发的三条弧临时费用是 Net1 = 1、Net5 = 2、Net3 = 3。先定 A 到 Net1 这条为永久。
- Net1 向外只能延伸到 B。网络到路由器费用为 0，所以 A 到 B 的累积费用还是 1，B 转永久。
- B 继续延伸，只连着 Net2，A 到 Net2 累积费用 1 + 2 = 3，大于此时 A 到 Net5 的 2，所以先把 A 到 Net5 定为永久。
- Net5 延伸出 E（临时，累积 2）。此刻最小的临时弧就是 A 到 E 的 2，E 转永久。从 E 向外延伸，Net7 被临时加入，累积 2 + 2 = 4。
- 比较所有临时连接，B 到 Net2 的 3 最小，定为永久，再向外延伸出 Net2 到 C。
- 继续比较，Net2 到 C 的 3 最小，定为永久，向外延伸出 C 到 Net6（累积 5）。
- 继续比较，A 到 Net3 的 3 最小，定为永久，向外延伸出 Net3 到 F。
- 继续比较，Net3 到 F 的 3 最小，定为永久，向外延伸出 F 到 Net4（累积 6）。
- 继续比较，E 到 Net7 的 4 最小，定为永久，延伸出 Net7 到 D。
- 继续比较，Net7 到 D 的 4 最小，定为永久，延伸出 D 到 Net6（累积 9）。
- 继续比较，C 到 Net6 的 5 最小，定为永久。【仍然存在节点未在最短路径树上，算法未结束】
- 继续比较，F 到 Net4 的 6 最小，定为永久。【所有节点都在最短路径树上，算法结束】

D 到 Net6 那条累积 9 的弧一直是临时的，算法结束时被去掉（Net6 已经用 C 那条 5 的弧进树了）。【注意：非永久弧最后会被去掉】

得到路由器 A 的最短树路由表（原文第 140 页）：

| 目标网络 | 费用 | 下一个路由器 |
| --- | --- | --- |
| 1 | 1 | - |
| 2 | 3 | B |
| 3 | 3 | - |
| 4 | 6 | F |
| 5 | 2 | - |
| 6 | 5 | B |
| 7 | 4 | E |

"下一个路由器"填的是这条路径上**离 A 最近的那一跳路由器**，不是目标网络的直连路由器。Net6 的费用 5 走的是 `A-Net1-B-Net2-C-Net6`，第一跳是 B，所以填 B 而不是 C。

#### Dijkstra 算法总结（原文第 141 页）

1. 初始化：设 $N$ 为网络节点集合，令 $N=\{1\}$。对不在 $N$ 中的节点 $V$：若 $V$ 与节点 1 相邻，则 $S(V)=L(1,V)$；否则 $S(V)=\infty$。
2. 找出最小 $S(W)$：找出不在 $N$ 中的节点 $W$，使 $S(W)$ 值最小，把 $W$ 加入 $N$。然后对仍不在 $N$ 中的每个 $V$ 更新

$$S(V) \leftarrow \min[S(V),\ S(W)+L(W,V)]$$

3. 重复步骤 2，直到所有网络节点都在 $N$ 中。

#### 最短路径的基本性质

最短路径算法具有**最优子结构性质**：两顶点之间的最短路径包含路径上其他顶点之间的最短路径。

形式化地说，对带权图 $G=(V,E)$，若 $p=\langle v_1,v_2,\dots,v_k\rangle$ 是从顶点 $v_1$ 到顶点 $v_k$ 的最短路径，则对任意 $1\le i\le j\le k$，子路径 $P=\langle v_i,v_{i+1},\dots,v_j\rangle$ 也是从 $v_i$ 到 $v_j$ 的最短路径。

原文第 141 页还配了一道八节点带权图的 Dijkstra 例题，边为 `A-B 2, A-G 6, B-E 2, B-C 7, E-G 1, E-F 2, G-H 4, C-F 3, F-H 2, H-D 2`，以 A 为根的结果是 `B(2,A) E(4,B) G(5,E) F(6,E) H(8,F) C(9,B) D(10,H)`。完整的分步表格和两个易错点写在 `14 计算题精练.md` 题 21。

### 小结：距离向量与链路状态的五点对比

| 对比项 | 距离向量路由 | 链路状态路由 |
| --- | --- | --- |
| 底层算法 | Bellman-Ford | Dijkstra / SPF |
| 信息交换方式 | 路由器发送**整张路由表**给邻居，仅向邻居发送更新信息 | 路由器仅发送**与其直连链路相关的状态信息**给网络中的所有路由器，确保所有路由器拥有一致的网络拓扑视图 |
| 收敛速度 | 更新是周期性的，完整路由表更新 | 更新是非周期性的，部分更新。收敛速度较快（全局信息一致） |
| 防环机制 | 容易产生路由环路和计数到无穷大，需要结合防环机制 | 用 SPF 算法，不易产生路由环路或错误的路由信息 |
| 边权重 | 适用于更一般的问题，图中边的权值可以为负 | 边的权为非负 |

两者都采用最短路径算法，这一点是共同的。

## 5.5 基本的网关路由协议

互连网（Internet）中的路由选择和数据传输依赖两级路由协议：内部网关协议（IGP, Interior Gateway Protocol）和外部网关协议（EGP, Exterior Gateway Protocol）。

### 1. 内部网关协议（IGP）

用于自治系统（AS）内部的路由选择。自治系统是在一个管理机构控制下的一组路由器和网络，它们使用一致的路由策略。

- 适用范围：单一自治系统内部，管理和优化一个 AS 内的路由选择。
- 常见协议：RIP（距离向量，适用于小型网络）、OSPF（链路状态，适用于大型复杂网络）、IS-IS（类似 OSPF，也基于链路状态）。
- 工作原理：周期性地广播或发送路由更新信息，维护网络拓扑和路由表；路由器根据收到的更新计算最优路径并更新自己的路由表。

### 2. 外部网关协议（EGP）

用于不同自治系统之间的路由选择，在 AS 之间建立路由连接，保证跨 AS 的数据传输。

- 常见协议：BGP（Border Gateway Protocol），当前最广泛使用的外部网关协议，基于路径向量路由算法。
- 工作原理：BGP 路由器交换路由信息，基于路径向量算法选择最佳路径；再把选定的路由信息传播给相邻的 BGP 路由器，逐步建立全网的路由路径。

### 区别与联系

| 维度 | IGP | EGP |
| --- | --- | --- |
| 层级结构 | 用于 AS 内部 | 用于 AS 之间 |
| 协议种类 | RIP、OSPF、IS-IS 等 | 主要是 BGP |
| 应用范围 | 管理局部网络路由 | 管理跨域路由 |

两级路由协议共同构成了互联网的路由体系。

### 5.5.1 互连网络的路由问题

- **多协议路由器**：网络互连可能需要多协议路由器，这些路由器能处理多种通信协议。
- **自治系统（AS）**：一个自治系统就是处于一个管理机构控制之下的路由器和网络群组。一个自治系统中的所有路由器必须相互连接，运行相同的路由协议。

### 5.5.2 内部网关路由选择协议

OSPF（Open Shortest Path First，开放最短路径优先）是典型的链路状态路由协议，是互连网中应用最广的路由协议。

SPF 算法是 OSPF 协议的基础，有时也称为 Dijkstra 算法。在 OSPF 协议中，最短路径树的树干长度被称为 OSPF 的 Cost，计算公式为

$$\text{Cost} = 100\times 10^6 / \text{链路带宽}$$

【还可以是 RIP（典型的距离向量协议）或自己设置的协议（因为是内部的，不用考虑安全问题）】

### 5.5.3 外部网关路由选择协议

BGPv4（Border Gateway Protocol，边界网关协议）是典型的外部网关协议，负责自治系统间的路由选择。

- BGP 是一种距离向量协议，使用增量的、触发性的路由更新，而不是常规距离向量协议的周期性整体路由表更新。（有变化才更新，而不是周期性更新）
- BGP 是一个通路向量协议，它通告前往目的地的一系列自治系统号。

## 5.6 虚电路中数据包的传输

数据包发送之前先用路由算法建立一条虚电路，发送者沿这条虚电路把数据包传给接收者。【虚电路号是局部的，不是全局唯一的】

### ① 虚电路路由表

- 定义：包的传送依赖于路由表，每个交换节点都有一个虚电路路由表。
- 内容：表中每一行记录一个虚电路的信息。
- 初始状态：所有虚电路建立之前，各节点的路由表是空的；虚电路建立完毕后，各交换机的虚电路路由表就形成了。

路由表共四列（原文正文写作 PROS / PROP，第 146 页的图里写的是 `PORS` / `PORP`，这里按图上的写法）：

| 列 | 含义 |
| --- | --- |
| PORS | 前驱节点或者信源节点的地址 |
| SNP | 从同一前驱节点来的不同虚电路的顺序号 |
| PORP | 后继节点或者信宿节点的地址 |
| SNS | 到同一后继节点的不同虚电路的顺序号 |

### ② 路由表的建立（原文第 145～146 页，图里的例子）

子网有五台交换节点 A～E，外挂五台主机 H1～H5。建立五条虚电路：

```
VC1: H1-A-B-E-H5
VC2: H1-A-B-D-H4
VC3: H2-B-D-E-H5
VC4: H3-C-B-E-H5
VC5: H1-A-B-C-E-H5
```

H1 发起 3 条虚电路 VC1、VC2、VC5，在 H1 这边分别编号 0、1、2；H2 发起 1 条 VC3，编号 0；H3 发起 1 条 VC4，编号 0。

SNP 和 SNS 就是"每个节点来的节点的顺序编号与去的节点编号"。比如在节点 B，从 A 来的那些虚电路 SNP 从 0 依次递增，去 E 的那些虚电路 SNS 也从 0 依次递增。

建成后的五张表（我按五条路径逐条核对过，与原图一致）：

| --- | --- | --- | --- | --- |

### ③ 虚电路的编号

每个节点对虚电路**独立编号**，两个好处：

- 便于分布式实现，不需要集中的机构管理虚电路的编号，每个节点只考虑经过自身的虚电路的编号。
- 虚电路的编号短，减少包的额外开销。

以虚电路 5 为例，包在路上的号码变换（原文第 146 页）：

```
H1 --[2]--> A --[2]--> B --[0]--> C --[0]--> E --[3]--> H5
```

【第一个写 SNP，接下去都写 SNS】进 A 那一段填的是 A 表里 VC5 那行的 SNP = 2，往后每一段填的都是上一个节点那行的 SNS：A 的 SNS = 2，B 的 SNS = 0，C 的 SNS = 0，E 的 SNS = 3。同一条虚电路在每一跳的编号都不一样，这就是"局部编号"的意思。

### 虚电路服务

定义：网络层向传输层提供的一种使所有分组**按顺序到达**目的端系统的可靠数据传送方式，也是通信子网向端系统提供的网络服务。

提供这种虚电路服务的通信子网，内部的实际操作可以是虚电路方式，也可以是数据报方式。【注意，服务和方式的区别，方式是通信子网内部（网络层向传输层），服务是通信子网向端系统】

- 以虚电路方式工作的网络一般总是提供虚电路服务。
- 以数据报方式工作的网络也可以提供虚电路服务：子网内部节点按数据报方式交换数据，而与端系统相连接的网络节点向端系统提供虚电路服务。对端系统来说，它的网络层与网络节点间的通信仍像虚电路工作方式一样，先建立连接，再交换数据，最后拆除连接。实际上每个分组在网络节点分成若干数据报，附上地址，以数据报的工作方式送到目的节点，目的节点再把数据报排序送给端系统，从而满足虚电路服务的要求。

## 5.7 拥塞控制和流量控制

- **拥塞控制**的基本目的是防止整个网络或网络的一部分出现过多的数据包。【子网内部】
- **流量控制**的目的是保证发送方发送的信息量不会超过接收方的接收能力。【终端之间】

### 5.7.1 拥塞控制

**拥塞**：网络或其一部分出现过多的包，导致网络性能下降的现象。

#### ① 包交换节点的模型

一个包交换节点（图上是节点 4）连着若干条链路，通向相邻节点和本地主机。每条链路上有输入缓冲区和输出缓冲区。【每个链路上有两个队列】

#### ② 拥塞产生的原因

节点的处理速度和链路的传输速度不够高。

#### ③ 拥塞对系统的影响

分对吞吐量的影响和对传输延迟的影响两方面：

- 丢包。
- 吞吐量降低。【缓冲区有限，队列长度超过缓冲区大小时，包就要被丢弃，丢的包越来越多，重传的包越来越多，能进入网络的包就越来越少，吞吐量就越来越低直至为 0，造成系统瘫痪】
- 传输延迟变大。

#### ④ 控制拥塞的五种方法

| 方法 | 做法 | 适用与局限 |
| --- | --- | --- |
| 预分配缓冲区 | 虚电路建立时通知节点为此虚电路预留缓冲区 | 常用于虚电路技术 |
| 丢弃包 | 节点收到过多的包来不及处理或无法发送时，丢弃部分包 | 适用于突发性拥塞；长时间大通信量时这招行不通 |
| 限制网内包数量 | 限制进入网络的包数量，在网络内设置若干个许可证 | 许可证丢失会导致传输能力下降，而且丢失还不容易被发现 |
| 流量控制 | 接收端调节发送端的数据速率，防止到达接收端的数据速率超过其处理速率 | |
| 阻塞包 | 每个节点监视所有输出链路的使用情况，达到一定状态时进入"警戒"状态，向源主机发送一个阻塞包 | |

### 5.7.2 流量控制

【端到端】流量控制可以在四个层次上进行，范围从小到大：

| 层次 | 范围 |
| --- | --- |
| 相邻节点间 | 子网内两个相邻交换节点之间 |
| 主机与源节点间 | 主机和它接入的那个网络节点之间 |
| 源节点与目的节点间 | 子网入口节点到出口节点 |
| 主机间 | 两端主机之间，最大的那一层 |

#### ① 主机和源节点间的流量控制

本质上是通过控制进入通信子网的信息量，防止整个网络缓冲区产生拥塞。

采用的方法：停止等待流量控制、缓冲区预约、许可证方案。

#### ② 源节点和目的节点之间的流量控制

流量控制任务与通信子网的工作方式紧密相关：

- 虚电路方式：流量控制任务较轻，因为虚电路方式本身要求有基本的缓冲区，包沿固定路径传送且按顺序到达目的节点。
- 数据报方式：缓冲区分配采用**先来先服务**且全部分配的方法，可能产生存储转发死锁。

**（1）存储转发死锁**

分两种（原文第 149 页的图）：

- （a）直接死锁：节点 A 的包全排队等着发给 B，节点 B 的包全排队等着发给 A，两边存储缓冲区都满了，谁也腾不出地方收对方的包，死锁。
- （b）间接死锁：三个节点首尾相接成环，A 等 B、B 等 C、C 等 A，各自缓冲区都满，同样解不开。（更正：原文图里三个节点标注为"节点 A / 节点 B / 节点 B"，第三个应为节点 C）

**（2）重装死锁**

节点 X 的缓冲区里排着 `C1 B2 A3 B1` 已经满了，节点 Y 的缓冲区里有 `A4 A2 A1`，正等 A3 到齐才能拼出完整报文交给主机 H。A3 卡在 X 里出不来，而排在它前面的 B1 又转发不到 Y（Y 没有用于存放 B1 的缓冲区），两边互相等着，发生重装死锁。

## 易混对比

| 对 | 区别 |
| --- | --- |
| 工作方式 / 服务 | 方式是通信子网内部（网络层向传输层）怎么传；服务是通信子网向端系统提供什么。数据报方式的子网照样可以对外提供虚电路服务 |
| 虚电路 / 数据报 | 虚电路建连接、路径固定、按序到达、开销小但不灵活；数据报独立转发、路径动态、可能乱序、每包带全地址开销大 |
| 非适应性 / 适应性路由 | 前者算法固定提前设计好，实现容易；后者随通信量和拓扑变化调整 |
| 孤立式 / 分布式 / 集中式 | 孤立式只看自己；分布式周期性和邻居交换；集中式由 NCC 统一算 |
| 距离向量 / 链路状态 | 整张表发给邻居 vs 自己那条发给全网；周期性全量更新 vs 触发式部分更新；易成环 vs 不易成环；权可为负 vs 权非负 |
| IGP / EGP | AS 内部 vs AS 之间；RIP/OSPF/IS-IS vs BGP |
| 拥塞控制 / 流量控制 | 拥塞控制针对子网内部包太多，是全局问题；流量控制针对收发双方速率不匹配，是端到端问题。流量控制同时也是拥塞控制的五种手段之一 |
| 存储转发死锁 / 重装死锁 | 前者是缓冲区互相占满、转发不出去；后者是报文的某个分片到不了，已到的分片又占着缓冲区不放 |
| SNP / SNS | SNP 按前驱节点编号，SNS 按后继节点编号。包在链路上带的号，第一跳写 SNP，后面每跳写上游节点的 SNS |

## 典型题

### 题 1　虚电路路由表填空

给一张子网拓扑和几条虚电路的路径，要求填出每个节点的四列表。做法固定：

1. 沿每条虚电路的路径，在每个经过的节点写一行，PORS 填上一跳（起点就写主机名），PORP 填下一跳（终点就写主机名）。
2. 把每个节点里 PORS 相同的行挑出来，按虚电路建立的先后给 SNP 排 0、1、2。
3. 把 PORP 相同的行挑出来，同样给 SNS 排 0、1、2。

检查点：同一节点里 (PORS, SNP) 不能重复，(PORP, SNS) 也不能重复，否则就分不清是哪条虚电路了。

### 题 2　链路状态数据库 + Dijkstra 求路由表

给一张带费用的二分图（节点分网络和路由器两类），求某台路由器的路由表。三个容易丢分的点：

- 网络到路由器的弧费用是 0，别当成有费用的边一起加。
- 弧是有方向的，同一条链路两个方向的费用可能不一样（A 到 Net3 是 3，F 到 Net3 是 2）。另外推演图上标的数字是累积费用，别和链路费用清单上的单段费用搞混。
- 路由表的"下一个路由器"填第一跳，不是最后一跳。

完整的例题见 `14 计算题精练.md` 题 21。

### 题 3　距离向量要迭代几轮才收敛

看网络里最长的那条最短路径有多少跳。本章的例子里 F 到 Net6 距离是 3，所以 F 要到第 3 轮才知道 Net6，整张表也在第 3 轮收敛。链路变坏时的计数到无穷推演见 `14 计算题精练.md` 题 20。
