## 本章要点

- 无线上不能直接套用 CSMA/CD，原文列了三个问题：冲突检测困难、隐藏终端、暴露终端。802.11 改用 **CSMA/CA**，在发送之前就把冲突躲开。
- 三种范围要分清：**TX-Range**（能收到帧）、**PCS-Range**（能听出有人在发）、**IF-Range**（会干扰接收方）。隐藏终端和暴露终端都是用这三个范围的相对大小定义的。
- CSMA/CA 就算信道空闲也要先等一个 IFS。退后计数器倒计时期间信道一忙就挂起，忙完再等一个 IFS 接着从没倒完的地方倒。
- SIFS < PIFS < DIFS，间隙越短优先级越高。ACK 和 CTS 用 SIFS 抢跑，普通数据用 DIFS。
- RTS-CTS 是信道预约，其他站点收到后更新 **NAV**，这叫虚拟载波侦听。
- 令牌环数据帧九个域：SD、AC、FC、DA、SA、LLC-PDU、CRC、ED、FS。AC 的比特模式 `PPPTMRRR`、ED 的 `JK1JK1IE`、FS 的 `ACrrACrr` 都是考点。
- FDDI 的公平性靠 TTRT、SA 两个寄存器和 TRT、THT 两个计时器。核心一句：**先发同步帧，THT 还是正的才能发异步帧**。
- ATM 信元固定 53 字节 = 5 字节报头 + 48 字节净荷。UNI 报头六个字段，NNI 报头少一个 GFC、VPI 从 8 位变 12 位。
- 帧中继砍掉了 X.25 的差错和流量控制，只留物理层和数据链路层，虚电路用 **DLCI** 标识。

## 7.3 无线局域网

### 无线局域网概述

**无线局域网（Wireless Local Area Network，WLAN）**是指以无线信道作为传输介质的计算机局域网，常用于家庭、办公和公共场所的无线网络连接。

设计目标：

- 覆盖范围小：受限于发射功率。
- 使用无需授权的频谱：如 ISM 频段。
- 面向高速率应用。
- 支持实时和非实时应用：如移动终端。

重要组织：

- **IEEE 802.11 工作组**：负责无线局域网标准的制定。
- **Wi-Fi 联盟**（Wi-Fi Alliance, WFA）：负责 Wi-Fi 技术的推广和认证。

一个定标准，一个发证书，别记反了。

### 无线局域网体系结构

无线局域网需要解决的问题分三组：

| 问题 | 具体内容 |
| --- | --- |
| 有限的无线频谱带宽资源 | 通道划分、空间重用；提高传输速率，解决传输问题；提高抗干扰能力和保密性 |
| 共享的无线信道 | 介质访问控制方法（CSMA/CA）；可靠性传输、安全性 |
| 组网模式管理 | BSS 构建、认证、关联；移动性支持（漫游）；睡眠管理（节能模式） |

对应的三层结构：

| 层 | 功能 |
| --- | --- |
| 物理介质相关子层（PMD 层） | 调制解调、编码/解码 |
| 物理层汇聚协议（PLCP 层） | 向上提供独立于传输技术的物理层访问点 |
| 介质访问控制层（MAC 层） | 可靠数据传输、介质访问控制、安全机制等 |

PLCP 存在的意义就是把下面五花八门的调制方式包装成统一接口，上面的 MAC 不用管物理层换了几代。

### IEEE 802.11 物理层

物理层技术概览：

| 维度 | 内容 |
| --- | --- |
| 频段 | 2.4 GHz、5 GHz（ISM 频段，无需授权；限制发送功率，例如 $\le$ 1 瓦） |
| 调制技术 | DPSK → QPSK → CCK → 64-QAM → 256-QAM → 1024-QAM |
| 调制方法 | 直接序列扩频（DSSS）→ 正交频分多路复用（OFDM）→ 正交频分多址（OFDMA） |
| 天线技术 | 单天线 → 单用户多入多出（SU-MIMO）→ 多用户多入多出（MU-MIMO） |

目标：提升传输速率、增强可靠性、支持高密度接入。

三条演进线索各管一件事：调制技术管每个符号塞几个比特，调制方法管怎么分频谱和分用户，天线技术管同时开几条空间流。

### 无线局域网组网模式

**基础架构模式**

- 组成部分：分布式系统（DS）、访问点（AP）、站点（STA）、基本服务集（BSS）、扩展服务集（ESS）、服务集标识符（SSID）。
- 通信方式：站点间通信通过 AP 转发。

原文第 190 页下图画的结构是：两个 BSS，每个 BSS 里一个 AP 加两个 STA，两个 AP 上面接同一个分布式系统（DS），整体外面那个大圈就是 ESS。

几个概念的层层包含关系：STA 连上某个 AP 就构成一个 **BSS**；多个 BSS 通过 DS 连起来对外表现为一个网络，这叫 **ESS**；**SSID** 就是这个 ESS 对外显示的名字，也就是手机上看到的那个 Wi-Fi 名称。

**自组织模式（Ad hoc）**

- 组成部分：站点（STA）、独立基本服务集（IBSS）。
- 通信方式：站点之间直接通信，共享同一无线信道。

IBSS 里没有 AP，也就没有 DS，所以它不能和外网互通，只能内部对聊。

### 7.3.1 IEEE 802.11 介质访问控制

#### 直接将 CSMA/CD 用于无线局域网的问题

- **冲突检测困难**：
  - 在接收端，发送功率和接收功率相差太大。自己发出去的信号盖过一切，根本听不见别人。
  - 站点在发送时关闭接收功能，无法在发送时同时检测冲突。
- **隐藏终端问题**：
  - 在同一 BSS 中，不是所有站点都能互相感知到对方发送的信号，导致冲突检测失败。
  - 载波侦听失败，但在接收站点处发生冲突。
- **暴露终端问题**：
  - 降低网络的吞吐量。
- **信号衰落**随时间发生变化，使问题变得更加复杂。

#### 无线传输相关的三种范围

| 范围 | 定义 | 取决于 |
| --- | --- | --- |
| 传输范围（TX-Range） | 成功接收帧的通信范围 | 发送功率和无线电波传输特性 |
| 物理层侦听范围（PCS-Range） | 检测到该传输的范围 | 接收器的灵敏度和无线电波传输特性 |
| 干扰范围（IF-Range） | 在此范围内的节点如果发送不相关的帧，将干扰接收端的接收并导致丢帧 | 接收端所处的环境 |

【传输范围和侦听范围不一定谁大，但是大概率不一样】【干扰范围是对接收方来说的】

原文第 192 页上图画了两个圆：发送模式下画的是传输范围套着侦听范围（侦听范围在外），接收模式下画的是干扰范围。**干扰范围是围着接收方画的，不是围着发送方画的**，这是区分隐藏终端和暴露终端的关键。

#### 隐藏终端问题

【有冲突没发现】

定义：由于距离太远或障碍物，导致站点无法检测到竞争对手的存在，隐藏站点不能侦听到发送端但能干扰接收端。

示例：A 向 B 传输数据时，C 也要向 B 发送数据。【A 检测不到 C，C 检测不到 A，但对 B 来说发生冲突。他们都认为信道空闲，但是对于 B 来发生冲突。对于 A 来说，C 是隐藏站点】

原文第 192 页给了三条几何条件，画成一个三角形：

| 两点 | 条件 |
| --- | --- |
| 发送端到目的端 | 小于传输范围，`< TX-range` |
| 目的端到隐藏站点 | 小于干扰范围，`< IF-range` |
| 发送端到隐藏站点 | 大于侦听范围，`> PCS-range` |

翻译一遍：发送端够得着目的端，隐藏站点也够得着目的端（能捣乱），但发送端和隐藏站点互相听不见。

#### 暴露终端问题

定义：由于侦听到其他站点的发送而误以为信道忙导致不能发送。暴露站点能侦听到发送端但不会干扰接收端。

示例：B 向 A 传输数据时，C 要向 D 发送数据。【但 B 发送的信号对 D 无影响，C 发送的信号对 A 无影响，但 B 和 C 认为互相干扰，都不发送。】

对应的三条几何条件：

| 两点 | 条件 |
| --- | --- |
| 发送端到目的端 | 小于传输范围，`< TX-range` |
| 发送端到暴露站点 | 小于侦听范围，`< PCS-range` |
| 目的端到暴露站点 | 大于干扰范围，`> IF-range` |

两个问题的危害方向相反：隐藏终端**该退让的没退让**，造成冲突；暴露终端**不该退让的退让了**，白白损失吞吐量。

#### CSMA/CA

CSMA/CA 是 Carrier Sense Multiple Access with Collision Avoidance，带冲突避免的载波侦听多路访问。

- 当信道空闲时间大于 IFS（帧间隙），立即传输。【原文批注：CSMA/CA 侦听到信道空闲时还要先等一个 IFS 才发，这点和以太网的 1-坚持不一样】
- 当信道忙时，延迟直到当前传输结束加上 IFS 时间。
- 开始随机退后过程：
  1. 从 $(0,\ CWindow)$ 中选择一个随机数作为退后计数器（backoff counter）。
  2. 通过侦听确定每个时间槽是否活动。
  3. 如果没有活动（空闲），则减少退后时间（倒计数）。
  4. **退后过程中如果信道忙，则挂起退后过程**；在当前帧传输结束后恢复退后过程。
- 目标：使用退后过程延迟发送以避免多个站点同时传输引起的冲突。

所有站点完成发送后，必须等待一段很短的时间才能发送下一帧。这段时间通称为帧间间隔或帧间隙（IFS，Inter-Frame Space）。

原文第 193 页的流程图走向是：等待传输 → 载波侦听检测信道 → 信道空闲吗？空闲就等一个 IFS，再问介质仍空闲吗，是则传输帧；不空闲就等到当前传输结束，等一个 IFS，再问介质仍空闲吗，是则执行二进制指数退后，然后传输帧。

**CSMA/CA 示例**（原文第 194 页上图，五个站点的时序）

图片中橙色的是在发送，蓝色代表回退计时，在等待（检测到忙的时候就得执行退让算法）。

站 1 和站 5 的退让时间比较长，所以站 2 先发。【注意，一旦有数据开始发送数据，倒计时就终止，在数据发送完后且等待 1 个 IFS 后接着倒计时（时间是之前倒计时没倒完的时间）】

但是站 4 和站 5 冲突，传完数据后终止执行（发生冲突后随机数会增加，等待时间会变长）。

「挂起而不是重置」这一点和以太网不一样，值得单独记：退后计数器停下来以后保留剩余值，下一轮接着倒，所以等得久的站点后面反而占优势，这是 802.11 保证公平性的机制。

#### 竞争窗口 CWindow 的选择

- 选择依据：应与网络负载情况相适应，冲突次数间接反映网络负载情况。【冲突次数越多，表明网络负载越重】
- **二进制指数退后算法**：竞争窗口初始值为某个最小值，发生冲突时加大窗口，直到达到最大值。
- 算法优点：
  - 网络负载轻时，选择较小的竞争窗口，减小站点等待时间。
  - 网络负载重时，选择较大的竞争窗口，避免站点间随机值过于接近导致过多冲突。

原文第 194 页的柱状图给了一组典型取值：

| 阶段 | 竞争窗口 |
| --- | --- |
| 初次发送 | 31（最小竞争窗口） |
| 一次重传 | 63 |
| 二次重传 | 127 |
| 三次重传 | 255 |
| 四次重传 | 511 |
| 五次重传 | 1023（最大竞争窗口） |

规律是 $CW = 2^{n+5}-1$，每冲突一次翻一倍再加一，到 1023 封顶。

#### 差错检测与确认重传

- 差错检测：32 位 CRC 校验（与以太网相同）。
- 确认重传：采用**停等机制**，即发送数据后等待确认，超时重传（重传定时器）。如果达到最大重传限制，丢弃该帧并告知上层协议。

原文第 195 页的时序图：源站等一个 DIFS 后发 Data，目的站等一个 SIFS 后回 Ack，其他站点要等到 DIFS 之后才能发自己的 Data。中间这整段标作「等待时间」。

**思考：采用停等机制的原因？为什么不采用流水线机制？**

1. 无线环境中的冲突和干扰。无线环境中信号容易受到各种因素的影响，如干扰、噪声和信号衰减。在这种环境下，确保每个帧的可靠传输显得尤为重要。停等机制能够在每帧传输后立即等待接收确认，确保帧已成功接收或在检测到错误时进行重传，从而提高了传输的可靠性。
2. 隐藏终端和暴露终端问题。无线局域网中存在隐藏终端和暴露终端问题，这使得冲突检测变得复杂。使用停等机制可以减小这些问题的影响，因为每次发送后都要等待接收确认，从而可以及时发现并处理冲突。
3. 资源有限和复杂性。无线通信资源有限，停等机制相对简单，容易实现和管理。而流水线机制需要更多的缓冲和复杂的管理策略，容易导致在无线环境中增加系统的复杂性和资源开销。

#### 不同帧间隙控制优先级

| 帧间隙 | 长度 | 优先级 | 用途 |
| --- | --- | --- | --- |
| SIFS（Short IFS） | 最短 | 最高 | Ack、CTS、轮询响应等 |
| PIFS（PCF IFS） | SIFS + 1 槽口时间 | 中等 | 轮询服务 |
| DIFS（DCF IFS） | SIFS + 2 槽口时间 | 最低 | 异步数据服务 |

原文第 195 页下图把三段间隙画在一起：信道忙结束后，SIFS 最先到期，PIFS 次之，DIFS 最后；DIFS 之后才是竞争窗口，竞争窗口按槽口时间分格。

设计逻辑：**等得越短，抢得越早**。ACK 和 CTS 必须紧跟着前一帧发出去，所以给它们最短的 SIFS，别的站点还在等 DIFS 的时候它们已经发完了。

#### RTS-CTS 机制与 NAV

RTS-CTS 是可选机制。【信道预约机制】用来进一步减少冲突可能性。

目的：通过信道预约，避免长帧冲突。

流程：

1. **发送端发送 RTS**（Request to Send）
   - 当发送端（源站点）准备发送数据时，首先发送一个 RTS 帧（发送请求帧）来预约信道。
   - RTS 帧中包含源站点的地址、目标站点的地址以及数据传输所需的时间。
   - 若 RTS 帧发生碰撞，源站就不可能收到 CTS 帧，源站会执行退避算法重传 RTS 帧。
2. **接收端回送 CTS**（Clear to Send）
   - 目标站点（接收端）收到 RTS 帧后，如果信道空闲且可以接收数据，会发送 CTS 帧（允许发送帧）作为响应。
   - CTS 帧中包含目标站点的地址、源站点的地址以及确认传输所需的时间。
3. **RTS 和 CTS 中的持续时间**
   - RTS 和 CTS 帧中指明的数据传输持续时间（包括数据和控制帧传输的时间）有助于其他站点了解信道的预定使用情况。
4. **维护 NAV**（Network Allocation Vector，网络分配向量）
   - 其他站点收到 RTS 或 CTS 后，会更新其 NAV，即网络分配向量，实现虚拟载波侦听。
   - NAV 表示信道预定的时间段，在这段时间内，其他站点将推迟自己的传输，避免冲突。

**虚拟载波侦听（Virtual Carrier Sense）**

- RTS 和 CTS 帧很短：
  - 由于 RTS 和 CTS 帧长度较短，即使产生冲突，信道浪费也较少。
  - 这种机制在信道预约期间有效减少了长帧冲突的可能性。
- NAV：是虚拟载波侦听的实现，通过维持信道预定信息，提高无线网络的效率和可靠性。

**RTS-CTS 怎么解决隐藏终端**

- 当源站点（如 A）发送 RTS 后，所有在 A 传输范围内的站点（包括隐藏站点）都会收到 RTS。
- 当目标站点（如 B）发送 CTS 后，所有在 B 传输范围内的站点（包括 A 的隐藏站点）也会收到 CTS，从而避免隐藏终端对接收端的干扰。

关键在第二条：隐藏站点听不见 A，但听得见 B，CTS 是 B 发的，所以隐藏站点一定收得到，收到就闭嘴。

完整时序（原文第 197 页上图）：

| 角色 | 时间轴 |
| --- | --- |
| 源 | DIFS → RTS → （等 SIFS）→ Data |
| 目的 | （收到 RTS 后等 SIFS）→ CTS → （收到 Data 后等 SIFS）→ Ack |
| 其他，第一组节点 | 收到 RTS，设 NAV(RTS) |
| 其他，第二组节点 | 收到 CTS，设 NAV(CTS)；收到 Data 头部，设 NAV(Data) |

第一组和第二组分别是听得见源站和听得见目的站的两批节点，两个 NAV 一叠加就把所有可能干扰的节点都盖住了。NAV 结束再等一个 DIFS，其他站点才能开始发自己的 Data。

#### 如何应对无线链路较高的出错率

- 解决方法：采用较小的帧，将用户数据帧**分段**以应对高出错率。对于用户而言，这个过程是透明的。
- 帧间传输： $F_i$ 帧中携带 $F_{i+1}$ 帧的传输时间信息，这样可以协调连续帧的传输，确保数据帧的完整性。

帧越短，一帧里撞上一个错误比特的概率越小，重传的代价也越小。代价是头部开销占比上升。

## 7.4 其它局域网技术

### 7.4.1 令牌环网

【对帧长有限制】

**概述**

令牌环网是一种网络拓扑结构，其中每个站点在特定时间内轮流传输数据。它对帧长度有限制，采用令牌传递机制来控制数据传输。

**令牌传递机制**

- 原理：每个站点只有在轮到自己发送的时候才能发送数据，同时**每次轮到只能发送一帧**数据。
- 令牌：令牌是一个简单的帧，绕着环从一个站点传送到另一个站点。环上的站点只有在拥有令牌的时候才能发送数据。

**物理层编码**：物理层采用**差分曼彻斯特编码**。（以太网用的是普通曼彻斯特编码，这里要分开记。）

**令牌环网访问模式**

1. 令牌传递
   - 每当网络空闲时，它便传播一个令牌。令牌是一个简单的帧，只有三个字节。
   - 令牌按顺序从一个网络接口卡（NIC）传送到另一个 NIC，直到遇到一个需要发送数据的站点。
   - 注意：A 到 D 的数据发送到 D 后，D 复制数据帧后仍然会将数据发回环中。
2. 数据帧返回发送站点
   - 当数据帧回到它的发送站点时，发送站点发现该帧的源地址和自己的地址相同。检查数据帧的最后一个域（帧状态域 FS），如果该帧的最后一个域中的相关信息被设置，发送站点明白这个帧已经被接收了，于是丢弃该帧，并将令牌释放回环里。

原文第 198 页把这个过程画成四格：(a) 令牌在环中循环；(b) A 获得令牌，向 D 发送数据；(c) D 复制数据帧，然后将数据帧发回环中；(d) 数据帧回到 A，A 释放令牌。

**令牌环的 MAC 帧格式**

令牌环网有三种类型的帧：数据帧、令牌帧和异常终止帧。

| 帧类型 | 域 |
| --- | --- |
| 数据帧 | SD、AC、FC、目的地址、源地址、LLC-PDU、CRC、ED、FS |
| 令牌帧 | SD、AC、ED |
| 异常终止帧 | SD、ED |

**1. 数据帧的各个域**

| 域 | 长度 | 内容与作用 |
| --- | --- | --- |
| 起始分界符 SD | 1 字节 | 用来警告接收站点一个帧即将到来。格式为 `JK0JK000`，其中 J、K 为违法码 |
| 访问控制 AC | 1 字节 | 比特模式为 `PPPTMRRR` |
| 帧控制 FC | 1 字节 | 类型位指明 LLC-PDU 域中的信息是数据信息还是控制信息；其他七位包含了在令牌环逻辑中使用的信息 |
| 目的地址 DA | 6 字节 | 包含帧的下一个目标的物理地址 |
| 源地址 SA | 6 字节 | 包含发送该帧的站点的物理地址 |
| LLC-PDU | 最大 4500 字节 | 上层数据 |
| CRC | 4 字节 | 包含 CRC-32 差错检测序列 |
| 结束分界符 ED | 1 字节 | 指明发送者数据或控制信息的结束。比特模式为 `JK1JK1IE` |
| 帧状态 FS | 1 字节 | 比特模式为 `ACrrACrr`，由接收者设置 |

违法码 J 和 K 的定义：

- **J**：开始和比特中间没有跳变。
- **K**：比特中间没有跳变。

差分曼彻斯特编码要求每比特中间必有跳变，J 和 K 故意破坏这条规则，所以它们绝不会和正常数据混淆，这就是用它们做分界符的原因。

AC 的 `PPPTMRRR` 拆开：

- **PPP**：三位优先级。
- **T**：指明该帧是令牌帧还是数据帧。
- **M**：监控位，用来防止永久循环的帧在网中存在。
- **RRR**：预留位，由希望对下一个令牌作预留的站点来填写。

ED 的 `JK1JK1IE` 里后两位：

- **I**：用于多帧传送中，表示还有后续帧要传送，此帧不是最后一帧。
- **E**：错误检测位，任何中间站点检测到任何错误时将该位置位。

FS 的 `ACrrACrr` 里：

- **A**：表示地址被识别。
- **C**：表示帧被接收者拷贝。

A 和 C 各出现两遍，是因为 FS 不受 CRC 保护（CRC 在它前面），重复一次相当于简易校验。发送站点回收帧时就看这两位：A=1 C=0 表示目的站在线但没收下（缓冲区满），A=0 C=0 表示目的站根本不在环上。

**2. 令牌帧**

只包含三个域：

- SD：指明帧即将到来。
- AC：除指明此帧是令牌外，还包括优先级域和预留域。
- ED：指明帧的结束。

三个域各 1 字节，这就是前面说的「令牌只有三个字节」。

### 7.4.2 令牌总线网

原文这一节下面没有文字，只有一张图（原文第 200 页）。图的内容是：

物理上是一条总线，A、C 接在总线上半，B、D 接在下半，四个站点用虚线箭头连成一个逻辑环。每个站点盒子里写着两个字段：

| 站点 | P（前趋站） | S（后继站） |
| --- | --- | --- |
| A | C | D |
| B | D | C |
| C | B | A |

### 7.4.3 FDDI 光纤分布式数据接口

【编码技术】【数据发送相对的公平性】这两条是原稿标出的重点方向。

**光纤分布式数据接口（FDDI）**：

- 由 ANSI 和 ITU-T 制定的标准化局域网协议。
- 支持 100 Mbps 的数据速率，采用环型拓扑结构。

**编码机制**

- **4B/5B 编码**：FDDI 使用 4 比特/5 比特编码机制。数据的每 4 个比特编码为 5 个比特，然后采用 **NRZ-I** 编码成信号。NRZ-I 在这里使用 1 反转。
- NRZ-I 在数据单元中含有一长串 0 的情况下，可能会丢失同步。4B/5B 编码将每个 4 比特数据转换为**不包含超过连续两个 0** 的 5 比特单元，从而保证信号里总有足够多的跳变。

两步走的分工：4B/5B 负责保证码流里 0 不会连成一串，NRZ-I 负责把比特变成电平变化。整理补充一句对比：曼彻斯特编码每比特要两个信号变化，编码效率 50%；4B/5B 是 4 比特换 5 比特，效率 80%，所以 100 Mbps 只需要 125 Mbaud 的信号速率。

**FDDI 的网络访问模式**

| | 令牌环网络 | FDDI |
| --- | --- | --- |
| 一次拿到令牌能发多少 | 只能发送一帧 | 访问由时间限定，在分配的访问时间内可以发送任意多帧 |
| 是否区分帧类型 | 不区分 | 区分同步帧和异步帧 |

FDDI 规定时间敏感的帧必须先发送，并区分两种数据帧：

- **同步帧（S-帧）**：对时间敏感的信息帧。
- **异步帧（A-帧）**：对时间不敏感的信息帧。

**控制令牌循环的三个时间寄存器**

| 寄存器 | 含义 |
| --- | --- |
| 同步分配寄存器 SA | 允许站点发送同步数据的时间，各站点可能不同 |
| 目标令牌循环时间寄存器 TTRT | 令牌绕环一周的平均时间，对所有站点相同 |
| 绝对最大时间寄存器 AMT | 保留了两倍于 TTRT 的一个值。令牌绕环一周不能超过这个时间，如果超过，则认为一些站点独占网络，环将被重新初始化 |

**控制数据帧发送的两个计时器**

| 计时器 | 行为 |
| --- | --- |
| 令牌循环计时器 TRT | 指明此次循环实际已经过去的时间和 TTRT 之间的差。一旦 TRT 被设置好，开始倒计数。当令牌返回时，站点将 TRT 中剩余的时间记录到 THT 中，然后站点基于 TTRT 值复位 TRT |
| 令牌持有计时器 THT | 一旦收到令牌，THT 开始倒计数。同步帧在收到令牌后立即发送。当同步帧发送完毕后，只要 THT 是正值，站点可以发送异步帧 |

记忆点：**TRT 管「令牌转一圈用了多久」，THT 管「我这次能占多久」**。上一圈转得快，THT 剩得多，本站就能多发异步帧；上一圈转得慢，THT 可能是负数，本站就只能发同步帧。公平性就是这么来的。

**FDDI 帧发送算法**

当一个站点 $i$ 获得令牌后，按如下算法发送帧：

1. 设置 $THT_i = TRT_i$；
2. 设置 $TRT_i = TTRT$；
3. 发送同步帧，可发送的时间为 $SA_i$；
4. 如果 $THT_i > 0$，则发送异步帧，直到 $THT_i = 0$；
5. 释放令牌。

**简单 FDDI 网络示例**

假设一个简单的 FDDI 网络，只有 A、B、C、D 四个节点（令牌按 A → B → C → D → A 的方向绕行），发送每帧所需时间为一个时间单元：

- 同步分配寄存器 SA = 5。
- 每个站点有许多异步帧需要发送。

## 7.5 异步传输模式（ATM）

【数据链路层，面向连接】

**异步传输模式（ATM）**是一种信元中继协议，由 ATM 论坛设计，并被国际电信联盟电信标准化部门（ITU-T）所接受。ATM 最初为广域网（WAN）设计，但现在也广泛用于局域网（LAN）中。

- **信元**：ATM 使用固定长度的信元（cell）作为基本的传输单元，每个信元由 **53 字节**组成，包括 **48 字节的数据负载**和 **5 字节的头部**。
- 数据速率：支持 155 Mbps 的数据速率。
- 面向连接：ATM 是一种面向连接的技术，通过虚电路实现数据传输，确保数据传输的顺序和可预测性。

固定长度是 ATM 最大的特点。长度固定，交换机就能用硬件做定时的流水线处理，不用像变长帧那样算边界，这是它当年敢喊「155 Mbps」的底气。

### 广域网协议对照

| 协议 | 类型 | 厂商 / 标准 | 速率 | 备注 |
| --- | --- | --- | --- | --- |
| HDLC（High-Level Data Link Control） | 面向比特 | ISO 标准，由思科（Cisco）广泛采用 | | 详见 `06 HDLC 协议与网桥.md` |
| PPP（Point-to-Point Protocol） | 面向字符 | 由华为（Huawei）广泛采用 | | 应用有 PPPoA（PPP over ATM）和 PPPoE（PPP over Ethernet） |
| 帧中继（Frame Relay） | | | 2 到 45 Mbps | 用于高效数据传输，适用于局域网和广域网之间的连接 |
| X.25 | | | 64 Kbps | 提供可靠的数据传输，广泛用于早期的广域网连接 |

速率一栏从 64 Kbps 到 45 Mbps 差了近千倍，这就是 X.25 被淘汰、帧中继接班的直接原因。

### 7.5.1 ATM 的设计目标

1. **提供新的适合的网络技术**：为新的高速传输介质和设备提供新的适合的网络技术。
2. **广域网连接**：在不降低现有系统效率或更换现有系统的情况下，在它们之间提供广域网连接。
3. **支持现有的电信体系**：新系统必须能够支持现有的电信体系，并和它们协同工作。
4. **面向连接**：新系统必须是面向连接的，这样才能保证顺序和可预测的传输。

### 7.5.2 ATM 应用适配层

ATM 标准定义了一系列和 OSI 模型不相类似的层，自上而下是应用适配层（AAL）、ATM 层、物理层。

**AAL 业务属性分类**

| 类 | 速率类型 | 定时要求 | 连接方式 | 示例 |
| --- | --- | --- | --- | --- |
| A 类 | 恒定比特速率 CBR | 端到端有定时要求 | 面向连接 | 实时语音和视频流（直播、交互） |
| B 类 | 可变比特速率 VBR | 端到端有定时要求 | 面向连接 | 压缩语音和视频流 |
| C 类 | 可变比特速率 VBR | 端到端无定时要求 | 面向连接 | 面向连接通信服务（虚电路） |
| D 类 | 可变比特速率 VBR | 端到端无定时要求 | 无连接 | 数据报通信服务（IP 报文） |

四类按三个二元属性排：A 是「恒定 + 有定时 + 面向连接」，B 把恒定改成可变，C 再把有定时改成无定时，D 再把面向连接改成无连接。一步换一个，顺着记不容易乱。

**AAL 的内部结构**（原文第 207 到 209 页的图，源文字没提取出来）

AAL 分四种协议：AAL1、AAL2、AAL3/4、AAL5。每种都由两个子层组成：**会聚子层（CS）**在上，**拆装子层（SAR）**在下。CS 负责把上层数据切块和加边界信息，SAR 负责补头尾、凑成 48 字节交给 ATM 层。

| 协议 | CS 的动作 | SAR 报头 | SAR 报尾 | 合计 |
| --- | --- | --- | --- | --- |
| AAL1 | 把上层数据切成 47 字节一块 | 1 字节：CSI 1 bit、SC 3 bits、CRC 3 bits、P 1 bit | 无 | 48 字节 |
| AAL2 | 切成 45 字节一块 | 1 字节：CSI 1 bit、SC 3 bits、IT 4 bits | 2 字节：LI 6 bits、CRC 10 bits | 48 字节 |
| AAL3/4 | 先加报头 T 1B、BT 1B、BA 2B 和报尾 PAD 0 到 43B、AL 1B、ET 1B、L 2B，再切成 44 字节一块 | 2 字节：ST 2 bits、CSI 1 bit、SC 3 bits、MID 10 bits | 2 字节：LI 6 bits、CRC 10 bits | 48 字节 |
| AAL5 | 加报尾 PAD 0 到 47B、UU 1B、T 1B、L 2B、CRC 4B，再切成 48 字节一块 | 无 | 无 | 48 字节 |

一条规律：净荷加上 SAR 的头尾永远凑成 48。AAL5 最省，SAR 层不加任何东西，所以它被 IP over ATM 选中，也是实际用得最多的一种。

### 7.5.3 ATM 层

ATM 层提供了路由、交通管理和复用服务。它从 AAL 层接受 48 字节的信息段，然后通过添加 5 字节的报文头将它们转换为 53 字节的信元（cell），再交给物理层。

**ATM 层信元报文头格式**

ATM 信元有两种格式：用户网络接口（UNI）和网络到网络的接口（NNI）。

| 字段 | UNI 长度 | NNI 长度 | 说明 |
| --- | --- | --- | --- |
| GFC（一般流量控制） | 4 比特 | 无 | 在 UNI 中提供了流量控制 |
| VPI（虚通路标识） | 8 位 | 12 位 | 标识虚通路 |
| VCI（虚通道标识） | 16 位 | 16 位 | 标识虚通道 |
| PT（有效数据类型） | 3 比特 | 3 比特 | 第一个比特定义了信元中有效数据是用户信息还是管理信息 |
| CLP（信元丢失优先级） | 1 比特 | 1 比特 | 实现拥塞控制。1 是高优先级 |
| HEC（报文头校验） | 8 位 | 8 位 | 采用 CRC 校验 |

两种格式都正好 40 比特等于 5 字节。NNI 去掉了 GFC，省下的 4 位并进 VPI，因为网络内部的虚通路数量比用户接口那一侧多得多，而流量控制在网络内部没必要。

**ATM 网络中的路由**

- ATM 网络中的路由是靠**交换机中的连接映向表**实现的。
- 一个连接映向表含有端口、VPI 和 VCI。

### VPI 和 VCI

- 每个信元携带的**虚通路标示符（VPI）**和**虚通道标示符（VCI）**用于识别路径。
- 在数据交换过程中，路径本身是固定的，但标识路径的 VPI 和 VCI 在不同链路上是不同的。
- VPI 和 VCI 可以由网络管理者赋予以创建**永久虚电路**，也可以在传输开始前由信令过程动态分配，称为**交换 VPI 和 VCI**。

VPI 和 VCI 是两级嵌套关系：一条传输媒体上有多个 VPI（虚通路），每个 VPI 里又有多个 VCI（虚通道）。中间的交换机只需要看 VPI 就能整批转发一束连接，不用逐条查 VCI，这样交换表能小很多。

**使用 VPI 的交换**（原文第 211 页下图）

示例：一个 VPI 为 153 的信元通过端口 1 到达交换机 1。交换机查表：

| 输入端口 | 输入 VPI | 输出端口 | 输出 VPI |
| --- | --- | --- | --- |
| 1 | 153 | 3 | 140 |

于是信元的 VPI 被改写成 140，从端口 3 发出去。

**使用 VPI 和 VCI 的交换**（原文第 212 页上图）

示例：一个 VPI = 153、VCI = 67 的信元从端口 1 进入交换机 1。

| 输入端口 | 输入 VPI | 输入 VCI | 输出端口 | 输出 VPI | 输出 VCI |
| --- | --- | --- | --- | --- | --- |
| 1 | 153 | 67 | 3 | 140 | 92 |

信元被改写成 VPI = 140、VCI = 92，从端口 3 发出。两个标识符都是**逐段链路局部有效**，这是虚电路交换和数据报转发最大的区别。

## 7.6 帧中继

【数据链路层】【虚电路】

**X.25 协议**：X.25 协议提供了广泛的差错和流量控制，这导致大量的确认和响应信息传送，占用了大量带宽。在早期传输介质容易出错的情况下，这种控制是必要的。然而，随着现代传输介质性能的提高，像 X.25 协议中那样严格的差错和流量控制措施变得不再必要。

**帧中继**：帧中继在数据链路层**不提供差错检测**，所有的差错检查留给使用帧中继服务的网络层和传输层协议进行。帧中继仅工作在物理层和数据链路层上。

### 7.6.1 帧中继的层次结构

帧中继只包含物理层和数据链路层这两个层次（原文第 212 页图）：

| 层 | 内容 |
| --- | --- |
| 数据链路层 | 传统数据链路层的简单的核心功能 |
| 物理层 | 支持可被 ANSI 识别的任何协议 |

X.25 除了这两层还有分组层（整理补充），帧中继砍到两层，这是两者层次上最直观的差别。

### 7.6.2 帧中继的操作

**永久虚电路（PVC）**

- 帧中继的传输基于永久虚电路（PVC）连接。
- 帧中继的虚电路使用**数据链路连接标识符（DLCI）**来标示。
- 在两个指定站点之间的所有通信都沿着同样的路径进行。

原文第 213 页上图画的是一片帧中继云，外面接了 A 到 J 十台主机，云里有六台帧中继交换机。同一条线路上标的 DLCI 在不同段是不同的值：比如 A 出去时是 `DLCI=1`，经过几跳以后到达 G 那一侧变成了 `DLCI=1`（另一段链路上的 1），而另一条从 A 出发标 `DLCI=2` 的虚电路到 B 那边变成 `DLCI=3`。这张图想说的就是**DLCI 只在一段链路上有意义，逐跳重新映射**。

**帧中继交换机的交换表**（原文第 213 页下图）

一台交换机有 4 个端口（上 2、左 1、右 3、下 4），交换表长这样：

| DLCI | 端口 |
| --- | --- |
| 341 | 1 |
| 367 | 2 |
| 258 | 3 |
| 149 | 4 |

交换机拿到一个帧，读出它的 DLCI，查表找到对应端口，直接转发过去。不校验、不确认、不重传，出错了由上层去管，所以它比 X.25 快得多。

## 典型题

### 例 1：FDDI 计时器推演（`14 计算题精练.md` 题 23）

条件：A、B、C、D 四站，TTRT = 30，SA = 5，每帧一个时间单元，每站都有大量异步帧。问 C 拿到令牌时的 TRT 和发完同步帧后的 THT。

思路：按帧发送算法五步走，重点是第 1 步「THT 拿的是当前 TRT 的值」和第 2 步「TRT 立刻重装成 TTRT」。A 占 30 个单元，B 的 TRT 从 30 减到 0；B 又占 5 个，C 的 TRT 就是 $-5$；发完 5 个 S-帧后 THT = $-10$，不能发异步帧。

完整四圈的表格在本文 7.4.3 节，逐步推导在 `14 计算题精练.md` 题 23。

### 例 2：判断隐藏终端还是暴露终端

给出四个站点 A、B、C、D 和它们的作用范围，问谁是谁的隐藏站点或暴露站点。

判断口径：

- 先确定谁在发、谁在收。
- 看第三个站点**听不听得见发送端**。听不见，往隐藏终端上靠；听得见，往暴露终端上靠。
- 再看第三个站点**会不会干扰接收端**。会干扰是隐藏终端，不会干扰是暴露终端。

原文的两个例子：A 向 B 发时 C 也向 B 发，C 是隐藏终端；B 向 A 发时 C 要向 D 发，C 是暴露终端。注意两个例子里 C 的位置没变，变的是谁在收。
