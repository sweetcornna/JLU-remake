# 03 数据交换与差错检测

整理自 `笔记/计算机网络.pdf` 第 54 至 65 页，对应原笔记的 2.5 数据交换技术和 2.6 错误检测和控制。CRC 的完整竖式演算放在 `14 计算题精练.md`，这里只给步骤和答案。

## 本章要点

- 三种交换技术按"占用方式"分：电路交换独占链路，报文交换和分组交换共享链路靠存储转发。
- 报文交换和分组交换的差别只在传输单位大小，但这个差别决定了节点时延和重传代价。
- 分组交换内部再分两种：数据报各走各的路，虚电路先定路径再传。虚电路不等于电路交换。
- 检错码只报警，纠错码能修。能修多少由**码距**决定：$d \ge e+1$ 能检 $e$ 位错，$d \ge 2C+1$ 能纠 $C$ 位错。
- 奇偶校验看方向：垂直（纵向）对付随机错误，水平（横向）对付突发错误。
- CRC 的全部操作就是"补 $r$ 个 0，模 2 除法，余数接回原数据后面"。模 2 除法没有借位。

## 2.5 数据交换技术

设备多了以后，不可能两两拉一条物理线。交换要解决的就是让没有物理链路直连的两个设备也能通信。

传统交换方式有三种：电路交换（Circuit Switch）、报文交换（Message Switch）、分组交换（Packet Switch）。后来又出现了 ATM 交换（也叫信元交换）和帧中继。

### 2.5.1 电路交换

电路交换在两个设备之间建一条临时的物理连接。可以把电路交换机想成一个多路开关。

通信开始前必须先建好一条被通信双方完全占用的物理通路，整个过程分三步。

1. **电路建立**（Call Setup）。在呼叫方和被呼叫方之间建连接，交换机和网络设备为双方分配带宽、信号通道这些资源。打电话时听到的拨号音、忙音、回铃音就发生在这一步，直到连接建好。
2. **数据传输**（Data Transfer）。电路建好后数据就在这条电路上传。通信期间双方独占这条电路，带宽不被别的通信共享。传的内容可以是实时的（语音通话），也可以是非实时的（文件传输）。
3. **电路拆除**（Call Tear-down）。数据传完把电路拆掉，释放资源给别的通信用。对应挂断电话、结束会话、关闭连接。

电路交换的特点：

1. 专用通道。给双方提供一条专用物理通道，通信稳定。
2. 资源预留。通信过程中预留够带宽和资源，通信量不大时这些资源也不给别人用。
3. 建立和拆除延迟。通信前要建、通信后要拆，频繁传小数据时这段开销很明显。
4. 适合实时通信。语音通话、视频会议这类要求连续性和实时性的场景靠它。
5. 效率问题。传输量不大时资源占着不用，不划算。

### 2.5.2 报文交换【网络层】

报文交换又叫**存储转发**。中间节点先把整个报文存下来，检查正确性和完整性，再往下一个节点发。

工作原理：

1. 报文创建。发送方把数据组织成报文，报文里有控制信息（目的地址、源地址等）和实际数据负载。
2. 存储和转发。报文到中间节点（交换节点或路由器）后，节点先把整个报文暂存，检查报文完整性和正确性，比如查报文头部的地址信息和可能的错误。
3. 路由选择。节点按路由算法和当前网络状况决定下一跳地址。
4. 报文传输。报文从当前节点转发到下一节点，直到到达目的地。

特点：

1. 独立性。每个报文独立传输，收发双方之间不需要建专用通路。
2. 存储和转发。每个中间节点都要存储和处理，这让报文交换网络能适应拥塞和动态路由变化。
3. 延迟。每个节点都要存储和处理，传输延迟较大。报文越长、节点处理越慢，延迟越明显。
4. 可靠性。每个节点都能查报文的错误，必要时重传，所以可靠性较高。
5. 灵活性。可以动态调整路由，应对故障或拥塞。

缺点：

1. 延迟问题。延迟主要来自每个节点的存储转发过程。报文很长或者节点处理速度有限时，延迟会很显著。
2. 资源利用率。每个节点都要存完整报文，有时候会造成资源低效利用。
3. 不适合实时通信。延迟太大，语音通话、视频会议这类用不了。
4. 出错全都得重传。整个报文是一个单位，错一个比特整份重来。

### 2.5.3 分组交换【网络层】

把较长的报文切成较短的数据单元，每个数据单元加上通信控制信息，就形成一个**分组**（packet）。

分组交换的特点：

1. 分组结构。长报文被分割成较短的分组，每个分组含数据和控制信息。
2. 存储和转发。网络中每个节点（路由器或交换机）存下到达的分组，按控制信息转发到下一节点。
3. 减少延迟。分组较短，可以在中间站点的内存里快速存储和转发，传输过程中的延迟比报文交换小。

分组交换与电路交换的比较：

1. 共享传输链路。多个通信会话可以共享同一条传输链路，链路使用效率高。
2. 流量和拥塞控制。可以根据网络状况动态调整分组的路由，处理流量和拥塞更灵活。
3. 广播和多播。支持一个分组同时发往多个目的地。
4. 多种通信设备互连。有利于不同类型、不同速度的通信设备互连。
5. 传输链路的使用效率较高。

【不再独占；依赖于存储转发技术；如果出错需要重传】

### 分组交换的两种类型

**数据报**（Datagram）。每个包独立于其他包被处理，任何一条链路可以同时为多对设备的通信服务。一次传输的数据报到达目的地时可能不按次序，重新排序的任务交给传输层完成。

**虚电路**（Virtual Circuit）。同一次通信的所有包之间的关系被维持住，路径在数据传输开始之前就选定了。所有属于同一次通信的分组沿相同路径传输，顺序有保证。

虚电路和电路交换的区别：虚电路可以同时为多个设备提供通信服务，电路交换是独占的。虚电路给一次通信会话提供的是一条临时或永久的**逻辑路径**，不是独占的物理通路。

### 虚电路的两种形式

**交换虚电路**（SVC，Switched Virtual Circuit）。通信开始前建立，通信结束后拆除，类似临时电话连接。每条虚电路在需要的时候被创建，而且仅仅在这次通信交换的过程中存在。

**永久虚电路**（PVC，Permanent Virtual Circuit）。预先建立、长期存在，类似租用线路。两个用户之间存在一条固定的虚电路，专门提供给这对用户，这条虚电路总是建立好的。

### 虚电路的优势

在虚电路中，只需在建立时指定目的地址，后续分组传输时只带**虚电路号码**就行。数据传送阶段每个包不需要携带完整的目的地址，仅需要一个虚电路号码标志，包的控制信息少了，额外开销也就少了。

（虚电路示意图见原文第 59 页，图中 $H_1$ 经 $VC_1$ 和 $VC_2$ 两条虚电路分别通到 $H_4$ 和 $H_5$，同一朵云里的交换节点被两条虚电路共用。）

### 三种交换技术对比

示意图见原文第 60 页。图上三列分别画出电路交换（连接建立、数据传送、连接释放三段，比特流直达终点）、报文交换（整份报文在每个节点存储转发）、分组交换（$P_1$ 到 $P_4$ 流水式地在节点间存储转发）。

| 对比项 | 电路交换 | 报文交换 | 分组交换 |
| --- | --- | --- | --- |
| 传输单位 | 比特流，不分割 | 整个报文 | 分组（切短的报文段） |
| 传输前是否建连接 | 必须建，分三阶段 | 不建 | 数据报不建，虚电路要建 |
| 链路占用方式 | 双方独占 | 多会话共享 | 多会话共享 |
| 中间节点行为 | 直通，不存储 | 存整个报文再转发 | 存一个分组就转发 |
| 主要延迟来源 | 电路建立和拆除 | 每个节点存整份报文 | 每个节点存一个分组，比报文交换小 |
| 出错重传代价 | 原文未展开 | 整个报文重传 | 重传出错的分组 |
| 链路使用效率 | 低，资源预留后闲着也不释放 | 较高 | 高 |
| 适用场景 | 实时通信，语音和视频会议 | 非实时数据传输 | 一般数据通信，支持广播和多播 |

数据报和虚电路都属于分组交换，别混：

| 对比项 | 数据报 | 虚电路 |
| --- | --- | --- |
| 传输前选路 | 不选，每个分组到节点才决定下一跳 | 传输开始前就把路径定下来 |
| 分组走的路径 | 可能各不相同 | 同一次通信全走同一条 |
| 到达顺序 | 可能乱序 | 保证顺序 |
| 乱序谁来管 | 传输层重新排序 | 不需要 |
| 地址开销 | 每个分组都带完整目的地址 | 只在建立时给目的地址，之后带虚电路号 |
| 形式 | 只有一种 | 分 SVC 和 PVC |

## 2.6 错误检测和控制

### 基本概念

**检错码**（Error Detection Code）：往数据里加特定的冗余位，接收方靠这些冗余位判断数据在传输中有没有出错。只报警，不修。

**纠错码**（Error Correction Code，ECC）：不光能检测，还能纠正一定数量的错误。代价是加更多冗余位，检测到错误时靠这些冗余信息推断并修复原始数据。

**编码效率**（Coding Efficiency）：数据信息在整个发送信息里的比重。冗余位加得越多，检错纠错能力越强，编码效率越低。按定义写成公式就是

$$\eta = \frac{\text{数据位数}}{\text{数据位数} + \text{冗余位数}}$$

（这个公式是按原文的定义写出来的，原文只给了文字描述。）

错误类型分两种：

- **随机错误**：随机噪声引起，往往是孤立的，影响的数据位较少。
- **突发性错误**：环境因素或其他突发性事件引起，可能导致连续多位出错。

### 码距与检错纠错能力

**码距**（Hamming Distance，$d$）是两个相邻有效编码之间对应位不同的位数。

- 检错能力：$d \ge e+1$ 时，可以检测出最多 $e$ 位的错误。
- 纠错能力：$d \ge 2C+1$ 时，可以纠正最多 $C$ 位的错误。

【注意这里的检错和纠错能力并非 100%，都只是大概率】

【必须得判断出错误的码离哪一个正确的码更近】这句是纠错公式的直观解释：出错的码落在某个合法码的"势力范围"里，才能判定它原来是谁。要让 $C$ 位以内的错误不产生歧义，两个合法码之间至少得隔 $2C+1$。

（更正：原文作"对应位不同的**最大**位数"。按上面两个公式的用法，这里的 $d$ 取的是任意两个合法编码之间不同位数的最小值，也就是最小码距，不然公式不成立。）

两个典型应用：奇偶校验码是最简单的检错码，加一个校验位让数据中 1 的总数为奇数或偶数；海明码是能检测并纠正单个位错误的纠错码。

### 2.6.1 奇偶校验码

设 $m$ 位数据单元为 $b_1b_2b_3\cdots b_m$：

- 偶校验：$r = b_1 + b_2 + b_3 + \cdots + b_m$
- 奇校验：$r = b_1 + b_2 + b_3 + \cdots + b_m + 1$

这里的加号是模 2 加（异或）。发送数据时把校验位 $r$ 连同数据一起发，接收方重算一遍看结果，判断有没有出错。

奇偶校验有三种组织方式，考点在于各自对付什么错误。

**垂直（纵向）奇偶校验**，适用于随机错误。每个数据块自己带一个校验位。原文第 61 页的例子（偶校验）：

| 数据块 | 块内 1 的个数 | 校验位 |
| --- | --- | --- |
| `0101001` | 3，奇数 | `1` |
| `0111001` | 4，偶数 | `0` |
| `1011101` | 5，奇数 | `1` |
| `1100111` | 5，奇数 | `1` |

原文在图上手写的批注是【奇数个 1 就补一个 1】，说的就是这个规则。

**水平（横向）奇偶校验**，适用于突发性错误。不给每个块单独加位，而是把若干个数据块按列做模 2 加，算出一个**校验字符**跟着一起发。还是上面那四个块：

```
0101001
0111001
1011101
1100111
-------- 按列模 2 加
0101010   ← 校验字符
```

原文在图上手写【这一位偶数个 1，填 0 即可】，指的就是逐列数 1 的个数。突发错误连着打坏一个块里的好几位，垂直校验可能因为错位数是偶数而漏掉，但这些坏位分散在校验字符的不同列上，横向就能兜住。

**水平垂直（纵横）奇偶校验**。两种一起用：每个数据块带自己的垂直校验位，整组再算一个横向校验字符，而且这个校验字符本身也要带一个垂直校验位。原文第 62 页图上发出去的是

```
10101010 | 1 0101001 | 0 0111001 | 1 1011101 | 1 1100111
 校验字符   ↑ 各块的垂直校验位
```

校验字符 `0101010` 里有 3 个 1，所以它自己的校验位是 `1`，拼起来是 `10101010`。

### 2.6.2 循环校验码 CRC

四个角色先分清楚：

- **生成多项式 $G(x)$**：一个二进制多项式，定义了 CRC 校验的位数和特性。写成二进制时，$x^k$ 项对应二进制的第 $k+1$ 位。【$x^4$ 意味着 $2^4$，也就是二进制第 5 位为 1】
- **待发送的信息 $U(x)$**：要校验的二进制序列。
- **余数 $R(x)$**：校验码本身。
- $r$：$G(x)$ 的最高阶次，也就是要补的 0 的个数、余数的位数。（原文这里用的字母是 $m$，和前面奇偶校验的数据位数 $m$ 撞了，看题时注意区分。）

发送方三步：

1. 在 $U(x)$ 后面补 $r$ 个 0。
2. 用补零后的串去除 $G(x)$，做**模 2 除法**，取余数 $R(x)$。
3. 把 $R(x)$ 拼接到原始信息 $U(x)$ 后面，得到要发送的循环校验码。这一步是字符串拼接，别当成加法去算。

模 2 除法的关键是不借位，减法规则是：

```
1-1=0    1-0=1    0-0=0    0-1=1
```

也就是逐位异或。什么时候上商 1、什么时候上商 0，看当前被除位段的最高位是不是 1，是就上 1 并异或 $G(x)$，不是就上 0 并异或全 0。

接收方：用同一个 $G(x)$ 去除收到的整串数据。余数为 0 说明传输没出错，余数非 0 说明出错了。

注意：

- CRC 不保证 100% 的错误检测率，但能检出大多数常见的错误类型。
- 生成多项式选得好不好，直接影响 CRC 的检错能力。
- CRC 是单向错误检测方法，用来检测数据完整性，不用来纠错。

### 2.6.3 校验和

发送方：

1. **数据分段**。把要发送的数据单元分成多个大小为 $n$ 比特的段。比如 $n=16$，每段就是 16 个比特。
2. **计算校验和**。用反码加法把这些数据段加起来，得到的 $n$ 比特结果取反，就是校验和。
3. **添加冗余位**。把校验和作为冗余位加到原始数据单元的末尾。
4. **发送数据**。把扩展后的数据单元发出去。

接收方：

1. **数据分段**。同样分成大小为 $n$ 的若干段，其中最后一段是校验和。
2. **验证数据**。用相同的反码加法把所有段（包括校验和）加起来。结果是 $n$ 个 1 就说明没出错，不是 $n$ 个 1 就说明出错了。

注意事项：

- 这种方法假设错误是随机的，而且不太可能同时影响多个比特。
- 检测突发错误（多位连续错误）时，校验和不够用，得上 CRC 这类更复杂的方法。

（更正：原文作"反码加法算法不使用进位""1 + 1 在反码加法中可能等于 0，因为没有进位"。标准的反码加法做的是正常二进制加法，只是把溢出到第 $n+1$ 位的进位回卷加到最低位，叫 end-around carry，进位并没有被丢掉。做题时按回卷算，接收方相加才会得到 $n$ 个 1。）

## 易混对比

| 容易混的 | 怎么分 |
| --- | --- |
| 虚电路 与 电路交换 | 虚电路是逻辑路径，同一条物理链路可以同时跑多条虚电路；电路交换是物理通路，通信期间被双方独占 |
| 虚电路 与 数据报 | 虚电路先定路径、保顺序、带虚电路号；数据报各自选路、不保顺序、带完整目的地址 |
| SVC 与 PVC | SVC 用时建、用完拆，像打电话；PVC 一直在，像租专线 |
| 检错码 与 纠错码 | 检错码只能发现错误，纠错码靠更多冗余位还能定位并修复 |
| 垂直 与 水平奇偶校验 | 垂直对随机错误，按块加校验位；水平对突发错误，按列算校验字符 |
| 模 2 除法 与 普通二进制除法 | 模 2 除法逐位异或，不借位；商只看最高位是不是 1 |
| CRC 的"拼接" 与 "相加" | 余数 $R(x)$ 是接在 $U(x)$ 后面的，不是和 $U(x)$ 做加法 |
| 检错能力公式 与 纠错能力公式 | 检错 $d \ge e+1$，纠错 $d \ge 2C+1$。纠错要求高一倍多，因为要判断离哪个合法码更近 |

## 典型题

原笔记给了两道 CRC 计算题。答案和竖式已经复核过，完整分步演算见 `14 计算题精练.md`。

**例 1**。$G(x)=x^4+x^3+1$，二进制 `11001`，最高阶 $r=4$；$U(x)=$ `1101011`。

补 4 个 0 得 `11010110000`，模 2 除以 `11001`，商是 `1001010`，余数 $R(x)=$ `1010`。

最后发送的数据是 `11010111010`。

**例 2**。$G(x)=x^5+x^2+x$，二进制 `100110`，最高阶 $r=5$；$U(x)=$ `10010110`。

补 5 个 0 得 `1001011000000`，模 2 除以 `100110`，余数 $R(x)=$ `00010`。余数不足 5 位要补前导 0，这一步最容易漏。

最后发送的数据是 `1001011000010`。
