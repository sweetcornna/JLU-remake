# 介质访问控制与以太网

整理自 `笔记/计算机网络.pdf` 第 171 页到第 188 页，对应原文第七章「局域网与广域网技术」的 7.1 IEEE 局域网通信协议和 7.2 以太网。同一章后半部分（无线局域网、令牌环、令牌总线、FDDI、ATM、帧中继）在 `08 无线局域网与其他局域网广域网技术.md`。

## 本章要点

- IEEE 802 把 OSI 的数据链路层劈成两半：上半是 **LLC**，对所有局域网都一样；下半是 **MAC**，每种局域网各有一套。局域网对 LLC 是透明的，只有 MAC 子层知道底下连的是什么网。
- 802.3 以太网、802.4 令牌总线、802.5 令牌环并列在 MAC 和物理层，上面共用 802.2 LLC。802 号段和名字要能互相背出来。
- 广播信道的核心矛盾是多个站点抢一条线。解决思路分静态分配和动态分配，动态分配又分随机访问、受控访问、有限竞争三大类。
- 演进路线 **MA → CSMA → CSMA/CD**，口诀是「不听就说」「先听后发」「边听边说」。
- 纯 ALOHA 的冲突危险期是 $2D$，分隙 ALOHA 降到 $D$，这是分隙 ALOHA 吞吐量翻倍的原因。
- CSMA/CD 的两个必考公式：最短帧长 $L_{min} = \dfrac{2R \times S}{V}$，退避时间 $t = r \times 2\tau$。以太网的 $2\tau$ 就是 51.2 µs。
- 以太网 MAC 帧七个字段的字节数要背死：7 / 1 / 6 / 6 / 2 / 46 到 1500 / 4。
- 判断 Ethernet V2 还是 IEEE 802.3，看第 13、14 字节这两个字节的值：大于 1500（`0x05DC`）是类型，小于 1500 是长度。
- 543 规则和 5-4-3-2-1 原则说的是同一件事的不同详略版本，考试两种问法都出现过。

## 7.1 IEEE 局域网通信协议

### 局域网与标准化需求

**局域网（LAN）**：在有限的地理范围内连接许多独立设备，使它们相互之间直接进行通信的系统。

标准化需求的来由很朴素：局域网产品的数量和品种迅速增加，各家做各家的，用户设备和局域网之间互连不上，所以迫切需要标准。

### 7.1.1 IEEE 802 标准家族

1980 年 2 月，IEEE（Institute of Electrical and Electronics Engineers，电子电气工程师协会）成立了 802 局域网标准委员会，制定了 IEEE 802 标准。【有关局域网的标准】

| 标准号 | 内容 |
| --- | --- |
| 802.1 | 一组协议的集合（写作 1x）：a 体系结构、b 网际互连、d STP（生成树）、x VLAN |
| 802.2 | LLC（逻辑链路控制）协议标准 |
| 802.3 | 以太网 CSMA/CD 媒体访问方法 |
| 802.4 | 令牌总线访问方法 |
| 802.5 | 令牌环访问方法 |
| 802.6 | DQDB-MAN（城域网） |
| 802.11 | 无线局域网协议 |

记忆上抓住 3、4、5 三个连号：**3 是以太网，4 是令牌总线，5 是令牌环**。

### 7.1.2 IEEE 局域网参考模型

**1. IEEE 802 与 OSI 的关系**

IEEE 标准把 OSI 下面两层拆得更细（原文第 172 页上图）：

| IEEE 标准 | 对应的 OSI 层 |
| --- | --- |
| 其它上层 | 其它上层 |
| 网络层 | 网络层 |
| 逻辑链路控制 LLC | 数据链路层 |
| 媒体访问控制 MAC | 数据链路层 |
| 介质访问单元 | 物理层 |
| 介质说明 | 物理层 |

- **逻辑链路控制（LLC）子层**是 IEEE 802 数据链路层的上子层，对于所有的 LAN 协议来说都是相同的。
- **媒体访问控制（MAC）子层**解决共享介质的竞争使用问题。它包含了将数据从一个地方传送到另一个地方所必需的同步、标记、流量和差错控制的规范，同时也包括下一个站点的物理地址。

**2. 802 与 OSI 的层次对应关系**

原文第 172 页下图画的是另一张对照表：802.1 网络互连对着 OSI 网络层，802.2 LLC 对着数据链路层上半，802.3 以太网 / 802.4 令牌总线 / 802.5 令牌环三个并排的盒子横跨 MAC 子层和物理层。

【局域网对 LLC 是透明的，只有 MAC 子层才知道所连接的是什么样的局域网】这句是考点。换成人话：程序往 LLC 交数据的时候不用管底下是以太网还是令牌环，差别全被 MAC 子层吸收了。

### 7.1.3 逻辑链路控制 LLC

**1. LLC-PDU 的格式**

LLC-PDU 与 HDLC 类似，包含四个域：

| 域 | 作用 |
| --- | --- |
| 目的服务访问点 DSAP | 接收方的服务访问点地址 |
| 源服务访问点 SSAP | 发送方的服务访问点地址 |
| 控制域 | 帧类型、序号、P/F 位等 |
| 信息域 | 上层交下来的数据 |

DSAP 和 SSAP 是 LLC 所使用的地址，SAP 叫**服务访问点**，用来标明接收和发送数据的计算机上的协议栈。

LLC 帧的类型分为三种：**信息帧、监控帧和无编号帧**（和 HDLC 的 I 帧、S 帧、U 帧一一对应，见 `06 HDLC 协议与网桥.md`）。

监控帧用于应答和流量控制，共有三种形式：

- 接收就绪帧（RR）
- 拒绝帧（REJ）
- 接收未就绪帧（RNR）

注意这里只有三种，比 HDLC 的 S 帧少了 SREJ。

**2. LLC 地址与 MAC 地址**

| | LLC 地址 | MAC 地址 |
| --- | --- | --- |
| 在哪 | LLC 帧的帧首，DSAP 和 SSAP | MAC 帧的帧首，目的站地址和源站地址 |
| 长度 | 由 LLC 定义 | 6 字节 |
| 性质 | 逻辑地址，标识数据链路层的不同服务访问点 | 站点的物理地址 |
| 回答的问题 | 数据交给本机哪个协议栈 | 数据送到哪台机器 |

## 7.2 以太网

【主要是数据链路层，部分是物理层】

以太网是由 Digital 公司、Intel 公司和 Xerox 公司联合开发的，三家的首字母凑出了后来的 DIX 标准名。

### 7.2.1 以太网访问模式

**广播信道面临的问题**

问题：可能有两个或更多站点同时请求占用信道。

解决办法：介质的多路访问控制（MA）。

方法：在多路访问信道上确定下一个使用者，也就是**信道分配**。分配方式分两种，静态分配和动态分配。

**静态分配与动态分配**

静态分配的问题：

- 资源分配不合理，不满足用户对资源占用的不同需求。
- 有资源浪费，效率低。
- 延迟时间增大 N 倍（N 是划分的份数）。

静态分配的适用情况：

- 适于用户数量少且用户数目固定的情况。
- 适于通信量大且流量稳定的情况。
- 不适用于突发性业务的情况。

动态分配的目的：更好地满足需求，提高信道利用率。

局域网上的流量天生是突发的，一台机器几秒钟不说话，一说话就是一大串，所以局域网走的都是动态分配。

**三大类多路访问协议**

| 类别 | 特点 | 代表 |
| --- | --- | --- |
| 随机访问协议 | 冲突不可避免 | ALOHA、CSMA、CSMA/CD |
| 受控访问协议 | 克服了冲突 | 令牌环、令牌总线 |
| 有限竞争协议 | 利用上述二者的优势 | 自适应树搜索一类 |

**冲突**

在 LAN 中，多个用户在没有任何控制的情况下同时访问一条线路时，会存在由于不同信号叠加而相互破坏的情况，这就是冲突。为了使冲突发生的可能性最小，需要有一种机制来协调通信。

以太网的媒体访问控制机制称为带有冲突检测的载波侦听多路访问（CSMA/CD）。它的发展路线是 MA → CSMA → CSMA/CD。

#### 1. 多路访问 MA

不提供通信管制，「不听就说」。

夏威夷大学的 Norman Abramson 及他的同事设计了 ALOHANet，用来连接檀香山和其它岛屿。协议有两个版本。

**纯 ALOHA 协议**

原理：任意时间发帧，冲突后重传。

特点：

- 冲突指两个以上的帧撞在一起。
- 随时可能冲突。
- 冲突的帧完全破坏。
- 破坏了的帧要重传。
- **冲突危险期： $2D$**。其中 $D$ 为发送一个标准长的帧所需的时间。

危险期为什么是 $2D$：站 A 在 $t_0$ 时刻开始发一帧，发到 $t_0+D$ 结束。任何在 $(t_0-D,\ t_0+D)$ 这段区间里开始发送的帧都会和它重叠，区间长度正好 $2D$。原文第 177 页上图画的就是这个，横轴上标出了 $t_0-D$、 $t_0$、 $t_0+D$ 三条虚线，中间那帧的头和尾分别和左右两帧撞上。

**分隙 ALOHA 协议**

工作原理：

- 分隙 ALOHA 是把时间分成时隙（时槽）。
- 时隙的长度对应一帧的传输时间。
- 帧的发送必须在时隙的起点。
- 冲突只发生在时隙的起点。
- **冲突危险期： $D$**。

只要不在同一个时隙起点开口，就不会撞上，危险期砍掉一半。代价是所有站点必须有统一的时钟。

#### 2. 载波侦听多路访问 CSMA

（更正：原文写作「载波帧听多路访问」，应为**载波侦听**多路访问，Carrier Sense Multiple Access。）

首先监听链路上是否已经存在通信，「先听后发」。由于存在传输延迟，还是会出现冲突：A 刚开始发，信号还没传到 B，B 一听信道是空的，也开始发。

「坚持」是指在发送数据之前持续监听信道状态的行为。按坚持策略分三种：

| 类型 | 信道空闲时 | 信道忙时 | 特点 |
| --- | --- | --- | --- |
| 非坚持 CSMA | 立即发送 | 等待一段随机时间后重新尝试 | 减少了冲突，但可能会有较大的传输延迟 |
| 1-坚持 CSMA | 立即发送 | 持续监听，直到信道变为空闲，并立即发送；发生冲突则等待随机时间后重传 | 增加了信道利用率，但可能会增加冲突的概率 |
| P-坚持 CSMA | 以概率 $P$ 发送，以 $1-P$ 的概率延迟一个时间单位 | 持续监听，直到信道变为空闲；没有发送成功就等一个时间单位后再以概率 $P$ 发送 | 在减少冲突和提高信道利用率之间做了折中 |

CSMA/CD 用的是 **1-坚持** 策略。非坚持的毛病在于信道明明空了它还在等；1-坚持的毛病在于几个站同时等到信道空闲会一起冲上去。

#### 3. 带有冲突检测的载波侦听多路访问 CSMA/CD

在传输的时候继续监听链路是否发生冲突，「边听边说」【半双工】。边发边收，发的和收的应该是一致的，对不上就说明撞了。

算法描述：

1. 如果链路是空闲的，则可以发送并同时检测冲突。
2. 如果链路是忙的，则继续侦听，直到检测到链路空闲。
3. 如果在发送过程中检测到冲突，则停止当前帧的发送，发**阻塞信号**（让其他站点也知道冲突），等待一段选定的时间。

原文第 180 页上方画了 A、B 两站的冲突时序，四个时刻依次是：

| 时刻 | 发生的事 |
| --- | --- |
| $t_0$ | A 开始发送帧 |
| $t_0+a^-$ | A 的帧头刚到 B，B 也开始发送帧 |
| $t_0+a$ | B 检测到冲突，停止帧的发送，开始发阻塞信号 |
| $t_0+2a$ | B 的被破坏帧到达 A，A 检测到冲突 |

从这张图能直接读出「最坏情况下要 $2a$ 才知道撞了」，也就是最短帧长的来历。

**退避算法**

为了解决冲突后重传的问题，CSMA/CD 采用退避算法：

1. 当第一次发生冲突时，设置参数 $L=2$。
2. 退避间隔取 1 到 $L$ 个时间片中的一个随机数。一个时间片等于链路上最大传输延迟的 2 倍。【注意是传输时间】
3. 如果再次发生冲突，将参数 $L$ 加倍，最大值为 1024。当 $L$ 增加到 1024 时，不再增加。
4. 帧的最大重传次数为 16，超过此次数则该帧不再重传并报告错误。

等待时间公式：

$$t = r \times 2\tau$$

其中：

- $r$ 从离散的整数集合 $\{0,\ 1,\ \dots,\ 2^{\min(k,10)}-1\}$ 中随机取一个数。
- $k$ 是重传（冲突）次数，最大为 16。
- 基本退避时间（基数）一般定为 $2\tau$，也就是一个**争用期**时间，对于以太网就是 **51.2 µs**。

这里的 $\tau$ 是链路单程最大传播时延， $2\tau$ 是一个往返，也就是第 2 条里说的「最大传输延迟的 2 倍」。

原文给的退避表：

| 重传次数 | $k$ | 离散的整数集合 $\{0,1,\dots,2^k-1\}$ | 可能的退避时间 |
| --- | --- | --- | --- |
| 1 | 1 | $\{0,\ 1\}$ | $0 \times 2\tau$， $1 \times 2\tau$ |
| 2 | 2 | $\{0,\ 1,\ 2,\ 3\}$ | $0 \times 2\tau$， $1 \times 2\tau$， $2 \times 2\tau$， $3 \times 2\tau$ |
| 12 | 10 | $\{0,\ 1,\ 2,\ 3,\ 4,\ 5,\ \dots,\ 1023\}$ | $0 \times 2\tau$， $1 \times 2\tau$， $2 \times 2\tau$， $\dots$， $1023 \times 2\tau$ |

第三行的 $k$ 取 10 不取 12，因为 $k = \min(\text{重传次数},\ 10)$，集合大小封顶在 1024。

原文用红字标出的两条结论：

- 如果连续多次发生碰撞，就表明可能有较多的站点参与竞争信道。但使用上述退避算法可使重传需要推迟的平均时间随重传次数而增大（即**动态退避**），因而减小产生碰撞的概率。
- 当重传达 **16 次**仍不能成功时，就表明同时打算发送帧的站点太多，以至于连续产生碰撞，此时应**放弃重传并向高层报告**。

**最短帧长的计算**

检测到冲突是需要时间的，如果帧太短了就检测不到冲突，所以存在最短帧长的限制。【发送帧的时间 $\ge$ 2 × 最大传播延迟】用于检测冲突的时间等于任意两个站点之间最大的传播延迟的两倍。

$$L_{min} = \frac{2R \times S}{V}$$

| 符号 | 含义 | 单位 |
| --- | --- | --- |
| $L_{min}$ | 最短数据帧长 | bit |
| $S$ | 任意两站点间的最大距离 | m |
| $R$ | 数据传输速率 | Mbps |
| $V$ | 电子传播速度，取 200 | m/µs |

**系统跨距**就是两个站点的最大距离，把上式反过来解出 $S$ 就是。以太网规定的最短帧长为 64 字节，由此可以算出它的最大系统跨距。算例见本文末尾的典型题。

冲突是半双工通信的副产品。半双工意味着一台设备传输数据时，其它设备只能处于接收状态。全双工以太网出现以后 CSMA/CD 就不需要了，最短帧长的限制也就失去了原来的意义。

**各种 CSMA 的性能比较**

CSMA/CD（1-坚持 CSMA）：

- 以太网采用了 CSMA/CD。
- 吞吐量比 ALOHA 高，比 P-坚持式 CSMA 低。
- 冲突比 ALOHA 少，比 P-坚持式高。
- P-坚持式 CSMA 付出了高延迟的代价。

原文第 181 页顶部的曲线图横轴是 $G$（每帧时间内的尝试次数），纵轴是 $S$（每帧时间的吞吐量），从上到下的峰值大致是：0.01-坚持 CSMA 接近 1.0，非坚持 CSMA 约 0.9，0.1-坚持 CSMA 约 0.8，0.5-坚持 CSMA 约 0.7，1-坚持 CSMA 约 0.53，分隙 ALOHA 约 0.37，纯 ALOHA 约 0.18。CSMA/CD 被圈在图的右下方。**P 越小吞吐量越高，但延迟越大**，这就是上面那句「付出了高延迟的代价」。

信道效率：

$$\text{信道效率} = \frac{1}{1 + 2BLe/(cF)}$$

其中 $F$ 为帧长， $B$ 为带宽， $L$ 为电缆长度， $c$ 为信号传播速度，假设每帧 $e$ 个竞争时间槽。

结论：在给定帧长的情况下，增加带宽或距离都会降低网络效率。分母里的 $B$ 和 $L$ 都在分子上， $F$ 在分母上，一眼能看出来。这也解释了为什么以太网提速的时候要么缩短最大电缆长度，要么加大最小帧长。

**543 规则**

- **5**：网络中最多有 5 个网段。
- **4**：全信道上最多可连 4 个中继器。
- **3**：3 个网段可连接终端，剩下两个网段只能起延长作用。

### 7.2.2 以太网 MAC 帧格式

七个字段，字节数如下（原文第 181 页图）：

| 字段 | 长度 | 作用 |
| --- | --- | --- |
| 前导码 Preamble | 7 字节 | 1 和 0 交替出现。警告系统接收即将到来的数据帧，并使系统能够调整同步输入时钟 |
| 帧起始分界符 SFD | 1 字节 | 模式为 `10101011`。标记了帧的开始，通知接收方后面所有的内容都是数据 |
| 目的地址 DA | 6 字节 | 标记数据帧下一个节点的物理地址 |
| 源地址 SA | 6 字节 | 包含最后一个转发此帧的设备的物理地址，也是上个节点的物理地址 |
| LLC-PDU 的长度/类型 | 2 字节 | 指出 LLC-PDU 域中的有效字节数；按值的不同，该字段可以表示长度或类型 |
| LLC-PDU | 46 到 1500 字节 | 以太网 MAC 帧将 802.2 的整个帧作为透明数据包含在此域中 |
| CRC | 4 字节（32 位） | 用于差错检测，确保帧在传输过程中没有出现错误 |

长度/类型字段的判断规则：

- 大于 1500（`0x05DC`）表示**类型**，例如 `0x0800` 是 IP 协议，`0x0806` 是 ARP 协议。
- 小于 1500 表示 **LLC-PDU 的长度**。
- 如果这个字段大于 1500，那么后面的 LLC-PDU 域携带的就是上层协议数据，不再是 802.2 的帧。

注意 SFD 的最后两位是 `11`，和前面连续的 `10` 交替不一样，接收方就是靠这个「连续两个 1」判断同步码结束、正文开始。

**Ethernet V2 与 IEEE 802.3 的区分**

主机运行 CSMA/CD 协议。常用的以太网 MAC 帧格式有两种标准：

- DIX Ethernet V2 标准（最常用的）
- IEEE 的 802.3 标准

思考：网卡收到帧如何判断是 Ethernet V2 帧还是 IEEE 802.3 帧？

答案就是上面那条规则。两种帧前 12 字节完全一样，差别只在第 13、14 这两个字节：Ethernet V2 里它是**类型**，802.3 里它是**长度**。因为 802.3 的数据域最大 1500 字节，长度值不可能超过 1500，而已分配的类型值都从 `0x0600`（1536）往上排（整理补充），两者不会撞车。

为了使 CSMA/CD 协议的正常操作，需要一个最小帧长度 **64 字节**。原因：检测到冲突需要时间，如果帧太短，则可能无法检测到冲突。

原文第 183 页下图还补了两点：

- 物理层实际发送时在 MAC 帧前面插入 8 字节，拆开就是 7 字节前同步码加 1 字节帧开始定界符。所以「前导码 7 字节 + SFD 1 字节」和「8 字节前导」是同一回事，看题目按哪种画法。
- MAC 地址举例：单播 `5C-26-0A-7E-4E-4C`，广播 `FF-FF-FF-FF-FF-FF`，组播 `01-00-5E-00-00-00`。

### 7.2.3 以太网种类

**IEEE 802.3 定义的类别**

- 基带类：使用数字信号传输数据，基带以太网使用曼彻斯特编码（旧标准）。
- 宽带类：使用模拟信号传输数据。

以太网发送的数据使用曼彻斯特（Manchester）编码。

**命名规则**

IEEE 将基带类划分为多个不同的标准，例如 10Base5、10Base-T、100Base-T。规则是：

- 开头数字指明数据传输速率（如 10 Mbps、100 Mbps）。
- 后面的字母或数字（5、2、T）指明最大电缆长度或电缆类别。
- Base 指明的是基带传输。

示例：

- `10Base5`：10 是 10 Mbps，Base 是基带，5 指同轴电缆（每段 500 m）。
- `100Base-T`：100 是 100 Mbps，Base 是基带，T 是双绞线。

宽带类的标准只有一个 `10Broad36`，用于小区网络连接。

**IEEE 802.3 标准的发展**

| 年份 | 标准 | 内容 |
| --- | --- | --- |
| 1982 | 802.3 | 10Base5 |
| 1985 | 802.3a | 10Base2 |
| 1990 | 802.3i | 10Base-T |
| 1993 | 802.3j | 10Base-F |
| 1995 | 802.3u | 100Base-T |
| 1997 | 802.3x | 全双工以太网 |
| 1998 | 802.3z | 1000Base-X |
| 2000 | 802.3ab | 1000Base-T |
| 2002 | 802.3ae | 10G |

**经典以太网的物理层**

- 最高速率：10 Mbps
- 编码方式：曼彻斯特编码
- 连接方式：使用同轴电缆和中继器连接

**5-4-3-2-1 原则**：任意两个收发器之间的距离不得超过 2.5 km，且经过的中继器不能超过 4 个。

| 数字 | 含义 | 说明 |
| --- | --- | --- |
| 最多 5 个网段 | 网络中最多可以包含 5 个网络段（Segment） | 这 5 个网段包括主干网段和终端网段 |
| 最多 4 个中继器 | 在这 5 个网段之间最多可以使用 4 个中继器（Repeater） | 中继器用于放大信号，但不增加带宽 |
| 最多 3 个混杂网段 | 混杂网段指可以连接多个节点并允许它们互相通信的网段 | 5 个里最多 3 个 |
| 至少 2 个链路段 | 链路段（Link Segment）通常用于连接中继器或其他网络设备 | 不直接连接终端设备 |
| 最多 1 个冲突域 | 冲突域是指网络中可能发生数据包冲突的范围 | 在经典以太网中所有节点共享同一个冲突域 |

543 规则是这条原则的简写版，「3 个网段可连接终端，剩下两个网段只能起延长作用」对应的就是「最多 3 个混杂网段，至少 2 个链路段」。

**各种以太网标准**

1. `10Base5`（粗缆以太网）：每个网段大小 500 m。原文第 185 页图上标了 RG-8 粗同轴电缆、收发器（MAU）、收发器电缆最长 50 米、电缆终接器，网络接口卡（NIC）在计算机内。
2. `10Base2`（细缆以太网）：原文第 186 页图上标了最大长度 185 米、RG-58 细同轴电缆、BNC-T 型连接器、电缆终接器。名字里的 2 来自 185 m 向上取到 200 m（整理补充）。
3. `10Base-T`（双绞线以太网）：原文第 186 页图画的是 10BASE-T Hub、RJ-45 插孔、4 对 UTP 电缆。
4. 快速以太网（`100Base-T`）：
   - 使用了与 10Base-T 相同的 MAC 协议和帧格式。
   - 与 10Base-T 的不同点是，编码系统改为 **4B/5B 编码**以适应 100 Mbps 速率。
   - MAC 帧格式仍然是 802.3 标准。
   - 保持最短帧长不变，但将最大电缆长度减小到 **100 m**。
   - 帧间时间间隔从原来的 9.6 µs 改为 **0.96 µs**。

4B/5B 编码是一种用于数据传输的编码技术，它将每 4 位二进制数据映射为 5 位二进制数据，主要应用于高速通信，如快速以太网（100Base-TX）。速率提高十倍、电缆长度缩到十分之一，正好让 $2\tau$ 不变，64 字节的最短帧长才能继续用。

**千兆以太网**

Gigabit Ethernet（原文写作 IEEE 802.3ab，1998）：

- 100 Mbps → 1000 Mbps（1 Gbps）
- 保留原有工作方式（帧格式、接口、过程规则）。
- 支持全双工和半双工两种工作方式。
- 半双工方式下使用 CSMA/CD，增加**载波扩充**和**帧突发**。
- 全双工方式不需要使用 CSMA/CD（缺省方式）。
- 流量控制和巨型帧（Jumbo frame）。

（更正：原文此处写「IEEE 802.3ab，1998」，与同一份资料第 184 页的年表矛盾。年表里 1998 年是 802.3z 的 1000Base-X，2000 年才是 802.3ab 的 1000Base-T。考试按年表答。）

【为保证 CSMA/CD 继续工作，电缆的最大长度再降低到快速以太网的十分之一？】这句是原稿作者自己打的问号，原文没有给答案，照录在这里。可以这样理解他的疑问：按快速以太网那一步的推法，速率再涨十倍，跨距就该再缩十倍到 10 m，那样根本没法用，所以千兆以太网改用了载波扩充（把短帧填到 512 字节）和帧突发这两个办法，而不是继续砍电缆长度。这段解释不在原文里，答题时只写「原文对此存疑」也不算错。

千兆以太网的几种物理层（原文第 187 页表）：

| 名称 | 线缆 | 最大长度 | 编码方式 | 优点 |
| --- | --- | --- | --- | --- |
| 1000Base-SX | 光纤 | 550 米 | 8b/10b | 多模光纤（50、62.5 微米） |
| 1000Base-LX | 光纤 | 5000 米 | 8b/10b | 单模光纤（10 微米）或多模光纤（50、62.5 微米） |
| 1000Base-CX | 2 对 STP | 25 米 | 8b/10b | 屏蔽双绞线 |
| 1000Base-T | 2 对 UTP | 100 米 | 4D-PAM5 | 标准 5 类 UTP |

**万兆以太网**

10-Gigabit Ethernet（IEEE 802.3ae，2002）：

- 1 Gbps → 10 Gbps
- 常记为 10GE、10GbE 或 10GigE
- **只支持全双工，不再使用 CSMA/CD**
- 重点是超高速的物理层

| 名称 | 线缆 | 最大长度 | 编码方式 | 优点 |
| --- | --- | --- | --- | --- |
| 10GBase-SR | 光纤 | 最多 300 米 | 64b/66b | 多模光纤（0.85 微米） |
| 10GBase-LR | 光纤 | 10 千米 | 64b/66b | 单模光纤（1.3 微米） |
| 10GBase-ER | 光纤 | 40 千米 | 64b/66b | 单模光纤（1.5 微米） |
| 10GBase-CX4 | 4 对双轴 | 15 米 | 8b/10b | 双轴铜缆 |
| 10GBase-T | 4 对 UTP | 100 米 | 64b/65b | 6a 类 UTP |

**40G 和 100G 以太网**

40 Gigabit Ethernet（40GbE）和 100 Gigabit Ethernet（100GbE），2010 年：

- 10 Gbps → 40 Gbps 和 100 Gbps
- 只支持全双工
- 保留以太网帧格式和 MAC 方法
- 保留当前 802.3 标准的最小帧和最大帧大小
- 联网设备可以通过可插拔模块支持不同的物理层类

**以太网的未来**

25/50G 和第二代 100G 以太网：

- 25G 以太网标准（IEEE 802.3by）于 2014 年发布，弥补了 10G 以太网的低带宽和 40G 以太网的高成本缺陷。采用 25 Gb/s 单通道物理层技术，可基于 4 个 25 Gbps 光纤通道实现 100G 传输。
- 未来速度预期：以太网联盟的 2020 技术路线图预计，2020 年到 2030 年之间，800 Gbps 和 1.6 Tbps 的速度将成为 IEEE 标准。

一条贯穿始终的线索：速率越往上走，CSMA/CD 的地位越低。10 Mbps 全靠它，千兆只在半双工下用，万兆之后直接废掉。

### 静态分配与动态分配

| | 静态分配 | 动态分配 |
| --- | --- | --- |
| 做法 | 预先把信道切成 N 份分给 N 个用户 | 谁要用谁临时去抢或去要 |
| 利用率 | 用户不发数据时那份资源也空着 | 高 |
| 延迟 | 延迟时间增大 N 倍 | 取决于协议 |
| 适用 | 用户少且固定、通信量大且流量稳定 | 突发性业务 |

### 纯 ALOHA 与分隙 ALOHA

| | 纯 ALOHA | 分隙 ALOHA |
| --- | --- | --- |
| 何时可发 | 任意时间 | 只能在时隙起点 |
| 冲突危险期 | $2D$ | $D$ |
| 冲突发生位置 | 随时 | 只在时隙起点 |
| 是否需要全网同步 | 不需要 | 需要 |
| 峰值吞吐量 | 约 0.18 | 约 0.37 |

### MA、CSMA、CSMA/CD

| | MA | CSMA | CSMA/CD |
| --- | --- | --- | --- |
| 口诀 | 不听就说 | 先听后发 | 边听边说 |
| 发前是否侦听 | 否 | 是 | 是 |
| 发中是否侦听 | 否 | 否 | 是 |
| 冲突后损失 | 整帧作废 | 整帧作废 | 检测到就立刻停，损失小 |

### Ethernet V2 与 IEEE 802.3

| | DIX Ethernet V2 | IEEE 802.3 |
| --- | --- | --- |
| 第 13、14 字节 | 类型，值大于 1500 | 长度，值小于等于 1500 |

| 常见程度 | 实际网络里几乎都是它 | 教材和考题里出现得多 |

### 543 规则与 5-4-3-2-1 原则

两者说的是同一套经典以太网组网限制。543 只列了网段数、中继器数、可接终端的网段数三项；5-4-3-2-1 多出「至少 2 个链路段」和「最多 1 个冲突域」两项。看题目问几项答几项。

## 典型题

以下三题的完整演算写在 `14 计算题精练.md`，这里只列条件、公式和答案，方便自测。

### 例 1：最短帧长与最大系统跨距（`14 计算题精练.md` 题 11）

以太网规定最短帧长 64 字节，速率 10 Mbps，电子传播速度 200 m/µs。求最大系统跨距。

代入 $L_{min} = \dfrac{2R \times S}{V}$，得 $512 = \dfrac{2 \times 10 \times S}{200}$，解出 $S = 5120$ m。

顺带算出单程传播时延 $\tau = 5120/200 = 25.6$ µs，争用期 $2\tau = 51.2$ µs，正好等于发送 512 bit 所需的时间。这三个数一起记。

### 例 2：二进制指数退避（`14 计算题精练.md` 题 12）

已知重传次数 $k$，问退避时间可能取哪些值。

按 $t = r \times 2\tau$， $r \in \{0,1,\dots,2^{\min(k,10)}-1\}$ 随机取。以太网 $2\tau = 51.2$ µs。第 1 次重传可能等 0 或 51.2 µs；第 2 次在 0、51.2、102.4、153.6 µs 里选；第 12 次及以后集合固定为 $\{0,\dots,1023\}$。重传满 16 次仍不成功就放弃并向高层报告。

### 例 3：CSMA/CD 信道效率（`14 计算题精练.md` 题 13）

按 $\text{信道效率} = \dfrac{1}{1 + 2BLe/(cF)}$ 代数。要能口头说出结论：帧长固定时，带宽翻倍或电缆拉长一倍，效率都会掉。
