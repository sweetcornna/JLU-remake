# 数据链路层：流量控制与差错控制

整理自 `笔记/计算机网络.pdf` 第 81 页到第 104 页，对应原文第四章的 4.1 线路规程和 4.2 流量控制与差错控制。同一章里的 HDLC 协议和网桥放在 `06 HDLC 协议与网桥.md`。

## 本章要点

- 数据链路层把不可靠的物理链路变成可靠的数据链路，传输单位是**帧**。要干的活是线路规程、差错控制、流量控制。
- 线路规程有两套：ENQ/ACK 用在两端地位平等的专用链路，Poll/Select 用在一主多从的多点链路。
- 流量控制管发送方发多快，差错控制管出错了怎么重传。考试里这两个定义经常一起考。
- 停等协议发送窗口和接收窗口都是 1，帧编号只需要 0 和 1。$WT$、信道利用率、有效数据传输率、传输效率这一套公式要会算。
- 滑动窗口按模 n 编号。回退 N 的发送窗口 $\le n-1$；选择拒绝的发送窗口加接收窗口 $\le n$。这两条不等式必考，而且要能说清为什么。
- ACK 编号的含义在两个协议里不一样：回退 N 里指期望收到的下一帧，选择拒绝里指已经正确收到的帧。这是最容易记混的一处。

## 数据链路层的职责

数据链路层提供两个**相邻**网络节点之间的可靠通信，把不可靠的物理链路变成可靠的数据链路。

"相邻"的意思是不需要找路：同一条总线上的两个站点相邻，同一个环上的两个站点也相邻。

传输的信息单元是**帧**（Frame）。主要工作有三项：线路规程、差错控制、流量控制。

## 4.1 线路规程

线路规程负责监视链路的建立，以及在给定时刻把数据传送权分配给某个具体设备。两种实现方式：

1. 询问/应答（ENQ/ACK）。发送方先发 ENQ 控制字符问接收方准备好了没有，接收方准备好就回 ACK，没准备好就回 NAK。属于异步通信协议，靠一问一答保证同步和正确。
2. 轮询（Poll）/选择（Select）。主设备周期性地向从设备发轮询信号，问它们有没有数据要发。从设备有数据要发时，由主设备用选择信号把它选中，然后传输。用在多设备环境。

### 4.1.1 询问/确认模式

使用场合：两个设备之间有一条**专用链路**，也就是点对点方式。只要链路两头的设备级别相同，任意一个设备都可以启动会话。【平等 + 链路专用】

工作方式三步：

1. 启动方发询问帧 ENQ，问接收方能不能收数据。
2. 接收方准备好了，回确认帧 ACK。
3. 接收方没准备好，回否认帧 NAK。

启动方发出 ENQ 之后会遇到 3 种情况：没有应答、回答是否定、回答是肯定。

### 4.1.2 选择/轮询模式

使用场合：**多点连接**系统。这种环境下不光要确定设备就绪没有，还要确定哪一个站点有权使用信道。

工作方式：主设备管理和控制链路，主设备发命令，从设备响应。链路上每个设备都有唯一地址来标识自己。

选择（Select），主设备想**发**数据时用：

1. 主设备发送选择信号 SeL，告诉从设备准备接收数据。
2. 从设备准备好了就回 ACK 同意接收，拒绝接收就回 NAK。

轮询（Poll），主设备想**收**数据时用：

1. 主设备逐个询问从设备有没有数据要发送。
2. 从设备没有数据发送时，必须回一个否定应答帧 NAK。有数据就直接用数据帧应答。

终止信息交互有两种方法：

1. 传输结束帧 EOT。从设备把所有数据发完之后，发一个 EOT 结束传输。
2. 时间到消息。主设备在一定时间之后发出"时间到"消息，结束当前的通信轮次。

## 4.2 流量控制与差错控制

**流量控制**是确保发送方不会溢出接收方缓冲区的一组过程。【主要控制发送方】

1. 防止接收方过载。数据流的速率要和接收方的处理能力匹配。
2. 接收方确认数据。接收方要对收到的数据做确认，发送方才知道数据有没有成功收到。

**差错控制**主要指错误检测和重传方法，目的是保证数据可靠传输。

自动重复请求（ARQ）：数据帧在传输过程中出错时，接收方返回一个否定应答帧 NAK，触发发送方重传出错的帧。

数据被重传的三种常见情况：

1. **帧破坏**。数据帧在传输过程中被破坏。
2. **帧丢失**。数据帧在传输过程中丢失。
3. **应答帧丢失**。数据帧已经被接收方成功收到，但是发送方没收到确认帧。

流量控制和差错控制通常结合在一起实现。实现这两件事的技术有两种：

1. 停止等待协议。发送方每发一帧就停下来，等到确认帧才继续。简单，但效率低。
2. 滑动窗口协议。发送方在收到全部确认之前可以连着发多个帧，效率更高。靠序列号和确认应答控制数据流，必要时重传。

### 4.2.1 停止等待协议【半双工】

流量控制的做法：

1. 发送方每发一帧就停止发送，等接收方的 ACK。
2. 收到一个 ACK 之后才发下一帧。
3. 一直持续到发送方发出一个传输结束帧。

优点是简单，容易实现。缺点有四条：

- 效率低。每次只能发一帧，发完还要等 ACK。
- 单帧传输。任何时刻线路上只有一帧在传输。
- 等待时间长。设备之间距离很长时，每帧之间等 ACK 的时间会很长，通信延迟大。
- 半双工通信。发送方等 ACK 时不能发下一帧，任意时刻只能发或者只能收。

#### 完成一帧发送所需的最短时间

$$WT = t_I + 2t_p + 2t_{proc} + t_s$$

| 符号 | 含义 | 算法 |
| --- | --- | --- |
| $t_I$ | 发送数据帧时间 | 帧长 / 接口速率 |
| $t_s$ | 发送确认帧时间 | 确认帧长 / 接口速率 |
| $t_p$ | 信号传播时延 | 距离 / 0.7 光速 |
| $t_{proc}$ | 节点处理数据时间 | 题目给出 |

两个 $t_p$ 是数据帧去、确认帧回各走一趟，两个 $t_{proc}$ 是接收方处理数据帧、发送方处理确认帧各一次。（时序图见原文第 88 页）

#### 停止等待协议的定量分析

**（1）无差错情况的信道利用率 $F$**

$$F = \frac{t_I + t_p}{WT} \quad \text{（旧版，基于半双工）}$$

$$F = \frac{t_I}{WT} \quad \text{（新版）}$$

信道利用率的定义是信道被占用的时间和总时间之比。两个版本的差别在于把传播时间算不算成"被占用"。做题时按老师给的口径用，新版更常见。

**（2）无差错情况的有效数据传输率**

$$S = \frac{D_1}{WT}$$

$D_1$ 是一帧里的有效数据位数，$WT$ 是发送一帧的时间。有效数据传输率的定义是单位时间内传输的有效数据位数。注意分子只算数据位，帧头帧尾不算。

**（3）有差错时正确传送一帧的平均时间**

无差错情况下发送一帧的最小时间间隔就是 $WT$，记作 $t_W$。出错率为 $p$ 时，正确发送一帧的平均时间间隔 $t_V$ 为

$$t_V = \frac{t_W}{1-p}$$

推导过程（原文第 90 页有手写推导）：一次成功的概率是 $1-p$，用时 $t_W$；错一次再成功的概率是 $(1-p)p$，用时 $2t_W$；依此类推，

$$t_V = (1-p)t_W + (1-p)p \cdot 2t_W + (1-p)p^2 \cdot 3t_W + \cdots = (1-p)t_W\left(1 + 2p + 3p^2 + \cdots\right)$$

括号里的级数记作 $S$，用错位相减：$S - pS = 1 + p + p^2 + \cdots = \dfrac{1}{1-p}$，所以 $S = \dfrac{1}{(1-p)^2}$，代回就得到 $t_V = \dfrac{t_W}{1-p}$。

**（4）系统的最大吞吐量和极限吞吐量**

最大吞吐量（每秒成功发送的帧数）：

$$\lambda_{max} = \frac{1}{t_V} = \frac{1-p}{t_W}$$

极限吞吐量（信道一刻不停地发数据能达到的上限）：

$$M = \frac{1}{t_I}$$

**（5）系统的传输效率**

$$\rho = \frac{\lambda_{max}}{M} = \frac{(1-p)/t_W}{1/t_I}$$

令 $a \equiv t_W / t_I > 1$，则

$$\rho = \frac{1-p}{a}$$

$\rho$ 和 $a$ 成反比，$a$ 越小效率越高。$a$ 的物理意义是"发一帧的总开销时间是纯发送时间的几倍"，距离越远、$t_p$ 越大，$a$ 就越大。

#### 停止等待协议中的差错控制

停等协议用 ARQ 处理错误，ARQ 要对付的三种情况还是：帧破坏、帧丢失、应答帧丢失。

对协议的四条要求：

1. 发送站要保留数据帧的**备份**。
2. 数据帧和应答帧必须**交替标识为 0 和 1**。接收方如果收到两个相邻的、编号相同的数据帧，说明收到了重复帧，应当丢弃一个。【帧编号够用就行，因为基于半双工，所以只需要 0 和 1 即可】
3. 用否定应答帧 NAK 通知发送方重发最近的一帧。
4. 用**定时器**判断数据帧在传输中丢失。

### 4.2.2 滑动窗口协议【全双工】

动机是逼近理论上限，也就是极限吞吐量。

- 发送方在收到应答之前可以先发若干帧。
- 接收方用一个 ACK 帧确认多个数据帧的接收。
- 具体能发多少、能收多少，看窗口大小。

两个窗口各管各的：

- **发送方窗口**存放已经发送但还没收到应答的数据帧，以及在收到应答帧之前还可以发的数据帧。
- **接收方窗口**存放已经接收但还没给应答的数据帧。只要窗口没填满，就可以在不发应答帧的情况下继续收帧。

帧编号规则：

- 数据帧按**模 n** 编号，编号从 0 到 $n-1$。
- 窗口大小是 $n-1$。【留有 1 个空位】
- 接收方发的 ACK 帧，编号是**接收方希望收到的下一帧**的编号。

【数据帧丢失，一定会超时重传；确认帧丢失不一定，因为是累积确认】

#### 滑动窗口协议中的差错控制

滑动窗口同样用 ARQ，分两种：

1. **回退 N**（Go-back-N）。【对接收方来说，不需要排序，比较简单；但是效率相对较低】
2. **选择拒绝**（Select-Rej）。【对接收方来说，需要排序；效率相对较高】

两者的共同要求：

1. 保留数据帧的备份。发送站必须保留已发送数据帧的备份，直到收到对应的 ACK 或者超时需要重传。
2. 发送否认帧。接收方除了发 ACK，还可以发 NAK，告诉发送方某个帧接收损坏或错误，需要重发。
3. 定时器。发送方用定时器判断数据帧是不是在传输中丢了，超时就重传。

### 回退 N 自动重复请求

一帧丢失或者损坏了，从最近一次得到应答的数据帧开始，**未被应答的所有帧全部重传**。

差错情况有三种。（时序图见原文第 95、96 页）

**（1）帧破坏**

A 站点连发 0 到 5 号帧。B 站点正确收到 0、1、2 号，回 ACK3。3 号帧到达时有错，B 回 NAK3。这时 A 已经把 4、5 号发出去了，B 因为没有正确收到 3 号帧，后面的帧一律不接收、直接丢弃。A 收到 NAK3 之后从 3 号开始重发 3、4、5。

**（2）数据帧丢失**

A 连发 0 到 4 号帧，2 号帧在路上丢了。B 收到 0、1 之后等的是 2 号，结果来的是 3 号，于是回 NAK2 并丢弃 3 号。随后到达的 4 号同样丢弃。A 收到 NAK2 之后从 2 号开始重发 2、3、4。

**（3）确认帧丢失**

A 连发 0、1、2 号帧，B 全部正确收到，回 ACK3，但是 ACK3 在路上丢了。A 等不到应答，定时器超时，把 0、1、2 全部重发一遍。B 这次收到的是重复帧，丢弃后重新回一个 ACK3。

原文第 97 页还有一张窗口滑动图，上方是发送方、下方是接收方：接收方 1 号帧出错发 NAK1，之后到达的 2、3 号帧被丢弃（图上标"1-3 帧丢弃"），发送方收到 NAK1 后重发 1、2、3。

#### 窗口的大小与编号范围的关系

在回退 N 协议中，如果帧的编号范围是 0 到 $n-1$，则**发送窗口的尺寸为 $n-1$**。【留有 1 个空位】

原文以 $n=8$ 举例说明为什么不能取 8（时序图见原文第 98 页）：

- **窗口尺寸等于 $n$ 时协议失败**。$t_1$ 时刻 A 发数据帧 0 到 7，$t_2$ 时刻 B 按顺序收全，发 ACK0，这个 ACK0 丢失。A 超时，$t_3$ 时刻重发 0 到 7。$t_4$ 时刻 B 收到的帧编号正好是它期望收到的编号（下一轮从 0 开始），于是把它们当成新帧，实际上全是重复帧。
- **窗口尺寸等于 $n-1$ 时协议成功**。A 发 0 到 6，B 收全后发 ACK7，ACK7 丢失。A 超时重发 0 到 6。B 期望收到的是 7 号，来的却是 0 到 6，编号对不上，于是判定为重复帧。协议正确。

一句话记法：**留一个空位，让"重发的旧帧"和"期望的新帧"编号错开**。

### 选择拒绝自动重复请求（Select-Rej）

只重传特定的丢失或损坏的帧，不从出错帧开始全部重发。

特点：

- **乱序接收**。接收方可以收到不按顺序到达的数据帧。
- **特定帧重传**。只有特定的丢失或损坏帧被重发。

与回退 N 的四点不同：

1. **排序功能**。接收设备必须具有排序功能，才能正确地重新排列乱序到达的帧。接收方发了 NAK 帧之后，必须存储所收到的所有帧，直到损坏的帧被重新收到为止。
2. **查找机制**。发送设备必须具有查找机制，才能发现和选择需要重传的帧。
3. **存储所有帧**。在所有重传帧被排序、所有重复帧被辨别出来并删除之前，收到的所有帧都必须保存。
4. **ACK 和 NAK 帧的编号**。ACK 帧的编号指的是**被正确接收的帧编号**（不是期望接收的帧编号，这一点和回退 N 相反）。NAK 帧的编号指的是错误或丢失的帧。

三种差错情况。（时序图见原文第 99、100 页）

**（1）帧破坏**

A 连发 0 到 5 号帧。B 正确收到 0、1，2 号帧有错，回 NAK2，然后继续把 3、4、5 号收下来缓存着。A 收到 NAK2 之后只重发 2 号。B 补齐 2 号、排好序之后回 ACK5，表示 0 到 5 都已正确收到。

**（2）数据帧丢失**

A 连发 0 到 5 号帧，2 号丢失。B 收到 3 号时发现缺 2 号，回 NAK2，同时继续收 4、5 号。A 只重发 2 号。B 补齐之后回 ACK5。

**（3）确认帧丢失**

发送窗口满时，或者传输完毕时，启动定时时钟。如果在预定时间段内没有应答到来，发送方把尚未应答的所有帧都重传一遍。这一点和回退 N 一样。

#### 窗口的大小与编号范围的关系

如果帧的编号范围是 0 到 $n-1$（模 n 编号），则

- 发送窗口尺寸 + 接收窗口尺寸 $\le n$；
- 如果要求发送窗口和接收窗口大小相等，则窗口尺寸 $\le n/2$。

原文仍以 $n=8$ 举例，反例是发送窗口取 5、接收窗口取 4（和为 9，超过 8）。（时序图见原文第 101 页）

- **发送窗口太大，协议失败**。A 发 0 到 4。B 收到 0 到 3 发 ACK3 并移动窗口，又收到 4 号发 ACK4 再移动窗口，此时可接收 5、6、7、0 帧。ACK3 和 ACK4 都丢了。A 超时重发 0 到 4，B 收到数据帧 0 落在自己的接收窗口里，当成新帧收下，其实是重复帧。
- **接收窗口太大，协议失败**。A 发 0 到 3。B 收全后发 ACK3 并移动窗口，可接收 4、5、6、7、0 帧（接收窗口是 5）。ACK3 丢失，A 超时重发 0 到 3。B 又把数据帧 0 当成新帧，其实是重复帧。

【选择拒绝 ACK 帧的编号指的是被正确接收的帧编号，不是指期望接收的帧编号】

### 窗口大小的选择【对于滑动窗口】

窗口大小直接决定传输效率和资源占用，太大太小都有代价。

1. 大窗口
   - 缓存空间要求高。已发送但未确认的帧都要存着。
   - 内存资源消耗大，在内存有限的系统上尤其明显。
2. 小窗口
   - 传输延迟。可能在第一个应答帧返回之前，发送方窗口里的帧就已经全发完了。
   - 效率问题。发送方在收到新的应答之前发不了新帧，只能干等着，拖慢传输。

计算条件：设一帧的发送时间为 $t_I$、传播时间为 $t_P$，窗口大小 $n$ 应该满足

$$n \cdot t_I > 2(t_I + t_P)$$

或者写成

$$n \cdot t_I > t_I + 2t_P + t_s$$

两个式子的思路一样：**窗口里所有帧发完所花的时间，要大于第一个确认帧回来所需的时间**，这样发送方才不会闲下来。第二个式子把确认帧的发送时间 $t_s$ 也算进去了，更接近 $WT$ 的定义。

### 滑动窗口协议中回退 N 的效率

正确传送一帧所需的平均时间：

$$t_V = t_I + \frac{p\,t_w}{1-p}$$

展开式是

$$t_V = (1-p)t_I + p(1-p)(t_I + t_W) + p^2(1-p)(t_I + 2t_W) + \cdots$$

系统最大吞吐量：

$$\lambda_{max} = \frac{1}{t_V} = \frac{1-p}{t_I\left(1 + p(a-1)\right)}$$

系统的传输效率：

$$\rho = \frac{1-p}{1 + p(a-1)}, \qquad a = \frac{t_w}{t_I}$$

和停等协议的 $\rho = (1-p)/a$ 对比着记：回退 N 因为不用每发一帧就等一次，分母里的 $a$ 被 $p$ 打了折扣，$p$ 越小分母越接近 1，效率越接近满值。

## 易混对比

### 询问/确认模式与轮询/选择模式

| 对比项 | 询问/确认（ENQ/ACK） | 轮询/选择（Poll/Select） |
| --- | --- | --- |
| 使用场合 | 点对点专用链路 | 多点连接系统 |
| 设备关系 | 两端级别相同，谁都能发起会话 | 一主多从，主设备控制链路 |
| 要解决的问题 | 对方是否就绪 | 对方是否就绪 + 谁有权使用信道 |
| 主设备想发数据 | 发 ENQ | 发 SeL（选择） |
| 主设备想收数据 | 不区分 | 发 Poll（轮询） |
| 从设备无数据可发 | 不适用 | 必须回 NAK |
| 终止方式 | 传输结束帧 | EOT 或主设备的"时间到"消息 |

### 流量控制与差错控制

| 对比项 | 流量控制 | 差错控制 |
| --- | --- | --- |
| 解决什么 | 发送方发得太快，撑爆接收方缓冲区 | 帧出错、丢失，确认丢失 |
| 控制谁 | 主要控制发送方 | 发送方重传，接收方检错 |
| 核心手段 | 窗口、确认 | ARQ（NAK + 定时器 + 备份） |
| 典型技术 | 停止等待、滑动窗口 | 回退 N、选择拒绝 |

### 三种协议方法总结（原文第 104 页表格）

| 方法 | 窗口大小 | 是否有序接收 | 做法 |
| --- | --- | --- | --- |
| 停止-等待协议 | 发送 : 接收 = 1 : 1 | 有序 | 发送窗口每次只能发送一个数据包，然后就停止等待 ack 包。接收窗口有序地接收数据包，接收成功后发送 ack 包给发送窗口，如果收到的数据包是无序的，就直接丢弃 |
| 回退 N 步协议 | 发送 : 接收 = N : 1 | 有序 | 发送窗口每次最多一次性发送 n 个数据包，接收窗口有序地接收数据包，当接收到有序的数据包后，发送 ack 包给发送窗口，如果收到的数据包是无序的，就直接丢弃。当数据包丢失的时候，会将发送窗口中的后面的所有数据包都重新发送 |
| 选择重传协议 | 发送 : 接收 = N : N | 无序 | 发送窗口每次最多一次性发送 n 个数据包，接收窗口无序地接收数据包，当接收到数据包后，发送 ack 包给发送窗口，ack 中会携带 SACK 信息，也就是接收窗口中的缓存信息。发送端会根据 SACK 信息来只重传丢失的数据包 |

【个人感觉 1 其实是窗口接受/发送帧的数量】

原文同一页还按协议列了特点和适用场景：

| 协议 | 发送窗口 | 接收窗口 | 特点 | 适用场景 |
| --- | --- | --- | --- | --- |
| 停止等待 | 1 | 1 | 简单易实现；每次只发一帧，吞吐量低；半双工 | 数据传输速率较低、传输距离较短 |
| 回退 N | >1 | 1 | 允许连发多帧，吞吐量提高；一帧出错就要重传它之后的所有帧；发送方需缓存所有未确认帧 | 传输速率较高、错误率较低的网络 |
| 选择拒绝 | >1 | >1 | 只重传损坏或丢失的帧，效率高；接收方要能排序和缓存乱序帧；收发两端都需要较大缓存 | 高速、高吞吐量、错误率较高的网络 |

### 回退 N 与选择拒绝

| 对比项 | 回退 N | 选择拒绝 |
| --- | --- | --- |
| 接收窗口 | 1 | >1 |
| 接收方是否排序 | 不排序，乱序帧直接丢弃 | 必须排序并缓存乱序帧 |
| 重传范围 | 出错帧及其之后的所有帧 | 只重传出错的那一帧 |
| ACK 编号含义 | 期望收到的下一帧编号 | 已经正确收到的帧编号 |
| NAK 编号含义 | 被损坏的数据帧编号 | 错误或丢失的帧编号 |
| 发送方是否需要查找机制 | 不需要 | 需要 |
| 窗口与编号关系 | 发送窗口 $\le n-1$ | 发送窗口 + 接收窗口 $\le n$；两者相等时各 $\le n/2$ |
| 实现复杂度 / 效率 | 简单，效率低 | 复杂，效率高 |

### 例 1：停等协议的信道利用率与有效数据传输率

接口速率 $C = 10$ Mbps（即 10 bit/µs），信号传播速度 $S = 200$ m/µs，收发双方距离 $D = 200$ m，节点处理时间 $t_{proc} = 1$ µs，一帧 200 bit（其中有效数据 160 bit），一个确认帧 40 bit。求信道利用率和有效数据传输率。

答案：$t_I = 200/10 = 20$ µs，$t_s = 40/10 = 4$ µs，$t_p = 200/200 = 1$ µs，

$$WT = 20 + 2 \times 1 + 2 \times 1 + 4 = 28\ \mu s$$

信道有效忙碌的时间是 $t_I = 20$ µs，所以信道利用率 $= 20/28 \approx 71.4\%$，有效数据传输率 $= 160/28 \approx 5.7$ Mbps。

（原文第 89、90 页，条件和过程都在那两页的幻灯片截图里。）

### 例 2：卫星通信的最小窗口

在卫星通信中，帧长 1200 bit，信道速率 4.8 kbit/s，传播延迟 $t_P = 250$ ms。全双工数据通信下，窗口至少应为多少？

答案：$t_I = 1200 / (4.8 \times 10^3) = 0.25$ s $= 250$ ms。代入 $n \cdot t_I > 2(t_I + t_P)$ 得

$$n > \frac{2 \times (250 + 250)}{250} = 4$$

即 $n > 4$，窗口**至少取 5**。
